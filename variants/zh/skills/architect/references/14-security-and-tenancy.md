# 安全与多租户（Security and Tenancy）

把安全当结构而非补丁：威胁建模、信任边界、纵深防御、爆炸半径、多租户隔离、密钥管理、供应链与合规。适用于设计涉及敏感数据、多租户、对外攻击面或 agent 工具权限的系统。

## 威胁建模：系统性地想坏事

新人做安全靠想起来就加一道：加个登录、加个 HTTPS、上线前跑个扫描。这是补丁思维，零散被动。架构师做安全是先把系统摊开，对每条数据流、每道信任边界系统性地追问会被怎么攻破。

STRIDE 六问（微软 1999）：假冒身份（S，破坏认证）、篡改数据（T，破坏完整性）、抵赖（R，破坏不可否认性）、信息泄露（I，破坏机密性）、拒绝服务（D，破坏可用性）、提权（E，破坏授权）。对着数据流图逐条排查每个进程、存储、数据流、信任边界。不用背字母，记住六件坏事：假冒你、改你数据、干完赖账、偷看不该看的、把你打挂、把自己变成管理员。

灵魂是**信任边界**：数据每次跨越边界（公网→网关、网关→服务、服务→数据库），信任级别都在变，坏事几乎总发生在边界上。外部输入跨进内部（注入）、低权限跨向高权限（提权）、敏感数据跨出系统（泄露）。防御资源按边界精准投放，不是均匀撒。网关边界主要防假冒和拒绝服务，服务边界主要防越权和篡改，数据边界主要防拖库泄露。

安全的结构性和其他属性不同：性能、可用性可以先上线再优化，安全的结构性漏洞往往上线即定型、事后补不上。

## 纵深防御与零信任

城堡与护城河模型的致命假设是内网默认可信。攻击者一旦突破边界（钓鱼、漏洞、内鬼），就在内网横着走（横向移动），SolarWinds 把单点突破放大成全军覆没靠的就是这招。远程办公、上云、微服务东西向流量爆炸，那道墙本身已经塌了。

纵深防御：别指望一道墙，层层设防（WAF → 鉴权 → 授权 → 加密 → 隔离 → 审计），攻破一层还有下一层。零信任：取消内网可信假设，从不信任、始终验证——不管请求来自公网还是内网，每次访问都重新验证身份、检查授权、加密传输；信任绑在用户 + 设备 + 请求上下文上，不绑网络位置。Google BeyondCorp 是最有名的落地：全员不用 VPN，所有应用部署公网，访问代理按身份、设备状态、资源敏感度动态放行。零信任不省事，有摩擦有开销，换来的是单点突破不再等于全盘沦陷。

最小权限贯穿两者：每个组件、每个账号只拿干活必需的那一点点权限，多一分不给。

## 爆炸半径

安全做到极致也无法保证永不被攻破，成熟的安全观从"绝不出事"转向"一旦出事能波及多大"。隔离就是把一次失误的代价关进小格子：攻击者拿到一个服务的权限，够不到别的服务的数据；偷到一个租户的口令，看不见别的租户。

缩小爆炸半径的手段：最小权限、网络分段（服务间只开必要端口）、凭证隔离（每服务一套密钥）、短时凭证（令牌几分钟过期，偷到也用不了多久）。故障隔离和安全隔离用同一套结构武器——舱壁、限流、熔断换个视角也在防攻击扩散：一个被攻陷开始疯狂发请求的组件，和一个故障疯狂重试的组件，伤害形态一样。为可用性建的舱，顺带在为安全服务。

## 多租户隔离谱系

多租户是 SaaS 的基本盘，好处是成本（共用基础设施），头号噩梦是租户串扰：A 公司的数据被 B 公司看到，最严重、最易上头条、最易流失客户。

隔离是谱系不是开关，核心取舍成本 vs 隔离强度：池化（所有租户共享一套资源，成本最低、隔离全靠代码纪律）→ 桥接（部分共享部分独立，如网关共享库独立）→ 竖井（每租户独立资源，隔离最硬合规最稳、成本随租户数线性涨）。数据隔离维度从软到硬：行级（同一张表靠 `tenant_id` 列）→ Schema 级 → 库级 → 物理级（独立物理机/账号）。

**行级隔离是串扰事故的头号温床。** 整个隔离只靠每条 SQL 都正确带上 `WHERE tenant_id = ?`。一处遗漏就灾难：新接口忘加条件、缓存键没带租户前缀（`user:123` 而非 `tenant:7:user:123`）、对象存储路径用可猜的自增 ID、后台任务跑全表、接口只校验登录没校验归属（IDOR）。这些漏点不报错、能跑通、测试常发现不了（开发自测只有一个租户的数据）。Salesforce 是池化的工业级范本：一套共享关系库承载单实例 8000+ 租户，关键在隔离不靠开发者自觉，靠平台层强制注入租户过滤 + 元数据驱动。

判断尺子：这份业务里租户串扰的代价多大。代价低（公开内容平台）池化省钱；代价高（医疗、金融、政企）往竖井走，贵几倍也值。**无论哪档，隔离强度可以按成本谈，但有一条不可谈：隔离必须由结构保证，不能靠人自觉**：平台层自动注入租户条件、ORM 全局过滤、自动化测试专门验证跨租户读不到。

## 密钥管理

系统里最值钱的是密钥与凭证，是爆炸半径最大的一类。三条铁律：集中保管、定期轮换、最小暴露。

最致命的错误是 secrets 进代码库：一旦 commit，它永远活在 Git 历史里，事后删文件没用；仓库被克隆/开源/泄露等于钥匙抄送全世界。扫描机器人盯新提交，几秒薅走误传的 AWS key 去挖矿。结构性做法：密钥从不进代码，用密钥管理服务（Vault/KMS/Secrets Manager）托管，运行时注入，CI 加 secret 扫描。轮换给已泄露的密钥止损，短时凭证让偷到的钥匙速朽，最小暴露让每把钥匙只开一扇门。Capital One 的反面教材：一个 SSRF 漏洞 + 权限过大的 IAM 角色（能访问 700 多个 S3 桶）= 1.06 亿人数据泄露——最小权限到位的话，那次入侵本该被关进一个小盒子。

**任何会被 grep 到、被 commit 到、被打进日志的明文，都该假设它已经泄露。**

## 供应链安全

现代软件自己写的代码可能只占 5%，其余 95% 是依赖：开源库、基础镜像、CI/CD 工具、构建脚本。攻击面绝大部分是别人的代码。信任是传递的：信任一个库等于信任它的所有依赖、维护者、构建流水线，链上任何一环被攻破，毒顺流而下波及全网。

两个反直觉放大效应。深度：手写依赖几十个，传递依赖成百上千——Log4Shell 波及广正因为无数团队不知道自己间接依赖了 Log4j。自动化：投毒的依赖可以无人值守地被构建进产物推上生产——SolarWinds 更是直接攻陷构建系统，让带正确签名的官方更新本身就是毒。

结构性做法：锁定版本（别盲目自动升到最新）、生成 SBOM（搞清楚到底用了什么）、扫描已知漏洞和可疑变更、最小化依赖（不用的库是白送的攻击面）、可复现构建（同样源码必出同样产物，投毒藏不住）。xz 后门的教训：近三年的社会工程渗透开源项目，后门藏在发布 tarball 里躲过代码审查，没被任何安全扫描发现，是被工程师偶然注意到 SSH 登录慢了 0.5 秒才揪出来的。"它是有名的开源库，应该没问题"这种盲目信任正是攻击者精心设计要利用的假设。

## 合规即架构

数据驻留、审计留痕、可删除权（GDPR 被遗忘权）、数据最小化，不是法务事项、不是上线后的开关，是结构性约束，事后加不上：数据驻留逼你按地域分区数据层（全球数据混在一个库，事后想摘出欧盟用户等于重做数据层）；可删除权几乎无法满足——数据散落在十几服务、几十张表、N 份备份里，还流进数仓和日志，所以数据归属必须从第一天织进结构；审计留痕要提前埋点；数据最小化从一开始就决定哪些字段根本不收。合规、安全、可用性这类结构性约束，越早纳入越便宜，越晚补越贵，贵到某个点就只能重做。

## AI 带来的两条新攻击面

**AI 生成代码**：会一本正经编出不存在的包名（Lanyi et al., "We Have a Package for You!", USENIX Security 2025：跨 16 个模型，推荐的包 19.7% 不存在）。攻击者抢注 AI 爱编的假包名投毒，坐等开发者照建议安装——slopsquatting，比 typosquatting 更阴险因为它规模化和可预测（同一模型对同类问题稳定幻觉同一批名字）。AI 代码还常默认不安全：拼接 SQL、关证书校验、硬编码密钥、漏鉴权、CORS 全开。治理靠结构：AI 推荐的包先核实真实存在且可信；安全门禁（code review/SAST/secret 扫描）不因"是 AI 写的"放松；把 AI 产出当不可信的初级贡献者的 PR。

**提示注入**：OWASP GenAI LLM Top 10（2025 版 LLM01，前版亦居首位）。根因是 LLM 把指令和数据放同一通道、无法可靠区分，藏在网页、检索结果、工具返回里的恶意文本可能被当命令照做。和 SQL 注入本质不同：参数化查询能根治 SQL 注入，提示注入是 LLM 本质特性，堵不死只能层层防。EchoLeak（Alekseev，2025 披露，CVSS 9.3）是首个实锤的生产级零点击提示注入：一封构造的邮件就能诱使 M365 Copilot 读内部文件并外传——微软做了注入分类器还是被绕过。铁律：把一切外部内容当不可信输入；真正的硬约束（沙箱、最小权限、白名单、不可逆操作人工确认）必须落在模型管不到、注入绕不过的结构层，不是写在提示词里求它别学坏。提示词是劝说，结构才是约束。一个只会聊天的模型注入了顶多胡说；一个能跑 shell、能改库、能转账的 agent，注入得手就是真实破坏——工具权限把安全从功能问题推到结构层。
