# 评测驱动架构（Evaluation-Driven Architecture）

把含 LLM 系统里的"够好"变成能检查的判据：明确契约用精确检查，允许多种正确回答的质量问题用代表性案例与语义评分。评测投入跟着失败后果走，小工具先有一份能重复跑的对照，也比空等一座评测平台强。

## 逐字断言不足以覆盖非确定性输出

`assert summarize(x) == "预期的那一句"` 看着很踏实，遇到开放式摘要却可能专门误伤正常改写。采样、模型版本和上下文一变，两次用词不同，意思都对，逐字比较就把好答案也报成 bug。换成事实是否准确、要点是否完整等语义判据。该精确的地方继续精确：输出格式、允许值、鉴权、退款幂等、状态转换，都可以保留相应断言和契约测试。模型会换措辞，不代表退款金额也可以随缘。

更难发现的是**退化无声**。模型升个版本、系统提示改一句，普通问答更流畅了，某类退款政策却开始答错，现有确定性测试未必会红，用户投诉可能先到。用同一批代表性案例对照变更前后，既看整体质量分布，也翻单个失败和高风险类别。平均分涨了，不会自动抵消一笔未经授权的付款。

## eval 三件套

**eval 集**：一批代表性输入 + 每条的期望要点。注意是要点/判据，不是逐字的标准答案。例：用户问"上周买的鞋开胶了能退吗"，期望要点是引用了质保政策、给出明确的能/否、没编造不存在的政策、口吻得体——评要点中了几条，不逐字比对。

**评分**：谁来判够不够好。

| 方式 | 适合 | 代价 |
| --- | --- | --- |
| 规则/程序判定 | 有客观判据（含不含关键词、格式、有没有引用） | 便宜稳定，只能判硬标准 |
| LLM-as-judge | 主观质量（答得好不好、相不相关） | 灵活，但裁判本身也非确定、也会错、也烧 token |
| 人工抽样 | 校准前两者、兜底高价值场景 | 适合定义标准和校准，但受标注者一致性、领域能力和成本限制 |

实务：规则能判的先用规则，主观的用 LLM-as-judge，定期人工抽样校准裁判——别盲信模型裁判，它也是个会出错的模型（比如偏好长答案）。

**门禁。** 评测结果要能影响发布决定，跑完只存一张漂亮报表，挡不住退化。频繁发布或后果重大的用途，适合把相关评测接进 CI；低风险小工具先做简短、可重复的本地对照即可。先定发布判据，再看候选分数，别考完试才改及格线。总分从 0.82 掉到 0.81，单跑一次未必说明变差；总分上涨，高风险类别也可能已经翻车。采用统计质量门禁时：

- 记录模型、提示、数据和解码设置，固定无关因素，明确被测变更；
- 对未授权付款等高风险行为设硬判据，不能通过平均分掩盖失败；
- 总体指标设容忍带而非单线；
- 对含随机组件的环节（采样温度、LLM 裁判）重复运行取均值或成对比较；
- 样本支持时报告效应量和不确定性；否则说明证据限制，增加案例后再判断是否退化；
- LLM 裁判用人工标注集校准并监测偏差（如偏好长答案）。

## 从小步、从真实失败攒起

新手一听评测集就想攒几千条，然后永远没开始。正确姿势：

1. **种子来自线上真实 bad case。** 每一条用户投诉、每一个答错的截图都是最值钱的样本——它们是真实失败，不是想象的失败。先攒十几二十条就能跑起来。
2. **离线 + 在线两条腿。** 离线 eval：固定数据集进 CI，把关上线前。在线 eval：对真实流量抽样打分或影子运行打分，把关上线后——真实分布永远比数据集刁钻。
3. **持续加 case。** 每次发现新的失败模式就固化成一条 eval，和写回归测试一个道理。eval 集是活的，随系统长大。

别等完美的评测集，先用粗糙的把循环跑起来。

## eval 不替代传统测试，是新增一层

确定性部分照样用传统测试，开放式质量另加语义评测。拿退款来说，建议是否符合政策、理由是否充分，需要质量判断；执行是否授权、金额是否正确、重复请求是否只退一次，要用明确断言和契约测试守住。同一条业务路径可以两套都用。不要因为接了 LLM，就把原有测试连人带椅子请出去。

把不确定性挡在副作用之外的设计在这里又兑现了一次：确定的部分还能用确定的方法测。

## eval 的成本与陷阱

把 eval 当架构组件，就要像对待任何组件一样看代价：

- **烧钱耗时。** 每条样本真实调用模型，LLM-as-judge 每评一次又多一次调用。eval 集越大跑得越勤成本越高，要在覆盖度和成本之间权衡。
- **裁判会错。** LLM-as-judge 非确定、有偏见，要人工抽样校准，别把它的分当圣旨。
- **过拟合与老化。** 盯着固定 eval 集调久了会为考高分而优化，对集外样本未必好；业务变了旧 eval 集会过时。持续更新，过时的 eval 比没有更糟。

eval 可以充当 AI 系统的质量适应度函数，把在乎的答案质量变成有记录、能失败、能影响发布的检查。换模型、改提示时，有案例可比、有失败可查，总比闭着眼睛赌它没变差强。门禁按风险和样本证据设，显著退化要追查，失败案例留下来。考过这一套题，证明不了天下的题都会做，未见输入仍要靠上线后的观察与持续补例。
