# AI 时代的架构判断（Architecture Judgment in the AI Era）

AI 对架构师工作的两个根本改变：实现廉价化（vibe coding）与 LLM 系统作为新物种。本篇是总纲，给出"什么变了、什么没变"的判断基准；LLM 系统的具体设计约束见 [AI 系统设计](./02-ai-system-design.md)。

## 两个同时发生的转变

转变 A：AI 改变了"怎么造"。自然语言到代码，实现从稀缺手艺坍塌成几秒生成。转变 B：AI 带来了"造什么"的新物种。LLM 本身成为一类系统的核心零件：对话产品、RAG 知识库、agent 平台、推理服务。

合起来的核心论断：**实现越来越廉价，判断越来越值钱。** 当 AI 几秒产出能跑的代码，护城河不再是"会写"，而是"会判断"——动手前判断这个系统该长什么样、会死在哪、我在拿什么换什么。

## vibe coding 放大一切，包括架构错误

Simon Willison 的区分：不是所有 AI 辅助编程都叫 vibe coding，它特指**不审查就接受 AI 产出的代码**。拿来做玩具、原型绝妙；直接推上生产，等于把一座没读过的房子交给用户住。

危险的机制是产出加速了，判断和验证却未必跟得上。代码写得快，架构错起来也可以很快，技术债还不用排队。demo 跑通之后，仍要追问：外部调用超时怎么办，重试会不会重复扣款，依赖挂了能不能降级，热点会不会压垮分片，网页里的一句提示注入能不能指挥工具。具体有没有遗漏，要查生成的设计、代码和测试，不能凭"AI 写的"就判有罪。原型到生产的鸿沟，不会因为生成速度快就自动填平。审查依据见[审查 AI 产出](./04-reviewing-ai-output.md)。

正确姿势不是拒绝 vibe coding，是带着判断用它：玩具与原型尽情 vibe，验证想法越快越好别过度设计；生产系统 vibe 出草稿、用判断收口，追问 AI 产出的系统数据一致吗、失败了会怎样、规模上来会死在哪、能演进吗、安全边界在哪。把判断喂给 AI：在 `AGENTS.md` 这类记忆文件里写下架构约束与质量目标，让判断变成 AI 持续遵守的护栏。

## LLM 系统的三个新约束

**非确定性。** 同样一句话问两遍，采样、模型版本和上下文变化都可能让答案换个说法，两次却都算对。拿标准答案逐字比对摘要，会把正常改写也判成 bug；退款执行了两次，则不能用"模型有随机性"来解释。确定性行为和明确的不变量继续用断言，开放式质量用代表性输入、期望要点与规则或模型评分来评估。分数掉了，先看掉在哪类问题、后果多大、是否超出运行波动，再决定能不能上线。具体做法见[评测驱动架构](./05-evaluation-driven-architecture.md)。

**上下文工程。** LLM 的上下文窗口是它的工作内存，有限且按 token 计费昂贵。如何在有限昂贵的窗口里放进恰好够用的信息，是 LLM 系统的核心功夫。本质是新的内存层级：上下文窗口（最贵最快）→ 检索 RAG（按需取）→ 长期记忆（跨会话落盘）。塞太多贵且"迷失在中间"，塞太少缺依据瞎答。

**成本/延迟/质量三角。** 强模型质量高但贵且慢，弱模型快省但质量打折，永远在三角里选位置。成本是一等公民：每次调用烧 token，常驻 agent 7×24 地烧。破解手段：模型路由（简单任务小模型）、缓存、批处理、预算上限。

## Agentic 系统是全部传统硬骨头的叠加

自主 Agent 系统不是新领域，是传统分布式难题的叠加态：行动循环必须有步数/成本/超时上限防失控烧钱（降载与熔断）；工具调用要幂等、多步任务像分布式 Saga（一致性）；长任务跑很久、节点会失败、分不清死活、要可恢复（部分失败）；多 agent 协作是分布式 + 扇出放大；提示注入是头号威胁、工具权限要最小化、要沙箱（安全）；agent 作为虚拟同事重塑团队分工（组织）。

所以 Anthropic 反复强调那句话：**能用确定的工作流解决，就别上自主 Agent。** 自主性越强，这些硬骨头叠加得越狠。成熟 agent 产品的灵魂全在如何给放飞的自主性装刹车，而刹车的设计原理就是传统的韧性、一致性、安全工程。

## 什么没有变

需求 → 约束 → 质量属性 → 取舍的思考框架对 LLM 系统照样成立，只是质量属性表里多了成本/延迟/质量/可评测性几行。没有最好的架构只有最合适的：长上下文还是 RAG、强模型还是弱模型、工作流还是 Agent，全是取舍没有银弹。先问为什么再看怎么做：AI 能秒答"怎么做"，但"为什么是它、代价是什么"依然要人来问。

AI 把实现变成商品，把判断的稀缺性推到历史最高。一个能对每个技术选择自然问出"为什么是它、代价是什么、会死在哪"的人，在 vibe coding 时代不是被替代，而是变得前所未有地不可替代。
