# AI 系统设计（AI System Design）

将 LLM 三个新约束（非确定性、上下文、成本三角）与自主 Agent 的硬骨头落成具体设计：工作流还是自主 Agent 的判断、行动循环的刹车、护栏与人审。适用于设计对话产品、RAG、agent 平台等含 LLM 的系统。

## 第一个判断：工作流还是自主 Agent

画任何框之前先做这个决策，它比后面所有设计加起来都重要。Anthropic《Building Effective Agents》的核心建议：**能用确定的工作流解决，就别上自主 Agent。**

判断方法：任务的步骤是不是基本固定、可预先编排？是，用确定性工作流（接单 → 分类 → 检索政策 → 生成方案 → 执行），可预测、好调试、便宜、好评测，大部分智能需求到这里就够了。否（任务开放、必须随机应变、步骤因情况而异），才用自主 Agent，并立刻给它装满刹车。

例如，查物流、退运费、改地址大多是固定流程；只有责任判定模糊、需要多方查证和权衡取舍的少数请求，才需要自主 Agent。可固化的步骤全部固化，只把真正开放的部分留给自主性。可预测性是工程美德。

## 落地三个新约束

**非确定性 → 测试 + 评测 + 执行护栏。** 同一输入两次运行可能走不同路径，摘要也可以有不同的正确写法。攒代表性输入和期望要点，换模型、改提示或改工具时对照检查；风险、容忍带与重复运行怎么判断，见[评测驱动架构](./05-evaluation-driven-architecture.md)。格式、允许值、鉴权和退款幂等照样写断言与契约测试。付款前，执行服务必须检查授权、输入和幂等，并取得政策要求的人工批准，模型一句"我很有把握"不能当付款凭证。能回滚的设计退路，不能回滚的明确批准、补偿或人工恢复路径；保留必要的调用轨迹，出了错才能查到是哪一步。

**上下文 → 当成内存层级来管。** agent 跑十几步上下文会爆。窗口（最贵最快，只放这一步真正需要的）→ 检索 RAG（按需取政策/历史）→ 长期记忆（跨会话落盘）。核心取舍：三条路没有银弹：长上下文简单但贵且模型会迷失在中间；RAG 精准但要维护检索质量；微调改行为但僵化。长任务定期压缩/摘要历史步骤，别让上下文无限膨胀。

**成本/延迟/质量三角 → 路由 + 缓存 + 硬上限。** agent 最烧钱：成本随步数线性涨，一个任务十几步等于十几次模型调用。模型路由（简单子任务给小模型，需要权衡判断才上大模型）；缓存（重复的政策检索、相同子问题复用）；**硬上限最关键**：每个任务设最多 N 步 / 最多 $X / 超时 T，超了就停，转人工——既是省钱也是防失控的生命线。

## 行动循环的刹车

自主 agent 是传统分布式硬骨头的叠加态，设计 agent 就是把刹车逐条装上：

| 难点 | 本质是 | 刹车 |
| --- | --- | --- |
| 行动循环可能原地打转、无限烧钱 | 降载/熔断 | 步数/成本/超时上限 + 重复检测，超限即停 |
| 工具调用有副作用、多步像分布式事务 | Saga/幂等 | 幂等执行；可补偿时定义补偿，不可逆动作明确批准与恢复方式 |
| 长任务跑很久、节点会挂、要可恢复 | 部分失败 | 检查点持久化，断了能续 |
| 多 agent 协作 | 分布式 + 扇出放大 | 从单 agent 起步，扛不动再拆；控扇出 |
| 提示注入是头号威胁 | 安全 | 工具沙箱 + 最小权限，外部内容当不可信输入 |
| 从原型渐进演化 | 演进 | 影子运行验证、灰度放量 |

没有控制阀的 agent 循环，可能变成一台自己烧钱、顺手闯祸的机器。步数、成本和超时上限负责让它停下来；沙箱、最小权限和人审关卡限制它能动什么；调用轨迹帮助事故后还原过程。刹车按动作和失败代价来装：只读助手答错了可以重答，付款 agent 多付一笔不会因为重跑就消失。自主性越高，需要校验的可能动作越多，执行服务的授权和资源限制就越不能靠模型自觉。

## 自主性的阶梯

单次问答 → 对话 + 受控动作（模型提议、代码执行）→ 确定性工作流（固定步骤、节点判断）→ 自主 Agent（自己规划下一步）。越往上能力越强，硬骨头叠加越狠：最贵、最慢、最难控、最危险。

AI 原生系统设计的一条实用原则：**用尽量低的自主性解决问题，并给不得不放飞的那部分装好刹车。** 对支付、退款，把模型提议与确定性执行分开，有助于在真正动钱的位置检查权限、金额、限额和幂等，并取得规定的人工确认。只画出这两个框还不够，少了校验，确定性代码也可以稳定地扣错钱。自主性每往上走一步，都要说清多给了什么权限，以及失控时谁能让它停。
