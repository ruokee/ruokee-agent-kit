# 视图（Views）

选择视图和抽象层级，用图表达系统的边界、关系和数据流。适用于设计沟通、评审材料和文档中的架构表达。

## 图的作用是对齐

画图的目的不是好看或交差，而是让所有人看到同一个系统。脑子里清晰的系统如果不画出来，产品、后端、前端各有一个略有不同的版本，这是项目混乱的常见根源。图把个人判断变成团队共识，是架构师的核心工作之一，不是附加技能。

画图本身也是思考。试图把系统画下来时，"这两个东西谁调谁""这里的边界到底在哪"会自己浮出来。画不出来的地方，往往就是没想清楚的地方。

## 烂图的四种毛病

- **没有边界。** 所有框平铺在一起，分不清哪些在同一进程、同一机器、同一信任域里。
- **箭头没方向没含义。** 线就是线，不知道是 A 调 B 还是 B 调 A，也不知道线上跑的是调用、数据还是事件。
- **抽象层次混乱。** 整个支付系统和某个工具函数画在同一张图里，读者不知道该用什么颗粒度理解。这是最隐蔽也最致命的一种。
- **框太多。** 四十个方块挤一页，读者直接放弃。

## C4：按缩放级别分层

C4 模型把图分成四个缩放级别，像地图软件一样逐层放大：

| 层级 | 画什么 | 给谁看 |
| --- | --- | --- |
| Context（上下文） | 整个系统一个框，周围是用户角色和外部系统 | 所有人，含非技术角色 |
| Container（容器） | 系统内部可独立运行、独立部署的大块及其通信 | 技术团队、架构、运维 |
| Component（组件） | 某个容器内部的模块构成 | 开发这块的工程师 |
| Code（代码） | 类和函数组织 | 基本不画，交给 IDE |

Container 不是指 Docker。它指一个能单独启动、单独部署的单元：前端应用、后端服务、数据库、缓存。判断标准是"它是不是一个能独立运行的进程或存储"。

日常最有价值的是前两层。Context 对齐系统和外界的关系，一个技术名词都不该有，非技术的人也能看懂。Container 直接对应部署和运维单元，架构判断最密集的一层：拆几个服务、数据怎么分、要不要缓存，都体现在这张图上。

C4 表达的是静态结构，回答不了所有问题。按问题选视图：

| 要回答的问题 | 用什么视图 | 最小例子 |
| --- | --- | --- |
| 结构：谁存在、谁连谁 | C4 Context/Container | 前端 → 网关 → 订单服务 → 库存服务 |
| 时序：一次请求/Saga 怎么走、失败分支 | 时序图（sequence） | 下单成功路径 + 库存不足的补偿分支 |
| 数据：事实源到读模型怎么流、一致性窗口 | 数据流图 | 主库 → CDC → 读模型（延迟约 1 分钟） |
| 运行时：节点/区域/故障域/部署拓扑 | 部署图 | 两个区域各一套完整栈，主从异步复制 |

常见误用是拿一张 Container 图回答时序或数据流问题——结构图能看出"谁连谁"，看不出"失败时谁先超时、补偿怎么走"。评审时对准问题类型选图，不比谁画得全。

Code 层通常跳过。代码本身和 IDE 生成的关系图就是最准确的 Code 视图，手画一份代码一改就过时。别手工维护注定过时的文档，把精力花在相对稳定、最需要沟通的层次上。

## 三种基本元素

- **框。** 一个有职责的东西，能回答"你是干嘛的"。同一张图里所有框的尺度要一致。
- **箭头。** 一段关系，必须有方向（谁主动）和含义（调用、数据、事件）。没方向没含义的线是烂图的头号来源。
- **边界。** 一条分界线，圈住属于一起的东西。可能是部署边界（跑在同一集群）、信任边界（框内的可信，框外的输入不可信）或系统边界（哪些是我们的）。

新人最容易忽略边界，而它最能体现架构思维。任何从外部进入系统的数据都不可信，在图上就是一条把系统和外部输入分开的信任边界。边界画在哪，往往就是安全和部署决策所在。

## 让图立刻变好的原则

1. **一张图只用一个抽象层次。** 要么都是大块，要么都是模块，不许混。
2. **箭头标方向和含义。** 一根没标注的线，就是一个没想清楚的依赖。
3. **框的数量控制在 7±2。** 超过 9 个框，往上抽一层或拆成两张图。
4. **自顶向下。** 先画 Context 确认系统和外界的关系对齐，再钻进 Container。一上来陷进组件细节，容易只见树木不见森林。
5. **为读者画图。** 给老板看的 Context 不出现技术黑话；给工程师看的 Container 不为省事省掉关键数据流。

## ASCII 图的实践

纯文本图在任何地方都能显示，能直接进 Markdown 和代码注释，能用文本 diff 看变更，朴素但实用：

- 框用 `┌ ┐ └ ┘ ─ │` 围起来；箭头用 `──▶`、`◀──` 标方向；边界用虚线框区分于实线的具体事物。
- 在箭头旁写几个字说明这根线在干嘛：`A ──调用 API──▶ B`。
- 先在草稿上想清楚布局再誊。ASCII 图改起来不方便，先想后画更重要。
- 同一层的框横向对齐、纵向拉开留白。挤在一起的 ASCII 图可读性断崖式下跌。
- 不追求像素级完美。目标是讲清结构和关系，不是当艺术品。
