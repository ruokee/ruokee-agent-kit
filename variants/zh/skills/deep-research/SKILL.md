# 深度研究

结构化、证据优先的深入研究流程。

研究不设固定时间或 token 上限。完成请求范围内的工作和交付物，为关键结论提供证据，并说明尚未解决的问题。不要仅因还有更多来源可查就延长研究。

## 工作流程

严格遵循以下流程。

1. **澄清研究问题**
    - 具体需要研究什么？
    - 需要多详细？
    - 是否有需要优先关注的角度？
    - 研究的目的是什么？

2. **识别关键方面**
    - 将主题拆分为子主题或研究维度
    - 列出需要回答的主要问题
    - 记录所需的重要上下文或背景

3. **广泛探索**
    - 从广泛搜索开始，了解主题全貌
    - 搜索主要主题，了解整体背景
    - 根据初步结果，识别需要深入探索的子主题、相关主题、角度或方面
    - 留意不同的视角、利益相关方和观点
    - 不要让最先找到的一两个来源决定整个研究方向

4. **深入研究**
    - 针对识别出的每个重要维度开展定向研究
    - 使用准确的关键词搜索各个子主题
    - 尝试不同的关键词组合和表述
    - 完整阅读重要来源，而非只看片段
    - 来源提及其他重要资料时，也要继续搜索这些资料

5. **验证**
    - 全面覆盖不同类型的信息，获取并完整阅读最重要的来源
    - 多个来源重复同一说法时，将它们视为同一证据链的一部分，整合并交叉验证
    - 将重要论断标注为事实、推断、判断、宣传或尚未解决的不确定事项
    - 证据与论断之间的支持关系不清楚时，不要给出确定性结论

6. **总结**
    - 整理并总结研究的关键发现
    - 提供结论摘要、来源列表、完整报告和尚未解决的问题
    - 根据证据撰写输出
    - 分别呈现事实、推断、判断、建议和待确认问题

## 来源获取

适用于“广泛探索”和“深入研究”。

优先通过 Skill 或 MCP，在用户空间将原始内容保存为可核查的 Markdown 来源文件。如果无法获取有效的网页内容，至少保存详细摘要、关键摘录、URL、作者、发布日期和访问日期，供后续分析使用。

来源：

- 官方文档、文章、博客、报告、统计资料：权威来源
- 一般网站：需要独立验证

## 原则

- 输出质量直接取决于前期研究的质量和数量。仅搜索一次绝不够。
- 优先寻找一手来源，包括官方文档、论文、出版物页面和直接的产品文档。
- 二手来源仅用于发现线索、补充背景或辅助比较。
- 将来源采集与最终综合分析分开，避免过早得出结论。

## 输出

除非用户另有要求，研究默认需要产出报告和文档。

记录支撑结论所需的来源材料、证据对照和尚未解决的问题。

## 子 Agent

- 尽可能使用子 Agent 并行采集、处理和分析资料。
- 子 Agent 的最大并发数量取决于运行环境的限制。
- 待分配任务超过并发上限时，按队列安排，前面的任务完成后再启动新的子 Agent。
- 不要因子 Agent 速度慢就中断正常推进的任务。及时纠正错误、补充缺失输入，并纠正范围偏移。
- 优先纠正问题，而非终止任务。任务无法恢复时，保存其当前状态。
