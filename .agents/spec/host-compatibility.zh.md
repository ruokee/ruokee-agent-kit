# 宿主兼容

本规格覆盖把代码加载进宿主进程的组件的维护承诺。

## 目标

面向 OMP 的组件采用共同维护下限 OMP `18.5.0`，包括 `omp-qol`、`omp-smart-context`、`omp-status-bar` 和 tk 的 `tools` 模式 OMP 适配器。tk 的 `tools` 模式 Pi 适配器采用独立下限 Pi `0.84.4`。

宿主演进时保留受维护宿主上的必要行为。用户得到明确维护声明，而不是安装或运行时版本门禁。

## 非目标

- 维护上限、支持版本白名单、公开支持矩阵、兼容管理器或共享兼容库。
- 仅因宿主低于维护下限就阻止安装、加载、注册、诊断或运行。低版本可能工作，但没有维护承诺。
- 为没有宿主进程代码的指令或配置设置维护下限。普通 Skill、tk CLI 模式 Skill、tk 的 Claude Code 与 Codex MCP 配置、workloop 资源包都没有此类下限。

## 公共面

各受影响组件的中英文 README 兼容性章节提供面向用户的权威声明。规格完整表达同一已确认数值和含义，任何一处都不另立不同目标。

OMP 的共同下限为 `18.5.0`，Pi 的独立下限为 `0.84.4`，不设维护上限。下限是维护承诺，不表示已验证等于或高于它的每个版本。面向其他宿主的组件根据实际加载要求、必要能力和行为确定下限；证据不足时记录缺口，不编造数值。

宿主 peer 声明列出必要包，不收窄为维护版本范围。面向 OMP 的组件，其 `@oh-my-pi/*` 开发依赖和检查基线固定为 `18.5.0`。组件仍可因确实缺失必要能力而拒绝对应功能，但不得构造版本白名单。

tk 运行时兼容范围、driver contract 和生成的工具合同独立于宿主维护下限。本政策不取消它们的接口兼容检查。

## 不变量

- 组件更新后仍提供受维护宿主上的行为。能用能力或输入形状区分时按此区分；只有形状无法区分已记录的语义差异时，才有理由按版本区分。
- 不保留只服务于低于下限宿主的代码，下限及以下引入的必要行为继续支持。
- 能力不可用时保留原生行为，或报告有界、可定位的原因，不声称成功。失败不无必要地禁用其他有效能力。
- 安装条件、自定义元数据、宿主 peer 范围、加载、注册和诊断都不把维护下限作为门禁。
- 提升共同 OMP 下限须有单独获批决定，所有面向 OMP 的组件一起更新，包括开发基线、规格和双语用户声明。Pi 保留独立版本线。
- 验证针对升级影响的行为，修改声明本身不证明行为成立。

## 验收标准

- 所有面向 OMP 的声明和规格都使用 `18.5.0`，tk Pi tools 适配器使用 `0.84.4`。纯指令和纯配置分发不宣称宿主代码维护下限。
- 不仅因版本低于下限而拒绝宿主。宿主 peer 不收窄，不添加仅为维护而设的上限或白名单。
- 更新保留受维护宿主的结果，缺失能力的失败保持局部且明确。区分实际运行的宿主行为、源码调查和声明的维护范围。
- 下限改变时，开发基线、必要行为与用户声明同步维护。
