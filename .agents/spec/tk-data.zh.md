# tk 数据

## 目标

定义 tk 的持久任务数据、发现、生命周期和共享写入要求。这些要求适用于全部 CLI 操作，包括维护。普通项目文件保持权威，无需服务即可读取。

## 公共面

### 项目配置

项目配置是 `.agents/tk_config.toml` 中的稀疏 TOML。默认值为：

```toml
task_root = ".tk"
subtasks_dir = ""
git_policy = "none"
creation_policy = "strict"
metadata_mode = "split"
```

写配置时省略默认值。全部采用默认值的项目可以没有配置文件。每个项目只有一个任务根目录和一种元数据模式。`task_root` 相对项目解析，`subtasks_dir` 相对每个父任务解析。后者只改变新子任务的创建位置，不改变现存任务的父关系或位置。

`init` 拒绝已初始化项目。`init --force` 根据本次调用的显式值和默认值重写稀疏配置，即使原配置无法解析也可执行。它不读取、迁移、移动、删除或以其他方式改变任务数据。

写入前，`git_policy=track` 要求受管文件未被忽略，`ignore` 要求任务根目录被忽略，`none` 不要求 Git 集成。这些检查不修改 Git 忽略规则、索引、配置或历史。读取不应用写入策略门禁。

### 元数据

schema 版本 1 恰有以下受管字段：

- `schema_version`：支持的整数 schema 版本，当前为 `1`。
- `id`：不可变 UUIDv7。
- `name`：合法任务名称，只由 rename 改变。
- `status`：`planning`、`open` 或 `closed`。
- `created_at`：不可变、带时区的 RFC 3339 时间戳。
- `depends_on` 和 `related_to`：同一任务根目录内的 UUID 集合。
- `extra`：可在 JSON 和 TOML 中无损表示的结构化值，按顶层键修改。

未知字段、缺少必需字段或版本、不支持的版本、错误类型均无效。`parent`、历史名称、关闭理由、actor 和会话绑定不是受管字段。父关系由包含关系确定，生命周期理由进入 WAL。

`split` 模式下，任务目录包含普通文件 `tk.toml` 和 `TASK.md`，分别保存元数据和正文。`embed` 模式下，普通文件 `TASK.md` 以严格 YAML frontmatter 开始，随后是正文。frontmatter 起止行必须恰为 `---`，接受 LF 和 CRLF 换行。两个分隔行之间的 YAML 字节，包括其中的行换行，但不含分隔行及正文，不得超过 1,048,576 字节。拒绝 tag、重复键、未知字段、不支持的类型、未闭合 frontmatter 和超限内容。模式不匹配或载体冲突是错误。

每次元数据写入和表示切换都保留正文原始字节。创建不接受正文输入，初始正文恰为 `# <normalized-name>`。此后标题是普通文本，不控制任务身份或受管名称。

### 名称

保存名称必须是 NFKC 文本，至少包含一个字母或数字。允许字符为字母、数字、普通 U+0020 空格、连字符和下划线。保存名称和生成目录后缀各自具有独立的实际显示宽度上限 32 个终端列。分隔符计宽，日期和序号前缀不计。生成后缀不含空白。超宽返回 `task_name_too_wide`。

删除空格、连字符和下划线后，剩余字符含大小写完全相同，才表示保存名称与生成后缀排版对应。排版对应不建立身份别名，也不改变搜索语义。

创建和显式 rename 先将输入规范化为 NFKC，保留字母和数字，将中间每段非字母、非数字字符折为一个连字符，删除首尾分隔符。空结果无效，规范化结果必须符合宽度上限。普通读取和检查不做规范化或移动。无关元数据写入和表示切换保留合法保存拼写。

### 发现

顶层任务目录使用 `<task-root>/YYYY/MM/DD-NN--slug/`，日期必须有效，序号为两位，分隔符为 `--`，非空后缀与保存名称对应。新子任务使用 `<parent>/<subtasks_dir>/NN--slug/`。真实嵌套任务也可以位于普通材料目录。最近的有效外层任务是其父任务，不保存 parent 字段。无效标记目录不取代有效祖代。

发现识别当前配置模式的载体。embed 发现标记要求开头 frontmatter 和 `schema_version` 头。普通 `TASK.md` 或普通 YAML 材料本身不构成任务。带标记但无效的载体不进入普通任务结果，由完整性检查报告。重复身份和无效的生成名称、路径对应仍是错误。

发现遍历真实目录，不遍历普通材料软链接。缺失、不可读、循环、项目内或项目外的链接目标既不产生链接诊断，也不贡献任务。名为 `TASK.md`、`tk.toml`、`wal` 或 `.tk-tmp` 的材料链接不会仅因 basename 获得受管角色。真正的受管任务根目录、载体、WAL 和保留临时存储保持其类型及表示要求。

一次发现最多处理 100,000 个真实目录，深度必须小于 256。必要 I/O 失败或超限使操作失败，不能返回部分图。显式绝对任务路径、载体路径或材料路径可定位其所属项目，即使 cwd 位于另一个项目。非 Git 反向发现有界：从生成式顶层日期结构确定候选根，再最多检查两个额外祖代层级以匹配配置，不向文件系统根无限搜索。

Git 项目使用 Git 根及项目配置，普通上下文目录使用有界最近项目发现。`git_policy=none` 不要求安装 Git。WAL、保留的 `.tk-tmp` 存储、清理数据、特殊文件和任务根目录外的路径不贡献任务。

### 创建

顶层创建要求名称。状态默认 `open`，时间默认当前时间，关系默认空，`extra` 默认空对象。提供历史时间戳时，该值必须可靠且带时区。`strict` 创建要求当次明确用户确认。`permissive` 允许无需再次确认就保存值得保留的工作。创建 `planning` 工作要求用户明确表达保存早期想法、调查或计划的意图。

子任务创建在 `open` 或 `planning` 父任务下接受 1 至 50 项。open 子任务无需新的顶层创建授权，任意 planning 子任务都要求当次确认。关系只能指向同根现存任务，不能指向同批未来的兄弟任务。写入前预检整批，然后按输入顺序创建。

子编号考虑所有已发现、叶子名为生成式名称的直接子任务，不受材料目录或配置创建目录影响。使用现存最大序号加一，不补洞，从 `01` 开始，到 `99` 为止。

子任务批次重试跳过现存匹配的直接子任务。匹配使用创建负责的字段：名称、状态、显式提供时的 `created_at`、关系和 `extra`，不包含正文。保存名称须先合法。重试比较允许新增普通空格，在创建规范化前先去掉它们。`AI学习` 和 `AI-学习` 等不同规范化请求仍相互独立。部分失败后报告成功项和剩余项。

### 关系

关系 UUID 集合排序并去重。目标必须存在于同一根目录，禁止自引用，依赖不能成环。`extra` 更新只影响顶层键。

组合关系和生命周期更新按候选关系校验，包括关闭资格。拒绝时元数据和 WAL 均不变。空更新或无净变化的更新返回 `changed:false`。

### 生命周期

允许 `planning` 转 `open`、任一活动状态转 `closed`，以及 `closed` 转 `open`。不允许转回 `planning`。

对 `open` 执行 `start` 无变化。closed 任务只能通过 `reopen` 恢复活动。`close` 和 `reopen` 要求当次明确确认及非空理由。关闭要求全部后代和依赖都已关闭。明确授权的强制关闭只绕过这两项检查，不绕过授权、关系合法性或其他不变量，也不自动关闭其他任务。

closed 祖先阻止其下任务重开和活动写入。closed 任务对普通更新和日志只读，但 rename 及符合条件的名称修复可以保留 closed 状态执行。会话或工作流完成不代表任务关闭。

### WAL

WAL 是 `wal/YYYY-MM-DD.md` 中仅追加的 Markdown。每条记录使用以下表示：

```markdown
## 2026-08-31T12:34:56+08:00 · actor

Message

Optional body
```

只有完整包含带时区 RFC 3339 时间戳、分隔符和 actor 的 H2 才开始新记录。其他 H2 文本属于正文。actor 是单行归属信息，不是授权。message 是非空单行文本，body 是可选 Markdown。不提供去重、事务或特殊正文转义格式。

元数据先提交，再追加自动 WAL 事件。WAL 追加失败时，元数据保持已提交，结果包含非致命 `wal_append_failed` 警告。log 只追加事件，不修改元数据，拒绝 closed 任务。

## 不变量

### 写入

单文件写入产生完整的原子替换，最后完成的完整替换决定最终字节。多目标操作在写入前完成全部领域预检，再按其规定顺序提交。提交点之间发生 I/O 失败或取消时停止后续写入，报告已完成目标、未完成目标和原始错误。不自动回滚，也不提供续做状态。

多目标操作仍有活动 producer 时，其他项目写入返回 `operation_in_progress`。producer 退出后，写入仍被阻止，直到 GC 清理遗留活动状态。读取、搜索和仅诊断检查保持可用。单文件更新不建立这种项目级活动状态。

## 验收标准

- 两种表示均拒绝格式错误的受管数据，并在支持的写入中保留正文原始字节、不可变身份字段、合法保存名称排版及关系语义。
- 名称和后缀分别接受 32 列、拒绝 33 列，分隔符计宽。子任务重试忽略已编辑正文和新增普通空格，但不合并不同规范化请求。
- 直接子任务、配置目录子任务和普通材料中的子任务都保留最近有效父关系。创建目录变更后编号仍单调增加，到 `99` 耗尽时报告错误。
- 公开 read、search 和 check 在普通软链接周围保留真实任务身份及父关系，包括悬空、不可读、外部和循环目标，不改变链接路径或目标字节。受管存储反例仍失败。
- 生命周期和组合更新被拒绝后元数据及 WAL 不变。强制关闭只绕过活动后代和依赖检查。
- 每个多目标提交点失败都报告真实已完成及剩余目标。WAL 失败不回滚已提交元数据。遗留活动状态在 GC 前阻止写入，同时读取可用。
