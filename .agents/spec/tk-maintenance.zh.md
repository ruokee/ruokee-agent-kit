# tk 维护

## 目标

定义 schema 迁移、表示切换、改名、完整性检查和临时内容清理。这些操作通过 CLI、MCP 和原生接口同等遵循 tk 的共享数据、发现和写入要求。

## 公共面

### 迁移

schema 迁移只使用正式发布的逐版本向前转换，并保留对每个已发布版本的迁移支持。迁移保留正文原始字节，预检全部选定载体，跳过已达目标版本的载体，再按确定顺序提交。拒绝未知版本、缺少转换和降级，不提供回滚或续做状态。

表示切换覆盖项目中全部已发现任务。完整预检后，按确定顺序提交任务，最后提交配置。保留名称和正文原始字节，不追加 WAL；中断时报告部分进度。

### 改名

rename 只改变所选任务的受管名称和适用的生成后缀。保留 ID、日期、序号、正文、状态及其他全部元数据。非生成式子目录不移动。closed 任务符合条件且保持 closed。

完整 UUID、精确目录或精确载体可定位可修复任务，包括无效、空或过宽的字符串名称，以及有缺陷但可识别的生成后缀。缺少名称、字段类型错误、身份损坏、不支持的 schema 或无关无效元数据不由 rename 修复。

无变化要求保存名称和适用路径与规范化目标精确相等，排版等价不足以满足。提交前再次精确核对计划，源发生变化则返回 `stale_rename_plan`。目录移动成功但元数据写入失败时报告部分完成。中间状态即使可读，仍须重试才能达到精确目标。

rename 报告旧路径的 Markdown 引用，不改写它们。`track` 下扫描工作树 Markdown，包括未跟踪文件，排除工作树已删除但仍在索引中的文件。`ignore` 和 `none` 下扫描任务根目录 Markdown。两种表示的正文都参与，frontmatter、WAL 和临时内容不参与。必要读取失败使扫描失败。上限为 100,000 个目录和小于 256 的深度，任一超限返回 `reference_scan_limit_exceeded`。

有效 dry-run 即使存在引用也成功。执行需要移动路径且存在旧引用时，在首次写入前返回 `broken_reference_conflict`，类别 `conflict`，退出状态 `3`。details 包含 `old_path`、规范化 `new_name`、绝对 `target_path` 及全部引用路径和行号。`--ignore-brokenlinks` 允许移动，但全部引用文件逐字节保持不变，结果仍报告引用。仅元数据修改和无变化结果报告引用，但不应用路径移动门禁。

### 完整性检查

`check` 只读，诊断受管元数据、表示、身份、父关系、名称、关系、生命周期、WAL 和保留临时存储错误，不修复文件。完整读取常规 WAL 文件，不设置固定历史总量上限。普通材料链接保持共享的发现行为。

完整检查发现阻断诊断时返回 `check_failed`，退出 `3`。必要 I/O 失败、取消或资源超限使检查不完整，返回 `check_incomplete`，退出 `4` 并停止，不能呈现貌似完整的诊断集。完整有效项目退出 `0`。

### 垃圾回收

GC 只删除能够证明由 tk 创建且 producer 已退出的临时内容。保留并报告活动 producer 内容、软链接、逃逸路径、未知清理格式，以及归属无法可靠确定的内容。不解析或迁移开发期旧清理格式。

GC 不修改任务数据、WAL、项目配置或规范 Harness 目标，不续做、回滚或完成领域操作。删除失败时停止，并报告已删除和未删除路径。dry-run 报告相同的可清理内容，但不删除。

## 验收标准

- 显式 rename 达到精确目标。
- 迁移和表示切换保留正文及名称字节，报告部分结果。rename 的引用门禁、显式覆盖、dry-run、精确复核和仅元数据行为符合规定合同。
- 完整性检查区分完整但无效与读取不完整，不把部分发现伪装成完整结果。GC 不动领域数据和归属无法证明的临时内容。
