# omp-qol

[English](./omp-qol.md) | 中文

[projects/omp-qol](../../projects/omp-qol/README.zh.md) 的规格。

## 目标

- 在一个包里提供可分别开关的 OMP 调整。
- 这些调整共用一次安装、一个配置入口和一套检查，每项调整有各自的开关、可用状态和失败报告。
- 符合恢复条件的流提前关闭后，在同一主会话中自动继续未完成工作。
- 本组件直接提供用户自有的模型规则。
- 在宿主自己不入账期间，补记压缩与 handoff 请求的用量，直到宿主自己记录为止。

## 非目标

- 外部工具的守卫，以及与这些调整无关的宿主行为。
- 替用户安装或迁移，或修改其他扩展、用户配置或已安装的宿主文件。
- 在等待入口上提供只含消息的续等、按进程名等待或只含服务的续等。
- 为压缩与 handoff 之外的请求类型记录用量，或编造本组件无法读取的 api、价格或分支。
- 在 remote 切换中精简无关设置。
- 改变宿主轮次内的原生重试、宿主分类器、提供方选择或子代理恢复。
- 匹配服务端错误正文、新增恢复设置，或恢复所有错误。
- 工具恰好执行一次、回滚或幂等续跑。
- 将模板策略、Delivery 插入或页脚改写纳入模型规则，自动安装或重排扩展，增加匹配维度或搜索路径、规则缓存、配置热刷新、逐 Provider 请求刷新或历史消息注入。

### 错误恢复

恢复适用于以 assistant 错误结束的主会话运行，包括宿主原生重试已经结束而错误仍未恢复的情形。恢复以运行的结束原因为依据，成功结束无论正文包含什么都按正常流程处理。

总开关与恢复开关启用时，默认 `knownTransient` 模式必须在以下 assistant 错误后自动续跑，除非取消、任一续跑上限、安全排除项或终止性客户端状态阻止恢复：

```text
Error: Upstream provider closed the connection before the response completed: stream ended without terminal event or completed response
```

默认模式接受宿主分类为瞬时或超时的错误、宿主的 `stream_interrupted_after_content` 结束标记，以及既无 HTTP 状态也无分类结论的错误。无状态未分类错误不需要中断标记。较宽的 `unclassified` 模式在相同安全检查后接受瞬时、超时与全部未分类错误，不因中断标记获得额外范围。

这使用原生 session-stop 续跑，不是原失败请求的原样重发。设置及完整排除清单仍由[恢复行为说明](../../projects/omp-qol/docs/adjustments.zh.md#上游错误后续跑)维护。

### 压缩请求用量

- 原生布尔键 `compactionUsageEnabled` 默认为 `true`，受 `enabled` 约束。取值非法时只停用本调整。设置沿用既有的全局/项目优先级与激活快照；重启 OMP 生效，切换会话不生效。
- 本调整替换宿主 `Agent` 原型上的 `telemetry` 访问器，因为压缩与 handoff 的调用点解析的正是该值。用户已设置的配置会被保留并挂接，且不增加自己的导出；没有配置时提供惰性配置。不延迟、重试、改道或改写任何请求，也不读取或存储请求内容、摘要或交接文档。
- 一个完成的请求通过会话管理器自身的接口写入一条 `model_usage` 条目：解析出的 purpose、实际运行的 api、provider 与 model、按会话文件形状整理的提供方 token 数、提供方给出的分项成本（宿主携带时）、从该请求自身 span 读到的停止原因，以及请求所属会话的分支位置。请求身份由 provider 与 model id 共同确定，经会话自身的模型注册表解析：宿主报告遥测归一化之前的原始 provider id 时按该 id 解析，否则只有注册表中该 model id 唯一对应一个 provider 时才接受。事件的 provider 是多个 provider id 可能归一化成的遥测标签，本身不作为身份，写入的 provider 是解析出的 provider id。解析结果指向别的 provider、在两个提供同一 model id 的 provider 之间择一，或依赖与注册 provider 同名的标签，都予以拒绝而不是写入。
- 范围内共四种 purpose：`compaction:summary`、`compaction:short-summary`、`compaction:turn-prefix`、`compaction:handoff`，由宿主盖在该请求自己 span 上的 oneshot 类型解析。列表封闭；`compaction_native`、`branch_summary` 及所有非压缩类型都不写入。
- 未消耗任何 token 的尝试不写入。会话不在本进程，或身份无法解析到该请求自己模型的请求不写入，并在 `/qol` 中计数，而不是给出猜测的 api。提供方成本未到达 estimator 路径的请求以零成本写入并计数；本组件从不自行估算价格。
- 补丁为进程级，放在一个注册表槽位中。安装方只有一个；同一 runtime 或其他 runtime 的后续激活把自身会话注册到已安装的补丁上，不再安装。切换日志的会话保持在补丁中：目标跟随会话管理器的当前 id，它离开的 id 被丢弃。设置无法读取或被拒绝的激活会停止其他激活安装的补丁，自己什么都不安装。
- 从 `@oh-my-pi/pi-agent-core` 导出 `compactionRequestUsage` 的宿主自己记录这些请求。本调整在激活时读取该导出，并以 `host-records-usage` 保持停用，因此已发布的修复会让补偿停用，而不是把条目写两遍。移除该能力需按调整项文档中的上游复核执行，并用一条决定记录这次移除。

### 模型提示词规则

- 原生 boolean `modelPromptsEnabled` 默认 `false`，受 `enabled` 控制。两个开关都开启时才注册 handler、读取规则、追加正文和诊断未使用文件。设置沿用全局与项目优先级及激活快照，重启 OMP 生效，切换会话不刷新。
- 本模块 boolean 无效只停用本模块。未知设置键、非对象根或 getter 失败沿用整组件拒绝。`/qol` 显示有效开关、状态和不生效原因，不启动模型 turn，不显示规则正文或模型身份。
- 每个受覆盖 turn 为当前 profile 解析 `getAgentDir()/model-prompts`，为当前项目解析 `getProjectAgentDir(ctx.cwd)/model-prompts`。只处理直接子项中非隐藏、小写 `.md` 普通文件，不递归、不跟随文件符号链接、不搜索祖先或资源根。缺失目录视为空集。每个目录按 JavaScript 文件名顺序排序，用户先于项目，不受读取完成顺序影响，两个来源的同名文件各自独立，正文各自保留。
- UTF-8 Markdown 接受一个开头 BOM，分隔行恰好为 `---`，支持 LF/CRLF。必需 `match` 是非空数组，条目为单键对象且值非空白字符串。`exact` 比较 `provider/id`；`model` 比较包含 `/` 的完整 id；`contains` 测试 `provider/id` 字面子串；`regex` 使用不带 flags 的 JavaScript `RegExp`。匹配区分大小写、按文本作或比较，每个文件一次，不解析别名、角色、家族、显示/传输名、思考后缀、通配符或模型列表。
- 顶层额外元数据被忽略且永不注入。条目内未知或多个键，无效 YAML、分隔行、`match`、值或正则，以及空白正文，在第一个失败点使整个文件无效，不部分应用。
- 每个命中贡献一个独立块，位于当前 turn 传入块之后。闭合分隔行及行尾之后的正文逐字保留，包括标题、空行、LF/CRLF、缩进、注释、模板形似文本和末尾换行。排除 frontmatter 与 BOM，不修改输入、不包装、裁剪、重渲染或改写上下文，不产生消息/历史。
- 每个受覆盖 turn 重新读取并按有效模型匹配。新增、编辑、删除和修复在下一 turn 生效，无需重启；无效或不可读文件在下一 turn 按空正文处理。没有模型、规则或命中时，输入原样传递，模块保持静默。连续 turn 不累积正文，原生轮内重建不重复。
- 文件失败只影响该文件，目录失败只影响该目录，handler 异常保留输入及更早组件结果，其他 QoL 模块继续运行。固定原因诊断使用可定位的作用域相对来源，按会话/来源/原因去重。使用当前 turn UI 通知，否则宿主 logger；不泄露正文、绝对路径、原始解析错误、正则源码或对话内容。
- 覆盖运行公开 `before_agent_start` 的普通主/子 turn。子 Agent 按自身有效模型匹配，保留角色、独立块与宿主协议。不为 plan-mode 子 Agent、Handoff、标题、分类或其他旁路新增入口。旁路请求、临时切换、回退及单次 Provider 请求沿用宿主当前提示词行为。后续 handler 保留其权力。
- 项目规则可以成为系统指令，不增加信任门槛、安全隔离、正则沙箱/超时或正文大小/额度限制。OMP 提供等价模型指令后，核对匹配、组合/块顺序、刷新时机与发现，再决定保留、收窄或移除。

## 不变量

- 全部无关设置保留键名、默认值、范围及校验。三个 remote 设置 `compactionCacheEnabled`、`compactionCacheProvider` 和 `compactionCacheMode` 不再存在，并按未知键拒绝；不保留运行时兼容路径。
- `waitMessagesSeconds` 和 `waitProcessSeconds` 在受支持的宿主上不起作用，中英文文档和 manifest 的设置说明写明这一点。
- 续等只服务独立的 `wait` 入口。入口缺失、属于他方或无法识别时，保留原生行为并报告有界的原因。
- 压缩期限补丁保留所有权检查：拒绝与带有 `Symbol.for("ruokee.omp.compaction-timeout.patched")` 标记的补丁共存，后续的同类激活也不会接管已有的所有者。
- 压缩请求用量调整只写范围内四种 purpose，只写消耗了 token 的请求，且只写其会话注册表能解析到本身份的请求。压缩与 handoff 请求的时序、路由与内容保持不变。
- 本组件写入的 `model_usage` 条目与宿主为自己辅助请求写入的形状一致，因此宿主的会话统计会在活动分支上计入它；追加跟随请求所属的会话。
- 压缩请求用量补丁保留所有权检查：一个注册表槽位、一个安装方，本版本无法读取的槽位或被其他扩展替换的访问器一律拒绝，释放时还原它替换掉的访问器。
- 自己记录这些请求的宿主会让本调整保持停用并报告有界原因。该能力的退休以已核实原生记录为前提，届时移除其代码、设置、文档与测试。
- 配置只来自 OMP 插件设置，每次激活读取一次。
- 一项调整出错不会停用其他调整。被拒绝的设置只给出键名和规则，不回显其值。
- 组件保留的每条代码路径都服务 OMP 18.5.0 及更高宿主，包括服务独立 `wait` 入口的等待路径。
- 恢复只处理主会话的 assistant 错误。正常输出引用错误不触发恢复；开关关闭或所需宿主接口缺失时保留原生行为。
- 安全排除与终止性 4xx 规则优先于两种模式及中断标记。恢复模块对副本分类，不改动原始 assistant 错误。
- 现有每链续跑预算及倍增退避跨模型运行生效。只有实际返回的续跑计入次数；同一运行及轮次的重复结束事件不增加等待或续跑。宿主上限独立生效。
- 正常完成、范围外错误或取消结束当前链。后续独立链使用新预算。会话切换、关闭、新运行或原链失效后，旧等待不得触发续跑。
- 恢复使用既有固定续跑文本，要求核对已完成工作及副作用，不携带服务端错误正文、命令或工具输出。历史、工具调度及审批仍由 OMP 管理。
- 恢复通知遵循现有开关，显示次数及等待时间。`/qol` 报告有效状态及配置，不启动模型运行。

## 宿主下限

OMP `18.5.0`，声明在[兼容性](../../projects/omp-qol/README.zh.md#兼容性)。`@oh-my-pi/*` 开发依赖锁定为 `18.5.0`，测试以该宿主的行为为基线。通用规则见 [.agents/spec/host-compatibility.zh.md](./host-compatibility.zh.md)。

## 验收标准

- 在组件目录运行 `bun run typecheck` 和 `bun test` 通过。
- 无关设置保留键名、默认值、范围及校验。三个旧 remote 键均触发既有未知键拒绝，不再配置任何调整。
- `waitMessagesSeconds` 和 `waitProcessSeconds` 的说明写明它们不起作用。
- 受维护宿主的真实 CLI 会话通过 `soft` 压缩时，为该次运行实际发出的每个摘要请求写入一条条目；执行 handoff 的会话为其请求写入一条；每条都带提供方的 token、分项成本、api、provider 与 model；宿主自身的会话统计计入这些条目，且增量等于写入的内容。该运行未发出的请求不产生条目。切换日志（`/new` 或恢复）之后再次压缩的会话继续写入条目，且写进它切换到的日志。
- 行为检查覆盖 purpose 表、零 token 与非压缩类型的跳过、成本认领的一次性、每种拒绝原因、保留用户 tracer 与用户自己的钩子、惰性 tracer、注册表的访问器身份、请求身份解析、写入的 provider、切换日志的会话，以及 `/qol` 行。被取消、失败或零 token 的尝试不产生条目，开关关闭时不安装配置也不写入。
- 每项调整的真实 OMP CLI 证据记录在 [projects/omp-qol/docs/adjustments.zh.md](../../projects/omp-qol/docs/adjustments.zh.md) 对应的验证小节，未运行的场景标为未验证。
- 受维护宿主的真实 OMP CLI 证明符合恢复条件的上游流关闭后，使用默认恢复设置，且不经用户消息便在同一主会话自动续跑。仅有原生重试或 `/qol` 启用状态不能证明该行为。
- 行为检查覆盖原始报错的真实宿主字段在默认模式下的恢复。新的真实会话再次出现其精确措辞不是开发前提；未运行的精确报错场景仍标为未验证。
- 相同故障下关闭恢复后，不出现 QoL 续跑。真实 TUI 显示次数及等待时间，等待期间取消会阻止续跑。
- 行为检查覆盖两种模式、有标记及无标记的无状态错误、安全优先级、独立上限、退避、跨运行失败链、重复事件、失效等待、开关、通知，以及原始错误与固定上下文的边界。
- 受维护宿主真实 CLI 请求证明显式启用后 QoL 单独注入命中正文，默认/总开关/模块关闭运行没有规则注入或未使用文件诊断。行为检查证明这些状态零读取，其他独立启用模块保持原样。
- 行为检查覆盖全部匹配键、大小写、含 `/` 完整 id、或关系一次、顶层元数据忽略、条目键严格校验、发现过滤、用户/项目顺序、同名来源及相同正文独立保留。
- 真实请求观察及行为检查保留传入块、工具、动态内容、BOM 排除和逐字正文。连续 turn、文件新增/编辑/删除/修复、模型切换及原生轮内重建符合刷新、不累积和不重复要求。
- 检查覆盖无模型/未命中、无效文件、文件/目录读取失败、意外 handler 异常、诊断隐私及会话/上下文去重、模块局部和整体设置拒绝、设置仅重启生效及文件下一 turn 生效。真实 `/qol` TUI 显示默认关闭和启用状态，不启动模型运行。
- 普通子 Agent 的 Provider-facing 请求保留自身模型、角色和独立块。未运行旁路明确标为未验证。
- 组件说明、manifest、仓库指引、双语文档及现行项目 Spec 的归属和即将弃用状态一致，保留全部剩余调整及每项无关有效要求。
