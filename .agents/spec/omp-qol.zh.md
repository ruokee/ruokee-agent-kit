# omp-qol

[English](./omp-qol.md) | 中文

[projects/omp-qol](../../projects/omp-qol/README.zh.md) 的规格。

## 目标

- 在一个包里提供五项可分别开关的 OMP 调整：持续等待、符合条件的上游临时错误后续跑、延长单个压缩期限、恢复会话时沿用原生历史，以及追加模型提示词规则。
- 这些调整共用一次安装、一个配置入口和一套检查，每项调整有各自的开关、可用状态和失败报告。
- 符合恢复条件的流提前关闭后，在同一主会话中自动继续未完成工作，不要求用户再发消息。
- 无需其他组件或选择模板，即可提供用户自有的模型规则。

## 非目标

- 外部工具的守卫，以及与这些调整无关的宿主行为。
- 替用户安装或迁移，或修改其他扩展、用户配置或已安装的宿主文件。
- 在等待入口上提供只含消息的续等、按进程名等待或只含服务的续等。
- 在 remote 切换中精简无关设置。
- 改变宿主轮次内的原生重试、宿主分类器、提供方选择或子代理恢复。
- 匹配服务端错误正文、新增恢复设置，或恢复所有错误。
- 工具恰好执行一次、回滚或幂等续跑。
- 将模板策略、Delivery 插入或页脚改写纳入模型规则，自动安装或重排扩展，增加匹配维度或搜索路径、规则缓存、配置热刷新、逐 Provider 请求刷新或历史消息注入。

### 错误恢复

恢复适用于以 assistant 错误结束的主会话运行，包括宿主原生重试已经结束而错误仍未恢复的情形。成功或非错误结束不因正文提到相同报错而触发恢复。

总开关与恢复开关启用时，默认 `knownTransient` 模式必须在以下 assistant 错误后自动续跑，除非取消、任一续跑上限、安全排除项或终止性客户端状态阻止恢复：

```text
Error: Upstream provider closed the connection before the response completed: stream ended without terminal event or completed response
```

默认模式接受宿主分类为瞬时或超时的错误、宿主的 `stream_interrupted_after_content` 结束标记，以及既无 HTTP 状态也无分类结论的错误。无状态未分类错误不需要中断标记。较宽的 `unclassified` 模式在相同安全检查后接受瞬时、超时与全部未分类错误，不因中断标记获得额外范围。

这使用原生 session-stop 续跑，不是原失败请求的原样重发。设置及完整排除清单仍由[恢复行为说明](../../projects/omp-qol/docs/adjustments.zh.md#上游错误后续跑)维护。

### 模型提示词规则

- 原生 boolean `modelPromptsEnabled` 默认 `false`，受 `enabled` 控制。任一开关关闭时不注册 handler、不读规则、不追加、不诊断闲置文件。设置沿用全局与项目优先级及激活快照，重启 OMP 生效，切换会话不刷新。
- 本模块 boolean 无效只停用本模块。未知设置键、非对象根或 getter 失败沿用整组件拒绝。`/qol` 显示有效开关、状态和不生效原因，不启动模型 turn，不显示规则正文或模型身份。
- 每个受覆盖 turn 为当前 profile 解析 `getAgentDir()/model-prompts`，为当前项目解析 `getProjectAgentDir(ctx.cwd)/model-prompts`。只处理直接子项中非隐藏、小写 `.md` 普通文件，不递归、不跟随文件符号链接、不搜索祖先或资源根。缺失目录视为空集。每个目录按 JavaScript 文件名顺序排序，用户先于项目，不受读取完成顺序影响，不按同名遮蔽或跨来源文件名/正文去重。
- UTF-8 Markdown 接受一个开头 BOM，分隔行恰好为 `---`，支持 LF/CRLF。必需 `match` 是非空数组，条目为单键对象且值非空白字符串。`exact` 比较 `provider/id`；`model` 比较包含 `/` 的完整 id；`contains` 测试 `provider/id` 字面子串；`regex` 使用不带 flags 的 JavaScript `RegExp`。匹配区分大小写、按文本作或比较，每个文件一次，不解析别名、角色、家族、显示/传输名、思考后缀、通配符或模型列表。
- 顶层额外元数据被忽略且永不注入。条目内未知或多个键，无效 YAML、分隔行、`match`、值或正则，以及空白正文，在第一个失败点使整个文件无效，不部分应用。
- 每个命中贡献一个独立块，位于当前 turn 传入块之后。闭合分隔行及行尾之后的正文逐字保留，包括标题、空行、LF/CRLF、缩进、注释、模板形似文本和末尾换行。排除 frontmatter 与 BOM，不修改输入、不包装、裁剪、重渲染或改写上下文，不产生消息/历史。
- 每个受覆盖 turn 重新读取并按有效模型匹配。新增、编辑、删除和修复在下一 turn 生效，无需重启；无效或不可读文件不沿用旧正文。没有模型、规则或命中时输入原样保留，不报告未命中错误。连续 turn 不累积正文，原生轮内重建不重复。
- 文件失败只影响该文件，目录失败只影响该目录，handler 异常保留输入及更早组件结果，不停用其他 QoL 模块。固定原因诊断使用可定位的作用域相对来源，按会话/来源/原因去重。使用当前 turn UI 通知，否则宿主 logger；不泄露正文、绝对路径、原始解析错误、正则源码或对话内容。
- 覆盖运行公开 `before_agent_start` 的普通主/子 turn。子 Agent 按自身有效模型匹配，保留角色、独立块与宿主协议。不为 plan-mode 子 Agent、Handoff、标题、分类或其他旁路新增入口。旁路请求沿用宿主当前提示词行为，临时切换、回退及单次 Provider 请求不增加独立刷新保证。后续 handler 保留其权力。
- 两个更新组件共存时，实际加载顺序为 system-prompt 在前、QoL 在后。仅 QoL 追加规则，模板和规则失败相互隔离。协调更新指引警示旧 system-prompt 规则 handler 与 QoL 同时启用的风险，不把安装命令顺序当作保证。
- 项目规则可以成为系统指令，不增加信任门槛、安全隔离、正则沙箱/超时或正文大小/额度限制。OMP 提供等价模型指令后，核对匹配、组合/块顺序、刷新时机与发现，再决定保留、收窄或移除。

## 不变量

- 全部无关设置保留键名、默认值、范围及校验。三个 remote 设置 `compactionCacheEnabled`、`compactionCacheProvider` 和 `compactionCacheMode` 不再存在，并按未知键拒绝；不保留运行时兼容路径。
- `waitMessagesSeconds` 和 `waitProcessSeconds` 在受支持的宿主上不起作用，中英文文档和 manifest 的设置说明写明这一点。
- 续等只服务独立的 `wait` 入口。入口缺失、属于他方或无法识别时，保留原生行为并报告有界的原因。
- 压缩期限补丁保留所有权检查：拒绝与带有 `Symbol.for("ruokee.omp.compaction-timeout.patched")` 标记的补丁共存，后续的同类激活也不会接管已有的所有者。
- 配置只来自 OMP 插件设置，每次激活读取一次。
- 一项调整出错不会停用其他调整。被拒绝的设置只给出键名和规则，不回显其值。
- 组件不保留只为 OMP 18.5.0 以前宿主存在的代码路径，包括只服务内置 `hub` 工具的等待路径。
- 恢复只处理主会话的 assistant 错误。正常输出引用错误不触发恢复；开关关闭或所需宿主接口缺失时保留原生行为。
- 安全排除与终止性 4xx 规则优先于两种模式及中断标记。恢复模块对副本分类，不改动原始 assistant 错误。
- 现有每链续跑预算及倍增退避跨模型运行生效。只有实际返回的续跑计入次数；同一运行及轮次的重复结束事件不增加等待或续跑。宿主上限独立生效。
- 正常完成、范围外错误或取消结束当前链。后续独立链使用新预算。会话切换、关闭、新运行或原链失效后，旧等待不得触发续跑。
- 恢复使用既有固定续跑文本，要求核对已完成工作及副作用，不携带服务端错误正文、命令或工具输出。历史、工具调度及审批仍由 OMP 管理。
- 恢复通知遵循现有开关，显示次数及等待时间。`/qol` 报告有效状态及配置，不启动模型运行。

## 宿主下限

OMP `18.5.0`，声明在[兼容性](../../projects/omp-qol/README.zh.md#兼容性)。`@oh-my-pi/*` 开发依赖锁定为 `18.5.0`，测试以该宿主的行为为基线。通用规则见 [.agents/spec/host-compatibility.zh.md](./host-compatibility.zh.md)。

## 验收标准

- 在组件目录运行 `bun run typecheck` 和 `bun test` 通过。
- 无关设置保留键名、默认值、范围及校验。三个旧 remote 键均触发既有未知键拒绝，不再配置任何调整。
- `waitMessagesSeconds` 和 `waitProcessSeconds` 的说明写明它们不起作用。
- 每项调整的真实 OMP CLI 证据记录在 [projects/omp-qol/docs/adjustments.zh.md](../../projects/omp-qol/docs/adjustments.zh.md) 对应的验证小节，未运行的场景标为未验证。
- 受维护宿主的真实 OMP CLI 证明符合恢复条件的上游流关闭后，使用默认恢复设置，且不经用户消息便在同一主会话自动续跑。仅有原生重试或 `/qol` 启用状态不能证明该行为。
- 行为检查覆盖原始报错的真实宿主字段在默认模式下的恢复。新的真实会话再次出现其精确措辞不是开发前提；未运行的精确报错场景仍标为未验证。
- 相同故障下关闭恢复后，不出现 QoL 续跑。真实 TUI 显示次数及等待时间，等待期间取消会阻止续跑。
- 行为检查覆盖两种模式、有标记及无标记的无状态错误、安全优先级、独立上限、退避、跨运行失败链、重复事件、失效等待、开关、通知，以及原始错误与固定上下文的边界。
- 受维护宿主真实 CLI 请求证明显式启用后 QoL 单独注入命中正文，默认/总开关/模块关闭运行没有规则注入或闲置文件诊断。行为检查证明这些状态零读取，其他独立启用模块保持原样。
- 行为检查覆盖四键、大小写、含 `/` 完整 id、或关系一次、顶层元数据忽略、条目键严格校验、发现过滤、用户/项目顺序、同名来源及相同正文独立保留。
- 真实请求观察及行为检查保留传入块、工具、动态内容、BOM 排除和逐字正文。连续 turn、文件新增/编辑/删除/修复、模型切换及原生轮内重建符合刷新、不累积和不重复要求。
- 检查覆盖无模型/未命中、无效文件、文件/目录读取失败、意外 handler 异常、诊断隐私及会话/上下文去重、模块局部和整体设置拒绝、设置仅重启生效及文件下一 turn 生效。真实 `/qol` TUI 显示默认关闭和启用状态，不启动模型运行。
- 普通子 Agent 的 Provider-facing 请求保留自身模型、角色和独立块。真实共存请求按文档顺序保留自有模板、Delivery、页脚和单次规则；两个失败方向保留另一组件结果。未运行旁路明确标为未验证。
- 组件说明、manifest、仓库指引、双语文档及现行项目 Spec 的归属和即将弃用状态一致，保留全部五项剩余调整及每项无关有效要求。
