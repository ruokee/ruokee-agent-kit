# omp-smart-context

## 目标

提供自包含的原生 OMP 包 `@ruokee/omp-smart-context`。各项能力独立开关，包括以普通请求中已证明的内容对齐 Remote 和 Handoff 请求、补充缺失的压缩用量、应用模型专属提示规则，以及在压缩后保留明确固定的文本。

本主规格覆盖包配置、状态、迁移、隔离和维护要求。完整要求集合还分别覆盖共同请求对齐、Remote、Handoff、用量、模型提示词规则及 Pin。

每项迁入能力只有一个活动归属。替换 smart-cache、独立 context-pin 及 QoL 的用量和模型规则能力时，保留已确认行为。QoL 留存调整的设置、默认值、校验和行为不变。

## 非目标

- 新压缩策略、重试、模型、观察器、角色指令或自动 Pin 维护。
- 保证提供方缓存驻留、命中率或收益。
- 自动安装、修改用户配置、改写 journal、兼容别名或跨组件运行时依赖。
- 将真实模型调用、提供方收益测量或全量 CLI/TUI 矩阵作为包整合的前提。

## 公共面

### 配置

OMP 原生插件管理器加载包并提供设置，不增加总开关或独立配置文件。

| 设置 | 类型或取值 | 默认值 |
| --- | --- | --- |
| `compactionCacheEnabled` | boolean | `false` |
| `compactionCacheProviderFilter` | string | `""` |
| `compactionCacheMode` | `standard`, `hooks` | `hooks` |
| `handoffCacheEnabled` | boolean | `false` |
| `compactionUsageEnabled` | boolean | `true` |
| `modelPromptsEnabled` | boolean | `false` |
| `pinEnabled` | boolean | `false` |

Provider filter 精确匹配当前模型的 Provider 身份，只决定 Remote 修复资格，不选择模型或路由。空 filter 使 Remote 对齐不可用。

OMP 项目值覆盖用户值。激活时读取并校验一次有效快照，缺少键时取默认值。设置和注册变更需要重启 OMP。导航或新建会话不刷新已有激活。模型规则文件在各受覆盖轮次单独刷新。

模块键无效只停用所属模块。未知键、非对象设置根或设置读取失败拒绝整个组件配置。报告固定原因，不回显被拒值。重复激活不重复执行能力。

### 状态

`/smart-context` 只读，不启动模型轮次、不刷新设置、不修复所有权冲突。各能力分别报告有效状态，停用时附固定原因。

Remote 和 Handoff 使用以下状态：

- `disabled`，能力开关关闭。
- `unavailable`，配置无效、缺少必要宿主接口、会话身份未确认、扩展所有权冲突或其他资格条件缺失导致不可用。
- `awaiting-reference`，尚无已确认且符合条件的普通请求参照。
- `already-aligned`，已校验的原生请求已经具有所需内容。
- `rewritten`，已经发送校验通过的对齐请求。
- `rejected`，缺少修复证明，完整原生请求原样发送。这不表示阻断、延迟或丢弃请求。

通过 `online`、`binding`、`candidate`、`sending` 分别展示可用性、操作绑定、候选校验和实际发送。Remote 还报告 `mode`。`dispatch`、`operation`、`reference` 是会话内计数，不是模型或 Provider 标识。

各对齐能力分别报告有界计数：`operations` 计逻辑操作，`sends` 计物理发送并包含重试，`retries` 计重试发送。`aligned` 包含已经对齐和成功改写的发送，`rewritten` 是其中正文改变的子集。`rejected` 计对齐校验失败后保持原生的发送，仍计入总分母。Remote 的 `reused`、`retained` 只描述最近一次发送。Handoff 的 `axes`、`unprojected` 描述恢复和保持原值的维度。按实际传输计数，不按载荷回调计数。

`compactionUsage`、`modelPrompts`、`pin` 分别报告自身状态和可选固定原因，区分启用、停用、配置无效和接口不兼容。激活未就绪时可以显示 pending。用量还报告实时进程注册状态、条目数、成本缺失数和身份未解析数。一项能力停用不使另一项停用。

状态不暴露正文、不透明历史、凭据、原始端点、私密路径、规则文本或动态私密标识。对齐发送、宿主采用压缩结果和提供方缓存命中是不同结果。

### 迁移

迁移替换旧 smart-cache 和独立 Pin 注册，包括手动扩展路径，并重启受影响进程。不热迁移参照，不接管旧实现或他方所有权。运行时不回读旧包配置作为后备。`/smart-cache` 没有别名；`/qol` 继续说明 QoL 的留存调整。

保留 smart-cache 的值及作用域覆盖。将 `compactionCacheProvider` 改名为 `compactionCacheProviderFilter`，从用户级和项目级 smart-context 设置中移除旧键。旧键按未知键处理，不是别名。

每项 QoL 迁出能力保留原有效 `enabled && moduleEnabled` 结果。先将项目覆盖合并到旧用户值，再计算项目结果。旧默认值为 `enabled=true`、`compactionUsageEnabled=true`、`modelPromptsEnabled=false`。从用户级和项目级 QoL 设置中删除这两个迁出键；在不含这些模块的 QoL 版本中，任一残留都会拒绝整个配置。保留无关键，包括 QoL 总开关。使用不再重复提供迁出行为的 QoL 版本。

已有 Pin 用户显式开启新的默认关闭开关。既有规则位置、文件名、元数据和正文无需转换。保留会话 journal 和 `model_usage` 条目。受支持的 Pin 记录版本 `2` 及标识 `omp-context-pin`、`omp-context-pin-change`、`omp-context-pin-result` 保留含义。条目 ID、操作身份、修订和正文原样重放，不为历史记录改名。

关闭 Pin 只停止新的保留文本消息，不擦除记录或普通历史。关闭用量只停止后续补充记录，不删除历史条目。关闭模型规则停止读取、注入和未使用文件诊断。规则编辑在下个受覆盖轮次生效，开关变更需要重启。扩展不自动执行迁移。

## 不变量

分发组件可以独立安装和使用，携带自己的依赖和文档。对齐、Pin、用量和模型规则保持独立状态归属与失败边界。一项失败不妨碍其他有效能力。

历史、压缩调度、准备、采用和续接归 OMP。每条物理请求最多一个对齐改写方。规则和 Pin 不因激活或整合重复出现，用量不重复记账。清理只释放本组件仍拥有的资源，不接管其他扩展的更改。

## 宿主下限

最低受维护 OMP 版本为 `18.5.0`，不设维护上限。这是维护承诺，不是安装门禁或运行白名单，也不认证全部后续版本。宿主依赖是不限版本的 peer。缺少能力接口只停用受影响能力。

## 验收标准

- 实际包入口通过原生配置独立加载。各迁入能力只有一个归属，QoL 不激活也不停止它。
- 默认值、作用域覆盖、重启生效的激活快照、局部设置错误和整个配置拒绝符合合同。下一轮规则刷新与设置刷新保持区别。
- 受控运行通过实际入口和受维护原生库覆盖普通请求及原生压缩准备、序列化，证明规则和 Pin 单次应用、每条物理请求最多一个对齐改写方、用量不重复，以及各项独立关闭。
- 已提交压缩后的普通续接逐字携带最新 Pin 正文，不把旧修订放在新正文之后。读取状态不产生模型请求。
- 迁移保留启用意图、无关设置、受支持记录和 QoL 留存行为。扩展不改写真实用户配置或 journal。
- 包声明、双语文档、规格及现行决定一致。初始未发布版本为 `0.1.0`。
- 验证资料记录候选、宿主版本、输入、观察和限制。历史证据保留原归属及条件。源码检查、受控整合、真实宿主行为和提供方测量保持区别。
