# omp-smart-context

[English](./README.md) | 中文

## 目标

在 `projects/omp-smart-context` 维护自包含原生 OMP 包 `@ruokee/omp-smart-context`。各项上下文能力可独立开关，保留其范围、状态归属、失败边界和宿主原生行为。

替换 smart-cache、独立 context-pin 及 QoL 迁出的用量和模型规则实现。每项迁入能力只有一个实现归属。QoL 留存调整的行为、设置、默认值和校验保持不变。

## 非目标

- 新压缩策略、策略框架、重试、模型、观察器、角色指令或自动 Pin 维护。
- 保证提供方缓存驻留、命中率或收益。
- 自动安装、修改用户配置、改写已有会话日志、兼容别名或跨组件运行时依赖。
- 将真实模型调用、提供方收益测量或全量 CLI/TUI 矩阵作为整合前提。

## 公共面

提供一个原生扩展入口，使用 OMP 原生包设置，不增加总开关或独立配置文件。设置如下：

- `compactionCacheEnabled`：布尔值，默认 `false`。
- `compactionCacheProviderFilter`：字符串，默认 `""`。精确筛选当前模型的 Provider 是否可修复，不选择模型或路由。
- `compactionCacheMode`：`standard` 或 `hooks`，默认 `hooks`。
- `handoffCacheEnabled`：布尔值，默认 `false`。
- `compactionUsageEnabled`：布尔值，默认 `true`。
- `modelPromptsEnabled`：布尔值，默认 `false`。
- `pinEnabled`：布尔值，默认 `false`。

`/smart-context` 只读，不启动模型轮次。各能力分别报告有效状态和固定停用原因。对齐分别报告阶段，以及逻辑操作、物理发送、重试、已对齐发送、改写和拒绝的有界计数，拒绝仍计入分母。普通请求参照确认、操作绑定、候选校验和实际发送分别表示。报告中的编号只用于会话内计数。用量报告实时注册状态、条目数、成本缺失数和身份未解析数。模型规则和 Pin 报告启用、关闭、配置无效或接口不兼容状态。

报告不暴露正文、不透明历史、凭据、原始端点、私密路径、规则内容或动态私密标识。

### 能力规范

- [请求对齐](./request-alignment.zh.md)维护普通请求参照、会话隔离、协调、失效和释放。
- [远端](./remote.zh.md)维护 Remote 适用范围、筛选、模式和复用要求。
- [Handoff](./handoff.zh.md) 维护两种受支持 API 的合同。
- [用量](./usage.zh.md)维护请求身份、记账、成本和原生替代。
- [模型提示词规则](./model-prompts.zh.md)维护发现、输入格式、匹配、刷新、注入和诊断。
- [Pin](./pin.zh.md) 维护用户及工具行为、记录、身份、容量、投影和持久化。

各子规范维护自身的不变量及验收。用户指南说明操作方式，不作为本规范集合的规范依赖。源码调查和候选验证记录归维护材料，不写入规范或使用说明。

## 不变量

### 配置

OMP 将项目覆盖合并到用户设置上。激活时读取并校验一次有效快照，缺失键取默认值。设置变更在重启后生效，导航或新建会话不刷新已有激活。规则文件在各受覆盖轮次单独刷新。

模块键错误只停用该模块。未知键、非对象设置根或设置读取失败拒绝整个组件配置。诊断只报告固定原因，不包含被拒绝的值。重复激活不重复注册。

### 归属

代码、manifest、依赖、检查及双语用户文档均位于可分发组件内。宿主依赖直接声明为不限版本的 peer。各能力保持独立状态和失败边界，不建立共享上下文存储或通用模块框架。请求对齐协调器不拥有 Pin、用量或模型规则状态。

历史和压缩的调度、准备、采用及续接归 OMP。一项能力失败或不可用时，其他有效能力仍可使用。新增能力未改变共同不变量时，无需反转无关决定。

### 迁移

替换旧 smart-cache 及独立 Pin 注册，包括手动扩展路径，然后重启受影响进程。不热迁移参照，不接管旧实现或外部扩展持有的接口。不得回读旧包设置作为后备。

保留 smart-cache 的值和各级覆盖。将 `compactionCacheProvider` 迁至 `compactionCacheProviderFilter`，从用户级及项目级 smart-context 设置中移除旧键。旧键是未知键，不是别名。

对每项 QoL 迁出模块保留原有效 `enabled && moduleEnabled` 结果。先将项目覆盖合并到旧用户设置，再计算项目结果。旧默认值为 `enabled=true`、`compactionUsageEnabled=true`、`modelPromptsEnabled=false`。从用户级及项目级 QoL 设置中移除两个迁出键，任何遗留都会拒绝整个 QoL 配置。保留无关设置。已有 Pin 用户显式启用新的默认关闭开关。既有规则文件及受支持记录无需转换。

## 宿主下限

以 OMP `18.5.0` 为共同维护下限，不设维护上限。开发用宿主依赖锁定在该版本，`@oh-my-pi/pi-agent-core`、`@oh-my-pi/pi-ai`、`@oh-my-pi/pi-coding-agent`、`@oh-my-pi/pi-tui`、`@oh-my-pi/pi-utils` 均声明为 `*` peer。下限是维护责任，不是运行白名单或安装门槛。缺少能力接口时停用所属模块，不牵连无关模块。

## 验收标准

- 实际入口仅使用自身依赖和原生配置加载。迁入能力只有一个实现归属，QoL 既不安装或停止迁出包装，也不注入迁出规则。
- 配置覆盖、默认值、激活快照、局部错误及整体拒绝符合上述要求。重启生效的设置与下一轮生效的规则文件互不混淆。
- 受控运行通过实际入口和锁定原生库，使用确定的本地传输响应，驱动普通请求及原生压缩准备和序列化。规则和 Pin 各出现一次，每条物理请求最多一个对齐改写方，用量不双记，各项独立关闭不影响其他能力。
- 已提交压缩后的普通续接逐字携带最新 Pin 正文，不把旧修订置于新正文之后。直接调用已注册状态处理器不产生模型请求。
- 迁移保留有效启用意图、无关设置、受支持记录和 QoL 留存行为。扩展不改写真实用户配置或会话日志。
- manifest、版本、组件清单、检查选择器、完整检查、双语文档、规范及现行 ADR 一致。未发布的新组件在各次修订中均使用首次版本 `0.1.0`。
- 记录实际候选、宿主版本、输入、观察和限制。历史证据保留原归属和条件。源码检查、受控整合、真实宿主行为及提供方测量分别作为独立证据。
