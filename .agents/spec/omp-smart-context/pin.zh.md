# Pin

[English](./pin.md) | 中文

## 目标

在当前会话分支的后续普通请求中逐字保留已接受文本，跨越已提交压缩，直到更新、删除或重置。固定文本不获得更高指令权限，不恢复撤销授权，不重启已完成工作。

## 非目标

代调用方读取文件或 URL，监听内容，将任意文字解析为操作，自动维护 Pin，迁移不支持格式，第二存储，使用宿主私有保存方法，通过其他会话保存，或额外启动模型轮次以强制持久化。

## 公共面

`pinEnabled` 是独立布尔值，默认 `false`，使用[组件激活快照](./README.zh.md#配置)。关闭或无效时不注册工具、命令或投影处理器，保留已有日志和普通历史。启用时安装一次并从当前会话上下文初始化。重新启用重放受支持记录，无需转换。OMP 保留自身 `/pin` 命令。

### 用户命令

`/ctx-pin` 打开当前分支列表，使用宿主主题及自适应宽度选择组件，顺序为添加项、创建顺序的条目、关闭项。行显示 `#<id>` 和折叠连续空白后的正文前缀，按可用宽度截断并加省略号。无可见正文时只显示编号。查看和编辑草稿只读，不发送消息、不改状态、不打断运行轮次。放弃草稿无影响，确认关闭列表。

`/ctx-pin add <body>` 保留 `add` 后一个分隔空格之后的每个字符。不做 shell 分词、引号处理、反转义或空白规范化。缺少正文或未知子命令只显示用法，不发送消息。

### Agent 工具

`ctx_pin` 提供六个动作：

- `list`：无动作专用输入，返回所有条目的编号、创建来源、修订号及 UTF-8 大小，不含正文。
- `get`：整数 `id`，返回一条完整正文及元数据。
- `show`：无动作专用输入，返回全部活跃正文和元数据，以及条目数、总活跃字节和分支上限，空集报告零。
- `create`：`content`，创建新条目。
- `update`：整数 `id` 及 `content`，替换当前条目正文。
- `delete`：整数 `id`，取消固定当前条目。

`content` 必须是非空字符串，文本原样保留。

编号接受正整数，不接受数字字符串。不隐式新增、不以改名创建、不接收修订号参数，也不按修订号准入。显示的修订号只供参考，旧草稿可覆盖更新正文。用户创建来源为 `user`，工具创建为 `agent`，更新保留创建来源。

所有动作声明 `read` 批准档位。没有显式工具策略时，`always-ask`、`write`、`yolo` 不提示，显式 `prompt` 或 `deny` 仍有效。不新增授权门槛或配置写入。保留类型、存在性、容量和记录完整性检查。

## 不变量

### 规范记录

当前分支的宿主会话日志为权威状态。使用自定义类型 `omp-context-pin`、版本 `2` 及以下载荷：

- `schemaVersion`：`2`。
- `operationId`：每次用户提交或新 Agent 写入分配的正整数，重试复用；只供内部使用，不在公共列表、消息或结果显示。
- `action`：`create`、`update` 或 `delete`。
- `entryId`：首次成功创建时分配的会话级正整数，不复用。
- `revision`：从 1 开始，每次接受的更新或删除递增一次。
- `body`：创建及更新的完整新正文，删除时不存在。
- `source`：`user` 或 `agent`。
- `toolCallId`：宿主 Agent 调用身份，用于识别重试。

读取、拒绝及正文未变更新不追加记录或新投影。先于当前条目查找识别已接受重试，返回原结果，不重复写入或恢复旧正文。操作身份被不同内容复用视为损坏，不视为重试。同操作同修订的记录重放无操作。

通过整个会话的公开条目恢复编号高水位，包括待消费提交预留及宿主持有的承载消息和结果。该扫描只分配编号，不应用其他分支正文、回执或操作。条目和操作编号单调增加，可有空缺，删除或重置后仍不复用。分配不可靠、条目不可读或超出安全整数范围时明确报错，不回绕或重置。不得保留仅服务 18.5.0 以前宿主的成员探测、`getEntries` 能力探测或无时间戳消息计数后备。

### 用户提交

确认写入通过普通用户消息提交，只含逐字草稿正文。在宿主消费消息并核对当前进程记录的文本、会话、Pin 期间、分支及目标条目存在前，操作保持待处理。只有当前进程持有的提交可生效。编辑后的消息、引用、其他进程提交、恢复历史及已消费文本均为普通文本。

一次提交认领一条消息，一条消息最多认领一次提交。记录确认时间，确认前已消费的同文消息不合格。有宿主消费时间戳时优先精确匹配。草稿仍持有期间出现相同文本可被识别为该草稿，这是可读用户消息的已接受代价。

确认后出现不匹配任何待处理提交的新用户消息时，放弃未执行文本的提交。会话启动、切换或关闭时丢弃未应用工作，可用时通过 UI 通知。最终拒绝在返回原分支或释放容量后仍保持拒绝。范围不可读不是最终结果，后续可读时可应用。结算后原文本成为普通历史，不应用两次。

只在消费消息时更新已接受状态。宿主尚未写入用户消息日志时，正文仅通过该请求表达，不重复或排队发送 Agent 变更投影。已消费用户写入在操作消息后紧接一条无正文结果，报告已接受、未变化或未应用及原因和条目编号。以宿主非主动模式交付同一结果，不启动新轮次，不承诺持久化。每个适用请求在该位置保留一份逐字相同结果，即使分支后面已有副本。会话或分支变化前，每种操作及结果只报告一次，新原因可产生新结果。未持久化待写结果最多保留 16 条，先放弃最旧项。

### Agent 交付

Agent 写入追加规范记录，再通过宿主非主动模式排队发送 `omp-context-pin-change`，不启动模型轮次。每个请求重放当前分支记录。导航或期间变化后，重新发送日志尚未显示为已发布的变更。投影对应操作未被当前分支接受时移除，即使条目和修订编号碰巧一致。已接受的当前分支副本保留。

保留日志变更顺序。缺少一项变更时，后续变更构成同一缺口，按顺序重新投影该后缀并移除过时承载消息。恢复的变更放在产生它的工具结果之后；没有该结果时按日志位置放在更晚变更承载消息之前；都没有则置于尾部。不将旧修订放在最新正文之后。用户消息保持原位置。用户写入通过自身消息表达，不复制为变更消息。结果类型为 `omp-context-pin-result`，不携带 Pin 状态，状态重放忽略它。

### 容量

单条正文及当前分支全部活跃正文分别限制为 `16,384` UTF-8 字节。两个入口均在变更前检查。拒绝不改变状态。总容量拒绝报告分支总量、被替换正文大小或创建时零、新正文大小、尝试总量及超出值。单条拒绝报告正文大小、单条上限及超出值。两种拒绝均要求复核整个活跃集合，拆分同文不减少总字节。超限时仍可读取和删除。

### 生命周期

`/new` 建立独立会话和编号。成功 `/clear` 结束当前分支 Pin 期间，但不降低会话级编号。`/fresh` 更换提供方流状态，保留本地历史及 Pin。会话切换、分支导航、`/tree` 和重启重放当前分支期间。重置前操作的重试返回已记录结果，不作为新操作。

只有已提交压缩边界才从活跃正文建立基础快照。放在匹配摘要后，否则最后摘要后，否则请求开头。没有新边界则保留旧快照。有效状态不变时快照字节不变。只移除扩展自身变更消息，原生用户消息或不透明历史仍可能含相同或较早正文。工具定义及格式不随条目变化。读取和未变化更新不改变记录及已发布投影，但普通工具调用和结果仍可扩展历史。

未知、损坏或无效记录使受影响活跃范围不可用。保留记录，拒绝写入及新快照或变更，同范围同原因首次报告宿主日志及可用 UI，此后不重复。字符串身份记录不支持，不转换。重置使旧期间损坏不影响当前正文，损坏点前已恢复身份仍不复用，已接受重试仍可识别。损坏点后的身份未知，无法识别的重复调用视为新调用。当前期间损坏则停止该范围。通过新会话或重置恢复，不静默修复。

### 持久化

会话文件创建及刷新归宿主。追加记录不等于确认写盘。在维护下限 18.5.0 宿主中，明确要求保存、文件已存在或会话已有助手回复时才写盘，新建未保存会话退出可丢失 Pin。宿主保存的日志支持跨进程重放，仅内存日志不支持。弹窗及工具描述必须说明该风险。不强制保存，也不在宿主未确认时声称已保存。

## 验收标准

- 默认关闭、显式关闭及设置无效均不暴露 Pin 工具、命令或新投影，保留记录及历史，其他能力继续工作。
- 六动作、用户确认、来源保持、当前条目更新、先识别重试、完整读取、编号、拒绝明细和状态未变行为符合合同。
- 待处理、取消、编辑、恢复、重复及分支切换的用户消息只在合格时应用。Agent 写入不启动轮次，已接受重试不追加、不恢复旧状态。
- 重置、分支重放、V2 记录、损坏、容量及持久化限制保持。压缩提交后最终请求逐字携带最新正文，不出现旧修订后置或投影重复。
