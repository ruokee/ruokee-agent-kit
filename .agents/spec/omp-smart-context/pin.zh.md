# Pin

## 目标

在当前会话分支的后续普通请求中逐字保留已接受文本，跨越已提交压缩，直到更新、删除或重置。固定文本不获得更高指令权限，不恢复撤销授权，不重启已完成工作。

## 非目标

代调用方读取文件或 URL，监听内容，将任意文字解析为操作，自动维护 Pin，迁移不支持格式，第二存储，使用宿主私有保存方法，通过其他会话保存，或额外启动模型轮次以强制持久化。

## 公共面

`pinEnabled` 是独立 boolean，默认 `false`。OMP 项目设置覆盖用户设置，变更需重启。关闭或无效时不暴露工具或命令，不增加保留文本投影，已有 journal 和普通历史不变。启用后从当前会话上下文执行一次。重新启用恢复受支持记录，无需转换。OMP 保留独立的 `/pin` 命令。`/smart-context` 报告 Pin 的有效状态和固定停用原因。

### 用户命令

`/ctx-pin` 打开当前分支列表，使用宿主主题及自适应宽度选择组件，顺序为添加项、创建顺序的条目、关闭项。行显示 `#<id>` 和折叠连续空白后的正文前缀，按可用宽度截断并加省略号。无可见正文时只显示编号。查看和编辑草稿只读，不发送消息、不改状态、不打断运行轮次。放弃草稿无影响，确认关闭列表。

现有条目提供查看、编辑、取消固定及返回列表操作。编辑只在确认后替换当前正文，取消固定也需要确认。无界面调用说明需要交互式 OMP 界面，不改变状态。

`/ctx-pin add <body>` 保留 `add` 后一个分隔空格之后的每个字符。不做 shell 分词、引号处理、反转义或空白规范化。缺少正文或未知子命令只显示用法，不发送消息。

### Agent 工具

`ctx_pin` 提供六个动作：

- `list`：无动作专用输入，返回全部完整活跃正文及其编号、创建来源、修订号和 UTF-8 大小，以及条目数、总活跃字节和分支上限。空分支明确没有固定正文，并报告零活跃字节和分支上限。
- `get`：整数 `id`，返回一条完整正文及元数据。
- `show`：无动作专用输入，返回全部完整活跃正文及其编号、来源、修订和 UTF-8 大小，以及条目数、总活跃字节和分支上限。空分支明确没有固定正文，并报告零活跃字节和分支上限。
- `create`：`content`，创建新条目。
- `update`：整数 `id` 及 `content`，替换当前条目正文。
- `delete`：整数 `id`，取消固定当前条目。

`content` 必须是非空字符串，文本原样保留。

`get`、`list` 和 `show` 逐字保留正文，包括连续空白、换行和超过显示预览长度的文本。`get` 的编号不存在时，明确报告没有该活跃条目。读取不改变记录、修订、活跃用量或投影。

编号接受正整数，不接受数字字符串。不隐式新增、不以改名创建、不接收修订号参数，也不按修订号准入。显示的修订号只供参考，旧草稿可覆盖更新正文。用户创建来源为 `user`，工具创建为 `agent`，更新保留创建来源。

所有动作声明 `read` 批准档位。没有显式工具策略时，`always-ask`、`write`、`yolo` 不提示，显式 `prompt` 或 `deny` 仍有效。不新增授权门槛或配置写入。保留类型、存在性、容量和记录完整性检查。

### Agent 指引

工具描述要求 Agent 主动固定丢失后会影响后续行动的信息，并遵守明确固定要求。按当前用途而非形式判断内容，保留恢复入口及防止重复工作的完成事实。没有明确要求时跳过易恢复事实。

相关信息包括决定、权限、限制、角色、目的地、恢复指针、结论和阻塞。分别保存独立变化的主题，更新已有主题而非重复创建，也不重复用户已确认的条目。

仍有用的主题发生事实变化时使用 `update`，去掉失效部分，保留有效内容。整个条目失效、被取代或重复时使用 `delete`，不把无关历史改成摘要继续保留。扩展把这些选择留给 Agent，不增加自动维护或按内容拒绝写入。

更新替换完整正文，保留仍有效的事实、条件、顺序、否定、例外、不确定性、义务和受保护引文。新候选不授予权限，也不解决未决条件。行动前修正撤销授权和无效目的地，等待或交出会话前保留恢复所需状态。普通读取、状态不变或单纯压缩不要求写入。引用是恢复指针，不自动读取文件。

## 不变量

### 规范记录

当前分支的宿主会话日志为权威状态。使用自定义类型 `omp-context-pin`、版本 `2` 及以下载荷：

- `schemaVersion`：`2`。
- `operationId`：每次用户提交或新 Agent 写入分配的正整数，重试复用；只供内部使用，不在公共列表、消息或结果显示。
- `action`：`create`、`update` 或 `delete`。
- `entryId`：首次成功创建时分配的会话级正整数，不复用。
- `revision`：从 1 开始，每次接受的更新或删除递增一次。
- `body`：创建及更新的完整新正文，删除时不存在。
- `source`：`user` 或 `agent`。
- `toolCallId`：宿主 Agent 调用身份，用于识别重试。

读取、拒绝和正文未变更新不追加记录或新投影。已接受操作的重试返回原结果，即使条目之后已经删除；不重复写入，不恢复旧正文。相同操作身份携带不同动作、目标条目、来源或正文是冲突，不是重试。公开重试识别不比较修订号。相同规范记录的再次重放没有效果。

条目及操作编号是正安全整数，在整个会话中递增，可以有空缺，在删除、重置、分支切换或恢复后都不复用。待处理预留和宿主持有记录中的身份均计为已使用。其他分支身份占用编号，但其正文、回执和操作不应用到当前分支。无法可靠分配、身份依据不可读或超出安全整数范围时明确报错，不重启编号或回绕。

### 用户提交

确认写入通过普通用户消息提交，只含逐字草稿正文。在宿主消费消息并核对当前进程记录的文本、会话、Pin 期间、分支及目标条目存在前，操作保持待处理。只有当前进程持有的提交可生效。编辑后的消息、引用、其他进程提交、恢复历史及已消费文本均为普通文本。

一次提交对应一条消息，一条消息最多对应一次提交。确认前已消费的相同消息不合格；有宿主消费时间时优先以其为准。草稿仍在等待期间重复相同文本，可被视为该草稿，这是可读用户消息的已接受代价。

确认后出现不匹配任何待处理提交的新用户消息时，放弃未执行文本的提交。会话启动、切换或关闭时丢弃未应用工作，可用时通过 UI 通知。最终拒绝在返回原分支或释放容量后仍保持拒绝。范围不可读不是最终结果，后续可读时可应用。结算后原文本成为普通历史，不应用两次。

只在消费消息时更新已接受状态。宿主尚未写入用户消息日志时，正文仅通过该请求表达，不重复或排队发送 Agent 变更投影。已消费用户写入在操作消息后紧接一条无正文结果，报告已接受、未变化或未应用及原因和条目编号。以宿主非主动模式交付同一结果，不启动新轮次，不承诺持久化。每个适用请求在该位置保留一份逐字相同结果，即使分支后面已有副本。会话或分支变化前，每种操作及结果只报告一次，新原因可产生新结果。未持久化待写结果最多保留 16 条，先放弃最旧项。

### Agent 交付

已接受 Agent 写入添加规范记录，并通过宿主非主动模式交付 `omp-context-pin-change`，不启动模型轮次。每个普通请求反映当前分支已接受状态。导航或期间变化后，尚未表达的已接受变更必须再次可见。未被当前分支接受操作的投影被排除，即使条目和修订编号恰好相同。保留已接受的分支副本。

投影变更保持 journal 顺序，包括较早变更缺失而后续变更已经存在的情况。缺失或需重排的后缀出现一次，不保留被替代的重复承载消息。恢复变更放在产生它的工具结果之后；没有该结果时，按 journal 位置放在较晚变更承载消息之前；两者都没有则放在尾部。旧修订不得位于最新正文之后。用户消息保留原生位置，不重复为 Agent 变更消息。`omp-context-pin-result` 不含 Pin 状态，不影响重放。

### 容量

单条正文及当前分支全部活跃正文分别限制为 `16,384` UTF-8 字节。两个入口均在变更前检查。拒绝不改变状态。总容量拒绝报告分支总量、被替换正文大小或创建时零、新正文大小、尝试总量及超出值。单条拒绝报告正文大小、单条上限及超出值。两种拒绝均要求复核整个活跃集合，拆分同文不减少总字节。超限时仍可读取和删除。

上限按字节计，不按字符或 token 计。元数据、工具历史及旧修订不受活跃正文上限约束，因此整个模型请求仍可能超出自身容量。

拒绝不附活跃条目预览。单条超限指引要求缩短该正文，而非删除其他条目。分支超限指引要求重试前删除失效条目，从仍有用的条目中移除失效部分，再精简冗余文本。两者均保留有效事实、要求及必须逐字保留的文本。必要内容无法无损容纳时，说明容量冲突并停止该写入，不丢弃必要内容。指引不得诱导未经整集合复核就反复缩短正文。

### 生命周期

`/new` 建立独立会话和编号。成功 `/clear` 结束当前分支 Pin 期间，但不降低会话级编号。`/fresh` 更换提供方流状态，保留本地历史及 Pin。会话切换、分支导航、`/tree` 和重启重放当前分支期间。重置前操作的重试返回已记录结果，不作为新操作。

只有已提交压缩才增加当前活跃正文的基础快照。快照放在匹配摘要后，否则最后摘要后，否则请求开头。没有新提交边界时保留现有快照。有效状态不变时，快照文本字节不变。只移除本扩展被替代的变更消息；原生用户消息或不透明历史仍可能含相同或较早文本。工具定义和 schema 不随条目变化。读取及未变化更新不改变记录或已发布投影，但对应的普通工具调用和结果仍会扩展历史。

未知、损坏或无效记录使受影响活跃范围不可用。保留记录，拒绝写入及新快照或变更，同范围同原因首次报告宿主日志及可用 UI，此后不重复。字符串身份记录不支持，不转换。重置使旧期间损坏不影响当前正文，损坏点前已恢复身份仍不复用，已接受重试仍可识别。损坏点后的身份未知，无法识别的重复调用视为新调用。当前期间损坏则停止该范围。通过新会话或重置恢复，不静默修复。

### 持久化

会话文件创建及刷新归宿主。追加记录不等于确认写盘。在维护下限 18.13.3 宿主中，明确要求保存、文件已存在或会话已有助手回复时才写盘，新建未保存会话退出可丢失 Pin。宿主保存的日志支持跨进程重放，仅内存日志不支持。弹窗及工具描述必须说明该风险。不强制保存，也不在宿主未确认时声称已保存。

## 验收标准

- 默认关闭、显式关闭及设置无效均不暴露 Pin 工具、命令或新投影，保留记录及历史，其他能力继续工作。
- 六动作、用户确认、来源保持、当前条目更新、先识别重试、完整读取、编号、拒绝明细和状态未变行为符合合同。
- 单条与集合读取准确保留短正文、多行、连续空白和长正文。集合读取包含所有活跃条目及其当前元数据，分支超容量时也保持完整。
- 工具描述按信息用途区分主动固定、更新、删除和正确的不操作。容量指引针对实际超限原因，不牺牲有效信息，不重复活跃条目预览。
- 待处理、取消、编辑、恢复、重复及分支切换的用户消息只在合格时应用。Agent 写入不启动轮次，已接受重试不追加、不恢复旧状态。
- 重置、分支重放、V2 记录、损坏、容量及持久化限制保持。压缩提交后最终请求逐字携带最新正文，不出现旧修订后置或投影重复。
