# Handoff 对齐

[English](./handoff.md) | 中文

## 目标

将原生 Handoff 请求与同会话已确认普通请求对齐，保留原生交接文档生成、采用和续接。

## 非目标

`openai-completions` 和 `openai-responses` 以外的 API，新命令或文档存储，替换手动压缩，虚构摘要，新增重试，或将 Responses 生成策略投影为普通请求值。

## 公共面

`handoffCacheEnabled` 为布尔值，默认 `false`，使用[组件激活快照](./README.zh.md#配置)。它没有 Provider 筛选或模式，独立于 Remote 设置。Responses Handoff 不要求启用 Remote、Provider 匹配或特定远端模式。V2 仍归 Remote。不支持的 API 保持原生行为。

## 不变量

遵守[共享参照及生命周期合同](./request-alignment.zh.md)。证明操作归属后再按实际请求类型处理，每条物理请求最多一个改写方。

### 参照确认

捕获同次已确认普通发送，以及 Provider、模型身份、API、系统提示词、思考状态和工具集合。准备结果不含工具时不建立参照。待确认工作冻结发送有效代次、持久及 Provider 身份、取消信号和完整归属，并在响应成功后重新核对。失效或已取消工作不能发布参照。通过宿主原生 wire-schema 转换冻结工具定义，包括可调用工具定义。

操作参照不随后续工作、认证刷新、传输重试或处理器状态变化而改变。Responses 来源取自同次普通上下文发送，不取自可能尚未同步的公开 Agent 状态。已确认最终普通传输和 2xx 响应建立独立参照。对齐请求本身不成为参照。

注册前观察两个 Handoff 方法的原生构造基线。基线未确认时不改动它们，已安装包装丢失时 Handoff 不可用。每条物理发送先核对操作的完整归属，再查阅操作缓存结果。归属改变永久撤销操作，即使后续值或正文恢复原样。载荷回调只标记准备完成，最终传输执行投影并统计每次委派或重试。

### 共同历史

仅在交接系统内容是参照系统内容的前缀，且参照的非系统历史是交接历史的严格前缀时改写。绑定的原生 Handoff 快照必须保留完整来源前缀，并有新增尾部。

来源比较只排除 assistant 顶层 `completedAt` 和 `contextSnapshot`，它们是宿主在发送后补写的本地记账字段。内容、提供方重放载荷、未知字段及其他字段必须严格一致。捕获的历史和出站输入均不修改，最终请求格式的历史证明仍独立执行。

### Chat Completions

恢复普通请求的 system/developer 片段和 `reasoning_effort`。仅在交接工具选择不显式时恢复普通 `tool_choice`。保留原生交接指令及新增历史尾部。恢复工具选择可能产生工具调用而非文档文本，仍按原生生成失败处理，不由扩展抑制或重试。

### Responses

使用原生序列化器识别准备后的系统表达，只恢复已证明缺失的系统内容。

顶层 instructions 必须与已知普通系统片段匹配，原生交接指令是其文本前缀。替换 instructions 时完整 input 不变。前置 developer 表达要求已知普通片段和共同历史唯一确定交接系统边界。只替换该前置系统内容，历史 developer 消息位置不变。允许恢复完整缺失片段或片段内部缺失的文本后缀。

工具定义必须匹配。图片、新历史、工具调用及结果配对、缓存键和交接身份保持原生。不把嵌套 reasoning、原生配置更新或 `none` 投影为普通请求值。保留宿主仅在 auto 下执行的兼容重试。严格识别的 reasoning 配置更新仅从共同历史比较中排除，不在出站 input 中插入或删除。有效思考及生成语义保持原生，差异计入对应维度或未投影计数。

必要证明不足时完整请求保持原生。独立不可恢复的维度跳过并计数，无关字段不否决已证明的系统投影。载荷回调结束后，在最终传输原子替换完整已校验候选。相同候选不重新序列化。

### 原生行为

操作失效、参照未确认或变化、系统前缀或历史投影变化时，以固定原因发送原生请求。`rejected` 不表示阻断、延迟或丢弃。

生成、触发、投机、取消、认证和传输重试、模型和方式回退、文档验证、历史提交及续接归 OMP。原生路由和独立旁路会话保持不变。原生手动 focus 和自动入口使用宿主生成器。不注册 `session_before_compact`，不新增重试、命令或文档存储。

只有行为验证确认受维护原生接口在所需路径提供等价结果、配置语义、隔离及失败行为后，才替换适配。仅有上游合并不足以成立。

## 验收标准

- 两种 API 只恢复允许的维度，保留原生交接指令及新历史，独立于远端设置工作。
- Responses 覆盖两种系统表达、历史 developer 位置、缺失片段及后缀、图片历史、可调用工具、原生 reasoning 更新和普通状态尚未同步的情况。
- 接受仅记账字段补写，拒绝内容、重放载荷、未知来源字段和最终请求历史变化。
- 导航、取消、工具或模型或系统或思考或 Provider 变化、压缩及释放均不能恢复旧参照或操作。归属恢复后的重试仍维持已撤销操作的原生发送。
- 实际发送及重试在传输处计数，后续载荷选项保留，竞争包装仍安装，文档采用或失败仍由原生处理。
