# Handoff 对齐

## 目标

将原生 Handoff 请求与同会话已确认普通请求对齐，保留原生交接文档生成、采用和续接。

缓存对齐的目标是覆盖几乎所有可使用原生 Handoff 的模型。模型和协议集合可扩展，各协议均遵循共同的归属、投影和原生行为要求。

## 非目标

新命令或文档存储，替换手动压缩，虚构摘要，新增重试，或超出允许投影维度的生成策略变更。

## 公共面

`handoffCacheEnabled` 为 boolean，默认 `false`。OMP 项目设置覆盖用户设置，缺少键时取默认值，变更需重启。它没有 Provider 筛选或模式。Handoff 不要求启用 Remote、Provider 匹配或特定远端模式。V2 仍归 Remote。尚无受支持投影的 API 保持原生行为。`/smart-context` 单独报告 Handoff 状态和计数。

## 不变量

共同请求对齐要求适用于 Handoff。实际请求类型及已确认操作归属决定资格，每条物理请求最多一个改写方。主会话、原生 task 子会话和 Eval 子会话保持隔离，即使其模型和请求文本相同。

### 参照确认

参照属于同次已确认普通发送，带有 Provider 和持久会话身份、有效模型及 API、系统提示词、思考状态和工具集合。这些事实及取消状态必须在成功响应后仍有效。准备结果不含工具时不建立参照。工具定义须匹配宿主请求表示，包括可调用工具定义。失效或已取消工作不能建立参照。

操作参照不随后续工作、认证刷新、传输重试或处理器状态变化而改变。用于证明的来源必须属于同次普通上下文发送，即使公开 Agent 状态尚未同步。只有已确认最终普通传输及随后 2xx 响应才能建立参照。新普通发送开始后，旧响应不能发布参照。对齐请求本身不能成为参照。

无法确认原生 Handoff 来源时保留请求。失去必要拦截能力时 Handoff 不可用。每次物理发送都须保持完整操作归属有效；归属改变永久撤销该操作，即使后续值或正文恢复原样。载荷回调属于准备，不是发送。在实际最终传输校验请求，并统计每次委派和重试。

### 共同历史

仅在交接系统内容是参照系统内容的前缀，且参照的非系统历史是交接历史的严格前缀时改写。绑定的原生 Handoff 快照必须保留完整来源前缀，并有新增尾部。

来源比较只排除 assistant 顶层 `completedAt` 和 `contextSnapshot`，它们是宿主在发送后补写的本地记账字段。内容、提供方重放载荷、未知字段及其他字段必须严格一致。捕获的历史和出站输入均不修改，最终请求格式的历史证明仍独立执行。

### Chat Completions

对 `openai-completions`，恢复普通请求的 system/developer 片段和 `reasoning_effort`。仅在交接工具选择不显式时恢复普通 `tool_choice`。保留原生交接指令及新增历史尾部。恢复工具选择可能产生工具调用而非文档文本，仍按原生生成失败处理，不由扩展抑制或重试。

### Responses

对 `openai-responses`，识别宿主已准备请求格式中的系统表达，只恢复已证明缺失的系统内容。

顶层 instructions 必须与已知普通系统片段匹配，原生交接指令是其文本前缀。替换 instructions 时完整 input 不变。前置 developer 表达要求已知普通片段和共同历史唯一确定交接系统边界。只替换该前置系统内容，历史 developer 消息位置不变。允许恢复完整缺失片段或片段内部缺失的文本后缀。

工具定义必须匹配。图片、新历史、工具调用及结果配对、缓存键和交接身份保持原生。不把嵌套 reasoning、原生配置更新或 `none` 投影为普通请求值。保留宿主仅在 auto 下执行的兼容重试。严格识别的 reasoning 配置更新仅从共同历史比较中排除，不在出站 input 中插入或删除。有效思考及生成语义保持原生，差异计入对应维度或未投影计数。

必要证明不足时完整请求保持原生。独立不可恢复的维度跳过并计数，无关字段不否决已证明的系统投影。完整候选在载荷回调结束后仍须有效，并在最终传输时作为一次完整替换应用。相同候选保留原有序列化结果。

### Anthropic

对 `anthropic-messages`，支持原生 API-key 和 OAuth 路径。只恢复有证明的缺失系统文本块或末块后缀。普通准备阶段的系统内容必须对应已确认请求的 system。保留本次 OAuth 副请求的 billing 和身份前缀，最终 billing 字节必须由原生 CCH 处理根据该请求完整正文产生。

要求请求工具定义匹配、原始来源完整前缀成立、共同请求历史是严格前缀，并有新增副请求尾部。比较只能规范化字符串/text 块表达及已知内容块上的缓存标记。保留其他所有字段、图片、工具参数与结果、签名及不透明重放。未知字段、工具参数内名为 `cache_control` 的字段、历史 system/control 项及 `Continue.` 不得被规范化隐藏。出站 messages 和 tools 不变。

保留原生 `tool_choice`，包括 `none`，以及 thinking、输出配置、上下文管理、metadata、身份、headers、signal、路由、认证和重试。未知生成策略形状使完整请求保持原生。不把普通请求的策略或身份复制到副请求。

系统缓存标记随已证明的参照片段处理。不得开启已关闭的缓存、改变原生 TTL 或移动 messages/tools 断点。只接受可证明的 ephemeral 标记，可选 TTL 为 `5m` 或 `1h`，显式断点最多四个，长 TTL 位于短 TTL 之前。顶层自动缓存、未知标记属性、不兼容的 TTL 策略或候选断点超额均拒绝整个投影。

替换正文前校验最终原生字节。候选相同、最终证明失败或无法证明调用方自有 fetch 时，保留原始正文及序列化。保留原生传输策略和选定的底层传输。Anthropic 专用接口失效不能停用 Remote 或其他 Handoff 协议。

### 原生行为

操作失效、参照未确认或变化、系统前缀或历史投影变化时，以固定原因发送原生请求。`rejected` 不表示阻断、延迟或丢弃。

生成、触发、投机、取消、认证和传输重试、模型和方式回退、文档验证、历史提交及续接归 OMP。保留原生路由、独立旁路会话，以及原生手动 focus 和自动生成行为。不增加 `session_before_compact` 拦截、重试、命令或文档存储。

只有行为验证确认受维护原生接口在所需路径提供等价结果、配置语义、隔离及失败行为后，才替换适配。仅有上游合并不足以成立。

## 验收标准

- 各受支持协议只恢复允许的维度，保留原生交接指令及新历史，独立于远端设置工作。
- Responses 覆盖两种系统表达、历史 developer 位置、缺失片段及后缀、图片历史、可调用工具、原生 reasoning 更新和普通状态尚未同步的情况。
- Anthropic 覆盖 API-key 和 OAuth、缺失片段与后缀、缓存标记移动、等价文本表达、最终原生 CCH 字节、原生文档采用，以及不残留部分投影的拒绝。
- 接受仅记账字段补写，拒绝内容、重放载荷、未知来源字段和最终请求历史变化。
- 导航、取消、工具或模型或系统或思考或 Provider 变化、压缩及释放均不能恢复旧参照或操作。归属恢复后的重试仍维持已撤销操作的原生发送。
- 实际发送及重试在传输处计数，后续载荷选项保留，外来所有权不变，文档采用或失败仍由原生处理。
