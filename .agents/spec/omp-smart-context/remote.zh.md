# 远端对齐

## 目标

将符合条件的原生 Remote V2 请求与同一会话已确认的普通请求对齐，保留原生压缩决策和输出。

## 非目标

Codex 请求，非 Codex `openai-responses` V2 以外的 API，新压缩方式，虚构显式工具选择，修改输出限制，新增重试，或保证提供方缓存收益。

## 公共面

`compactionCacheEnabled` 为 boolean，默认 `false`；`compactionCacheProviderFilter` 为字符串，默认 `""`；`compactionCacheMode` 默认 `hooks`，接受 `standard` 或 `hooks`。OMP 项目设置覆盖用户设置，缺少键时取默认值，有效激活快照只在重启后改变。空筛选值报告 `provider-filter-empty`，对齐不可用。`/smart-context` 分别报告 Remote 和 Handoff。

当前会话模型必须支持 Remote，OMP 必须选择 Remote，当前模型的 Provider 必须精确匹配已启用修复的筛选值。筛选不改变模型、Provider、路由或压缩方式。不匹配时原生压缩照常进行。主会话、原生 task 子会话及 Eval 子会话保留既有覆盖。Handoff 拥有独立开关和协议合同。

保留各会话类别原生手动、自动、轮内及投机入口的首次、后续与进程恢复后压缩。宿主缺少入口时不新增入口。Codex、V1 及未识别请求形状保持原生。

## 不变量

共同请求对齐要求负责参照确认、操作生命周期、内容复用证明及发送。Remote 另须保留未知字段、显式策略差异和原生回退。任何资格或证明条件失败，都完整保留原生 Remote 请求。

### 来源

在原生 CLI/SDK 会话中，隐藏且归属于 Agent 的 `eval-state-context` 只有作为未持久化显示快照时，才能从来源保留要求中排除。已进入规范历史的快照保留来源依赖，包括恢复时重建的副本。普通请求和原始消息不变，除此之外仍须完整保留规范来源。`standard` 还要求已识别准备与未过滤来源相符。

相同文本的用户消息、归属于用户的自定义内容、可见快照及其他自定义类型均保留全部来源依赖。该识别不赋予局部独立性，不恢复被裁剪输出。

### 复用模式

两种模式均对齐已识别的原生共同内容，包括有效工具定义准备、提醒、重放语义和隐式工具选择默认值。V2 保留自身输出限制或其缺省状态。

已知的布尔 `stream_options.include_obfuscation` 差异不妨碍复用。保留原生 Remote 请求的值或缺省状态；未知流选项差异仍视为未分类。

- `standard` 接受已识别的原生准备差异。
- `hooks` 还可复用已证明的完成处理结果。完整保留范围允许合法插入、重排、恢复、跨范围合并、图片和已有载荷后变换。有状态处理器只运行一次。

局部匹配不能推翻与之矛盾的完整保留来源范围。两种模式均遵守共同的完整范围及局部单元证明要求。

保留原生工具输出改写、删除的依赖、新增普通消息及工具和图片尾部、不透明历史、调用及结果配对和触发边界。不可拆结果的依赖变化时，完整请求保持原生并报告 `projection-dependency-changed`；来源或单元边界未确认时报告 `projection-unconfirmed`。两种拒绝均视为未对齐并计入总数。不提供冻结的纯投影协议，不重复运行黑盒处理器。

### 原生替代

只有行为验证确认受维护原生接口在所需路径提供等价结果、配置语义、隔离及失败行为后，才替换适配。仅有上游 PR 合并不足以成立。

## 验收标准

- 两种启用模式均可对齐已识别原生正例。关闭、空筛选、筛选不匹配、模型不支持、原生未选 Remote 及范围外 API 保留原生决策和请求。
- 筛选从不改变实际模型或路由，包括未修复但原生 Remote 成功的情况。
- 完整保留及合格局部复用保留普通内容，不重复运行处理器或恢复裁剪数据。依赖未证明时以相应原因拒绝完整改写。
- 未持久化的隐藏 Agent Eval 快照可视为显示元数据。规范日志条目、恢复的快照、相似用户消息及其他自定义消息保留来源依赖。
- 最终实际传输保留未知字段、原生限制、新尾部、不透明字节及独立 Handoff 行为。
