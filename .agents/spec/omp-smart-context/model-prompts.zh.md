# 模型提示词规则

[English](./model-prompts.md) | 中文

## 目标

在各受覆盖普通轮次追加用户编写的模型专用系统指令，不替换宿主模板，不修改已有块，不累积先前轮次的正文。

## 非目标

新增匹配维度或发现目录，别名或模型家族匹配，glob 或模型列表语法，缓存规则，每次请求或轮内刷新，额外旁路注入，以及保证高于后续扩展的优先级。

## 公共面

`modelPromptsEnabled` 为布尔值，默认 `false`，使用[组件激活合同](./README.zh.md#配置)。关闭时不注册注入处理器，不读取规则目录或文件，不诊断未使用文件。开关独立于 Pin、对齐和用量。`/smart-context` 报告状态及固定原因，不包含正文或模型身份。

## 不变量

### 发现

每个受覆盖轮次读取 `getAgentDir()` 给出的当前配置档案用户 agent 目录下的 `model-prompts`，以及 `getProjectAgentDir(ctx.cwd)` 下的同名目录，即当前项目 `.omp/model-prompts`。只读取直接子项中的非隐藏、小写 `.md` 普通文件。忽略文件符号链接及子目录，不搜索祖先或额外资源目录。目录不存在时视为空。没有有效模型时不读取规则。

用户目录正文先于项目目录。同目录按 JavaScript 字符串顺序排列文件名。项目文件不覆盖同名用户文件，不同文件的相同正文仍贡献独立块。异步读取完成顺序不影响排列。

### 格式

读取 UTF-8 Markdown，允许一个开头 BOM。文件头元数据的起止分隔行必须精确为 `---`，使用 LF 或 CRLF 换行。必需的 `match` 是非空数组。每项恰有一个受支持键及非空白字符串值：

- `exact`：比较完整 `${model.provider}/${model.id}`。
- `model`：比较完整 `model.id`，包括其中的 `/`。
- `contains`：对 `${model.provider}/${model.id}` 进行字面子串匹配。
- `regex`：以不带标志的 JavaScript `RegExp` 匹配同一字符串。

各项为或关系，命中多个条件仍只追加该文件一次。匹配区分大小写，只比较文本，不解析别名、角色、家族、显示名、请求名或思考后缀。额外顶层元数据忽略且不注入。未知键或多键条件使整份文件无效。空白正文无效。

### 注入

返回新数组，先保留每个输入块的原文和顺序，再为每份匹配文件追加独立块。正文从结束分隔行的换行之后开始。排除元数据和开头 BOM，逐字节保留正文、LF/CRLF、缩进、空行、标题、注释、类似模板的文本及尾部换行。不增加包装、标题、裁剪、渲染、上下文改写、消息或日志条目。

每个受覆盖轮次重新读取规则和事件的有效模型。新增、编辑、删除及修复在下一轮生效，无需重启。读取失败不复用旧正文。没有模型、规则或匹配时保留输入块。宿主轮内提示词覆盖在同轮重建中保持有效，下一轮从宿主基础提示词开始，不累积早前正文。设置修改仍需重启。

### 覆盖

覆盖执行 `before_agent_start` 的普通主轮次及普通子轮次。子会话按自身有效模型匹配，保留角色、独立块和协议。不为计划模式子会话、Handoff、标题、分类或其他旁路增加入口。旁路请求继续使用宿主对实时 Agent 提示词的处理。刷新按轮次，不按每条提供方请求、自动回退或临时轮内模型切换。后续处理器可以覆盖结果，不重排扩展，也不声明最终请求优先级。

### 失败

文件在首个错误处整体跳过：`frontmatter-missing`、`frontmatter-invalid`、`match-missing`、`match-empty`、`entry-shape`、`entry-key`、`entry-value`、`regex-invalid` 或 `body-blank`。`file-unreadable` 只影响一个文件，`directory-unreadable` 只影响一个目录。其他有效来源继续。处理器意外失败报告 `unexpected-error`，保留输入块及早前处理器结果。诊断失败不能停止轮次。

使用当前事件 UI 通道，无界面时使用宿主日志。诊断包含固定原因及范围内相对来源，按会话、来源和原因去重。新建及分叉会话拥有独立记录，返回已有会话时保留该激活的诊断记录。不披露正文、绝对路径、原始解析异常、正则文本或对话。开关类型无效只停用该模块，设置根被拒按整个组件规则处理。

### 信任

启用的项目规则成为系统指令。不新增项目信任门槛、隔离、正则沙箱或超时、正文配额或大小限制。大规则占用提示词空间，慢目录拖延轮次准备。用户文档必须说明这些后果及规则位置。

### 上游替代

OMP 通过 [issue #6739](https://github.com/can1357/oh-my-pi/issues/6739) 或等价能力提供模型专用指令时，比较匹配维度、替换或追加组合、块位置、刷新时机、目录发现、优先级及顺序，再决定保留能力、只保留缺失部分或移除，并同步版本和决定。只有模板不足以证明等价。

## 验收标准

- 关闭或无模型时零读取。发现、四种匹配、或关系单次追加、校验、BOM 和目录顺序符合合同。
- 最终组装及序列化请求各包含一次匹配正文，逐字节保真且不含元数据，宿主块和动态内容保留。连续轮次及提示词重建不累积正文。
- 文件新增、编辑、删除、修复、cwd 和有效模型变化在规定轮次边界生效。
- 文件及目录失败局部隔离，意外失败保留输入，诊断保持隐私和会话归属，普通子会话使用自身模型，不增加旁路覆盖。
