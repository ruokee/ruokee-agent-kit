# QoL 压缩期限

## 目标

提供默认关闭的压缩期限延长能力，明确其进程级代价和所有权限制。本调整遵循组件共同的配置、激活、状态和隔离要求。

## 公共面

### 配置

| 键 | 默认值 |
| --- | --- |
| `compactionTimeoutEnabled` | `false` |
| `compactionTimeoutMs` | `900000` |
| `compactionTimeoutFloorMs` | `300000` |
| `compactionWindowGuardMs` | `3600000` |
| `compactionTimeoutNotify` | `true` |

`compactionTimeoutFloorMs` 是 300000 至 3599999 的整数。`compactionTimeoutMs` 是大于该下限且不超过 3600000 的整数。

`compactionWindowGuardMs` 是不小于有效 timeout 且不超过 14400000 的整数。

### 状态

`/qol` 的压缩行显示 timeout、floor、guard、通知开关和实际进程级状态。

### 压缩期限

期限调整是默认关闭的进程级实验。远端自动压缩、手动压缩前或宿主报告正在压缩时开启窗口。窗口期间，有限的 `AbortSignal.timeout(ms)` 请求满足 `floor <= ms < timeout` 时获得配置 timeout。其他输入保持原生行为，包括非法输入的原生错误。窗口外全部输入保持原生行为。

第一个未中止的压缩取消信号归属当前操作。已经中止的信号关闭窗口；后续取消只关闭自己所属窗口，不能关闭之后的窗口。相同信号的重复通知，包括串行回退方法，沿用同一窗口，不延长 guard 期限，不重复通知和资源。不同的活动信号、重叠操作、另一会话的窗口或无法识别的事件顺序停止本进程实验并报告原因，第二个活动操作报告 `overlapping-round`。

压缩结束、压缩提交、会话切换、关闭、取消或 guard 到期中最早发生者关闭窗口。guard 从最初开窗事件开始计时。通知开启时，每个窗口只在首次延长期限时报告。

一个激活拥有进程级实验。后续激活的包版本与有效设置相同，则保留实验但不接管所有权、不开启窗口，并报告 `incompatible` 和 `patch-owned-elsewhere`。原所有者开窗期间，它仍共享进程级影响。不同版本或设置快照停止可识别的现有实验。停用或设置非法的激活也停止实验，不启用任何模块；其自身开关状态与 `/qol` 展示的进程实际状态分别表达。

所有者结束会话时停止实验，`owner-stopped` 成为本进程终态。必须重启 OMP 才能重新激活。会话切换只关窗，不结束激活。拒绝与可识别的旧压缩补丁共存，拒绝未知所有权、已被覆盖的自有调整、缺少必要宿主能力或已经停止过实验的进程。事件注册失败报告 `registration-error`，不留下活动实验。只释放仍由本组件拥有的资源，不覆盖其他扩展安装的替代项。

接受以下代价和限制：

- 窗口是时段，不是隔离的请求或项目。进程内全部匹配 timeout 都被延长，包括无关调用者和其他会话。
- 只能延长新建期限。关闭窗口不能缩短已创建的信号。期限限制单个信号，不限制全部重试和回退总时间。
- 启用实验会放弃宿主投机压缩。拦截生效时，不启动投机压缩，不将阈值延后给已有投机，也不消费投机结果。原本后台准备的压缩可能使前台等待。
- 原生压缩使用 300000 毫秒。floor 高于该值会使压缩请求本身不再匹配；`/qol` 明确说明。
- 进程级调整不写持久配置或会话状态。关闭并重启后恢复原生行为。

## 验收标准

- 压缩检查覆盖区间边界、原生错误不变、同信号回退、取消、guard 到期、重叠操作、匹配和冲突激活、所有者退出、外来所有权、默认关闭及进程级影响。
- 真实远端压缩超过原生期限后仍成功完成，随后仍能正常发起模型请求。宿主升级须重新验证该行为，修改维护声明不能代替该证据。
