# 仓库

## 目标

只收录 Ruokee 编写和维护的能力，以及分发所需的第一方打包、安装、文档和验证。每项能力采用宿主或构建系统的原生形式，每个可分发组件保持自包含。

提供完整的双语目标、历史可追溯的持久决定、清晰的工作规则和共享术语。贡献者与 Agent 能区分要求的结果、实现选择、操作说明和执行证据。

让社区参与者获得清楚的行为要求、私密举报渠道，以及与维护者实际责任相符的处理安排。

提供真实可用的私密漏洞报告渠道，明确处理责任、修复范围和披露约定。

## 非目标

- 第三方能力、fork、上游镜像、空能力分类，或为假设需求预建的结构。第一方能力可引用、摘录或改编许可允许的第三方材料，不因此把该第三方能力作为维护对象。
- 受跟踪的开发者本地目录、机器清单、部署或恢复配置、凭据、私有主机名、内部服务 URL，或设备专属模型、Provider、渠道配置。忽略的本地材料及其链接不是公开依据。
- 内部维护 Skill 的公开分发或跨项目适配、由它们维护任务 Goal，以及新增维护 CLI、sidecar、归档 manifest 或通用适配框架。
- 在检查中安装依赖、格式化源码，或以全局工具替代缺失的本地前置条件。

## 公共面

### 仓库区域

- `projects/` 保存独立维护的扩展、可执行程序和宿主包，以及其组件文档和检查。
- 普通公开英文 Skill 位于 `skills/<name>/`，中文变体位于 `variants/zh/skills/<name>/`。项目组件在自身边界内拥有 Skill 源码和语言资源，自行组织内部布局，保留宿主发现、安装身份及完整自包含分发。
- `docs/` 保存仓库级文档，`scripts/` 保存仓库级安装、维护和检查。组件专属材料随组件保存。
- `.agents/spec/` 保存长期规格。每个项目组件、普通 Skill 分发、仓库约定和宿主兼容都有完整规格集合。非规格索引列出每个集合的全部文件及两种语言。
- `.agents/adr/` 保存当前决定及曾经生效、后来被替代的决定。`.agents/rule/` 保存工作规则，每个活动一份双语页面，不使用日期文件名或子目录。其索引不是未来活动的封闭清单。
- `.agents/skills/maintain-spec/` 与 `.agents/skills/maintain-adr/` 保存可由项目原生 Skill 机制发现的英文内部维护 Skill。

### 文档

规格完整说明目的、必要行为、输入条件、默认值、限制、失败结果、兼容和可观察验收。删除原实现及其说明资料后，完整规格集合仍能支持内部不同但功能基本一致的新实现。内部函数、算法、构建组织、验证日志和会话记录不属于规格内容。

规格正文没有仓库文件链接，包括语言、其他规格、ADR、规则和源码链接。裸路径及对当前行为的引用不能委托需求。路径本身是已确认外部接口时，可以连同其完整行为写入。语言、主题和决定导航由非规格索引提供。规格就地维护，不保存修订历史或生命周期状态，并与有效决定及已确认要求一致。

ADR 保留持久选择、理由、重要替代方案、结果和必要历史合同。设计解释实现。用户文档独立说明同一已确认合同的安装和用法。验证材料保存方法与证据。规则约束贡献者的动作、顺序、权限和禁止事项。仓库 README 介绍能力和开发，Agent 指引保留导航及高频规则。在用户指南中说明同一目标不产生冲突的权威来源。

仓库词典定义仓库开发使用的规范英文术语、中文对应和含义。组件术语表保持自包含且语义一致。命令、字段、文件名和第三方专名保留原始拼写。新增术语或改变含义需维护者确认，有意采用的别名明确记录。

### 社区行为规范

仓库在根目录以 `CODE_OF_CONDUCT.md` 和 `CODE_OF_CONDUCT.zh.md` 提供 Contributor Covenant 3.0 改编的完整英文和中文准则。英文为 GitHub 默认入口，两种语言互设链接，各语言的 README 和贡献指南均能进入对应准则及私密报告说明。

准则承诺友好、安全、公平的社区，尊重每个人的尊严、权利和贡献，不因种族、民族、种姓、肤色、年龄、体貌特征、神经多样性、残疾状况、生理性别或社会性别、性别认同或表达、性取向、语言、哲学或宗教信仰、国籍或社会出身、社会经济地位、教育程度及其他身份属性而区别对待。真诚参与并遵守准则者享有同等参与权利。参与者认识到文化、背景和语言可能影响对言行的理解。

鼓励的行为包括尊重社区宗旨和活动、善意与诚实、尊重不同观点和经历、对言行及贡献负责、建设性反馈、弥补伤害，以及维护社区福祉。限制的行为包括在明确界限或停止要求后仍进行骚扰、人身攻击、基于无法改变的身份或特征作出刻板判断或歧视、不恰当的性化、未经许可分享或利用隐私信息、暴力及其他伤害，以及其他威胁社区福祉的行为。实施、威胁实施或宣扬这些行为均违规。虚假身份或通过冒充规避处置、缺少来源署名、不符合社区规范的宣传，以及不负责任地呈现受限制内容也受限制。意见分歧或技术批评本身不一定违规，但其中对待他人的方式可能违规。

Ruokee 通过 `ruokee@foxmail.com` 私密接收并处理行为报告，正文提供可见的 `mailto:ruokee@foxmail.com` 链接。报告不放在公开 Issue 或 PR。报告说明要求提供事件经过、时间地点、相关链接或记录及行为是否持续，只包含相关个人信息。报告私密处理，向相关当事人披露的细节限于了解和处理事件所需。Ruokee 审阅材料，必要时要求补充说明，并按情节和严重程度决定处置。不承诺固定回复或结案时限。

Ruokee 可以编辑或移除违规内容，并限制项目管理空间中的参与。措施与行为及影响相称，以停止伤害、尽可能恢复建设性参与为目标。处置指南包括：

- 私下书面警告，说明违规并要求停止；承认责任、确认要求或私下道歉可帮助弥补伤害。
- 警告不足或行为较严重时，在明确期限内限制特定活动或互动。
- 严重或反复违规时，在明确期限内暂停项目管理空间中的参与，并说明恢复条件。
- 其他措施无法制止反复违规，或违规严重到继续参与会危及社区安全时，永久封禁。

严重违规可以跳过较低步骤。在可行时向受限制者说明原因，同时避免不必要地披露报告隐私。项目没有单独的行为准则委员会、独立申诉机构或指定备用接收人。涉及 Ruokee 的报告仍由 Ruokee 接收，无法在项目内独立复核。

准则覆盖仓库、Issue、PR 和其他项目明确管理空间中的维护者、贡献者及其他参与者，也覆盖项目官方账号、指定代表等正式代表项目的活动。普通使用软件或贡献内容不构成代表身份。

归属说明标明 Contributor Covenant 3.0、Organization for Ethical Source、Mozilla 的分级处理工作，以及按单维护者能力对报告、处理方式和范围所作的改编。改编文本保留 CC BY-SA 4.0 许可，并提供来源、许可、常见问题和译文链接。仓库其他内容保留 MIT 许可，README 区分准则的许可。

### 漏洞报告

仓库根目录发布 `SECURITY.md` 与 `SECURITY.zh.md`，两语政策完整等价并相互导航。英文为 GitHub 默认安全策略。各语言的 README、贡献指南和 Issue 模板均进入对应政策及私密报告说明。普通问题和行为举报保留各自独立渠道。

仓库启用 GitHub 私密漏洞报告，入口为 `https://github.com/ruokee/ruokee-agent-kit/security/advisories/new`，使用平台默认表单。Ruokee 关注报告通知、接收并评估报告，协调后续处理。后续沟通继续在同一私密报告中进行。Ruokee 可以请求补充信息、接受报告并协作修复，或说明不受理的原因。尚未公开的细节不进入公开 Issue 或 PR。不承诺固定回复或修复期限。

策略覆盖仓库维护的第一方代码、脚本和 Skills。报告说明要求提供受影响组件或文件、版本或提交、相关操作系统、运行时或宿主信息、复现步骤或最小示例，以及观察到的安全影响和受影响的人。示例与日志不包含凭据或无关个人信息。报告前不要求先证明归属。仅源于宿主产品的问题归其维护者处理；归属不清时，可根据报告判断。模型不符合预期的输出本身不能确定为仓库漏洞，本仓库 Skills 引起的具体安全影响可以报告。

安全修复以 `main` 当前内容为目标。接受旧版本报告，但不承诺历史版本回补。使用者更新到包含修复的版本或提交。此修复范围不改变组件的宿主维护下限。

Ruokee 与报告者逐案协调公开时机，通常在修复或缓解措施可用后公开。紧急风险可能需要不同安排，由双方另行沟通。不设固定披露期限，也不要求无限期保密。

### 维护 Skill

`maintain-spec` 在新增、修改、移除或审查长期规格，以及功能工作影响目标、边界或验收之前适用。它覆盖新主题、目标变化、遗漏、边界澄清、实现偏离、移除和文字修复。依据包括相关当前规格、已确认需求、含日期变更的有效决定、项目补充，以及既有链接之外的必要来源。任务讨论可以说明批准或建议目标。现有代码或建议选择不等于需求批准。

维护方法保全条件、数值、默认、例外、失败结果、权限与兼容，将混合条款中的外部要求和实现分开，维护完整的语言与引用集合，并检查新实现者能否脱离实现资料判断符合性。来源冲突只暂停对应条款，交维护者裁决；不受影响的获授权工作继续。

`maintain-adr` 在创建、修复、更新、反转、归档或审查 ADR，以及改变持久选择之前适用。它区分事实修复、非冲突更新、完整继任和生命周期动作，保留原作者、身份、真实日期、直接关系、历史要求和双语含义。两个 Skill 都不负责任务 Goal 或任务生命周期，不扩大权限，不为无关工作强制要求加载对方，不为未改变持久选择的变更创建 ADR。只读工作保持只读。

每种主要方法由其 Skill 及必要参考主要持有。各层索引保存项目覆盖、语言、权限、Git 政策和导航，不保存另一套完整方法。描述与 Agent 入口说明何时加载，无需用户反复点名。

### ADR 记录

ADR 只有决定一种文档类型。记录采用 `decision/YYYY/MM/DD-name.md` 和 `archived/YYYY/MM/DD-rN-name.md`，中文配对位于同目录。两个根目录保留 `.gitkeep`，根 README 文件对保存项目补充。`YYYY` 为四位，`MM` 和 `DD` 为两位。只为实际记录创建日期目录，每月没有文件数量上限。活跃和被拒提案不是 ADR 状态，未采纳草稿不进入归档。

新主题使用首次正式决定日期和简短规范英文主题。日期取依据有效批准及已完成的对应实现编写决定之日；纯文档选择取决定编写日。讨论、任务创建和未来集成都不决定身份，后续审查不使其改名。既有决定保留身份，包括历史提案日期。反转保持当前规范路径不变，只递增该决定从 `r1` 开始的档案序列，同日、跨月和跨年都不重置。抽出独立主题时建立其自身决定日期、身份与序列，同时保留真实关系。语言对应文件、普通更新、事实或命名修复不消耗修订号。

标题说明主题而非生命周期。决定包含 `Decision owner` 与 `Decision writer`，前者是负责的维护者，后者是原作者，普通维护不替换原作者。模型作者名称省略 provider、router 和 channel 前缀，可以保留宿主名称。档案额外包含实际 `Archived` 日期，位于 `Reversed by` 之前。继任的 `Reverses` 指向直接前驱；更早档案随中间前驱进入其档案位置，不跳到最新当前版本。不用 `Status` 字段代替生命周期目录。完整叶文件名连同日期、修订号、语言后缀和扩展名最多 60 个字符。双语负责人和作者字段一致，完整元数据块后紧接双向语言链接，语义冲突由维护者解决。

决定章节依次是动机、可选的实质分析、决定、考虑过的替代方案、结果。非冲突补充放在末尾变更章节，使用真实日期三级标题；独立新增可以链接另一决定。动机以简短一句独立说明选择，不依赖标题或链接，理由与证据放在后面。替代方案须真实进入同一选择并解释重要取舍；结果中的风险和接受的代价须有可信原因与实质后果。空的替代方案写 `None` 或 `无`，省略无依据主张。记录保存必要公开理由与契约，不成为组件手册、执行计划或审查对话。

维护者决定是否采用持久选择及归档被替代决定。任务保存讨论、批准及其范围、被否决选项和待执行安排；公开协作可以使用可访问的 Issue 或 PR，不将其设为必需依赖。任务状态、Plan、审查结论或实现完成不授予批准、归档、集成或任务关闭权限。已有有效批准可以复用。普通否决保存在任务材料，重要否决理由进入采纳的决定，有长期约束的“不采用某选项”本身可以成为决定。公开决定不依赖私有任务记录来解释选择。该机制不增加任务状态、运行时功能或强制替代 RFC 流程。

需要实现的选择，其正式决定随对应实现一起集成，纯文档选择可以独立集成。替代变更合入前，当前决定仍是主线权威。反转指出原有效条款、新选择和二者不能同时成立的原因；代码量、功能、宿主依赖或改名本身不构成冲突。取得所需批准并完成实现后，在同一变更中形成保留未受影响合同的完整继任、归档被替代版本且不覆盖既有档案，并修复直接关系与引用。档案在关系与事实链接修复后冻结，保留历史选择。当前权威引用和历史引用指向所需版本。命名或有依据的身份修复不改变承诺，不改写真实事件，也不保留旧名别名。持续变化的当前文档不能替代必要历史合同。

### 开发检查

`pnpm check:changed` 对相对本地 `main` 合并基线的已提交和待提交变更选择去重后的检查并集；`--base <ref>` 使用另一个合并基线，不获取远程历史。重命名和删除仍作为输入。文档消费者的专属规则优先于普通 Markdown 分类。已知说明性 Markdown 对仍存在的文件选择格式检查，已登记组件变更选择组件检查，共享、未知或分类不可靠的输入选择一次完整检查。空选择不表示可以合入。

`pnpm check` 是完整检查集合，其覆盖与选择器及其回归检查一致。组件检查位于组件内。缺少被选中的前置条件时明确失败。检查命令不安装依赖或格式化源码。独立分支具有独立可写依赖与构建目录，同一信任边界内可以共用包管理器内容缓存。

## 不变量

- 可分发组件只引用自身文件，不导入或读取其他仓库组件及仓库支持文件。可以按名称声明其他组件、工具或 Skill 为前置条件，并使用其公开接口。内部维护 Skill 可读取所维护的项目材料。
- 代码、注释、配置和默认公开文档使用英文。普通公开文档在同目录配对为 `name.md` 与 `name.zh.md`，入口为 `README.md` 与 `README.zh.md`。两种语言完整并一起维护。普通文档互相提供语言链接，规格使用外部索引。Skill 语言变体保持自己的组件布局，不添加跨语言文件链接。
- 规格之外的仓库文件链接相对于所在页面，当前树使用 `./`，离开时使用 `../`；复制到 GitHub Issue 或 PR 正文的模板除外。这些模板正文中的仓库文件链接使用指向默认分支文件的完整 GitHub URL。其他仓库文件链接不使用前导 `/`、根相对路径或 GitHub 绝对 URL。标题片段引用保持有效。`AGENTS.md` 以行内代码提及，不作为公开链接。
- 文件名与标题只有一个简短主题，使用祈使句、短语或名词，除非具体要求另有规定。标题标点仅允许 `-`、`.`、`、`，名称不并列无关主题，不添加显式锚点声明。
- Prettier 格式覆盖所有受跟踪 Markdown。来源署名和适用许可信息保存在仓库层、组件 README 或决定，不放在纯 Skill 树内。
- 提交信息采用英文 Conventional Commits 标准类型。可选 scope 为 `skills`、`extensions`、`adr`、`repo`，跨领域变更省略 scope。提交钩子格式化暂存文件并拒绝无效信息。
- `main` 是唯一长期分支。短期开发分支经独立授权后 squash merge。获授权的依赖单元可从冻结、已提交、已核验的前置候选开始，前后单元分别可审查。提交、合并、推送、删分支与任务关闭是不同权限。
- 最终合入候选干净、已提交、包含目标 `main`，完整检查成功与其 commit、tree、目标绑定。受跟踪内容变化、待提交变更、候选变化或目标推进使成功失效。集成后的树与已验证树相同。
- 组件功能变化携带 `X.Y.Z` 版本更新。最终 squash 变更默认只递增一次 `Z`，`X` 或 `Y` 由维护者决定。未发布的首次添加在修订中保持初始版本，通常为 `0.1.0`。版本声明一致。
- 组件不保留不可达代码、重复实现或假设需求的设计。简化保全已确认命令、工具、设置、格式和行为。

## 验收标准

- 每个主题具有完整双语目标。读者不打开实现资料即可确定必要行为及失败结果，并以这些结果判断不同内部实现。规格正文没有仓库文件链接或间接需求委托。
- 分发组件可脱离仓库支持文件安装和运行。语言配对表达等价能力、限制和指令，清单与导航能定位完整集合。
- 实际维护加载适用 Skill 与有效依据，保全未受影响要求，产生一致的现行文档和历史关系。只有发现或格式通过不满足此结果。
- 新决定依据获准选择及必要的已完成实现形成，待执行选择保存在任务中。同日及后续反转保留稳定当前路径、连续的独立序列、实际事件日期和准确直接前驱。历史记录仍解释原选择。空替代方案是有效结果，不保留缺乏依据的替代方案或风险主张。
- 无效提交类型或 scope 被拒绝。受影响检查保留规定的并集、删除输入、消费者优先级及完整回退。内部 Skill 与规则 Markdown 仍属于已知文档输入。
- 最终候选满足完整检查的身份绑定条件。当前决定、规则、Skill、索引、词典和必要语言版本一致，不削弱既有组件行为。
- 两种语言的入口均能到达完整行为要求及已确认私密举报地址。报告责任、隐私、处置方式、适用范围和无法独立复核的边界在各语言及公开入口中一致。
- GitHub 能识别默认分支发布的准则文件。准则保留来源归属及 CC BY-SA 4.0，不改变仓库其他内容的许可证。
- 两种语言的入口均能到达完整安全策略及可用的 GitHub 私密报告入口。报告责任、后续沟通、范围、以 main 为目标的修复政策和披露约定在各语言及入口中一致。
- GitHub 展示默认分支发布的安全策略，私密报告已启用，Ruokee 可查看私密报告并拥有覆盖安全提醒的有效仓库通知订阅。入口检查不要求提交测试报告。
