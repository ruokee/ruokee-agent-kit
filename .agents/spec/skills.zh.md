# Skill

本规格覆盖普通公开 Skill 及其安装生命周期。tk Skill 与 workloop 是独立项目组件，内部维护 Skill 属于仓库维护能力，不是公开安装源。

## 目标

以中英文分发可独立理解、可被宿主发现的指令组件。保留各 Skill 的触发边界、必要行为、证据标准和权限。选定语言的完整目录安装到 `<skill root>/<name>/`，不带仅存在于源码中的语言前缀。

## 非目标

- 第三方能力、fork 或上游镜像。第一方 Skill 可在取得必要许可并署名后引用、摘录或改编第三方材料。
- 在纯 Skill 树内放插件 manifest、市场元数据、包变更日志、包 README、许可或声明文件、宿主专用 Agent 定义。`grill-me` 的明确调用策略保留。
- 为假设 Skill 预建结构、全局安装注册表、普通安装器的网络访问、默认安装全部 Skill，或管理项目组件与 Harness 配置。

## 公共面

### 身份

英文源位于 `skills/<name>/`，中文源位于 `variants/zh/skills/<name>/`。每个目录包含声明名称、适用描述及所维护版本的 `SKILL.md`，以及所需本地参考、工作流、示例或术语表。两个变体保持相同 Skill 身份、文件集合、范围和可观察指令。每个 Skill 根中的同一名称一次只安装一种语言。

`grill-me` 由用户调用。`architect`、`code-quality`、`python-engineering`、`msgspec`、`deep-research`、`well-said` 支持 Agent 根据匹配工作加载，也支持明确调用。双语能力索引列出相同名称和调用方式，并提供两种语言入口。

### grill-me

`grill-me` 显示名为 `Grill Me`，将不完整想法或已有计划转为共同理解和可执行规格。仅通过宿主 Skill 机制的明确调用才触发，普通规划、审查、深入讨论或提及 Skill 都不触发。两个变体在适用调用元数据中声明 `disable-model-invocation: true` 与 `policy.allow_implicit_invocation: false`。

对想法先明确需求再选择方案，对计划先确认其需求依据。区分问题或机会、预期结果、候选干预、偏好、证据、推论、决定、不确定性和风险，只拆分可独立决定的分支。核对事实前提及候选是否服务目标，不要求用户证明个人偏好。保留有依据的部分，将不匹配的方案交用户选择，对缺乏依据的部分缩小或延期，不悄悄删除目标。

建立用户、场景、范围、非目标、约束、授权、材料、偏好、验收和停止条件。维护带依赖的审视图，只处理前提已确定的问题。提问前调查可查事实，证据优先级依次为当前明确用户陈述、指定材料与项目决定、直接本地证据、权威上游、其他来源、模型推论。读取相关指定材料。只问用户才能提供的含义、经验、优先级、授权，或证据不能解决且不能安全延期的重要选择。可采用低风险、可逆的操作默认值，选择方向或风险姿态的默认值需确认。

每轮最多三个独立实质问题，无固定轮数上限。跨轮和恢复持续递增全局 `Q` 编号，澄清保留原编号，新主题获得新编号。每个面向用户的实质问题都显示编号，记录位置、交互方式和结束确认属于不编号的协调。首轮前提供全程普通文字或适合时结构化提问两种方式，用户选择后者之前实质问题默认使用普通文字。开放问题始终用普通文字，结构化问题需要边界清楚且可独立回答的选项。发现类问题解释重要性而不预设回答，决策类问题给出事实、建议、影响和真实选项，不强制编码回复。

优先使用已有获授权记录，否则建议并确认具体位置，默认文件名为 `grill.md`。参考材料不自动成为记录输出。记录以追加为主，保留基线、审视图、来源、准确编号问题、回答、需求合同、偏好、决定、默认、延期、纠正和影响。每轮展示前保存每个问题的准确文字及编号。禁止或无法记录时，在上下文保留同样状态和编号并说明存储限制，不声称已经保存。结论变化时追加替代结论及影响，不擦除历史。

下一轮前处理每次回答：区分接受、修改、质疑、延期、跳过和未决，保留回答及影响，更新需求与偏好，重新打开受影响分支，调查新事实。用户质疑或深入讨论时暂停问题队列。复用已确认偏好，按适用范围解决冲突回答。明确有后果的未述假设，不把探索当同意。

用一个粗略全局百分比表达就绪度，不按条目数计算。首次实质回答前最多约 20%；目标或成功条件不明时通常不超过约 30%；重要条件仍靠假设时约 60%；需求大体完整但有已命名阻塞时约 80%；仅剩最终阻塞或审计时约 90%；只有审计和结束条件通过才是 100%。通常使用十位、偶尔五位的粗值并标明近似。初始审视图后、约每五轮完成后、重大范围变化时、按请求及结束前，说明阶段、依据、已完成和剩余重要分支、依赖、未知与延期，不打断尚在讨论的问题。

结束前审计假设、失败路径、可逆性、支持、验收、冲突和隐藏方向默认。提供可纠正的共同理解，包含问题、结果、场景、边界、偏好、方向、证据、风险、默认和未决事项。重要事项已解决或安全延期、用户确认共同理解且结束条件成立后才完成。用户提前结束时报告就绪度和剩余不确定性。最终确认前不实施对象，除非用户明确要求边决定边行动；调查与获授权记录可以继续。

### architect

用于跨模块、服务或部署边界的系统级分析、设计、审查、技术选型和演进。覆盖系统视图、数据与状态归属、质量属性、分布式约束、一致性、韧性、扩展、组织、安全边界、AI 系统与评估、技术选择及长期变化。参考材料按需提供解释、推导、示例和取舍，不构成必须顺序阅读的课程或独立模板目录。

单模块内部设计、具体实现、代码级审查、产品行为定义、优先级排序、普通讨论或仅提及架构不触发该 Skill。明确加载也不扩大范围或授权实现。项目事实来自当前代码、配置和运行证据，产品要求和用户优先级仍由对应来源决定。

区分观察、推导结论、未验证假设、建议和用户决定。项目事实标明位置、配置、输出或观察窗口，估算说明输入、公式与不确定性。带数值的案例和受版本影响的外部能力声明需要有日期或版本的一手来源。经验法则须标明，不作为升级触发依据。提供真实候选、适用条件和取舍，将技术选择转为成本、风险和时间后果。分析设计围绕边界与视图，用户决定是否实施。

### code-quality

用于可维护性、抽象、设计原则和模式、重构、代码异味、测试、范式适配及架构质量。明确真正关注的是正确性、可读性、变更成本、可测试性、性能还是交付成本。仅在有具体信号时读取相关指引，为其他目的加载入口不触发全部参考读取。

快速审查是具体 diff、文件或明确文件集合的默认模式。范围不清或全仓库目标需缩小，或由用户明确要求完整审查。返回零至五个高置信问题，按重要性排列，每项含严重性和置信度、位置、可观察事实、影响和最小充分建议。零问题有效，不自动升级模式。

完整审查需用户明确要求完整、系统性、架构或设计审查、重构评估。分阶段读取前明确范围和必要上下文，评估变更成本、原则冲突、实际变化点、异味、范式匹配，以及安全重构所需行为覆盖。对高严重性问题考虑合理误报解释，不足以成立时降级。按类别组织问题，说明事实、影响、判断、正反证据、建议和验证，仅保留有价值的未决问题和备注。

分析模式提供咨询和建议，不是问题清单。根据实际代码和约束比较真实选项，说明决定性取舍，给出建议或询问必要的用户选择。代码外形相似不证明重复知识，也不足以支持抽象；模式需要真实变化点。不重复格式器或 linter 能机械判断的问题。审查和分析不授权改代码、自动重构、批量抑制或不安全修复，既有报告写入许可另行保留。

### python-engineering

用于 Python 项目结构、版本和依赖政策、类型、测试、docstring 和 API 文档、自定义 lint、语言特性、标准库选择与工具。判断基于项目实际版本、依赖声明、配置、代码、调用方和测试。覆盖脚本、包、应用与 workspace，注解和类型边界，上下文管理器、异常组、装饰器、模式匹配，资源生命周期，以及适用时 uv、Ruff、ty、mypy、basedpyright、pytest、coverage、pre-commit 和自定义 lint 的一致使用。

默认快速审查明确目标，返回零至五个含严重性、位置、事实、影响和最小建议的问题。检查语法版本、依赖分组、布局、公共类型、资源清理、数据模型及无必要复杂度。完整审查需明确的完整、全面、系统性或架构审查请求，分阶段读取，采用更完整的工程维度，复核严重问题，并在分组问题中增加置信度、证据、判断和验证。两种模式均不制造问题，也不重复格式器、linter 或类型检查器的结果。

分析读取实际机制和约束，有真实选项时提供两至三个，以适合当前条件的建议开头，说明代价，将重要用户专属取舍留给用户，使用文字而非审查评分。任何模式都不静默授权编辑。只读和分析请求不运行创建环境或缓存、改锁文件、安装依赖、改源码的命令。不安全修复、批量修改、跨文件重构、依赖变化和行为变化需要相应明确许可，保存报告的独立许可仍保留。

### msgspec

支持 Struct 定义、字段、默认、改名、继承、选项、可用注解、校验约束、带标签联合、类型转换、自定义 hook，以及 JSON、MessagePack、YAML、TOML 和 JSONL 序列化。提供适用的 Pydantic、dataclasses 比较、排障，以及基本使用、带标签联合、自定义转换的可运行示例，只加载需要的指引。

区分直接 Struct 构造与类型化解码或转换：类型和 `Meta` 约束在解码、转换时适用，直接构造运行 `__post_init__` 而不进行这些检查。保留被省略的 `UNSET` 与编码为 null 的 `None` 差异。仅为原生不支持的类型使用 hook，使用 YAML、TOML 前确认可选依赖，重复操作复用已配置编码器与解码器。性能比较说明官方方法和负载，不给无条件速度倍数。

### deep-research

为广泛调查和有来源报告提供证据优先的深度调研。明确问题、用途、深度和重要维度，先广泛探索再定向调查，完整读取重要来源并跟进关键线索。不让最先几个来源决定整个方向，也不把一次搜索当作充分证据。

优先官方和一手来源，二手来源用于发现线索或支持比较。同一证据链中的重复陈述不算独立确认。资料收集与综合分开，区分事实、推论、判断、宣传、建议和未决不确定性，支持关系不清时不下确定结论。

默认提供结论摘要、来源清单、完整报告和未决问题，并保留支撑所需的来源材料与比较。优先保存可验证的 Markdown 来源，完整内容不可得时保留实质摘录或摘要、URL、作者、发布日期和访问日期。在环境并发上限内使用子代理并行处理独立调查，超额工作排队；纠正错误，不因正常工作缓慢而中断。调研没有固定时间或 token 上限，在请求范围及交付物完成时停止，不因仍有更多来源而无止境扩展。

### well-said

适用于所有输出，包括回复、文档、代码和配置中的注释，以及 Agent 之间的消息。每种语言通过 `SKILL.md` 入口提供完整写作指导，版本位于 `metadata.version`，署名不进入指令正文。组件负责内部组织，不固定文件数。使用前加载全部必要指导，不按写作信号选择片段；仍在上下文时复用，丢失后补读。描述或摘录不足以代替全文。加载失败时明确适用限制，不声称已应用缺失规则。

面向读者和所需格式直接表达。遵循用户指定的文件、文本和结构，审阅在未获编辑授权时保持只读。保留含义、事实、数值、范围、条件、顺序、否定、义务、归属、不确定性、作者声音及必需原文。需要时命令、标识、引文和日志逐字保留。清晰的文字可以不改。

去除夸大、无依据归属、营销、套话、装饰性强调、强凑列表、无必要同义替换、黑话、填充、过度保留态度和泛泛结尾。使用具体动词、主动语态、熟悉词汇和可读句长。不使用破折号，也不以括号或其他横线替代同一结构。标题只有一个简短主题，标点仅允许 `-`、`.`、`、`。表格用于可比较数值、类别或枚举值，不用于文字描述。避免装饰性 emoji、弯引号、不必要粗体和标题式大写。

把免责声明和未完成工作叙述视为可能的工作问题，在授权内补完或重做，而不是润色掉缺口。工作正确时明确有证据的结论，删除空洞自我辩护。保留真实阻塞、证据、重要未知、风险、权限条件和必需状态报告。这些表达用于判断，不是禁词表。

从成文中移除写作会话残留、不可访问的私有引用、废弃方案、对审查者的回复和临时控制指令。只有成文的读者也能理解主张和来源。不把未测试改成不支持、要求改成已实现、假设设计改成现有能力。文章保留实质信息而不编造经历，只省略读者能自行补足的前提，不省略判断结果所需事实。Agent 消息保留行动需要的任务、依据、范围、实际状态和验收，去除无关过程叙述。

### 安装

公开生命周期命令为 `sh scripts/skills.sh <check|install|uninstall> [names] --target <skill-root>`。`check` 与 `install` 接受 `--language en|zh`，默认 `en`；`uninstall` 不选择语言。目标是已安装 Skill 的父目录，不是所选 Skill 目录。工具需要 POSIX shell 和常见文件比较工具，不需要仓库开发依赖、Node、Bun、Python、jq、Rust、构建或网络。Git 可选，Git 检出可报告比较的 HEAD 及源变更。

`check` 只读，不创建目标、备份或状态。指定名称时精确比较这些 Skill，包括缺失目标；不指定时比较已安装 Skill 并统计其余数量。报告来源、目标、声明版本或 `unknown`，以及 `identical`、`differs`、`cannot compare`、`not installed` 或损坏链接。比较完整目录，覆盖支持文件的修改、新增和删除。版本相同不代表内容相同，内容不可读是失败而不是匹配。顶层符号链接比较其目标内容，损坏链接不算已安装内容。

`install` 一次处理一个选定 Skill。目标不存在时复制完整目录，内容一致时报告 `no change` 且不写入，内容不同时保持目标不变，除非 `--replace` 明确授权替换。替换前备份原目标，再替换整个目录，删除仅存在于目标的文件，不合并目录。目标不可读时不动它。失败保留旧内容或完整备份，说明未完成事项，以非零状态退出，不把部分副本报告为已安装。

`uninstall` 先报告准确目标，不做修改，`--yes` 只授权这个目标。普通目录先备份后删除，符号链接只取消链接而不修改其目标。保留相邻 Skill、根目录和源码检出。手工复制的安装不需要注册或迁移。同名目录只是比较候选，不证明来源或覆盖权限。

每次替换或移除报告 `${XDG_STATE_HOME:-$HOME/.local/state}/ruokee-agent-kit/skill-backups/` 下唯一的操作备份，位于发现根和仓库 Skill 源之外。备份含完整原目录，链接则保存 `link-target.txt`；这是副本，不是安装注册表。恢复前将当前安装内容保留到新的临时保留目录，避免重复恢复产生嵌套或丢弃后续变化。

任何写入会触及任一语言的仓库 Skill 源时，在创建任何内容前拒绝，包括目标根等于、位于或包含源树，以及备份位于源树内。替换顶层链接不透过链接写入。路径尚不存在的部分含 `.` 或 `..` 时拒绝，不做与文件系统解析结果不同的折叠。

退出状态 `0` 表示比较一致或生命周期操作完成、无变化；`1` 表示已安装目标不同、指定目标缺失，或需 `--replace`、`--yes` 而未修改；`2` 表示用法、名称、路径、读取、比较或文件操作失败。工具读取脚本所在检出，不执行 Git pull 或改 Harness 配置，也不能证明宿主发现或重载。手工完整目录复制和受支持的顶层链接都是有效安装，链接内容跟随源变化。宿主专属重新加载由用户负责。

## 不变量

- 每个分发语言组件只引用自身文件。仅提及其他组件、工具或 Skill 的名称不要求声明依赖。实际前置条件须显式声明，可按名称或通过公开接口使用；不得链接、导入或读取另一个仓库组件的文件或包，也不得依赖仓库支持文件。
- 语言变体文件集合相同、语义覆盖完整。文件链接相对于所在文档书写，解析到该组件内部，安装后仍可使用，不带源码专用布局前缀。
- 每个 Skill 负责内部指导组织，保留完整能力、参考导航、术语及自身调用合同。`SKILL.md` 仍是可发现入口，内部目录和文件数不能代替这些行为要求。
- 来源作者、适用许可和必需署名准确保存在仓库层或合适的组件 README、决定中。引用材料本身不使 Skill 成为第三方镜像。
- 审查和分析对其对象保持只读，单独的报告权限保留。任何 Skill 不静默把分析转换成实现。
- Skill 加载的是指令而非宿主进程代码，因此不设宿主维护下限。

## 验收标准

- 每种语言目录可独立发现且完整，不含越界文件引用。匹配和不匹配请求保留触发边界，尤其是仅明确调用的 `grill-me` 与仅系统级信号触发的 `architect`。
- 审查场景可合理返回零问题，遵循模式限制和只读范围，区分证据与建议。调研给出有来源结论和有边界的不确定性。写作保留事实与作者意图，同时修复实际缺陷。
- Grill 保留准确全局编号和可恢复问题原文，在依赖问题前处理回答，不在结束条件成立前宣告完成。缺少记录权限只改变存储，不改变提问合同。
- 安装、检查、替换、恢复和移除保留完整内容、明确覆盖权限、源保护、相邻安装及规定失败和退出行为。文件相同不证明宿主已经加载该版本。
- 能力索引、语言内容、调用元数据和版本一致。既有合同要求真实宿主或模型验证时，行为变化保留该义务，包括 grill-me 与 architect 的触发行为，以及 well-said 的发现、完整加载和写作遵循。文件检查和场景走读是不同证据。
