# QoL 持续等待

## 目标

在一次调用的总期限内，继续符合条件的原生任务等待窗口。本调整遵循组件共同的配置、激活、状态和隔离要求。

## 非目标

只含消息的续等、按进程名等待、只含服务的续等，或用轮询模拟这些能力。

## 公共面

### 配置

| 键 | 默认值 |
| --- | --- |
| `waitEnabled` | `true` |
| `waitContinueEmptyWindows` | `true` |
| `waitJobsSeconds` | `1200` |
| `waitMessagesSeconds` | `1200` |
| `waitProcessSeconds` | `1200` |

三个等待时间设置接受 `0.05` 至 `3600` 秒的有限数值。`waitMessagesSeconds` 和 `waitProcessSeconds` 仍校验，但在受支持宿主中不起作用。

### 状态

`/qol` 的等待行显示 `entry=wait`、`effectiveDefaultSeconds`，并将 `messageContinuation`、`processWait`、`serviceContinuation` 标为 `not-applicable`。

### 持续等待

只扩展可识别的独立内建 `wait` 入口。入口缺失、属于他方、结构无法识别或缺少必要宿主能力时保留原生行为，并报告有界原因。保留原生读取审批、严格校验、可中断性和必要工具加载行为。

公开可选参数 `timeout` 接受 `(0, 3600]` 秒的有限数值，决定本次调用总期限。省略时使用 `waitJobsSeconds`。工具参数的下限不是配置项的 `0.05` 下限。

`waitContinueEmptyWindows=true` 时，只有原生结果标明空窗口、任务列表非空且全部任务仍在运行，才在同一次调用内续等。判断宿主结构化结果，不判断正文。消息、已结算任务、无任务、错误、steering、中断、取消、未知结果结构和服务事件立即返回。开关为 false 时返回第一个原生窗口。

总期限只结束当前等待调用，不启动或取消任务及进程，不在原生等待之外消费消息或结果。调用者取消优先并保留自身原因。即使期限已到，随后到达的原生结果仍胜出并原样返回。只有本次期限已经到达，且拒绝属于宿主已知中止 `ToolAbortError`、`AbortError` 或精确消息 `Operation aborted` 时，才转成期限结果。其他错误原样抛出。

期限到达而没有终态结果时，返回最后一个确定的全运行窗口及有界期限说明；没有此类窗口则返回最小说明。说明指出可再次调用 `wait` 或使用 `proc://`。全部退出路径释放当前调用的等待资源。

## 验收标准

等待覆盖显式和默认期限、全运行续等条件、全部终止结果、调用者取消、原生结果竞态、无关错误和拒绝替换未知入口。等待期限结束后后台工作继续。
