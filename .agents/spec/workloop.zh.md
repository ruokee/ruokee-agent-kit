# workloop

## 目标

为新的 tk Task 提供纯指令工作流，从目标澄清与必要设计，到规划、实现、独立核验及项目定义的交付。任一语言均能通过 Harness 既有 Skill 机制和自然语言请求独立使用。

在修订和上下文恢复中保留已确认要求、权限边界、证据和当前执行状态。指令引导 Agent 行为，不通过程序强制执行。

加载当前活动所需的完整指令，不强制读取无关操作细节。通过直装分发一种所选语言 Skill 和对应的 OMP 薄 Prompt 模板。

## 非目标

- 工作流运行时、程序化动作约束、OMP 包清单、专用安装器或隐式安装前置依赖。
- 识别或迁移旧工作流别名和材料名称。以 workloop 开始的任务继续按既有身份恢复。
- tk 之外的任务管理或通用用户级、项目级配置层次。这些方向暂缓，不是永久禁止。
- 隐式集成、本机安装、重启、发布、付费或真实模型实验、破坏性清理、Task 关闭。

## 公共面

### 入口

独立 Skill 身份为 `workloop` 和 `workloop-zh`。两者都提供完整等价的 Clarify、Execute、Verify、Ship、Supervise 和可选 Setup 指令。入口解析请求并路由到活动，每种语言的共享规则有唯一所有者和明确加载条件，不设置全员必读的大篇公共正文替身。使用用户语言及适用写作规则，保留事实、决定、条件、否定、归属和真实不确定性。引用的指令、示例和否定句不触发操作；了解用法的请求得到解释，不启动执行。

解析实际操作、项目、所属 Task、有效要求、范围和许可。tk 负责持久身份、关系、生命周期和材料归属，通过公开接口使用，不读取其实现文件。其他 Skill 只用于适用活动。推荐 Herdr，但不强制，其他受支持终端协作机制也有效。

OMP 通过五个 Prompt 模板提供 `/wl-clarify`、`/wl-exec`、`/wl-verify`、`/wl-ship`、`/wl-supervise`，语言固定为安装时的选择。模板只提供 Skill 身份、操作、加载指示和用户输入。先加载已安装 Skill，再沿其路由读取操作，不从 Prompt 目录取得工作流正文。输入不选择另一种语言。空参数不生成输入标题或空输入段；非空输入保留宿主解析后的字符，不做模板转义或二次解释。没有新增参数时保留足够的有效会话或 Task 上下文，仅在确实无法确定 Task 或所需目标时补充信息。前期 Check 是隐含材料检查，不是额外命令。

### 材料

通过 tk 解析材料归属。父任务、依赖、顾问或更早会话不自动拥有新结果。同一工作复用 Task，创建、关系和关闭遵循项目权限。单元标签在所属 Plan 内从 `U01` 开始，修订时保持稳定。Plan 可混合正文单元和 tk 子任务链接，执行或修订前须读取所链接的细节。

操作通常允许保存普通结果材料。明确的仅对话、不记录、不写入或更窄限制优先。更新前读取原材料，在实质结果形成时及返回前保存。必要存储缺失须明确列为未满足条件，不通过改写到别处规避。

- `goal.md` 用自然语言说明预期结果、范围、约束和完成或停止条件，不写实现方法。
- 可选 `design.md` 解释方案及必要实现细节。可选诊断记录症状、观察条件、证据和有依据或不确定的原因，不写修复建议。
- 调研概括结论和可追溯来源，访谈可保存 `grill.md` 或既有记录。可选活动不要求空文件或材料角色矩阵。
- 每个可执行 Task 都有独立 `plan.md`，单单元任务也不例外。
- 既有执行记录，通常为 `execution.md`，保存单元、基线、候选、完成行为、输入、检查、观察、修复和限制。
- 自动准备自检使用自己既有的记录，通常为 `plan-check.md`，不写入两种独立报告。实现自检属于执行记录或其链接的自检报告。
- 按请求进行的独立准备审查追加到 `material_check.md`，已执行候选的独立 Verify 追加到 `verification.md`，均不覆盖既往评估或失败。只产出 Markdown 的执行单元仍是实现候选。已有记录保持明确职责，不迁移历史文件，未请求审查不创建空报告。
- 既有交付记录，通常为 `ship.md`，说明实际交付结果。

稳定结果属于 Task 材料，活动角色路由、待处理指派、临时许可和会话身份属于可恢复的会话状态。父任务链接子任务证据，不接管其归属或复制全文。

### Clarify

Clarify 处理新想法、具体设计问题、已知目标的直接规划，以及材料修订，不重启已完成的访谈。遵循仅讨论、仅设计、不规划、暂停和不写入限制。

明确问题、预期结果、范围、约束与停止条件，在选择方案之前质疑不必要、不可行或有害的工作。先读项目事实和既有模式，事实缺失时进行适度调查。区分观察、假设、提议和决定。用户专属优先级和重要取舍须在说明证据、真实选项及建议后交用户决定，不能把可查事实交给用户回答。

已知目标可直接进入所请求的设计或规划。当目标、必要设计和可预见的重要选择明确时，在同一次 Clarify 中形成 `plan.md`，仅讨论、仅设计、不规划、暂停或写入限制阻止时除外。不需要另外请求创建 Plan，形成 Plan 也不授权执行。每个单元说明完整且可独立评估的结果、目标和设计依据、变更、非目标、依赖、可观察验收、检查、权限与材料归属。预先解决可见的产品决策，不把它们藏进可执行步骤。区分可从已验证候选取得的代码依赖，和必须实际存在的部署、服务或已发布产物状态。

Plan 形成后自动进行前期自检。前期材料的独立 Verify 仅按请求启动，不因自检达到上限而启动。通常包含作者在范围内修复及同一核验者复检，直到当前通过或出现真实阻塞。单轮或只报告限制优先。仅设计请求不强制形成 Plan。不必要、不可行或用户决定不继续的工作可在有依据的结论处结束，不填充空阶段；关闭仍需单独权限。除非同时实际请求执行，Clarify 不实施，也不在结束时邀请执行。

### Execute

Execute 在当前会话实施，直接协调自检和独立 Verify，无需 Supervisor。缺失或尚不可执行的计划将对应准备工作交回 Clarify，不编造要求。

指定子集时按该子集执行，否则连续处理所有剩余且依赖就绪的单元，通常一次一个，可串行完成多个。普通执行包含范围内实现、修复、本地准备、检查、临时进程及项目要求的候选保存，无需重复中间许可，也不要求 `auto` 或 `noask` 关键词。`confirm` 要求逐项确认，但不免除检查。

实现、修复、检查及单元之间复用普通许可，重要需求选择、受保护动作和明确人工接入点分别处理。缺少许可或外部状态只阻塞依赖动作，继续不受影响的获授权就绪工作。此规则同样约束 Supervise。

执行和监督禁止结构化提问工具，也不能通过包装器或其他 Agent 规避。不可缺少的用户专属决定用普通文字提出，同时继续不受影响的获授权工作。恢复后以明文保留禁止事项。

完整实现所需行为及受影响合同，不交占位实现、不预建能力、不降低验收。运行变更行为、保存稳定候选、取得快速自检及独立 Verify，修复范围内问题、更新受影响检查，再由同一适用核验者复检。实质材料矛盾只将对应工作交回 Clarify。缺失前置条件是阻塞，不是交付部分替代品的理由。

项目允许时，冻结、已提交、已核验的前置候选可在合入前成为后续单元基线。保留各单元基线、候选和审查边界，前置候选变化时更新后继及失效证据。不为启动后续开发而合并。实际外部状态依赖仍需满足。

当前独立核验通过后继续下一个获授权就绪单元，不仅为用户验收或合入而停下。剩余工作全部阻塞时，保留所有已完成候选和每个准确阻塞。Worker 仅在被指派边界返回，该边界不缩小所有者的整体授权。

### Verify

Verify 独立评估指定准备材料或实现，目标保持只读。解析原始要求、Plan 及链接细节、设计、决定、规则、候选身份和回复对象。作者清单或实现是证据，不是需求权威。含糊、变化中、缺失或冲突的目标须先明确。

标明准确 commit、tree 和工作状态，或冻结材料集合。不修改或格式化候选，评估期间作者停止编辑。检查相关变更和消费者、权限、依赖、修复历史及实际证据。只在授权内执行适度非破坏性检查。复用有效证据时标明作者、候选、条件与覆盖，不声称自己重新运行过。

返回一个裁决：

- `passed`：候选满足所需结果，且在该范围内证据充分。
- `changes required`：有证据的缺陷或未满足要求需要修正。
- `unable to determine`：缺少必要信息、稳定身份、能力、权限或证据。既不是通过，也不是已确立的实现缺陷。

问题说明严重性、位置、观察、违反的要求或实质风险，以及恢复目标的最小修改。可选改进不变成失败。作者负责修复，适用的隔离核验会话负责受影响范围复检，并保留足以发现回归的周边覆盖。材料和设计问题交回 Clarify，实现偏离交回 Execute。

按目标职责而非文件扩展名分类，独立准备审查使用 `material_check.md`，已执行候选的独立 Verify 使用 `verification.md`。每次评估追加范围、候选与基线、依据、实际输入、检查、观察、复用证据、问题、裁决和限制。新成功不覆盖旧失败。受指派核验者保存获授权报告后，向活动所有者发送最终结果，不等待所有者回复。报告保存后传递失败时恢复原报告，不重复评估。

### Ship

Ship 按实际请求和有效权限交付项目定义的可观察结果，没有通用的合并、安装、发布动作包。使用既有定义或明确请求，只为真实未决的重要选择提问。声明流程不授权执行流程。

明确准确候选、依赖顺序、当前 Verify 范围、验收与项目门禁。其他候选或部分范围的通过不覆盖本次交付。复用有效许可和证据，对候选或目标变化导致失效的检查重新验证。定义之外的受保护动作需单独许可。需要集成时遵循项目方法与依赖顺序，不把集成强加为所有交付的前提。

观察实际目标位置与结果。复制不等于发现，重启不等于成功加载，运行不等于验收，提交审阅不等于已被审阅。授权清理前保留重建依据，只停止有权控制的自有资源。实现缺陷交回 Execute，目标或设计问题交回 Clarify。独立新工作可依适用权限拥有自己的 Task。Ship 不强制追加收益回收阶段，也不自动关闭 Task。

### Supervise

Supervise 通过独立 Worker 调度已明确 Plan，自己不实施，也不充当这些 Worker 的独立核验者。准备不足时交回 Clarify。范围、并发、指派和受保护权限分别处理。

指派完整且依赖就绪的单元。范围和项目允许时，独立单元可并行；共享文件同一时间只有一个编辑者。指派包含 Task 和单元、Plan 依据、工作位置、编辑边界、许可、限制、依赖候选、必要检查、授权材料、预期结果、停止点及回复对象。Worker 使用 Execute，返回实际运行结果、自检次数和独立报告。

Supervisor 读取并核对最终报告，不把生命周期标签或完成声明当裁决。问题交回负责 Worker，不重置其快检次数。缺失证据在范围内补齐，传递失败后恢复已保存结果。每个当前通过后调度下一个获授权就绪单元。全部完成时一起交付候选，阻塞部分保持原范围，不悄悄删除。

### Setup

Setup 可选，用于初始化、重新配置，或实际失败后的针对性准备。将选定的持久默认值及项目约定保存到获授权的外部项目指引，不复制通用工作流算法，不写入已安装 Skill、Task 结果或新数据库。保留无关指引，以替换既有默认值的方式修改，不添加冲突副本。仅配置时不强制读取 Task、执行、自检或协作流程，不创建占位 Task。

默认值可包含独立角色模型及推理级别、分开的前期和单元自检上限、协作机制、项目工作约定，以及 Ship 的可观察结果。不为定义默认值而启动角色、安装工具或探测可用性。默认值变化不替换活动的明确选择。会话路由与临时许可不是持久默认值。Setup 不授权实现或交付。

### 分发

通过 Harness 既有的复制或受支持目录链接机制安装一种完整语言 Skill。两种语言版本一致，各自不依赖仓库文件或另一语言。替换时把旧完整安装保存在发现根之外，整体替换而不合并，将废弃文件移出发现范围，失败时旧副本可恢复。切换语言先移除旧身份及模板，再安装另一套。移除只作用于自有安装资源，取消链接保留源码。共享根目录、无关文件、备份和源码 checkout 保持完整。Setup 不是安装或普通使用前置，安装不安装 tk 或其他前置依赖。

OMP 直接安装一个 Skill 和五个同语言模板，不使用包管理、Extension 代码、构建步骤或运行时依赖。仓库普通 Skill 安装器不管理此组件。默认用户根目录为 `~/.omp/agent/skills/` 和 `~/.omp/agent/prompts/`；配置或 profile 重定位时，使用目标会话相同的环境和 profile 执行 `omp config path` 取得实际 agent 根。明确采用项目级安装时使用 `.omp/skills/` 和 `.omp/prompts/`。完整所选 Skill 放入其同名目录，仅将五个选定的 `wl-*.md` 模板平铺到 Prompt 根。OMP 递归发现时仍使用 basename，因此两种语言模板不能在该根共存。首次安装要求目标不存在，已有自有资源使用完整替换，不覆盖未知内容，也不把新 Skill 嵌套到旧副本内。

直装前，通过原安装管理器解除既有 `@ruokee/workloop` 包。OMP 包移除清除其注册和插件状态，不删除链接源码 checkout 或独立安装资源。将自有同名文件命令移到发现根外，保留无关或其他所有者的资源，其他冲突与其所有者协商解决。

内容不同的同名 Skill 中，较高优先级保留裸名称，其他副本获得命名空间身份；相同副本去重，自定义 Skill 目录有自己的覆盖规则。原生文件命令高于包文件命令。内置、扩展和自定义处理器先于文件命令，文件命令先于 Prompt 模板。`wl-` 前缀不能保证无用户重名，相同优先级之间的顺序不是合同。用户能够辨认实际发现来源。

OMP Prompt 安装、替换、语言切换和移除后需启动新会话，加载对应模板集合。`/reload-plugins` 刷新插件资源、Skill 和文件命令，不重载 Prompt 模板。已有会话可能保留旧内容。其他 Harness 遵循自身实际加载条件，只有支持该格式时才接收 OMP 模板。文件放置、宿主发现及实际指令加载是不同结果，复制、版本一致或发现本身都不证明已加载正文或 Agent 行为正确。

## 不变量

- 区分已确认要求、提议约束、观察行为、测试和生成的计划。代码或 Agent 声明不批准需求，延期不是永久排除，动机不产生验收门禁。
- 范围、普通操作许可、受保护权限、等待政策、用户验收、交付和 Task 状态分别处理。加载 Skill 或保存报告不扩大它们。
- 角色宿主、准确模型选择器、推理级别和位置独立选取，顺序为当前明确请求、同次执行仍有效的选择、项目默认。保留别名，不可用时报告实际错误，不静默替换；不从执行者推导 Verify。
- Senior 仅在明确指派后存在，默认值不激活该角色。建议可处理范围内重要实现选择，不能改变目标、优先级、受保护许可、免除检查或替代独立 Verify。
- 每次快检使用新的只读上下文，作者修复。未配置时选择三至五次上限。准备自检与每个实现单元分别计数。准备自检按 Clarify 轮次计数：上一轮返回后，因新的请求、返回的材料或设计缺陷，或因需求、依据变化，新一轮从自己的计数开始，上一轮耗尽不阻止本轮。仅为获得新计数而宣布的轮次仍属同一轮。每轮准备自检内，首次检查与复检共享计数；每个实现单元内，首次检查与复检共享该单元计数。材料修订、修复、复检及独立反馈不重置适用计数。会话恢复或另一 Agent 继续同一轮同样不重置。开启新一轮不重置任何实现单元的自检计数。启动或通信失败不消耗实质检查次数。当前通过即提前结束；达到适用上限后完成修复、不再增加快检，并明确未解决或未复检修改。独立 Verify 没有此上限。
- 每个实现单元都需自检及独立 Verify。准备阶段在形成 Plan 后自检，仅按请求独立 Verify。次数耗尽或旧候选通过都不能证明当前成功。
- 协作使用正常启动、普通消息、明确位置和活动回复路由，保持角色隔离、适当会话复用和候选冻结。重新指派前先完成或恢复忙碌指派，不读私有工作会话文件，不在执行中擅自插入消息。
- 跨会话工作和咨询默认等待最终结果，后台返回后也通过宿主阻塞等待。明确 `nowait` 只允许保存待处理跨会话指派，不移除原生自检屏障、检查或权限限制。最终结果到达后无需再次要求继续。核对发送者、单元、候选、裁决和保存报告。
- 证据记录候选、条件、输入、结果与范围。源码调查、文件检查、受控集成、真实 Harness、UI 和真实模型结果证明不同事实。行为变化使受影响证据失效，复用未变化证据须说明身份和范围。
- 恢复保留活动所需状态，包括适用的 Task、操作、范围、依据、候选、许可、禁止事项、当前 Clarify 轮次或实现单元的自检次数与上限、待处理指派及下一步。从实际安装 Skill 重读缺失的入口、操作及条件必读指令，记住引用不等于已加载内容。仅配置的恢复不要求执行状态，恢复待处理分派不重复动作，不要求特定持久化 API。
- 普通操作不预先做假设性环境探测。实际失败后针对事实调查并在授权内补前置条件，不伪造成功、降低验收或静默替代。

## 验收标准

- 两种语言 Skill 独立表达全部操作，行为、权限、计数、失败处理和恢复等价，内部引用不越出安装目录。
- 直接引用 Skill、Setup 和各 Prompt 入口明确初始读取、条件读取及交接指令。每条有效规则有所有者和可达加载条件，仅配置不强制读取完整执行或自检流程。
- 目标和设计就绪后同次形成 Plan、重要选择未决、仅设计、不规划、暂停、不写入、无需行动、混合 Plan、串行 Execute、独立 Worker、明确子集和前置条件不可用等场景产生规定结果与停止边界。
- 构造一个前一轮 Clarify 已耗尽准备自检的 Task，再因新请求或返回的缺陷进入新一轮 Clarify。新一轮第一次检查按本轮上限计为 1/N，上一轮记录和所有实现单元计数保持不变。新一轮内的修复消耗下一次计数，不开启新一轮。会话恢复不重置新一轮计数。
- 首次自检通过可提前结束；同一 Clarify 轮次内，修订与独立反馈保留累计次数，后续 Clarify 轮次重新开始准备计数且不重置实现单元计数；新一轮第一次检查按本轮上限计数，同一轮修复消耗下一次计数而不开启新一轮，会话恢复不重置该计数，上一轮记录和实现单元计数保持不变；上限耗尽时明确未验证修改。候选变化后进行受影响复检，不继承旧通过。
- 自动自检、按请求进行的独立准备审查、已执行候选 Verify 有各自的触发者、写入者、记录、候选历史和复查规则。Markdown 执行产物仍是实现候选，检查不授予用户验收或受保护许可。
- 已验证依赖开发可在没有合入许可时继续，真实外部依赖仍阻塞其消费者。交付遵循项目实际结果和许可。
- 每套 OMP 安装暴露五个固定语言入口，按宿主解析语义保留空输入续接、带引号的多词输入、特殊字符和模板样式输入。实际安装来源及资源重名可识别。
- 任一完整语言均可脱离仓库首次安装、完整替换、双向切换、移除和内部加载，不产生嵌套副本、旧语言残留或无关文件删除。新会话要求与文件放置及发现分别判断。
- 已登记组件 Markdown，包括两种已知语言 Skill 的共享 Reference 目录内全部 Markdown 和语言模板，选择格式检查，无需逐文件登记 Reference。未知操作、语言、旧命令路径、非 Markdown 文件、共享输入及混合未知变更保留完整回退。删除及重命名分类保持有效，不增加工作流运行时检查器。结论区分场景走读、实际宿主发现、模型行为和用户验收。
