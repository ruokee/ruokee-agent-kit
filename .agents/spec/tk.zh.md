# tk

## 目标

为 Agent 工作提供持久的项目内任务记录，使其在上下文丢失后仍可跨会话、跨 Harness 和 CLI 使用。项目文件是状态的权威来源。用户无需运行 tk 即可读取普通 Markdown 材料。

通过公开 CLI 提供任务发现、搜索、读取、创建、关系维护、生命周期变更、日志、完整性检查、改名、元数据迁移、表示切换和临时文件清理。

提供英文和中文 CLI Skill，使用当前可执行文件携带的分发内容离线安装、更新、切换语言和卸载普通 Skill。

完整 tk 规格集合由本产品规格，以及数据、维护、接口、分发、Agent 行为五份主题规格组成。这些主题定义要求，不规定内部模块布局。

## 非目标

- 数据库、全局任务注册表、后台索引、远程服务或常驻守护进程。
- 优先级、排期、收件箱、看板、Issue 镜像、Agent 协调、工作流执行或持久会话绑定。
- 锁、租约、compare-and-swap、自动合并、自动回滚或多目标操作的续做状态。
- rename 时自动改写 Markdown 引用。
- 增加元数据、schema 字段、运行时状态、命令或自动目录的材料模式。

## 公共面

公开可执行文件 `tk` 是唯一接口，提供一致的任务身份、存储语义、统一结果、稳定错误类别和版本信息。

英文 `tk-cli` 和中文 `tk-cli-zh` 是普通 Skill，安装到已知 Harness 根目录或用户指定根目录。源码和安装后 Skill 均包含自身引用的全部文件，不依赖其他仓库组件、规格、任务材料或审查记录。

## 不变量

- 任务身份、受管元数据、关系、生命周期和受管路径由 tk 管理。普通任务正文及支持材料在用户授权范围内保持可独立编辑。
- `TASK.md` 标题属于正文，与受管名称和目录后缀相互独立，不受 32 列上限约束，也不要求 rename。
- 合法保存名称的排版在读取、检查、无关元数据写入和表示切换后保持不变。显式 rename 达到精确的规范化目标。
- 不遍历普通材料软链接，也不单纯因为它是链接而产生诊断。受管存储保留自己的类型要求。
- 多目标操作在首次持久写入前完成全部领域校验。之后的 I/O 失败或取消报告真实进度，不自动回滚或续做。
- 领域拒绝与进程失败区分，不把不完整或格式错误的输出伪造成成功领域结果。
- 公开使用文档保持独立可用，并表达相同要求。设计解释实现，验证材料记录方法和证据。两者都不替代规格集合中的必要行为。

## 宿主下限

CLI Skill 不包含宿主进程代码，没有宿主维护下限。运行时和组件格式兼容要求保持独立。

## 验收标准

符合要求的实现必须同时满足数据、维护、接口、分发和 Agent 行为规格：

- CLI 保留现有项目数据的领域行为，包括拒绝写入和非致命 WAL 警告。
- 两种元数据表示在支持的元数据操作及表示切换中保留任务身份和正文原始字节。
- 合法名称排版、精确 rename、普通软链接、完整发现失败、生命周期授权和多目标部分结果在公开接口上保持可观察。
- 两种语言可在各已知 Harness 根目录和自定义根目录安装、卸载，不调用宿主命令或读取配置。只管理两个 CLI Skill 子项，保留其他内容。
- Harness 场景观察普通 Skill 发现及卸载后状态。已安装 Skill 场景验证任务选择、创建策略、生命周期权限、catchup、WAL、修复授权、材料模式和 CLI 命令使用。文件放置、编译和 Markdown 检查不证明 Agent 行为。
- 产品产物自包含，不携带审查记录或任务材料。语言配对保留相同行为和约束。
