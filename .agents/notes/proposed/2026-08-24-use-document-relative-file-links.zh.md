# Agent Note: 文件路径使用文档相对链接

Status: proposed
Decision owner: Ruokee
Draft writer: OMP GPT-5.6 Sol

[English](./2026-08-24-use-document-relative-file-links.md) | 中文

## 动机

当前 `File paths` 规则要求，路径向上返回两层或更多层级时，改写为不带前导 `/` 的仓库根目录相对路径。这种写法在本地编辑器中可以点击跳转，但 GitHub 从当前 Markdown 文档所在目录解析相对链接，因此嵌套文档会跳转到错误位置。添加前导 `/` 虽然能让 GitHub 从仓库根目录解析，但本地编辑器可能把它当成文件系统绝对路径。

文件引用需要采用一种同时支持 GitHub 按当前分支解析相对链接和本地编辑器点击跳转的写法。

## 提议

更新 `AGENTS.md` 的 `File paths` 规则，要求供读者跳转的仓库文件引用使用 Markdown 链接。链接目标必须相对于引用所在的 Markdown 文档。当前目录或下级目录使用 `./`，向上返回时使用所需数量的 `../`。不再把多层向上路径改写为仓库根目录相对目标，链接目标也不使用前导 `/`。

当链接文本用于标明文件时，文本使用仓库根目录相对路径，让文件在仓库中的位置保持清晰。例如，`docs/zh/` 下的文档这样链接 architect Skill：

```markdown
[skills/architect/SKILL.md](../../skills/architect/SKILL.md)
```

显示文本从仓库根目录标明文件，相对于当前文档的链接目标则让同一个链接可以在 GitHub 和本地编辑器中跳转。

同时按新规则更新仓库中现有的文件引用。

## 考虑过的替代方案

**保留不带前导 `/` 的仓库根目录相对目标。** GitHub 会从嵌套文档所在目录解析它，无法到达目标仓库文件。

**使用以 `/` 开头的目标。** GitHub 会从仓库根目录解析，但本地编辑器可能从文件系统根目录解析。

**使用 GitHub 绝对 URL。** 跳转会依赖仓库 URL 和分支，不再与本地检出的文档使用同一个目标。

## 验收标准

1. `AGENTS.md` 要求可跳转的仓库文件引用使用相对于当前文档的 Markdown 链接目标。
2. `File paths` 规则使用 `./` 和所需数量的 `../`，不再保留多层路径例外。
3. 链接目标不以 `/` 开头；同一仓库中的文件不使用 GitHub 绝对 URL。
4. 嵌套文档示例使用同一个链接，在 GitHub 与本地编辑器中到达同一文件。
5. 仓库中现有的可跳转文件引用均按新规则更新。

## 风险

移动 Markdown 文档会改变相对链接目标的解析起点。移动文档时必须在同一变更中更新受影响的链接。
