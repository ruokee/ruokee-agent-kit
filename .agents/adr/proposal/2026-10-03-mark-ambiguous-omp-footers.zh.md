# ADR 提案：仅在必要时标记 OMP 页脚归属

Draft owner: Ruokee
Draft writer: OMP GPT-6.1 Sol

[English](./2026-10-03-mark-ambiguous-omp-footers.md) | 中文

## 动机

仅在 append 可能被误当成宿主固定 critical 尾部时，为 OMP 模板页脚加入归属标记。

[模板决定](../decision/2026-09-30-render-system-prompt-from-host-template.zh.md#模板路径上扩展负责的内容)要求删除原生外层尾部、不透明数据逐字节保留以及转换幂等。[OMP 18.5.0 页脚](https://github.com/can1357/oh-my-pi/blob/v18.5.0/packages/coding-agent/src/prompts/system/project-prompt.md#L54-L62)在 append 之前渲染主代理或子代理的固定 critical 块。删除宿主原生块后，append 起点的完整副本必须保留。

有已加载正文或规则路径的页脚，其加载说明会被替换为自有文本，因而已有归属信号。没有加载说明的页脚缺少这种信号，重复转换可能把 append 当成另一个宿主尾部，静默删除用户文本。

## 分析

设 `F` 是没有加载说明的有效 `<project-context>` 块，`C` 是完整的已识别原生 critical 块，`A` 是 append 字节。`F + "\n\n" + C + "\n\n" + A` 既可能是带原生尾部 `C`、append 为 `A` 的未转换页脚，也可能是 append 为 `C + "\n\n" + A` 的已转换页脚。Delivery 关闭时，两种情形的完整块数组可以相同。仅凭文本无法对同一输入同时要求删除和保留，因此需要转换状态信号，开启 Delivery 不能解决归属问题。

## 提议

在 [projects/omp-system-prompt/README.zh.md](../../../projects/omp-system-prompt/README.zh.md#宿主模板路径) 的模板页脚合同中增加有条件的归属标记，以中性、无策略指令的注释表示。

1. 仅在三个条件同时成立时插入标记：有效页脚没有加载说明；本次转换移除了精确识别的宿主固定 critical 尾部；append 本身以完整的已识别原生 critical 块开头。普通 append 和有加载说明的页脚不新增标记。
2. 标记位于外层 `<project-context>` 内，但在 workstation 数据、上下文正文、路径列表、工作区数据、活动仓库文本和 append 之外。标记及其必要分隔符是相对于原转换输出仅允许增加的文本。
3. 通过自有加载说明或位于已校验结构位置的标记识别已转换页脚，不把其后的 append 当成宿主尾部。识别仍依赖文本，不证明作者身份，也不是安全边界。
4. 其它受维护旧输入的转换输出继续与原输出逐字节一致。有条件标记是唯一例外，不允许改写不透明字节或插入策略指令。
5. 保持 `<project-context>` 块首、数组位置及静态前缀缓存边界。归属识别在 Delivery 的两种取值及切换中都成立，不使用进程内缓存，也不新增设置。
6. 保留默认块路径、旧 `PROJECT` 严格合同、有界失败行为、策略文本、模板产物、模型规则、维护下限及按结构判断的适用边界，不新增宿主版本门禁，也不修改已安装宿主文件。

这扩展了现行模板决定，不改变其受保护数据或其它归属规则。标记占用页脚外层空间，不进入现行决定要求逐字节保留的字段。完整输出例外仍需明确限定，不能仅从这一位置区别推导出无限制的修改许可。

## 考虑过的替代方案

**为所有没有加载说明的页脚加入标记。** 统一标记能给这些输出提供归属信号，但也会改变没有 append 歧义的普通旧输出，超过必要的兼容例外。

**保留全部旧输出字节，在提示词之外携带状态。** 显式来源或处理状态接口可以区分相同文本，而不增加 Provider 可见字节。但它需要独立的接口及生命周期设计，不能沿用当前纯文本合同。本提案将归属保留在已校验的页脚表示中，仅在歧义形态承担输出变化。

## 验收标准

- 仅在已校验的外层边界删除精确识别的主代理或子代理原生尾部。未知尾部和有歧义的外层结构保持既有保留及诊断行为。
- 上下文正文、路径列表、workstation、工作区及活动仓库数据、append 字节保持精确，包括 append 起点的完整已知 critical 块。
- 有加载说明的旧输入及普通 append 的旧输入产生原来的完整输出。只有满足全部三个插入条件的页脚增加标记及其分隔符。
- 设置未变化时，再次处理已转换块数组得到相同的完整数组，不返回替换。Delivery 切换只改变 Delivery 章节，不改变页脚或 append。
- 旧 `PROJECT` 路径，以及组件未变化的策略、设置、模型规则和维护声明保持原有合同。
- 真实宿主的 Provider 观察覆盖需要标记和无需标记的形态，包括普通子代理。文档区分这些观察与 API 回归，不声称宿主全面认证。

## 风险

- 标记对 Provider 可见。要求完整提示词逐字节一致的消费者可能拒绝该输出，即使不透明数据未变。三个插入条件限定了所接受的差异。
- 如果在上下文正文或 append 中匹配标记，可能把原生页脚误认成已转换结果，留下宿主策略文本。归属只能在已校验的外层结构位置识别，不透明文本不能参与识别。
