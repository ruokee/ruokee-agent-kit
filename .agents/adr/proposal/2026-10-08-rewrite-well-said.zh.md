# ADR 提案：重写 well-said Skill

Draft owner: Ruokee
Draft writer: OMP

[English](./2026-10-08-rewrite-well-said.md) | 中文

## 动机

将 `well-said` 重写为指导自然、直接表达的双语 Skill，并把来源署名与许可放在写作指令之外。

重写从能力最原始的需求和原始资料出发。旧 Skill 只作辅助参考，不作为验收清单。章节覆盖或范围不同，本身不能说明重写稿有问题。

写作指南应当说明怎样产出有用的内容。来源署名和法律通知服务于另一种用途。将其放在同目录附加文件中，既保留可获取性，也不让这些内容成为写作指令。文件须区分 Ruokee 对 well-said 的作者归属，以及 Lauren Tan 对复用的 unslop 材料的作者归属。

## 提议

### 能力与写作规则

保留 `well-said` 作为独立编写、可由模型调用的 Skill。适用说明为"输出任何内容时使用"，包括回复、文档、代码注释和 Agent 交流。继续支持明确调用。应用写作规则不增加修改文件或可执行内容的权限。

每个语言组件的 `SKILL.md` 提供完整的英文或中文写作指南，按写作流程、文风模式、防御性表述、可见的编写会话残留、文章写作和作者声音组织。两种语言都保留原意，以及作者真实的观察与判断。两个版本均不依赖其他 Skill 或仓库支持文件。

将防御性表述视为文字问题，也视为可能尚未完成工作的信号。覆盖证明姿态、认知边界和未执行工作的交代。两种语言都列出中英文代表表达，说明危害和处理方式。这些表达用于提示判断，不构成禁用词表。

区分表述问题和工作问题的处理方式。只是措辞过于保守时，把已有依据的结论说清楚。工作缺失或结果有误时，在授权范围内补做或返工。工作本身没问题时，按读者需要重写有用段落，删除空洞段落。保留事实、实际风险、重要未知、授权条件、必要论证，以及用户或适用流程要求的状态报告。

### 组件文件、归属与版本

英文组件继续位于 `skills/well-said/`，中文组件继续位于 `variants/zh/skills/well-said/`。两者均为自包含分发组件，文件集合相同：

- `SKILL.md` 包含写作指令，在 frontmatter 的 `metadata.version` 中声明版本。
- `SOURCES.md` 和 `SOURCES.zh.md` 说明作者归属、来源版本和复用范围。
- `LICENSE` 沿用仓库的 Ruokee MIT 许可，对应 well-said 的原创材料。
- `LICENSE.unslop` 完整保留复用 unslop 材料的 Lauren Tan MIT 通知。

Skill 正文不重复来源署名、许可文本或版本号。来源说明只链接组件内文件及外部来源。安装或分发组件时，一并保留附加文件。

使用 `1.0.0` 作为正式发布的起始版本。写作过程中的修订编号不充当软件版本。后续发布遵循仓库版本政策。普通 Skill 不增加包 manifest、检测器、plugin 或运行时依赖。

### 需要反转的决定

实现本提案时，反转[当前 well-said 决定](../decision/2026-09-12-add-well-said-skill.zh.md)。其中两项明确条款与提议的文件布局冲突：

- **组件布局与内容归属**要求每个 `SKILL.md` 包含来源署名和完整第三方通知。本提案将其放在同目录来源与许可文件中。若两处都保持强制要求，就会重复写作指令不需要的材料。
- **编辑与交付**要求在 `SKILL.md` 正文标注语义版本。本提案以 `metadata.version` 作为唯一版本声明。保留正文要求会增加第二处需要维护的声明。

后继决定须保留仍然有效的第一方归属、自包含双语分发、编辑权限、语义保护、加载和验证要求。写作规则按独立重写的内容表达，不要求保留旧 Skill 的章节清单或措辞。来源署名和许可义务在迁移位置后继续有效。

现有决定在实现变更依照仓库 ADR 流程替代它之前继续有效。本提案不改变 Skill 安装机制，也不定义可选的严格模式 plugin。

## 考虑过的替代方案

- 继续修改旧 Skill。选择从原始需求和资料重写时，已否定这一路线。该方案仍以旧文本为起点，没有采用所选的重写稿。
- 将来源署名、法律通知和版本保留在 Skill 正文。这是当前决定的布局，会把分发信息混入写作指令。正文版本也会与提议的 frontmatter 声明重复。

## 验收标准

1. 两个语言组件提供完整写作指南，范围、规则、例外、示例和版本一致。仓库能力索引描述相同的适用方式。
2. 防御性表述规则说明危害和处理方法，区分工作问题与文字问题，保留会影响读者判断或行动的信息。两种语言均提供中英文代表表达。
3. 每个组件独立包含来源说明及两份许可文件，署名区分 well-said 与复用材料的作者归属。来源署名和法律通知不出现在 Skill 正文。
4. 两份入口均声明 `metadata.version: "1.0.0"`，正文不重复版本号。完整组件可独立安装，不依赖其他组件或仅仓库内存在的材料。
5. 满足仓库必需检查及既有的真实宿主、真实模型和语义保护验证要求。验证同时检查漏清理与有害误改，并区分发现、加载和实际输出行为。
6. 实现提供完整的后继决定，保留仍然有效的要求，同步受影响的规范和公开文档，并依 ADR 生命周期替代旧决定。

## 风险

只复制 `SKILL.md` 的分发方可能遗漏必需的第三方许可通知。因此每个语言组件都包含完整附加文件，分发时须保留整个组件目录。

若把代表表达当成自动删除规则，可能删去有用的不确定性或掩盖未完成的工作。指南须区分工作问题与文字问题，验证须包含应保留事实、限定或必需状态报告的场景。
