# ADR 提案：同目录维护中英文公开文档

Decision owner: Ruokee
Draft writer: OMP GPT-6 Astra

[English](./2026-09-07-colocate-bilingual-docs.md) | 中文

## 动机

[公开文档决定](../decision/2026-08-20-maintain-bilingual-public-documentation.zh.md)要求中文用户文档位于 `docs/zh/`。这种做法按目录分开语言版本，而 [ADR](../README.zh.md) 和组件文档已经采用同目录的中英文文件对。

统一采用同目录规则，可以让读者直接推知另一语言文件的位置，并让两种语言的文档都靠近其所属组件或主题。仓库首页也应提供完整的能力索引，由组件入口页继续引导读者访问详细文档。

## 提议

### 语言配对

代码、注释、配置和默认公开文档使用英文。需要中文文档的每份公开 Markdown 页面在同目录下配对，使用 `name.md` 和 `name.zh.md`。仓库及组件入口页使用 `README.md` 和 `README.zh.md`。不按语言维护独立目录，也不在原路径保留重复页面。

对应文档互相提供语言链接，并在同一变更中更新。要求语义一致，不要求逐句翻译。每份文档都应独立成立。路径、命令、API 名称、状态值和代码标识符保留仓库中的原值。

公开行为和用法文档需要中文对应版本。内部实现笔记、注释、生成文件和仅面向维护者的材料，不因其存在就要求翻译。不创建空的语言占位文件。

ADR 保留现有的配对格式、语义权威性、元数据和生命周期规则。Skill 保留宿主可发现的打包格式，以及 `skills/<name>/` 和 `variants/zh/skills/<name>/` 下的语言变体。独立命名的 tk Skill 也保留现有组件路径。本提案调整普通公开文档布局，不改变 Skill 身份或安装路径。

### 公开入口

仓库的 `README.md` 和 `README.zh.md` 作为双语能力索引。两者列出相同的可用能力，区分用户触发和 Agent 触发的 Skill，并按适用 Harness 对扩展分组。每个 Skill 提供基础版本与中文变体链接，扩展则链接到对应语言的组件入口页。

组件 README 文件对介绍能力并链接使用和设计文档，不重复详细命令参考或规范性合同。补齐 tk README 文件对作为组件入口，保留现有指南和设计页面对详细行为的内容归属。

独立 Skill 索引的内容由仓库 README 文件对承载后，移除这些索引。修复入站链接与引用，使其使用当前入口，包括 [deep-research 决定](../decision/2026-09-06-migrate-deep-research.zh.md)。保留文档相对链接和组件自包含要求。

### 决定维护

本提案获得批准并实施后，将反转[维护中英文公开文档](../decision/2026-08-20-maintain-bilingual-public-documentation.zh.md)。创建完整替代决定，保留其中仍有效的语言、翻译范围、语义一致和 ADR 配对规则，并采用同目录公开文档配对及上述入口职责。

同步修改仓库编写指令，使其采用相同规则。更新 [tk 文档决定](../decision/2026-08-29-maintain-tk-documentation.zh.md)及对应文档设计页，补充组件 README 导航职责，不改变主题归属。修复受影响记录中的事实链接和入口描述，不改变无关能力行为或 ADR 制度。

## 考虑过的替代方案

继续按当前决定维护独立的中英文文档目录。这可以保留现有根目录文档约定，但普通文档与 ADR、组件页面将继续采用不同的配对规则，另一语言文件的路径也取决于文档类别。

## 验收标准

1. 普通公开 Markdown 文档在同目录使用 `name.md` 和 `name.zh.md` 配对，包括仓库和组件 README。编写指令描述这一规则，不再要求中文文档位于 `docs/zh/`。
2. 仓库 README 文件对的介绍、能力索引和开发说明语义一致。列出的能力均可进入有效文档，包括具有完整内容的 tk 组件 README。
3. 被取代的语言目录入口页和独立 Skill 索引不保留重复或跳转占位文件。受影响的入站链接和命令示例使用当前路径。
4. 语言互链与文档相对文件链接均有效。Skill 语言变体目录和安装路径保持不变。
5. 按现有 ADR 生命周期，用完整双语决定替代冲突的公开文档决定。受影响的 tk 文档规则和 deep-research 索引引用与当前入口一致。
6. 变更通过 `pnpm check`、受影响页面的本地链接检查和双语语义审阅。不要求新增永久文档检查器。

## 风险

公开页面移动后，仓库外部的书签或入站链接可能失效。仓库内维护的链接可以同时修复，但无法在此更新所有外部引用。
