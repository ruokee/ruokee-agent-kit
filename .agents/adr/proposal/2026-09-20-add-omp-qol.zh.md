# ADR 提案：添加可配置的 OMP 使用体验调整

Draft owner: Ruokee
Draft writer: OMP GPT-6 Astra

[English](./2026-09-20-add-omp-qol.md) | 中文

## 动机

OMP 可能在后台工作仍在运行时返回空的 hub 等待窗口，在原生恢复未解决模型错误后停止，或在请求期限到达时中断慢速远端压缩。这些情况需要用户或模型反复介入。

OMP 18.2.4 提供委派原生工具和请求会话续跑的公开扩展接口。[hub 实现](https://github.com/can1357/oh-my-pi/blob/1c0303b1f2ec515cbf4b44a9a49d68a029531aac/packages/coding-agent/src/tools/hub/index.ts#L365-L515) 负责任务可见性和结果交付，但[公开压缩钩子](https://github.com/can1357/oh-my-pi/blob/1c0303b1f2ec515cbf4b44a9a49d68a029531aac/packages/coding-agent/src/extensibility/shared-events.ts#L375-L403) 不提供请求超时覆盖。这些接口支持小范围的等待与恢复调整；压缩仍需在保留原有期限和接受进程级影响之间取舍。

## 提议

### 组件与配置

在 `projects/omp-qol` 添加一个可独立分发的 OMP 扩展 `@ruokee/omp-qol`，集中提供 hub 等待、主会话错误恢复和实验性压缩期限调整。共同包提供统一的安装与配置入口，各模块保持独立控制。遵循[组件自包含决定](../decision/2026-08-24-keep-components-self-contained.zh.md)。

遵循[原生设置决定](../decision/2026-09-10-use-codex-web-plugin-settings.zh.md)，以 OMP 原生插件设置作为唯一配置来源。用户值、项目覆盖和配置解析由 OMP 负责。等待和保守恢复默认启用，压缩调整须显式启用。公开有效设置和模块可用状态，并尽可能将模块故障限制在该模块内。

组件范围限定为这些行为调整。Herdr 等外部工具的守卫及无关宿主行为不在范围内。

### 宿主职责

等待和恢复使用 OMP 公开扩展接口。任务所有权、消息消费、结果交付、权限检查、会话历史和原生压缩协议继续由 OMP 管理，避免维护第二套机制。

等待可以在有界总期限内续接原生空窗口。结束等待不能取消后台工作或隐藏已交付结果。恢复可以在符合条件的模型错误后请求有次数限制的续跑，同时遵守用户取消、固定安全排除和原生续跑上限。不得直接重放已完成工具，也不承诺模型续跑不会重复副作用。

安装与迁移由用户控制，不自动修改已有扩展或私人配置。重叠实现需要显式迁移，因为无法始终检测其影响或安全地组合使用。

### 压缩实验与替换条件

将压缩期限调整作为默认关闭的实验功能，采用有界的进程级超时调整。它保留 OMP 的压缩协议、历史替换、重试和回退，避免接管整个压缩流程。

该机制也可能延长同一进程中无关工作的匹配超时。启用即选择这一限制，不提供请求隔离或严格项目隔离。发生冲突或无法确定所有权时，应停止调整，不静默共享设置。停用无法缩短已经创建的期限。

OMP 提供受支持的请求级超时设置或钩子后，应采用该接口并退役全局机制，不为同一期限策略保留两个所有者。

### 文档与版本依据

每个调整项分别说明 OMP 源码基线、实际验证版本和已知适用条件。在组件的 `docs/` 提供中英文说明，由对应 README 链接，解释原生行为、为什么需要调整、工作机制、限制，以及何时不再需要该调整。

有关硬编码、缺少配置或行为回归的结论，应有匹配版本的源码或变更证据。区分可观察的限制与上游作者明确说明的理由。行为或宿主兼容性变化时同步维护这些依据；全包兼容范围不代表每个调整项均已验证。

## 考虑过的替代方案

- 多个独立扩展包。在打包分析中考虑过。它保留独立发布，但配置、兼容性与迁移分散在多份安装中。共同包可以集中这些入口。
- 专用 YAML 配置文件。在配置分析中考虑过。所需设置适合 OMP 原生设置，额外解析器和优先级系统会增加维护，却没有提供所需的新能力。
- 替换原生压缩流程。在超时分析中考虑过。它能直接控制请求选项，但会将协议、历史、重试和回退责任转移给本组件。
- 推迟压缩调整，直到 OMP 提供请求级接口。在评估隔离能力时考虑过。它避免全局影响，但保留原有期限。本提案选择将进程级机制作为须显式启用、默认关闭的实验功能。

## 验收标准

1. 组件可独立分发并使用原生设置。用户能够分别控制各模块，并从完整的中英文文档了解有效状态和兼容边界。每个调整项都有版本依据和可跟随的机制说明入口。
2. 等待与恢复减少反复介入，同时保留原生权限、取消、结果交付和续跑上限。失败可观察，不静默地将宿主职责转移给扩展。
3. 压缩证据证明远端工作能够超过原生期限后成功，且后续模型请求仍可用。验证须揭示对无关工作、取消和冲突的影响。超时改写提示不能单独证明成功或隔离。
4. 验证结合[仓库自动检查](../decision/2026-09-12-unify-repository-checks.zh.md)与真实 OMP CLI 行为。明确报告已测试宿主版本、无法执行的场景及失败模块，兼容声明和单元测试不替代运行时证据。

## 风险

进程级压缩调整可能延长无关请求。模糊的生命周期事件可能扩大影响范围，清理无法缩短已经创建的期限。默认关闭和有界作用范围可以减少暴露，不能提供隔离。

自动续跑可能重复副作用，并在原生重试后继续增加成本。保守的恢复条件和尝试上限能够限制风险，不能保证模型恰好执行一次。

宿主变化或重叠扩展可能导致等待结果丢失、重复恢复或超时所有权冲突。兼容检查和冲突处理可以减少这些风险，不能据此保证所有宿主版本与扩展组合都受支持。
