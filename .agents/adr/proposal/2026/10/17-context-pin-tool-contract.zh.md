# Context Pin 工具契约

Draft owner: Ruokee
Draft writer: OMP DeepSeek V4.1 Flash

[English](./17-context-pin-tool-contract.md) | 中文

## 动机

修改 Context Pin 的工具契约，使调用者按当前条目操作，不必提供 revision，并能一次读取完整活跃集合。

工具当前要求 `update` 和 `delete` 提供 `expectedRevision`。调用者必须在每次写入前取得最新 revision，读写之间 revision 变化会被拒绝。组件还只有摘要列表和单条读取，调用者需要整个活跃集合时，只能组合多次读取或依赖旧视图。这些要求增加读后写的工作，也容易让 Agent 在不检查其他活跃条目的情况下局部修改。

## 提议

- `update` 和 `delete` 按 `id` 指向活跃条目，并作用于执行时的当前条目。公开 schema 不再接受 `expectedRevision`；revision 仍保留为内部记录、显示值和重放依据。
- 新增只读 `show`，返回当前分支全部活跃条目，包括每个条目的 id、来源、revision、UTF-8 字节数和完整正文，以及条目数、总活跃字节和分支上限。空分支时，`show` 说明当前分支没有固定正文，并报告总活跃字节为零和分支上限。`list` 仍返回摘要；`get` 仍读取一个条目。
- 分支容量拒绝报告分支上的总活跃字节、被替换正文（`create` 为零）、拟写入正文、尝试后的总量和超出量。单条拒绝报告正文大小、单条上限和单条超出量。两种拒绝都不写入、不改变活跃集合，并要求调用者检查整个活跃集合。两种拒绝都不把拆条描述为减少活跃字节的方法。
- 重试沿用现有操作身份。已接受操作的重试返回原结果，不追加记录，不改变活跃集合和后续写入。相同身份携带不同动作、条目目标、来源或正文时是冲突；不比较 revision。重试识别先于当前条目查找，因此已接受的 `delete` 重试在条目已删除后仍返回原结果。只有新的调用针对未知条目时才失败。
- 用户确认的编辑或删除作用于当前条目。对话框打开时显示的 revision 只是展示信息，不是准入条件。旧草稿因此可能覆盖对话框打开期间被更新的正文。

组件 [README](../../../../../projects/omp-context-pin/README.md) 及其[中文版](../../../../../projects/omp-context-pin/README.zh.md)是动作列表和可观察行为的公开契约；[组件规范](../../../../spec/omp-context-pin.md)说明目标和不变式。[当前组件决定](../../../decision/2026/09/15-omp-context-pin.md)继续有效；本提案扩展该决定，不改变其归属、`read` 审批档位或对可调上限的委托。

## 考虑过的替代方案

- 保留 `expectedRevision` 必需。考虑过，因为它能发现并发变化。但它保留读后写工作，并会在无关更新后拒绝写入，不满足 revision 不作为调用条件的要求。
- 把 `expectedRevision` 设为可选。考虑过作为兼容折中。它留下两种并发行为不同的写入模式，并把旧读写路径保留为常规路径。
- 只保留 `get` 作为完整读取。考虑过，以避免新增动作。读取多个条目需要多次调用，且可能混用不同时刻的 revision。
- 给 `show` 增加 `id` 参数。考虑过，以与 `get` 对称。它会与 `get` 重复，并失去一次读取完整活跃集合的能力。
- 保持现有容量文案。考虑过，因为它已经报告上限和尝试大小。它不引导检查其他活跃条目，也没有说明拆条为什么不减少活跃字节。

## 验收标准

- 工具提供六个动作：`list`、`get`、`show`、`create`、`update` 和 `delete`。
- `update` 和 `delete` 不带 `expectedRevision` 成功，并作用于当前条目。新的调用针对未知条目时仍然失败；已接受的重试先于该查找得到答复，因此 `delete` 重试在条目已删除后仍返回原结果。
- 相同身份的已接受操作重试返回已接受结果，不追加，且活跃集合和后续写入不变。相同身份携带不同动作、条目目标、来源或正文时作为冲突失败；不比较 revision。
- `show` 返回全部活跃条目、正文和元数据，以及条目数、总活跃字节和分支上限。空分支时，它说明当前分支没有固定正文，并报告总活跃字节为零和分支上限。它不写记录、不改变 revision、不改变活跃用量。
- 分支容量拒绝报告分支上的总活跃字节、被替换正文（`create` 为零）、拟写入正文、尝试后的总量和超出量。单条拒绝报告正文大小、单条上限和单条超出量。两种拒绝都不写入、不改变活跃集合、要求检查整个活跃集合，不把拆条说成容量解决办法。
- 既有受支持的 journal 记录保持原样重放；条目 id、操作身份和 revision 不重新编号，也不迁移。
- 组件 README、组件规范、工具描述和版本随工具行为更新。
- 实施后的决定记录本契约，并移除本提案。

## 风险

- 旧用户草稿可能覆盖对话框打开期间被更新的正文。用户确认写入，但对话框不再防止并发变化。
- 从旧视图编辑的 Agent 可能覆盖较新的正文。移除 revision 门槛也移除了让这种覆盖可见的拒绝。
- `show` 可能返回大量正文并消耗上下文。它是显式读取，不是默认动作。
- 调用者可能忽略整体容量提示，继续缩短一个正文。提示改变消息，不保证模型行为。
- 仍发送 `expectedRevision` 的旧调用者可能因宿主拒绝未知字段而失败。公开文档和 schema 同次修改。
- README、规范和工具描述可能漂移。它们在同一次实现中修改，决定链接公开面。
