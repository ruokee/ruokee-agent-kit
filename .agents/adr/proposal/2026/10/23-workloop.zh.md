## 动机

以完整的单语言 Skill 和同语言 OMP Prompt 模板分发 workloop，按当前活动加载工作流指令。

现行 [workloop 决定](../../../decision/2026/10/22-workloop.zh.md)同时提供可独立安装的语言 Skill，以及暴露两种语言并在调用时选择语言的 OMP 包。直接安装需要明确所选 Skill 及对应入口的维护归属。旧包或同名文件命令与新模板并存时，宿主还可能调用与用户刚安装的模板不同的入口。

公共 Skill 正文在确定所需操作之前就包含材料格式、检查循环、角色协作和执行细节。Setup 和单个操作因此先收到尚不需要的指令。把整篇正文搬到另一份必读文件，仍会保留同样的加载问题。

规划条件、执行权限和独立评估也需要明确边界。目标具备规划条件后，应直接形成 Plan，不再等待一次例行规划请求。准备自检、按请求开展的独立材料审查和执行候选的独立核验需要分别记录，避免混淆其结论。

## 提议

### 分发

反转现行决定中要求 OMP 资源包和调用时语言选择的组件及分发条款。组件仍位于 `projects/workloop/`，保留可独立安装且能力等同的 `workloop` 和 `workloop-zh`。分发完整的普通 Skill 目录及按语言区分的两套 Prompt 模板，不提供包清单、运行时、Extension、构建系统或专用安装器。

一次 OMP 安装选择一种完整语言 Skill 及对应的 `/wl-clarify`、`/wl-exec`、`/wl-verify`、`/wl-ship`、`/wl-supervise` 模板。每个模板固定所选 Skill 身份，只传递操作、加载指示和用户输入，不根据输入选择语言，也不复制工作流正文。空参数不生成用户输入标题或空段落；非空参数保留宿主参数解析器产生的字符。没有新增参数时沿用足够的当前会话或 Task 上下文，不要求用户重新描述。仅在当前 Task 或所需目标确实无法确定时补充信息。

安装指南负责首次安装、完整替换、切换语言、移除及宿主加载条件，区分文件放置、发现和实际加载。切换管理方式时先移除 workloop 的旧包资源及冲突的同名文件命令，不改动无关资源。只将选中的模板安装到宿主实际的 Prompt 发现位置，使用宿主支持的加载方式，不假定文件命令重载也能重载模板。Setup 保持可选。其他 Harness 继续使用自己的 Skill 机制，以自然语言选择操作。

### 指令归属

替换现行组件条款中由 `SKILL.md` 持有公共合同的布局，采用最小入口、操作正文和按活动读取的共享 Reference。入口负责用途、前置依赖、请求解析、路由、必要的跨操作边界及缺失指令的恢复，详细共享合同不再从此处无条件加载。保留用户语言、适用的项目写作规则和事实完整性，包括条件、否定、归属和真实的不确定性。保留有效需求与权限、暂缓与禁止的区别，以及现有的不迁移边界。

每个操作负责自身步骤和结果材料。共享的 Task 归属、自检、角色选择、协作及执行约束在每种语言 Skill 内各有一个所有者，调用处明确读取条件。Setup 负责外部配置选择，不把工作流复制进项目指引。保留现行初始化条款的配置范围、禁止嵌入机器特定模型的要求，以及不建立通用用户和项目配置层级的边界。直接引用、Setup 和 Prompt 入口应加载当前活动的完整指令，不强制提前读取无关操作细节。不以另一份所有路径都必读的大文件替代原来的大入口。

每种语言目录安装后仍完整自包含。当前所需指令离开上下文后，必须从实际安装位置重新加载。各操作保存恢复自身工作所需的状态，共享协作指引负责实时路由和待完成分派的恢复。只改配置的请求无需保留完整执行状态。加载或重读指令不表示模型已经遵守。

### 规划

目标和必要设计清楚、可预见的重要选择已解决，且没有只讨论、只设计、不做 Plan、暂停或不写入限制时，Clarify 在同次操作中形成或修订独立的 `plan.md`，随后自检准备材料。工作不可行、无需行动或决定不再继续时，可以保存有依据的结论，不强行形成 Plan。

准备阶段可在操作许可内维护普通材料和必要临时文件。这些材料的产出或检查不授予实现、配置、Git 或托管元数据修改许可，不启动实现，也不邀请下一操作。保留稳定单元标签、已完成结果、可选材料、关联子任务的材料归属，以及 Goal、诊断、设计和执行计划之间的职责区别。

### 检查记录

细化现行材料和检查条款，为其中三类评估职责分配不同记录。保留 Verify 已有的独立材料审查能力，不增加操作或命令：

- Clarify 自动自检使用已有的准备检查记录，例如 `plan-check.md`，不写入 `material_check.md` 或 `verification.md`。
- 准备材料的独立审查按请求启动，将材料候选、范围、证据和结论追加到 `material_check.md`。
- 已执行单元的独立 Verify 将实现候选、范围、证据和结论追加到 `verification.md`。

按对象职责分类，不按文件扩展名分类。Execute 产出的提案即使只修改 Markdown，也属于实现候选。不为未请求的活动创建空报告，不仅为统一命名而重命名已有自检记录。

保留新的只读自检上下文、作者修复、准备阶段与各单元分别计数、首次及复查累计、当前通过即停，以及达到上限时报告未解决或未复检改动的规则。根据任务规模和复杂度选择三至五次的默认上限，适用外部指引可覆盖该上限。每个实现单元仍须自检和独立 Verify。独立审查不受自检轮次上限限制，达到上限不自动发起准备审查。独立核验者保持只读，保留历史评估，区分通过、需要修改和无法判断。候选变化使受影响证据失效。

请求准备材料独立审查时，范围覆盖作者的范围内修订，以及同一只读核验者的必要复查，直到当前通过或出现真实阻塞；用户限定审查范围时遵循其限制。

### 执行权限

分别处理需求选择、普通执行、受保护动作和用户验收。可预见的需求选择在 Clarify 解决。有效执行请求覆盖其范围内的普通实现、修复、自检、独立 Verify 和必要复查，不在单元间重复索取例行许可。已授权的临时目录文件检查仍属于其检查范围。项目允许时，已验证且已提交的前置候选可以在集成或最终用户审阅之前提供开发依赖，不能代替确实需要的外部部署或已发布状态。

项目规定的提案批准、归档、集成、推送、安装、发布、付费和 Task 关闭仍需有效授权。缺少许可只阻塞依赖它的动作，其他已授权且就绪的工作继续。遵循明确的逐项确认请求或人工接入点。不把避免重复索权写成所有重要选择一律推迟到最后。

保留角色独立选择、Senior 须明确分配、隔离且可复用的 Verify 会话、候选冻结、普通消息派工、最终结果等待、已保存结果恢复及范围绑定的证据。Execute 直接实现，Supervise 调度 Worker。Worker 到分派边界停止，执行负责人继续总体已授权 Plan。两种操作仍禁止结构化问答工具。Ship 由项目及有效授权定义，不设通用动作包。

### 合同一致性

形成现行 workloop 决定的完整后继，保留其身份和所有仍有效条款。[workloop Spec](../../../../spec/workloop.zh.md)、两种语言 Skill 及 Prompt、使用和安装指南，以及仓库检查选择规则均与所选合同一致。登记组件维护的 Prompt 和 Reference 路径，未知或共享输入仍回退到完整检查。两种语言 Skill 及对应 Prompt 同次维护，表达等同的行为，两种 Skill 使用相同组件版本。

保留通过名称和公开接口使用 tk 的前置要求、不限 Harness 的独立使用、不提供旧别名或材料迁移、可选初始化，以及实际失败后定向恢复而不主动预检环境的边界。文件检查、宿主发现、真实模型行为、用户验收、交付和 Task 关闭仍分别判断。共享 Task 指引保留身份，支持已有 workloop Task 的继续、修复和恢复。

## 考虑过的替代方案

将完整公共合同保留在必读入口或共享文件中，能提供一个直观的读取位置，但每个入口仍须加载与当前活动无关的执行及协作细节。按活动归属正文、按条件读取共享 Reference，既让每条规则只有一个所有者，也减少无关的必读上下文。

## 验收标准

- 任一种完整语言 Skill 都可脱离仓库和另一语言独立使用，所有必需的内部加载路径均留在所选目录内。
- 一次 OMP 直装暴露一种语言 Skill 及五个同语言 Prompt。替换、切换语言和移除不留下嵌套 Skill 副本或冲突的 workloop 入口，并保留无关资源。
- 空 Prompt 输入不增加空段落，也不丢弃可用 Task 上下文；非空输入保留宿主解析后的字符。入口模板不持有工作流逻辑。
- 直接引用 Skill、Setup 及每个 Prompt 路径均能加载当前活动的必需指令，无关的执行和检查细节按条件读取，不是所有入口的必读内容。
- 具备规划条件的请求在同次 Clarify 中获得 Plan 及自动准备自检，同时遵循明确限制和不行动结果。
- 三类评估各自使用对应记录和触发条件，保留候选绑定的历史，不授予实现或用户验收权限。
- 已获授权且依赖就绪的执行不因例行审批门槛停止，项目受保护动作和明确人工接入点仍保留各自条件。
- 两种语言 Skill 及 Prompt、双语文档、完整决定后继、Spec 和检查消费者表达相同边界。文本检查不证明真实模型行为。

## 风险

残留的同名 OMP 文件命令优先于新 Prompt 模板。只复制模板而未移除 workloop 旧资源，会让看似成功的安装仍调用旧入口。安装说明必须覆盖这项切换及宿主实际的发现和加载条件。
