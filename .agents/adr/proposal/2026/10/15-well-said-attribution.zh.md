# well-said 署名

Draft owner: Ruokee
Draft writer: OMP DeepSeek V4.1 Flash

[English](./15-well-said-attribution.md) | 中文

## 动机

把 well-said 的来源署名与许可信息移出 Skill 组件，交给仓库自身的文档承载。

两个 well-said 组件当前各自带有四份同目录附加文件：`LICENSE` 对应 Ruokee 的原创内容，`LICENSE.unslop` 对应复用的 unslop 材料，`SOURCES.md` 与 `SOURCES.zh.md` 记录作者归属、固定的上游版本与类目映射。[well-said 决定](../../../decision/2026/09/12-well-said.zh.md)要求这一文件集合，[Skill 规格](../../../../spec/skills.zh.md)要求 Skill 树携带来源署名与许可通知。

这两个位置都不适合这类材料。Skill 里的文件会作为指令进入 Agent 上下文，或与指令一起被宿主和 Agent 当作同一个组件读取，法律通知对写作会话没有意义，还可能被读成能力规则的一部分。署名与许可信息服务于仓库的读者，因此仓库把它们记在 Skill 树之外：`README.md` 条目用一行署名写出来源与作者，后继决定承载上游路径、固定版本与许可。

## 分析

英文的文风规则与作者声音指导仍大量逐字沿用固定上游版本 `99559f2f52047978602ef365589275831e76af07`。去掉编号前缀后，三十六条文风规则里有二十三条与上游某条逐行相同，四个流程步骤中也有一个相同，作者声音的六条要点完全相同。第 20、21、22、23、31 条是本地新增。其余英文章节 `Guidance`、`Defensive phrasing`、`Trimming chain of thought leakage` 与 `Writing articles` 是本地内容。

复用材料仍然保留其来源与适用的许可。仓库把这一记录放在 README 署名与后继决定里，后者保留上游仓库路径、固定版本、pstack 的 MIT 许可与作者。本仓库也从不单独分发组件副本：安装器把组件目录从当前检出复制到宿主的 Skill 路径，仓库不发布按组件拆分的产物。所以组件内的通知文件并不覆盖本仓库的任何分发路径。

## 提议

### 组件布局

每个语言组件只保留 `SKILL.md`。从 `skills/well-said/` 与 `variants/zh/skills/well-said/` 删除 `LICENSE`、`LICENSE.unslop`、`SOURCES.md` 与 `SOURCES.zh.md`。写作指导与 `metadata.version` 不变，仓库中任何位置都不新增替代性的通知文件。

### 署名

`README.md` 的 well-said 条目增加 `Inspired by [unslop](https://github.com/cursor/plugins/blob/main/pstack/skills/unslop/SKILL.md) by [Lauren Tan](https://github.com/poteto).`，`README.zh.md` 用中文写出同一署名。README 条目承载署名，许可、上游路径与固定版本由后继决定保存。

### 位置规则

`.agents/rule/boundary.md` 保留 `保留来源署名，并遵守适用于被复用材料的许可和署名要求。`，并新增：`许可与声明文件不放在 Skill 树内，它们可能被读成能力本身的一部分。把来源署名与许可信息记在仓库层面：仓库根 README、组件自带的 README，或拥有该材料的决定。` 位置句覆盖声明文件与署名、许可信息的记录位置，并为能力自身决定要求的来源引用行留出空间：[architect 决定](../../../decision/2026/08/22-architect.zh.md)要求两个语言版本的 `SKILL.md` 写出来源作者与许可，而规则不得与现行决定冲突。

`.agents/spec/skills.md` 改成以下三条不变量：

- 「Skill 树只放宿主可发现的材料，例如 `SKILL.md`、工作流、参考、示例和术语表，不放许可与声明文件。」其中 `grill-me` 一句保持不变。
- 「改编自第三方的材料把来源署名与许可信息记在仓库层面：仓库根 README、组件自带的 README，或拥有该材料的决定。」
- 「每个语言组件在 `metadata.version` 声明版本，且只包含 `SKILL.md`；来源署名写在仓库根 README，具体要求见 well-said 决定。」

中文文件表述相同，中英两份文件同步变更。

### 决定替换

[well-said 决定](../../../decision/2026/09/12-well-said.zh.md)无法与本提议并存。其「组件布局」列出这四份文件，并要求安装或分发时随组件携带；「验证要求」第 3 条要求每个组件持有自己的来源文档与两份许可文件；「结果」段的结论是每个语言组件必须包含自己完整的附加文件。这三处都把通知放在组件内部。

后继决定保留仍然有效的规则：能力范围、编辑权限、加载、Agent 交流、版本策略、其余验证要求，以及上游事实。

[第一方能力决定](../../../decision/2026/08/20-first-party-capabilities.zh.md)不反转。其归属条目要求复用材料满足适用的许可与署名要求，并未规定仓库在哪里记录这些信息；README 署名与后继决定即满足该条。

实施时只反转 well-said 决定一次。被替换的中英两份文件带 `Archived` 与 `Reversed by` 移到 `archived/2026/09/12-r2-well-said.md` 与 `archived/2026/09/12-r2-well-said.zh.md`；后继决定写入规范路径，`Reverses` 指向该归档；较早的归档 `archived/2026/09/12-r1-well-said.md` 的 `Reversed by` 当前指向被替换的决定，须跟随它改指 `r2`。归档的 `r2` 两份保留它当时选择的布局，其中指向被删来源文档的链接改写成指向后继决定的说明句。已消耗的提案随后删除。

## 考虑过的替代方案

**只删除组件 `LICENSE`。** 这是选择删除范围时考虑过的最小方案。它去掉仓库许可的副本，而上游通知仍留在每个组件里与写作指令并列，位置正是本次要改的对象。

**保留 `SOURCES.md` 与 `SOURCES.zh.md`，删除两份许可文件。** 这是把删除范围收窄到两份许可文件时考虑过的方案。它保留固定版本、类目映射与作者归属划分，同时把两份来源文档留在每个组件里，位置正是本次要改的对象。

**保留 `LICENSE.unslop`，删除其余三份文件。** 这是判断组件是否保留上游通知时考虑过的方案。它把上游通知留在组件内。它为一文本仓库并不使用的分发路径保留一份 Skill 树里的法律通知。

**通知继续留在 Skill 树里，改为按需加载。** 这是考虑组件如何暴露非指令文件时的方案。它能保持组件自包含。它仍然把法律文本放在与指令一起被宿主和 Agent 读取的位置，并为写作会话不需要的材料增加一条加载规则。

**位置规则只写进 Skill 规格。** 这是选择位置规则落点时的候选之一。该规则将只覆盖普通 Skill，漏掉自带 README 的扩展。

**位置规则只写进边界规则，同时从 Skill 规格删掉错误表述。** 这是同一轮里另一个单文档落点方案。读 Skill 规格的 Skill 作者在那里看不到位置规则，需要到边界规则里查。

**不改规则，改为记录一次已接受的偏离。** 这是在把位置认定为真正的缺陷之前考虑过的方向。边界规则会保留无条件的许可义务，新增偏离通道，并由某份决定把本次复用登记为例外。它为一种本仓库没有分发路径的情形增加了例外机制。

**README 署名同时写出许可名称与版权年份。** 这是拟定 README 署名措辞时考虑过的方案。署名保持为署名，许可与固定版本留在读者查询复用条款时使用的决定里。

**README 链接指向固定版本而不是 `main`。** 这是拟定 README 链接时一并考虑过的方案。README 链接指向上游 Skill 的当前位置，固定版本由决定记录。

## 验收标准

1. `skills/well-said/` 与 `variants/zh/skills/well-said/` 各自只含 `SKILL.md`，两份文件与变更前逐字节一致，`metadata.version` 不变。
2. `README.md` 与 `README.zh.md` 写出 unslop 启发署名，链接到上游 Skill，并写出作者 Lauren Tan。
3. `.agents/rule/boundary.md` 保留署名与许可义务，并写明仓库在哪里记录署名与许可信息；`.agents/spec/skills.md` 不再要求 Skill 树携带来源署名与许可通知，并排除树内的许可与声明文件；中英两份对应文件表述一致。
4. well-said 决定被反转一次：被替换的文件带实际 `Archived` 日期与 `Reversed by` 归档为 `r2`，后继决定位于规范路径并带 `Reverses`，承接前任仍然有效的规则与上游版本；较早归档的 `Reversed by` 指向 `r2`。第一方能力决定不变。
5. 没有受跟踪文件仍链接到被删或被移动的文件；每处引用按含义分类，当前权威保留规范路径，历史引用跟随归档版本；相对路径与语言互链均可解析。
6. 已消耗的提案被删除，仓库检查通过。

## 风险

被删除的 `SOURCES.md` 中的类目映射只剩 Git 历史，日后核对来源需要读历史，而不是读文件。

读者可能把新的位置规则读成复用材料的许可义务已经取消。边界规则保留该义务，后继决定记录许可、固定版本与作者。

按含义分类引用可能出错：把当前布局的引用指向归档版本，会让已被替代的布局被读成当前布局。

本次改动涉及两个组件、两份 README、一份规格、一份规则和多份双份决定。漏掉任何一处，仓库就会同时表达两种布局。
