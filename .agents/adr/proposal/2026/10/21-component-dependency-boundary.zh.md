# 组件依赖边界

Draft owner: Ruokee
Draft writer: OMP DeepSeek V4.1 Flash

[English](./21-component-dependency-boundary.md) | 中文

## 动机

把组件自包含收窄到文件与代码引用，让组件正文可以声明必需的工具或 Skill。

现行的[组件自包含决定](../../../decision/2026/08/24-component-self-containment.zh.md)禁止组件文件链接、依赖或指示 Agent 加载另一个 Skill、Extension、Plugin 或 Package，并把运行时需要另一个仓库组件的示例纳入规则范围。按字面理解，工作流不能声明自己需要 tk，Skill 也不能按名称提及另一个可加载的 Skill。

[仓库规格](../../../../spec/repository.zh.md)、[Skill 规格](../../../../spec/skills.zh.md)、[边界规则](../../../../rule/boundary.zh.md)、[组件词典](../../../../../docs/dictionary/component.zh.md)和[词典摘要](../../../../../docs/dictionary/README.zh.md)重复了同样宽泛的表述，都没有区分仓库文件引用与文字声明的前置条件。

规则真正针对的失败，是引用解析到组件之外的文件，并且只安装该组件时失效。按名称或公开接口提及工具或 Skill 不会形成这种文件引用。组件有合理的运行时前置条件，读者需要看到明确声明。

## 提议

反转组件自包含决定，记录一条边界：跨组件的文件与代码引用继续禁止，文字声明的前置条件允许。

### 有效冲突

现行条款禁止链接、依赖或指示 Agent 加载另一个组件，并把运行时需要另一个仓库组件的示例纳入范围。提议的选择允许组件声明另一个工具或 Skill 为前置条件，并按名称或通过公开接口调用，不涉及文件引用。一个声明需要 tk 并按名称调用 tk 的工作流符合提议的选择，却违反现行条款，两者无法同时成立。

### 引用边界

组件的文件集与代码保持自包含。组件内的仓库文件引用必须解析到该组件目录内。这包括 Markdown 链接、书面文件路径、导入、包依赖和运行时文件读取。组件目录之外的仓库支持文件对组件不可用。

### 声明的前置条件

组件正文可以提及其他组件、工具或 Skill，把它声明为前置条件，并按名称或通过公开接口指示使用，包括加载 `skill://grill-me` 这样的 Skill。声明的前置条件不是文件或代码依赖。组件不必内置该前置条件、复制其实现或提供回退。

自包含仍然表示组件的文件集完整、能够独立安装、具有确定版本并可被单独阅读。它不表示组件没有运行时前置条件。前置条件必须显式声明，不能通过指向另一个组件文件的链接隐式形成。

### 示例

允许：

- 工作流声明需要 tk，并调用 `tk` 命令，组件内不含 tk 文件路径。
- Skill 按名称提及另一个 Skill，例如 `skill://grill-me` 或「加载 grill-me」，不链接其文件。
- Skill 按名称把另一个 Skill 列为相关阅读。
- 组件声明某个已安装的外部工具是前置条件，不携带该工具的文件。
- 示例按名称调用公开工具或 Skill。
- 组件引用公开外部资料、外部 URL 或上游文档，或提及与组件同名的外部库。

禁止：

- Markdown 链接、书面路径或代码引用解析到组件目录之外的仓库文件，包括 `../code-quality/...`、`../../docs/...`、`skills/<name>/...`、仓库根相对路径和绝对路径。
- 导入、require 或运行时按路径读取另一个组件的文件或包。
- 依赖 `.agents/spec/`、`.agents/rule/` 或组件目录之外的其他仓库支持文件。
- 示例只有取得另一个组件的文件才能运行。
- 中文变体使用源码专用的 `variants/zh/` 前缀书写链接。

组件目录之外的仓库文档、ADR、manifest、安装器和集成代码仍可引用组件。

实现会用完整后继决定替换现行决定，保留文件边界，同步修改仓库规格、Skill 规格、边界规则、组件词典和词典摘要的中英文版本，且不改变组件文件布局、安装、分发或版本行为，也不移动组件内容。

## 考虑过的替代方案

需求分析考虑过现行禁止、一种更窄的边界选择，以及一种内置方案。

**维持宽泛禁止。** 组件无法声明真实的前置条件，读者只能自行推断。合法的名称引用，例如工作流需要 tk、Skill 提及另一个待加载的 Skill，仍会被当作越界。

**只禁止 Markdown 链接。** 书面路径、导入和运行时读取会被允许。组件仍可能以安装后失效的形式引用自身之外的文件，规则针对的失败会重新出现。

**内置所有前置条件。** 组件复制另一个组件的文件或实现，从而不存在外部前置条件。这会在组件之间重复内容，副本的版本与行为也会逐渐不一致。

## 验收标准

1. 后继决定与仓库规格、Skill 规格、边界规则、组件词典和词典摘要用中英文表达同一区分：文件与代码耦合禁止，正文可以提及其他组件、工具或 Skill，并把它声明为前置条件。
2. 上述来源中不再有条款可被合理读成禁止组件正文提及其他组件、工具或 Skill。在自包含语境中，「依赖」指文件或代码依赖，或已用更精确的措辞说明。
3. 声明需要 tk、按名称调用 `tk` 且组件内不含 tk 文件路径的 Skill 符合要求。
4. 按名称引用 grill-me 或 `skill://grill-me`、不链接其文件的 Skill 符合要求。
5. 使用 `../code-quality/...`、`../../docs/...`、仓库根路径、绝对路径、跨组件 import 或按路径读取另一个组件文件的组件不符合要求。
6. 示例按名称调用公开工具或 Skill 时允许。示例必须读取另一个组件文件才能运行时不符合要求。
7. 中英文来源语义一致，没有组件文件移动，安装、分发和版本行为不变。
8. 反转在归档中保留原决定的历史与理由，并遵循 ADR 规则。
9. 现有自包含检查，如果存在，继续针对文件引用，不因正文提及而失败；没有新增自动检查禁止提及其他组件、工具或 Skill。

## 风险

**前置条件不兼容。** 组件可以把另一个工具或 Skill 声明为前置条件，却无法控制其版本。用户安装组件时缺少前置条件或版本不兼容，会遇到失败，或得到比组件承诺更弱的结果。组件的完整功能此时取决于该前置条件，自包含不再保证功能上的完全独立，但文件集与代码引用仍保持自包含。

**文件引用在审查中漏过。** 边界收窄后，审查者可能把书面路径当成单纯提及。这样的路径一旦通过，组件安装后会因为缺少被引用的文件而失效，文件边界也会逐个案例被侵蚀。
