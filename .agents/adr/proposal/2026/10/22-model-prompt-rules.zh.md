## 动机

将模型提示词规则迁入 smart-context，保留规则文件及逐 turn 行为。

[现行决定](../../../decision/2026/09/14-model-prompt-rules.zh.md)将规则归属 QoL，并要求总开关和模块开关同时启用。新归属需要独立开关，不改变用户规则数据，也不增加注入入口。

## 提议

延续 `14-model-prompt-rules` 身份。将 QoL 归属及总开关依赖替换为 smart-context 归属和独立的 `modelPromptsEnabled`，仍默认 `false`。开关在激活时读取一次。关闭时不注册注入 handler、不读取规则目录、不诊断未使用文件。无效模块设置只停用本模块。通过 `/smart-context` 报告状态，不启动模型轮次，不暴露规则正文或模型标识。

保留当前 profile 的用户 agent 目录和项目 `.omp/model-prompts`。只读取直接子项中的非隐藏、小写 `.md` 普通文件。保留区分大小写的 `exact`、`model`、`contains` 和 `regex`，文件内或关系，以及每个命中文件只追加一次。保留 frontmatter 校验及移除、开头 BOM 移除，以及包含换行形式在内的正文逐字保真。

每个受覆盖的 `before_agent_start` turn 重新读取规则及有效模型。保留输入块，用户文件先于项目文件，同目录按文件名排序，每个命中文件贡献独立块，不增加包装。普通子 Agent 使用自身模型。连续 turn 不累积追加正文。无模型、规则或命中时保留输入。

保留文件及目录失败隔离、按事件所属会话去重的固定相对来源诊断，以及保留更早 handler 结果的意外异常恢复。不为 Handoff、plan-mode 子 Agent、标题生成、分类、轮内回退或单次 Provider 请求增加入口。直接宿主依赖归属新组件，保留既有原生替代复核。

项目规则文件会成为系统指令。保留既有边界，不增加项目信任门禁、安全隔离、正则沙箱或超时，也不增加正文大小限制。公共文档必须说明目录及注入效果。因此，含有匹配规则的项目可以改变在其中打开的会话的系统指令。

移除 QoL 实现及 `modelPromptsEnabled` 设置。迁移保留原 `enabled && modelPromptsEnabled` 的有效结果，分别处理用户及项目覆盖，清除两个 QoL 作用域的迁出键。规则文件不变，不自动迁移配置。

仓库检查和实际提示词装配及序列化路径的受控运行构成整合验收。以此替代强制真实模型或完整 CLI/TUI 覆盖，不将单独 handler 返回值当成 Provider 请求证据，不改称历史运行的覆盖范围。

## 考虑过的替代方案

无

## 验收标准

- 默认关闭时无文件读取、注入或未使用文件诊断，独立于 Pin 和压缩设置。
- 既有文件保留匹配、排序、正文保真、下一 turn 刷新及失败隔离。
- 受控最终请求中匹配正文只出现一次，不含 frontmatter，不丢失原生块。
- QoL 不再注入规则，迁移后的有效开关保留用户意图。

## 风险

规则仍占用提示词空间，逐 turn 准备需要等待目录读取。宽泛文本匹配可能影响非预期模型。迁移开关时忽略原 QoL 总开关状态，可能启用用户原先关闭的规则。
