# 非 seance 任务参数清理

Draft owner: Ruokee
Draft writer: OMP DeepSeek V4.1 Flash

[English](./17-task-argument-cleanup.md) | 中文

## 动机

新增一个 `omp-qol` 模块，在宿主校验前删除非 seance 任务项中的 seance 专用字段 `sourceSession` 与 `model`。

当会话暴露 `seance` 代理时，OMP 18.11.3 在每个 `task` 项上展开 `sourceSession?` 与 `model?`，不只限于选择 `seance` 代理的项。[`validateSeanceFields`](https://github.com/can1357/oh-my-pi/blob/v18.11.3/packages/coding-agent/src/task/seance.ts) 在解析后的代理不是 `seance` 时拒绝任何已存在的值，因为它与 `undefined` 比较，而不是判断值是否有意义。把可选字段当成输入参数的模型可能发送 `sourceSession: ""`、`/dev/null` 或其他占位值，导致整批任务在派发前失败。一个会话出现过 4 次这类失败，`sourceSession` 的值为 `""` 和 `/dev/null`，`model` 的值为 `""` 和 `@ds-flash`。省略这两个字段的重试成功。

宿主在派发前校验整批任务。若推测启动生效，已经从已闭合 `tasks[]` 项启动的子代理会被丢弃。上游修复，即忽略空值或只向 `seance` 项暴露这两个字段，不在本仓库范围内。qol 组件可以在扩展接缝处删除字段，不改变 task schema 或宿主派发路径。

## 分析

### 宿主校验

会话暴露 `seance` 代理时，task schema 在每个任务项上展开这两个可选字段。当默认代理符合 schema 的标识符模式时，schema 还会填入默认代理，因此省略 `agent` 的模型仍可能带着具体的非 seance 值进入事件。`tool_call` 事件通常收到 schema 校验后的参数；schema 失败后的宽松回退可能保留原始参数。处理器返回的 `input` 会替换后续用于派发、展示、持久化和执行的参数。task 工具自身的 `validateSeanceParams` 在 `execute` 内执行，晚于事件。处理器因此可以在失败的检查之前删除字段，不需要包装工具。

schema 的正常校验会删除可选字段中的 `null` 和字符串 `"null"`。schema 失败后的宽松回退可能保留原始参数，因此不按字段值判断的清理规则能覆盖两条路径。

### 推测执行

推测执行是 OMP 在工具调用完成流式生成前提前开始工作的优化。对于批量 `task` 调用，宿主在每个任务项的 JSON 对象闭合后立即启动对应子代理，不等完整调用结束。完整调用校验失败、被拦截或参数变化时，宿主中止已启动的运行。[`task.speculativeLaunch`](https://github.com/can1357/oh-my-pi/blob/v18.11.3/packages/coding-agent/src/task/settings.ts) 默认开启这项行为。

另一个实验性设置 `tools.speculativeExecution.enabled` 默认关闭。它允许通过校验的本地读取在正常派发前开始。网络请求、provider 完成和文件系统写入不在此列。

扩展注册 `tool_call`、`tool_result` 或审批生命周期处理器时，或任务审批不是自动允许时，OMP 会关闭这两类提前执行。处理器可能拦截调用或要求审批，而非自动允许的调用不能提前开始。注册清理处理器因此会让启用该模块的每个会话失去推测启动，而不只是带有这两个字段的调用。

启用 `taskArgsEnabled` 后，`task.speculativeLaunch` 因此不再生效。模块不修改宿主设置；是注册的处理器让 OMP 拒绝启动。本提案接受这一有效默认值。需要推测启动的用户可以关闭清理。实验性的推测读取在启用时也会被拒绝。

### 与组件的契合

`@ruokee/omp-qol` 在一个包、一个设置入口和一套检查下提供可独立开关的调整。[OMP QoL 决定](../../../decision/2026/09/20-omp-qol.md) 已经确定该边界。[组件 README](../../../../../projects/omp-qol/README.md) 与[组件规格](../../../../spec/omp-qol.md)负责模块机制和逐项证据。wait 模块已经确立了一种模式：会话没有暴露预期的内建工具时拒绝动作。组件的维护下限是 OMP 18.5.0，该版本提供这里使用的 `tool_call` 输入替换契约。在未暴露 seance 字段的宿主上，不携带这些字段的调用没有可删除的内容，处理器不返回 `input`。

## 提议

为 `@ruokee/omp-qol` 新增 `taskArgs` 模块，由 `taskArgsEnabled` 控制，默认值为 `true`。默认开启接受上文描述的有效推测启动损失：模块启用期间，`task.speculativeLaunch` 不生效。模块为内建 `task` 工具注册一个 `tool_call` 处理器。

### 改写规则

处理器从事件输入中读取每个任务项的 `agent`。当 `agent` 是字符串、去除首尾空白后非空且不等于 `seance` 时，处理器删除该项自身的 `sourceSession` 与 `model` 键。字段值不参与判断：空字符串、占位值和非空值都删除。两个键都不存在的项保持不变。

批量调用对每个 `tasks[]` 项应用该规则，不改批量顶层的字段。单项调用把顶层参数当作一项处理。处理器只复制发生改动的对象，并且只在确有改动时返回新的 `input`。其他参数，包括 `task`、`solutionSpace`、`tools`、`context`、`name` 和未知字段，保持值和结构不变。

`agent` 缺失、为空、纯空白、非字符串或为 `seance` 的项保持不变。宿主可能在事件之后解析默认代理，扩展无法以与宿主同等的权威得知该默认值。

模块不改变 task schema、工具描述、审批策略、派发、后台生命周期或结果渲染。

### 激活

模块从属于包的主开关。`taskArgsEnabled` 值非法时只禁用该模块。只有在会话暴露的 `task` 工具的 `sourceInfo.source` 为 `builtin` 时，模块才注册处理器；工具缺失或被同名工具替换时，模块保持未激活并给出原因。

### 状态

`/qol` 报告模块状态和本次激活期间 `input` 发生改动的调用次数。批量调用改动多个任务项时只计一次改写调用。计数器是诊断状态，不持久化。

### 边界

模块不修复所有畸形任务形状。`agent` 缺失或为空的调用保持原样，由宿主按默认代理和原生规则解析、校验；结果取决于解析出的代理和其余参数。把字段放在批量顶层的调用也保持原样，由宿主原生校验。宿主的校验错误提示模型把字段放到 `tasks[]` 内的单个 `seance` 项上；该模块不改写这种形状。

模块不重试、不拦截结果，也不增加模型可见的提示。它只是宿主扩展接缝处的输入清理。

### 上游修复

宿主应忽略空值，或只向 `seance` 项暴露这两个字段。本提案不替代该修复。当组件的维护下限包含修正后的宿主契约时，可以停用该模块。

## 考虑过的替代方案

- **通过扩展工具 API 包装 `task`。** 扩展 API 可以通过 `ctx.invokeTool` 委托同名原生实现，因此不必复刻派发、审批或后台生命周期。它仍需要替换工具定义、schema、描述和原生渲染路径，并随宿主变化保持这些内容同步。`tool_call` 处理器改动更少，且保留原生工具。已否决。
- **在提示词或 Skill 中要求模型省略字段。** 不增加处理器，也不付出推测执行代价，但依赖每个模型和会话遵守指示。观察到的失败说明这不可靠。已否决。
- **收到 `tool_result` 错误后让模型重试。** 不改写参数，但消耗一轮失败调用，并且仍依赖重试正确。已否决。
- **只删除空字符串。** 范围更窄，也能保留未来宿主可能接受的 `model` 非空值，但观察到的占位值包括 `/dev/null` 和 `@ds-flash`，因此无法修复已报告的情况。已否决。
- **在 `agent` 缺失或为空时推断默认代理。** 能覆盖更多形状，但需要复制宿主 spawn 策略，结果也可能是 `seance`。扩展无法可靠得知宿主默认值。已否决。
- **模块默认关闭。** 默认保留推测执行，但不改设置的用户仍然会遇到失败。模块只改变宿主本来会拒绝的调用。已否决。
- **等待上游修复并记录规避方法。** 不增加新的组件行为，但当前宿主没有修复，用户会继续损失整批任务。作为唯一动作时已否决。

## 验收标准

1. 开启模块后，带有 `sourceSession`、`model` 或两者的非 seance 项在交给宿主派发时不再包含这两个字段，调用能正常派发，不再出现 `only accepted for the seance agent` 错误。
2. `seance` 项保留这两个字段，并继续遵循宿主对非空 `sourceSession` 的要求。
3. `agent` 缺失、为空、纯空白或非字符串的项保持不变，批量顶层字段也保持不变。
4. 只改变两个目标字段。其他参数、嵌套值、task schema 和工具描述保持原有行为。
5. 会话没有内建 `task` 工具或工具被替换时，模块保持未激活并报告原因。
6. 关闭 `taskArgsEnabled` 或包主开关后，在下次激活时恢复原生参数和行为。
7. `/qol` 报告模块状态和本次激活期间的改写调用次数。
8. 真实 OMP 会话展示成功派发并留下证据。未运行的情景记录为未验证。
9. 组件规格、README、调整文档和包描述说明模块、设置项、默认值以及推测执行的损失。
10. 现有 qol 模块的行为和设置不受影响。
11. 实施后由决定记录该选择，已消费的提案被移除。

## 风险

本提案接受 `## 分析` 中描述的推测启动有效损失。该损失和其余风险如下：

- **已接受的推测启动损失。** 只有在未注册生命周期处理器且任务审批为自动允许时，OMP 才会在完整调用结束前启动批量子代理。模块默认开启后，每个启用 qol 的会话都会在每次批量 task 调用中失去提前启动，包括不带这两个字段的调用。启用了推测读取的用户也会失去该优化。这是接受的代价，但仍会给批量派发增加延迟。
- **上游修复后仍付代价。** 如果后续宿主不再向非 seance 项暴露这两个字段，处理器仍然注册，推测执行代价会持续到模块被关闭或停用。
- **未来合法的 `model` 选择器。** 如果宿主以后允许普通代理通过该字段选择模型，清理会删除一个合法选择。
- **输入改写的后写生效。** 多个扩展为同一次调用返回 `input` 时，宿主采用最后一个结果。qol 的改写可能覆盖另一个扩展的改写，也可能被后注册的处理器覆盖。每个处理器看到的都是原始输入。
- **覆盖不完整。** 没有可用 `agent` 的调用保持原样，结果取决于宿主默认代理和原生校验；把字段放在批量顶层的调用也保持原样。用户可能把该模块理解为对所有 seance 字段错误的完整修复。
- **静默修正。** 模块隐藏模型的参数错误。`/qol` 计数器是唯一信号，提示词或 schema 的问题可能在无可见失败的情况下持续存在。
- **依赖宿主细节。** 清理依赖事件输入替换契约、schema 默认行为和内建工具来源。宿主对任一项的变化都可能让模块失效，或删除宿主现在接受的字段。
