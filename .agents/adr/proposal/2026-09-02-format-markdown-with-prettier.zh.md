# ADR 提案：使用 Prettier 格式化 Markdown

Decision owner: Ruokee
Draft writer: OMP GPT-5.6 Sol, Ruokee

[English](./2026-09-02-format-markdown-with-prettier.md) | 中文

## 动机

Prettier 已经能够为段落、标题、列表、引用、链接、代码块和表格等 Markdown 结构产生确定的格式。本仓库目前没有使用 Prettier 格式化 Markdown，这些布局仍由作者和编辑器决定。现有检查只覆盖基础空白和换行问题。

采用 Prettier 可以为仓库建立统一的 Markdown 基础格式。Prettier 原生表格格式化会为单元格补空格，使 Markdown 源文件中同一列的单元格等宽。在本仓库中，这些填充会降低 Markdown 源文件的可读性，也会占用不必要的 Agent 上下文。因此，配置后的格式必须采用不做等宽填充的紧凑表格，并统一处理中文与拉丁字母或数字之间的空格。

## 提议

采用 Prettier 作为仓库的 Markdown 格式化器。

仓库的 Prettier 配置必须：

- 对普通 Markdown 产生确定的格式；
- 使用不做等宽填充的紧凑格式处理 Markdown 表格；
- 统一处理中文与拉丁字母或数字之间的空格；
- 保留文档语义和代码围栏中的内容；
- 对已经格式化的输入再次运行时不产生变更。

仓库应提供应用该格式和检测不符合格式的受 Git 管理 Markdown 文件的方法。文档应说明如何格式化全部受 Git 管理的 Markdown 文件和指定文件。

实施时，格式化现有受 Git 管理的 Markdown 文件。清理只做机械格式变更，并与人工内容修改分开。任何有意保留的格式例外都必须明确，并针对具体仓库实例进行审查。

实施变更新增双语决定文件对 `2026-09-02-format-markdown-with-prettier`，并删除本提案文件对。

## 考虑过的替代方案

**继续手工维护 Markdown 格式。** 布局仍取决于每位作者和编辑器，仓库检查也没有统一的预期结果。

## 验收标准

- `proposal/` 包含这组完整的中英文文件，语言链接互指，语义一致。
- 本次提案变更在 Git 中只修改这组文件，不添加格式化配置或生成的格式变更。
- 仓库提供有文档说明的方法，使用 Prettier 格式化全部受 Git 管理的 Markdown 文件和指定 Markdown 文件。
- 格式化会产生不做等宽填充的紧凑 Markdown 表格，并统一中文与拉丁字母或数字之间的空格。
- 格式化保留文档语义和代码围栏中的内容。
- 重复运行格式化器时不产生变更。
- 仓库检查可以发现不符合配置格式的受 Git 管理 Markdown 文件。
- 历史清理只包含格式化器输出，以及明确列出并经过审查的例外。
- 完成实施后，仓库包含新增的双语决定文件对，不再包含本提案文件对，并通过全部仓库检查。

## 风险

Prettier 可能改写 Markdown 布局，让意外内容变更更难发现。批量处理全部文件前，应先审查有代表性的输出，再把生成的清理与人工修改分开。

全仓库清理会产生较大的 diff。如果混入无关内容变更，审查结果不再可靠。

格式化器会给贡献者环境增加运行时和依赖安装要求。开发文档必须写明所需环境和失败后的处理方法。
