# ADR 提案：统一 tk 使用模式

Draft writer: OMP anyrouter/gpt-6-astra

[English](./2026-09-11-align-tk-usage-patterns.md) | 中文

## 动机

[Skill 模式参考](../../../projects/tk/skills/tk-zh/references/patterns.md)与 [Skill 设计](../../../projects/tk/docs/design/skill.zh.md)使用不同的材料分类，也缺少共同的工作协议，说明何时建议模式、用户如何采用，以及采用后 Agent 持续维护什么。目录示例不足以说明如何保存跨日期活动、让调研主张持续对应证据，以及保留被大幅改版替代的设计。

[文档维护决定](../decision/2026-08-29-maintain-tk-documentation.zh.md)将 `scratchpad` 固定译为“临时记事区”。使用“草稿纸”作为模式中文名称与该选择冲突，需要形成完整的新决定。

## 提议

### 四种可选模式

为普通 Task 材料定义四种内置使用模式：

| 英文名称 | 中文名称 | 默认材料 |
| --- | --- | --- |
| Records | 记录 | `records/YYYY-MM-DD-topic.md` |
| Deep research | 深度调研 | `research/report.md` 和 `research/README.md` |
| Iterative design | 迭代设计 | `revision_<N>/README.md` 及该版本目录内的材料 |
| Scratchpad | 草稿纸 | `scratchpad/` 下的文件和子目录 |

一个 Task 可以组合采用，也可以都不采用。实验、正式决定、审查和验证证据仍可作为普通材料存在，不另列为内置模式。正式决定遵守项目指定的机制和位置。

模式约束 Agent 行为与普通材料的组织方式，不增加 tk 元数据、schema 字段、`extra` 约定、运行时状态、命令或自动目录生成机制。运行时、生命周期、工具路由和安装合同保持不变。

### 采用与共通维护

- 主动建议模式前，确认相应信号已经出现，并说明会增加哪些材料、以后维护什么。用户采用后，在 `TASK.md` 正文中简要声明，并链接已有入口材料。用户明确要求采用某种模式时，该请求就是采用授权，无需重复确认。
- 模式采用不替代创建 Task 或改变生命周期所需的授权。普通材料的日常创建和编辑沿用既有权限。删除、移动材料，或覆盖归属及含义不明的材料，须符合适用授权；采用模式不授予清理权限。
- 项目规则和已有材料结构可以覆盖默认路径。只为已经发生的工作创建材料，不预建空目录、不补造过去活动、不创建未来日期记录，也不为了匹配示例迁移已有 Task。
- `TASK.md` 保存当前事实、当前决定和重要入口。普通材料保存可复用的详细内容。WAL 即 Work Activity Log，通过 tk 追加简洁的持久事件摘要。三者通过链接配合，不整篇复制材料。

### 记录

当实质调查、实施、验证或决策活动已经发生在第二个本地自然日时，可以建议记录模式。同日任务以及仅计划以后继续的工作不满足主动建议条件。

只为有实质活动的本地日期维护记录。每份记录保存背景、动作、证据入口和当时结论。保留先前判断，后续更正写入后续材料，`TASK.md` 指向当前结论。稳定设计、参考资料和来源保存在各自的材料文件中，记录可以链接这些材料。记录不替代 WAL 或正式决策记录。

### 深度调研

工作要求收集、保存或交叉核验外部来源，或已经形成来源清单和来源材料时，可以建议深度调研模式。只读一个已知文档或回答普通 API 用法问题不满足该条件。

使用 `research/report.md` 保存结论，`research/README.md` 导航已有调研材料。计划、来源地图、主张核验及其他支撑材料按需增加。只有 Task 专属来源需要本地留存时，才创建 `research/sources/`。

持续维护来源来历与访问日期、关键主张对应的证据、来源之间的冲突、尚未核验的部分和结论适用边界。`TASK.md` 提供报告的直接入口。只有来源列表不足以说明证据支持了什么，未核验的推断须与事实区分。

### 迭代设计

出现两次以上相互替代的大幅改版、旧方案被整体推倒，或主要边界持续变化时，可以建议迭代设计模式。增量补充、措辞调整和普通评审修正不需要新版本。

每轮设计在 `revision_<N>/` 下自包含。其 `README.md` 说明背景、目标、主要方案和材料入口。只有新的大幅改版才创建下一轮，普通修正继续编辑当前版本。

被替代的版本保留当时状态。`TASK.md` 只把当前版本作为设计入口。需要解释取代关系时，将说明放在新版本中，不通过改写旧设计抹去先前判断。

### 草稿纸

尚未整理的片段、笔记、输出、小脚本或其他临时文件需要持久保存时，可以采用草稿纸。稳定结论应进入整理后的普通材料，无需留存的简短问答不需要草稿纸。

`scratchpad/` 内可使用任意文件和子目录，不强制模板、文件名或层级。有价值的内容稳定后，整理到合适的普通材料，`TASK.md` 只保留必要的当前结论和入口。失效内容须与当前事实区分。删除和移动遵守适用授权规则。

### 文档与决定归属

四个自包含 Skill 使用相同的材料行为：[tk](../../../projects/tk/skills/tk/SKILL.md)、[tk-zh](../../../projects/tk/skills/tk-zh/SKILL.md)、[tk-cli](../../../projects/tk/skills/tk-cli/SKILL.md) 和 [tk-cli-zh](../../../projects/tk/skills/tk-cli-zh/SKILL.md)。每个 Skill 保留完整的模式参考文件。同语言 tools 与 CLI 的参考内容相同，中英文语义对应。Skill 文件的引用留在各自组件内。

[Skill 设计](../../../projects/tk/docs/design/skill.zh.md)负责 Agent 行为合同，[术语表](../../../projects/tk/docs/design/GLOSSARY.zh.md)负责四种名称及其含义，[文档设计](../../../projects/tk/docs/design/documentation.zh.md)负责译名维护，[验证合同](../../../projects/tk/docs/design/validation.zh.md)负责可观察验收。这些合同及其语言对应页与 Skill 参考一并维护。

反转[文档维护决定](../decision/2026-08-29-maintain-tk-documentation.zh.md)中 `scratchpad` 的固定译名选择，中文统一为“草稿纸”。完整的新决定应纳入上述模式合同，并保留原决定及其变更中所有其他仍有效的规则，包括公开文档集合、主题归属、最终状态写法、双语维护、Skill 自包含、组件选择和自定义 CLI Skill 根目录的文档覆盖，以及 README 导航。关系链接与现行引用应将新决定标识为当前权威。

## 考虑过的替代方案

无

## 验收标准

- 四份 Skill 参考及归属公开文档恰好定义上述四种模式。每种模式都说明主动建议的信号、反例、默认材料和持续维护行为。其他工作可以保留普通材料，无需成为额外模式。
- 场景核验覆盖第二个本地自然日的活动与同日任务、来源收集和交叉核验与单篇文档查询、大幅设计改版与普通修正、临时片段与稳定结论。
- 采用前，Agent 说明建议，不在 `TASK.md` 中声明已经采用模式。明确请求可直接采用。项目自己的目录结构仍可使用，不强制迁移或创建空材料。
- 记录保留先前判断，`TASK.md` 指向当前事实，WAL 保持为 tk 管理的简洁活动历史。调研主张能够追溯到证据及不确定边界。被替代的设计版本保持自包含，仅当前版本作为设计入口。
- 草稿纸维护保留有用内容，并区分失效材料。任何模式都不额外授予删除或移动材料、创建 Task、改变生命周期的权限。
- 同语言 tools 与 CLI 的模式参考内容一致，两种语言描述相同行为，每个 Skill 自包含。固定中文译名为“草稿纸”，新决定保留其余有效文档规则，关系链接和入站链接有效。
- 仓库检查通过，场景验证通过四个 Skill 分别检查四种模式。Markdown 格式检查和 Rust 测试不能单独证明 Agent 行为正确。变更不增加运行时或元数据机制。

## 风险

四份自包含 Skill 参考和双语公开合同需要分别维护。如果只更新部分文件，可能再次出现已有的分类偏差，使 Agent 遵循的采用或维护规则与用户阅读的规则不一致。应在同一变更中更新相关文档，并在审查时比较语义。
