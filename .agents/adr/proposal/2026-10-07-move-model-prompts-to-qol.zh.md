# ADR 提案：将模型提示词规则迁入 QoL

Draft owner: Ruokee
Draft writer: OMP

[English](./2026-10-07-move-model-prompts-to-qol.md) | 中文

## 动机

将模型提示词规则从 `@ruokee/omp-system-prompt` 迁入可独立开关的 QoL 模块，并将 system-prompt 标记为即将弃用。

只需要模型规则的用户目前也必须安装 system-prompt 组件，尽管规则追加并不依赖其模板策略。QoL 已提供原生插件设置、独立模块开关、故障隔离和状态报告。

维护者观察到，近期 OMP 更新大幅精简了内置提示词，并提供了模板支持，降低了独立 system-prompt 扩展的必要性。这是即将弃用状态的动机，不表示原生模板能替代模型匹配与逐轮规则刷新，也不为这项观察指定某个上游版本。

## 提议

### 需要反转的决定

以下有效条款不能与本选择同时成立：

| 现行决定 | 有效条款 | 新选择与冲突 |
| --- | --- | --- |
| [在系统提示词扩展中追加模型范围的提示词规则](../decision/2026-09-14-add-model-prompt-rules.zh.md) | system-prompt 拥有规则；文件存在即启用，没有开关；扩展内部两个 handler 先处理模板再追加规则；未知 frontmatter 键使文件无效 | 规则只由 QoL 提供，独立开关默认关闭；提示词组合跨越组件边界；额外顶层元数据被忽略。归属、启用方式、handler 所属位置与顶层校验不能同时保留两种含义。 |
| [仅通过组件模板渲染系统提示词策略](../decision/2026-10-04-use-system-prompt-template-only.zh.md) | 模板路线职责包含追加模型规则的第二个 handler | system-prompt 只保留模板职责。规则追加归 QoL，不再是 system-prompt 的 handler。 |
| [在独立等待入口上维护 OMP 体验调整](../decision/2026-10-04-use-standalone-qol-wait.zh.md) | QoL 只限于已有行为调整 | 模型规则成为一项新增 QoL 调整。只扩展到此能力，不纳入外部工具守卫或无关宿主行为。 |

反转只改变这些冲突选择。其他合同，包括有效的 `Changes` 条款及其证据边界，继续有效。完整后继决定必须在各自范围内保留它们；历史宿主观察不能证明迁移后的能力已验证。

### 归属、设置与迁移

QoL 无需 system-prompt 或选定模板即可提供模型规则。原生 boolean 设置 `modelPromptsEnabled` 默认 `false`，受既有总开关 `enabled` 控制。任一开关关闭时，不发现、读取或追加规则，也不诊断未使用的规则文件。

沿用 OMP 插件设置的权威来源、全局值与项目覆盖，以及每次激活读取一次的快照。配置修改需要重启 OMP；同一进程内切换会话不刷新。模块 boolean 无效只停用模型规则。未知设置键、非对象根或设置 getter 失败沿用既有整体拒绝行为。设置诊断只说明键与规则，不回显取值。

`/qol` 显示有效开关、模块状态和不生效原因，不启动模型轮次，也不泄露规则正文。规则模块已注册不表示当前模型必然命中或每个文件均有效；文件故障不永久停用模块。

移除 system-prompt 的规则发现与追加能力，不保留转发入口、别名或兼容垫片。规则文档保留现有位置，无需改写。安装、协调组件更新、设置修改及实际扩展加载顺序由用户负责；两组件都不改写用户配置、模板、规则、已安装宿主文件或安装状态。

同时启用两个更新后的组件时，实际扩展加载顺序必须为 system-prompt 在前、QoL 在后，保留先处理模板再追加规则的结果及独立失败边界。迁移指引必须说明这一要求，不能把安装命令的先后当作保证。两组件不重排扩展，也不声称优先于后续 handler。先更新共同安装的 system-prompt，再启用 QoL 规则，避免旧规则 handler 再次追加。

### 在 QoL 保留的规则合同

保留现行模型规则决定和 [projects/omp-system-prompt/README.zh.md](../../../projects/omp-system-prompt/README.zh.md#模型提示词规则) 中的发现、匹配、组合、刷新和失败合同，只改变上述归属、开关、handler 所属位置与顶层键语义。QoL 自身双语文档须完整承载所得公开合同，不依赖 system-prompt 组件。

- 从宿主解析的当前 profile 用户 agent 目录和当前 turn 项目 agent 目录读取 `model-prompts`。不搜索祖先或资源根目录。只读取直接子项中非隐藏、以小写 `.md` 结尾的普通文件，不递归，不跟随文件符号链接。目录缺失视为空集。
- 每个目录按 JavaScript 文件名字符串顺序排序，读取完成顺序不改变结果。用户正文在项目正文之前。同名文件互不遮蔽；不同来源的相同正文仍分别贡献，不按文件名或内容去重。
- 读取 UTF-8 Markdown，允许开头 BOM，分隔行必须恰好为 `---`，接受 LF 和 CRLF。`match` 仍是必需的非空数组，条目是单键对象且值为非空白字符串。`exact` 与 `provider/id` 相等，`model` 与完整裸 id 相等，包括其中的 `/`；`contains` 是 `provider/id` 的字面子串；`regex` 是不带 flags 的 JavaScript 正则。匹配区分大小写，按文本比较；条目为或关系，一个文件只应用一次。不增加别名、角色、家族、显示名、传输名、思考后缀、通配符或模型列表解析。
- 忽略额外顶层 frontmatter 键，永不注入。匹配条目内未知键或多个键仍使整个文件无效。无效 YAML、缺失或畸形分隔行、无效 `match`、无效条目或值、无法编译的正则及空白正文均在第一个失败点跳过文件，不部分应用。
- 每个匹配文件贡献一个系统提示词块，内容恰好为闭合分隔行及其行尾之后的正文。排除 frontmatter 和 BOM；保留标题、空行、LF、CRLF、缩进、注释、模板形似文本和末尾换行。不包装、裁剪或重新渲染。保留当前 turn 传入块的内容和顺序，不修改数组，不将规则写成消息或历史。
- 每个受覆盖 turn 重新读取，并按当前有效模型匹配。新增、编辑、删除和修复在下一 turn 生效，无需重启。不用旧正文恢复当前不可读或无效文件。没有模型、没有规则或未命中时保持传入提示词原样，不报告未命中错误。保留宿主基础提示词与重建边界，连续 turn 不累积规则块，轮内重建不重复追加；不通过正文去重掩盖该合同。
- 文件失败只影响该文件，目录失败只影响该目录。handler 意外异常保留传入提示词。规则失败不停用 QoL 其他模块，不撤销其他组件已完成的提示词处理。诊断使用固定原因和可定位的作用域相对来源，按会话、来源与原因去重；交互时使用宿主通知，否则使用宿主日志。不暴露规则正文、绝对路径、原始错误、正则源码或对话内容。

规则仍是 Agent turn 级指令，覆盖运行公开 `before_agent_start` 钩子的普通主会话和普通子 Agent turn。每个子 Agent 使用自身有效模型，保留角色、独立块和宿主协议。不为 plan-mode 子 Agent、Handoff、标题生成、分类或其他绕过钩子的请求增加入口。临时旁路请求沿用宿主对当前 Agent 提示词的处理。临时模型切换、回退和单次 Provider 请求不新增独立刷新保证。

保留现有信任和执行边界：项目规则可以成为系统指令，JavaScript 正则没有沙箱或执行超时，正文不增加大小或额度限制。不增加信任门槛、规则缓存或配置热刷新。OMP 提供等价模型指令能力后，复核匹配维度、提示词组合与块顺序、刷新时机和发现约定，再决定本地能力保留、收窄或移除。

### system-prompt 即将弃用

在组件说明和仓库入口将 system-prompt 标记为即将弃用，并说明模型规则归 QoL。不描述为已移除或不可用。保留模板、Delivery、页脚处理和当前维护。不设移除日期、停止维护政策、自动卸载或用户文件删除。

[只用组件模板的决定](../decision/2026-10-04-use-system-prompt-template-only.zh.md) 除模型规则 handler 外继续有效：可选宿主模板选择与原生优先级；自有静态骨架识别；未识别输入静默空操作；模板与不透明数据逐字保留；逐轮 `renderDelivery`、其默认和 fail-open 行为，以及外来块冲突处理；独立有界失败；幂等处理，包括在已转换页脚上改变 Delivery。宿主模板读取失败仍由宿主负责。

页脚修正保留已知主 Agent 与子 Agent 尾段、含糊边界拒绝和既有条件式中性归属注释。该注释及必要分隔符仍是逐字保留的唯一例外，只在有效页脚无加载指引、转换移除了恰好已知的 critical 尾段、append 以完整已知 critical 块开头时加入。保留其位于不透明数据之外的有效结构位置、`<project-context>` 块起点和数组位置，以及静态前缀缓存边界。不使用进程内归属缓存或新增设置。文本识别不是来源证明或安全边界。

### 不变的 QoL 与宿主合同

QoL 原有全部模块保留行为、设置键、默认值、范围、状态报告、激活快照、故障隔离和宿主职责。包括等待与恢复边界、进程级补丁归属和释放规则、原生重放、缓存请求身份与证明要求，以及 [QoL 决定的变更](../decision/2026-10-04-use-standalone-qol-wait.zh.md#变更) 中有效的 `standard`/`hooks` 缓存模式合同。新增模型规则不放宽既有归属或原生接口替换义务。

两组件保持自包含，使用未修改的宿主与公开扩展接口，依照[共同 OMP 下限决定](../decision/2026-10-04-raise-omp-host-floor.zh.md)保留共同维护下限 `18.5.0`。不受限的宿主 peer 仍是元数据，不是运行门槛。不增加维护上限或旧宿主兼容路径。源码分析、自动检查和真实宿主观察继续分开；未运行场景仍为未验证。

## 考虑过的替代方案

无

## 验收标准

- 显式启用后，仅 QoL 即可在受覆盖主会话和普通子 Agent turn 将命中正文追加到 Provider-facing 系统提示词，无需组件模板。默认关闭与任一开关关闭均不读取、追加或诊断未使用规则。`/qol` 准确报告状态，不运行模型或泄露规则。
- 既有文件保留发现、顺序、匹配、正文逐字、逐轮刷新、不累积和局部失败行为。额外顶层元数据被忽略，未知匹配条目键仍拒绝文件。配置重启语义、模块 boolean 无效与设置整体拒绝保持区分。
- 更新后的 system-prompt 没有规则 loader 或转发入口。按指引的实际加载顺序，两组件保留模板、Delivery、页脚与独立失败行为，只有 QoL 追加规则。后续 handler 保留宿主赋予的权力。
- 两个自包含组件和仓库文档以中英文描述一致的归属、设置、覆盖、迁移与信任边界。受影响的项目 Spec 保留无关要求，完整后继 ADR 保留有效的不冲突条款及证据边界。
- 公开说明将 system-prompt 标记为即将弃用，引导模型规则用户使用 QoL，同时保留剩余能力和维护，不设删除日期，不自动改变用户文件或安装。既有 QoL 合同与共同宿主下限不变。
- 真实宿主观察注明版本和实际运行条件，区分 Provider-facing 证据、handler 返回值和状态输出。历史证据及未运行路径不描述为迁移后功能验证。

## 风险

- 新 QoL 规则模块与旧 system-prompt 安装共存时，同一文件可能追加两次。默认关闭和协调更新指引降低风险，但不使混合版本兼容。
- 实际加载顺序错误时，system-prompt 可能识别或改写模板形似规则正文，而不是在其处理后追加。指引中的顺序是要求，不是自动保护，也不保证免受后续扩展影响。
- 默认关闭的迁移会使只更新 system-prompt、未显式启用 QoL 能力并重启 OMP 的用户停止获得规则注入。保留路径和说明开关避免文件迁移，但不保留过去的文件存在即启用行为。
