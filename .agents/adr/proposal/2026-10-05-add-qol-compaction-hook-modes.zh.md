# ADR 提案：增加 QoL 压缩钩子模式

Draft owner: Ruokee
Draft writer: OMP

[English](./2026-10-05-add-qol-compaction-hook-modes.md) | 中文

## 动机

为 QoL 的远端压缩缓存对齐增加通用钩子模式。

普通请求使用宿主完成的上下文投影，远端压缩却可能在准备共享历史时跳过该投影。合法的插入、重排和上下文恢复因此可能使现有整条请求护栏拒绝对齐。护栏正确保护了请求，但共享缓存前缀仍然不同。

[远端压缩缓存决定](../decision/2026-10-04-use-standalone-qol-wait.zh.md#远端压缩缓存对齐)要求确认在线参照、明确归属、不可变的操作参照、整条请求等价及原生投机压缩。钩子支持必须扩展这条边界，不能绕过它。[组件独立决定](../decision/2026-08-24-keep-components-self-contained.zh.md)也禁止依赖其他扩展的文件或私有状态。

## 提议

### 提供两种处理模式

在原生 OMP 插件设置中加入 `compactionCacheMode`，取值为 `standard` 和 `hooks`，默认 `hooks`。

- `standard` 保留现有对齐及已识别的宿主差异。未识别的钩子差异使整条请求保持原生形式。
- `hooks` 额外使用宿主完成的上下文投影，但必须证明它与已确认在线请求及原生共享历史的对应关系。没有相关钩子时也执行通用对齐，不要求安装配套扩展。

两种模式都不启用缓存模块。默认关闭、显式配置提供方、受支持的所属会话 API 边界及其他设置不变。设置每次激活读取一次，重启生效。非法模式只使缓存模块无效，诊断说明键名和规则，不暴露值。有效模式参与 owner 兼容判断，并由 `/qol` 报告。

### 将投影归属与请求归属统一

观察所属宿主 runner 的原始上下文及完成后的结果，不重新运行处理器，不读取其私有状态。只有证明投影的原生编码对应实际原样发出的在线 payload，才能接受该投影。序列化仍由宿主负责；本组件不得维护第二套 serializer，也不得按扩展名称、正文前缀或组件文件识别扩展。

原生操作在明确的会话、模型和根信号归属下固定已确认参照及对应投影。新在线工作可以更新最新参照，但不能改变旧操作的快照。认证和传输重试保留原快照。相似 payload、时间、缓存键和路由标识不构成归属依据。

复用投影前缀前，先证明原生共享历史的对应关系，再验证整条候选请求。保留新增普通及工具历史、压缩专属尾部与触发项、opaque 数据、显式工具选择、缓存键、路由和模型策略。对应关系未知或存在任何未识别差异时，整条原始请求保持不变，不能只修复其中一部分。

### 保留原生生命周期与组件边界

缓存对齐不得注册 `session_before_compact`，不得隐藏其他处理器或绕过宿主否决。原生手动、自动和投机准备、等待、重试、回退、结果校验、历史替换及采用仍由宿主负责。其他独立启用的模块保留自己的钩子和设置。

投影观察限定于所属 runner 和原生操作生命周期。只保留最新已确认在线参照，以及通过仍存活的原生操作信号可达的参照，不保留无限增长的操作历史。取消、身份或上下文变化、激活冲突、会话导航、包装丢失及接口不可用都必须阻止陈旧改写。shutdown 只还原仍由自己持有的函数及其原始属性形态。

维持 [projects/omp-qol/README.zh.md](../../../projects/omp-qol/README.zh.md#兼容性) 声明的宿主维护下限和包边界。源码检查不代表运行验证。实际宿主覆盖与 provider 缓存测量分别记录。等价且受维护的原生准备接口出现后，优先替换适配。

本提案兼容扩展当前远端压缩缓存决定，其拒绝和等价规则继续有效，不需要反转现行决定。实现时应在该决定的 `Changes` 中记录新增模式和投影归属，同步组件规格及双语公开文档，不改变无关模块合同。

## 考虑过的替代方案

- **只保留当前对齐。** 比较原生共享历史与投影后的在线请求时考虑过。它保持安全，但继续拒绝合法插入、重排和恢复，不能提供要求的钩子处理能力。
- **为压缩重新运行公开的普通消息准备路径。** 检查宿主准备接口时考虑过。它能取得投影，却会再次调用处理器，可能读取比操作已确认在线参照更新的状态。观察原先完成的投影可以避免额外副作用和陈旧参照错误。
- **等待受维护的共享准备接口。** 评估宿主相关观察时考虑过。它免去维护当前 runner 包装的成本，但当前宿主中的差异继续存在。这类接口仍是替换适配的条件。

## 验收标准

- 两种模式及默认值可从原生插件设置和 `/qol` 观察；非法配置仍只影响缓存模块。
- 没有相关钩子时，两种模式保留通用对齐，不新增消息，不要求其他组件。
- 通用插入、重排和上下文恢复场景中，`standard` 拒绝未知差异，`hooks` 只对齐已证明的共享前缀。新增历史和 opaque 内容保持不变。
- 投机操作在更新的在线工作和原生重试期间保留原投影；有效结果经原生生命周期采用，不额外发送替代请求。
- 对应关系未知、传输未确认、归属冲突及陈旧或已取消操作都使整条请求保持原生形式。生命周期清理不能覆盖其他 owner 的函数。
- 实际 CLI 证据区分请求一致性、原生压缩行为及真实 provider 缓存收益；合成用量不作为缓存测量。

## 风险

- 宿主 runner 或编码变化可能使投影观察失效，对齐因而不可用。保持原生请求，报告有界原因，并维护分版本运行证据，不能放宽等价条件。
- 对应关系或归属判断错误可能将另一操作的投影上下文拼入请求，造成历史丢失或无关上下文泄露。替换任何字节前，必须具备明确身份、传输确认、不可变操作参照及完整校验。
- 原始与投影上下文快照会在操作存活期间额外保留对话数据。将保留范围限制为最新在线参照及原生信号生命周期，并在归属结束时释放观察。
