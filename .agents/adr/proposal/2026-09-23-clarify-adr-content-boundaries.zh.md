## 动机

本提案通过要求首句独立说明目标、单列可选分析、限制实现细节，以及在保留原意的前提下清理现有记录，降低 ADR 的审查负担。

读者应能辨认需要批准的选择及其理由，而不必审查组件的全部实现。正常演进不应仅因旧记录把文档数量、内部机制或阶段性不做事项固定为永久约束，就必须反转一份范围很广的决定。

## 分析

[ADR 指南](../README.zh.md)已排除进度日志和复制的实现清单。[tk 文档决定](../decision/2026-09-11-align-tk-usage-patterns.zh.md#主题归属)也将详细契约交给所属页面维护。通用指南没有解释何种技术细节对决定必不可少，也未要求动机首句独立说明所做的工作。

一次反转可以符合现行规则，同时暴露原承诺过窄的问题。[初始 QoL 决定](../archived/2026-09-20-add-omp-qol.zh.md#压缩实验及其替换条件)在进程已登记其他所有者时停用进程级调整；其[后继决定](../archived/2026-09-21-reuse-a-matching-compaction-patch.zh.md#压缩实验及其替换条件)允许匹配的激活保留已有补丁，而不成为另一所有者。这确实改变了一条明确规则。另一例是 [tk 文档后继决定](../decision/2026-09-11-align-tk-usage-patterns.zh.md#动机)，它将固定译法的变化作为重述整套文档政策的冲突依据。术语内容的归属和记录范围，使反转的范围超过了该译法变化所需的范围。

应分别判断新选择是否违背已采纳规则，以及原规则是否需要写到这样的细节程度。反转更少本身不能证明决定更好。既有明确约束在被正式改变前仍然有效。

## 提议

### 先说明目的，必要时再分析

提案和决定的动机首句必须说明对象及具体问题、拟作出的变更或目标，不依赖标题、链接或后文才能理解。新增能力不必被包装成缺陷。反转提案开头说明拟作出的改变，后继决定则说明它记录的完整选择。

允许在 `## Motivation` 之后、`## Proposal` 或 `## Decision` 之前紧接可选的 `## Analysis`。中文在 `## 动机` 后紧接 `## 分析`。没有实质分析时省略，保留其他必需章节。

分析只包含影响选择的观察、证据、约束、推导和不确定性，不能成为实施计划或调研笔记的副本。动机保留解释为何需要这项选择的上下文；两者不相互重复，也不重复替代方案章节。

### 在 ADR 中保留选择及必要契约

ADR 记录一项完整且连贯的长期选择、理由、必要边界与归属、重要公开承诺，以及重大的兼容、安全、成本和失败后果。其范围不必覆盖整个组件，也不必细分到每个参数单独建档。

仅当省略某项技术细节会妨碍读者理解选择或重要取舍，或丢失必须保留的契约时，才将它写入 ADR，并只写必要片段。配置权威、身份不可变性或进程级副作用，即使需要具体标识符说明，也可能是必需内容。

完整的 API 与配置表、schema、命令参考和持续维护的清单，归所属公开文档。内部函数名、算法步骤、逐文件修改、执行计划、测试命令与验证日志，归实现文档、代码、测试或任务材料。验收标准描述外部可观察的结果，不列测试操作步骤。ADR 链接可访问的公开契约，不把忽略的任务材料作为公开依据。

移走一条有约束力的条款，不等于取消它，必须保留其含义和可访问的引用。历史记录应保留足以解释当时选择的原有细节，指向持续变化的当前文档不能替代历史契约。

### 避免无意形成永久约束

区分有意封闭的协议、归属规则或安全边界，与示例和可增长的清单。优先链接清单的所属页面，而不固定数量或穷举文件树。确实需要封闭集合或禁止事项时，说明受保护的边界和理由。

当前范围限制或首个版本不需要的选项，不自动成为永久禁令，应在起草决定时说明区别。不能事后把既有禁令降格以绕开它，也不能仅为让文案可扩展而预建抽象或配置。

防御规则应针对实际操作及其危害。普通校验、损坏修复、生命周期变化和重复激活可能需要不同前提。保留身份、权限和副作用保护，不用与保护边界无关的全面限制取代它们。

### 反转前说明冲突

反转提案必须指出有效条款、新选择，以及二者为何不能同时成立。代码量、增加功能、增加宿主依赖或文件改名，本身都不足以证明需要反转。

无冲突新增继续使用带日期的 `Changes` 或 `变更`；值得独立记录时链接另一份决定。纯表达维护没有形成新选择，不需要反转。完整的后继决定保留该决定范围内仍有效的规则，不复制组件的实现规格。

### 清理全部现有记录并保留历史

将这些规则应用到清理开始时已有的每一组中英文 ADR，包括活跃提案、当前决定、归档决定和被拒绝提案。改善开头，必要时分离分析，删除或迁移不必要的实现材料。逐组核对，不抽样。

保留记录中的选择、理由、约束、不确定性、历史能力范围、原始作者、日期和反转关系。不将旧记录改成今天的功能说明，不通过编辑批准、拒绝或实施其他提案。如果删除细节会改变有约束力的承诺，除非另行明确的契约变更获准，否则保留。本次清理不重写 Git 历史。

清理需要对 [ADR 机制决定](../decision/2026-09-02-establish-adr-mechanism.zh.md#格式与双语维护)作出一次性例外。该决定规定归档决定在修复关系和事实链接后冻结，被拒绝提案同样冻结。结构与措辞调整即使不改变含义，也超出了这些许可。因此，本提案明确将该决定列为反转对象。后继决定必须保留其余有效机制规则，加入上述编写规则，并写明例外范围。冻结记录在本次清理之外继续冻结，批准提案不构成随意重写它们的一般许可。

[动机决定](../decision/2026-08-22-use-motivation-heading-in-adrs.zh.md)通过无冲突的 `变更` 记录首句要求。双语指南和术语表应一致描述形成的政策。只有机制替换需要生命周期与关系变更，其他记录保留原状态。独立的 [ADR 维护 Skill 提案](./2026-09-03-add-adr-maintenance-skill.zh.md)保持未批准状态，本提案不引入 Skill、元数据模型或专用检查器。

无

## 验收标准

1. 两种语言的指南均要求动机开头可独立理解，并在提案和决定的动机后紧接可选分析。
2. 指南明确区分必要的决定契约与实现材料、封闭约束与可增长清单、有依据的冲突与无冲突新增。
3. 全部现有 ADR 配对逐一按这些规则接受语义核对。其选择和历史仍可追溯，无法安全删除或迁移的约束性细节仍被保留。
4. 机制后继决定明确记录冻结材料的一次性例外，并保留其余有效规则；动机决定记录兼容的细化要求。关系链接和当前权威引用保持有效。
5. 两种语言表达相同的义务、例外和历史含义。清理不改变组件行为，不批准无关提案。

## 风险

- 将约束性细节误当成附带信息，可能静默削弱已采纳的保证，或抹去历史选择的理由。迁移到持续变化的文档，也可能使旧选择无法还原。删除这些文字前，必须保证语义保留且历史上下文仍可访问。
- 作者可能将清单与契约的区别理解为忽略明确限制的许可，或将冻结记录的例外理解为持续许可。反转仍须指出具体冲突，例外只适用于本次清理。
