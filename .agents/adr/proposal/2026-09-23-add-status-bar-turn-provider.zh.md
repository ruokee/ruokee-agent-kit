# ADR 提案：为 OMP 状态栏增加轮次指标

Draft owner: Ruokee
Draft writer: OMP DeepSeek V4.1 Flash

[English](./2026-09-23-add-status-bar-turn-provider.md) | 中文

## 动机

用户需要看到本次会话发起了多少次模型请求。把它和 widget 已经报告的 token 读数放在一起看，用户就能判断这次会话的 token 效率，及时发现消耗明显高于其他轮次的低效率调用，为后续调整 OMP 的用法提供参考。

widget 通过已花费的 token、缓存命中率和上下文用量报告消耗，但没有任何读数说明这些消耗来自多少次模型请求。

## 分析

由会话活动推导出的读数只能作为内置 provider 发布。公开的 provider 契约只给实例提供它的 options、它的配置、一次发布调用和受管定时器；它不携带会话数据和事件，宿主也只对内置 provider 绑定会话数据源。为公开契约增加这样一条通道，比增加这个读数本身的改动更大。

宿主向扩展报告每一轮，并同时给出响应是如何结束的，因此 Package 可以在不依赖上游改动的情况下统计成功响应。

[建立 widget 的决定](../decision/2026-09-05-use-omp-status-bar-widget.zh.md)把各 provider 的契约交给 Package 的使用文档，那里面已经列出了内置 ID、它们的 options 和颜色，而决定本身把内置 ID 固定为恰好六项。

## 提议

### 增加轮次指标

增加一个内置 provider，显示本次会话中有多少次模型请求得到了成功响应。

数值为会话累计值。它跨提问、跨 agent run 增长而不重新开始，并在会话被恢复或切换后保持。它始终反映会话所持有分支的历史，因此把会话回退到较早的位置或放弃一次尝试会让它下降，这是预期读数。只有成功的响应才使它前进；失败的请求、被中断的响应，以及在模型调用前就被拦下的请求都不改变它。

widget 渲染固定标签 `Turn`、一个空格和数值。有进行中的轮次时对数值加强，其余情况变暗，数值为零时不渲染内容。

provider 把该计数作为一项独立读数发布，不据此再推导任何指标。

### 替换封闭的内置 ID 列表

反转[建立 widget 的决定](../decision/2026-09-05-use-omp-status-bar-widget.zh.md)。

有效条款是其中「提供内置指标 Provider」一节的首句，它把内置 ID 固定为恰好六项。

后继决定改为记录：Package 提供内置指标 provider，并以链接指向 Package 使用文档，由该页面持有当前清单，而不是在决定里固定 ID 列表或它的数量。该条款承载的范围边界保留：不提供金额、cost 或 premium request 读数，也不保留旧的 `tokens` 别名。

二者不能同时成立。该条款不接受固定列表之外的内置 ID，而轮次指标增加了第七个内置 ID，因此这项新增无法作为对决定的更新来记录。

## 考虑过的替代方案

无

## 验收标准

1. widget 提供一个内置 provider，显示本次会话中有多少次模型请求得到了成功响应，渲染形式为 `Turn <数值>`。
2. 数值只对成功的响应前进。失败的请求、被中断的响应，以及在模型调用前被拦下的请求都不改变它。
3. 数值为会话累计值。它不在提问边界或 agent run 边界重新开始，并在会话恢复或切换后反映该会话所持有分支的历史。
4. widget 在有进行中的轮次时对数值加强，其余情况变暗，数值为零时不渲染内容。
5. 两种语言的文档把该指标纳入内置清单，并说明它的含义、显示形式和数值在跨会话时的行为。
6. Package 的行为测试断言计数规则、显示状态和会话行为。
7. 后继决定以链接指向使用文档，由该页面持有内置清单，因此此后增删内置 ID 是清单变更，而不是反转决定。
8. 该指标在声明的 OMP peer 范围内可用，不需要上游改动。

## 风险

数值在一次会话绑定前后可能相差一。绑定按会话已经记录的历史计数，而紧接在它之前结束的那一轮可能尚未记录，因此同一会话可能出现相差一的两个数值。
