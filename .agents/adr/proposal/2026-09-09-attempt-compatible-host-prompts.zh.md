# ADR 提案：移除版本限制后尝试替换提示词

Decision owner: Ruokee
Draft writer: OMP GPT-5.6 Sol

[English](./2026-09-09-attempt-compatible-host-prompts.md) | 中文

## 动机

当前扩展在检查已渲染系统提示词之前，会拒绝除 OMP `18.1.11` 之外的所有版本。OMP 新版本仍可能提供扩展能够转换的输入，但版本门禁会直接停用扩展，使默认提示词继续生效。

扩展在生成替换结果前，已经校验完整目标结构。结构校验才是有效的兼容性检查。版本号本身不能证明已渲染输入不兼容。

本提案反转[当前 OMP 系统提示词扩展决定](../decision/2026-09-07-add-omp-system-prompt.zh.md)中的精确运行时版本门禁。

## 提议

只要宿主加载扩展，且扩展能够调用所需的公开 API，就尝试替换提示词。实测 OMP 版本只构成验证证据，不限制激活或安装。

每个 turn 执行现有的结构识别、设置读取、Skill 元数据匹配、输出构造和输出校验。全部成功时应用自有提示词。操作抛出异常或输入未通过结构检查时，保持传入提示词不变，并通过现有会话诊断通道报告简短原因。

删除 `unsupported-version` 运行时失败原因。不得检查宿主版本来决定是否激活、转换、告警或回退。OMP 宿主包作为 peer dependency 声明，但不设置版本限制。

## 考虑过的替代方案

### 保留精确运行时版本门禁

这是当前行为。它使扩展在任何 OMP 新版本发布后都无法尝试结构兼容的提示词，因此该方案不符合兼容要求。

### 维护已审查版本白名单

白名单仍会在每次未列出的发布后，先于实际输入检查停用扩展。它重复相同的故障模式，还增加了维护工作。

## 验收标准

- OMP 新版本由正常转换流程处理，不再被拒绝为 `unsupported-version`。
- 不检查宿主版本，结构兼容的提示词仍会被替换。
- 结构不兼容的提示词保持不变，并输出现有的有界替换诊断。
- turn 处理中出现意外异常时，传入提示词保持不变，并发出有界诊断，不阻止模型请求。
- 公开文档将实测 OMP 版本列为验证证据，不定义支持版本边界。
- 组件检查与仓库检查通过。

## 风险

后续宿主可能保留可识别的提示词形状，却改变公开 API 或扩展保留的区段语义。结构检查可能遗漏这种语义变化，随后扩展会应用错误替换。真实宿主检查只能为实测版本提供证据，无法排除未实测宿主上的同类故障。
