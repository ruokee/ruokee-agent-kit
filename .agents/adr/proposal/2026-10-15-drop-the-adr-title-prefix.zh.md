# ADR 提案：去掉 ADR 标题前缀

Draft owner: Ruokee
Draft writer: OMP

[English](./2026-10-15-drop-the-adr-title-prefix.md) | 中文

## 动机

去掉每个 ADR 标题里的类型前缀。

决定[厘清 ADR 内容边界](../decision/2026-09-23-clarify-adr-content-boundaries.zh.md)要求提案标题以 `# ADR proposal: ` 或 `# ADR 提案：` 开头，决定标题以 `# ADR decision: ` 或 `# ADR 决定：` 开头。每个 ADR 文件都带有其中一个前缀。

生命周期目录已经说明了记录的类型和状态：`proposal/` 与 `rejected/` 放提案，`decision/` 与 `archived/` 放决定。前缀在标题里重复了路径已经写明的信息，它带的冒号还与仓库的标题规则冲突，那条规则要求标题不写标点。这些文件里还有标题规则禁止的其他标点，出现在标题与小节标题上，本次清理一并改写。

改动这条措辞等于改动现行决定的一个条款，仓库要求用反转来改：反转该条款、把被反转的决定归档，并由后继决定连同新标题形式一起承接继续有效的规则。

## 分析

没有任何受跟踪文档链接到前缀生成的锚点。在受跟踪的 Markdown、脚本与源码中检索 `#adr-decision-`、`#adr-proposal-`、`#adr-决定`、`#adr-提案` 均无结果。因此去掉前缀不会改变任何入链。

元数据块的位置、语言链接的落点与章节顺序对两种记录类型遵循同一模式，去掉前缀后四个生命周期目录共用一种标题形式。

一个活跃提案[增加 ADR 维护技能](./2026-09-03-add-adr-maintenance-skill.zh.md)在前缀清理时一并改写。

## 提议

ADR 标题在两种语言里只写主题：英文 `# <title>`，中文 `# <标题>`。类型与状态由目录说明。

改动包含四部分。

1. `.agents/adr/README.md` 与 `README.zh.md` 不再要求前缀，提案与决定的头部示例以 `# <title>` 与 `# <标题>` 开头。
2. 后继决定替换被反转决定的标题条款，并保留它继续有效的规则：术语、提案流程、记录格式、编写规则、决定生命周期、维护规则，以及 `## Changes` 下已记录的两条更新。
3. 反转按 ADR 规则进行：后继决定写 `Reverses`，被反转决定补 `Reversed by` 与带归档日期的 `Archived:`，中英两份文件在同一改动里移入 `archived/`。
4. 每个 ADR 标题的中英两份都去掉前缀，并清理这些文件里标题规则禁止的其他标点，标题与小节标题一并处理。要改写的小节标题包括归档档案里含英文所有格的那几条，例如 `Keep a resumed process's first request in the native replay form`。

第 4 步会改动冻结文件。决定[厘清 ADR 内容边界](../decision/2026-09-23-clarify-adr-content-boundaries.zh.md)为它授权的每次清理记录一项有界例外，范围限于该次清理开始时已存在的语言对。本提案为本次清理申请这样一项例外，只覆盖标题与小节标题的措辞，并要求编辑后每条被记录的选择、理由、约束、不确定项、能力范围、作者、日期与反转关系都保留。例外由后继决定记录。

已落实的提案在实现改动中删除，这是 ADR 规则的要求。

## 考虑过的替代方案

- 把前缀当作格式字面量保留，理由是头部模板而非正文规定了它。在界定本次改动范围时考虑过。弃用原因是目录已经说明类型与状态，标题只是重复，而且冒号与标题规则的冲突仍未解决。
- 本次不改 ADR 标题，只清理其他面。在界定本次改动范围时考虑过。弃用原因是标题规则同样覆盖 ADR 标题，未清理的文件会让规则与仓库继续不一致。

## 验收标准

- 两种语言里每个 ADR 标题都只写主题，不带类型前缀。
- 每个 ADR 文件里的每个标题都不带标题规则禁止的标点。
- `.agents/adr/README.md` 文件对为两种记录类型给出无前缀的标题形式。
- 后继决定存在并承接被反转决定继续有效的规则，包括术语、提案流程、记录格式、编写规则、生命周期与维护规则；被反转决定带着 `Archived:` 与 `Reversed by` 归档，后继决定写有 `Reverses`。
- 归档的文件对保留每条被记录的选择、理由、约束、不确定项、能力范围、作者、日期与反转关系。
- 本次清理的例外被记录，且限于清理开始时已存在的文件对。
- 没有入链指向本次清理去掉的锚点，无论该锚点来自一级标题还是小节标题。
- 仓库的完整检查套件通过。

## 风险

- 单看标题已经无法判断记录类型，按标题分类的读者或脚本会静默误判。目录、双向语言链接与元数据块仍然说明类型。
- 改写冻结的标题与小节标题可能丢掉已记录的内容，使历史决定、理由或反转关系消失而记录表面完整。例外把编辑限制在改写标题与小节标题的措辞上，评审时逐对比较归档文件与其先前版本。
