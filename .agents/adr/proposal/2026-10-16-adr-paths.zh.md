# ADR 路径

Draft owner: Ruokee
Draft writer: OMP

[English](./2026-10-16-adr-paths.md) | 中文

## 动机

使 ADR 正式决定的规范路径在反转时保持不变。

目前后继决定使用不同的日期和名称。仅 ADR 机制就有日期为 2026-08-22、2026-09-02、2026-09-23 和 2026-10-15 的记录。每次反转都移动正式路径，会让当前引用随之变动。单靠日期也无法区分同一决定在同一天产生的连续归档。

记录积累后，平铺的生命周期目录越来越难浏览。部分历史标题和文件名还包含按[文档命名规则](../../rule/documentation.zh.md#命名)应留在正文中的细节。在长名称后直接追加修订号，会保留这一命名问题。

## 提议

### 身份

以决定首次提出的日期和简短的规范主题名标识当前记录及其全部归档版本。普通反转保留该日期和名称。实际归档日继续写入 `Archived: YYYY-MM-DD`，带日期的 `Changes` 条目保留其事件日期。

承接原主题的后继沿用其身份和修订序列。抽出的独立主题建立自己的首次提出日、规范名称和序列，并保留真实来源与反转关系。共享前驱或存在 `Reverses` 链接，本身不说明两个记录属于同一决定。

提案使用自己的首次提出日期，包括反转旧决定的提案。拒绝提案时保留该日期。反转提案的日期不替换旧决定的身份日期。

### 路径

保留 `.agents/adr` 及四个生命周期目录。ADR 正文放入其身份对应的年、月目录：

```text
.agents/adr/proposal/YYYY/MM/DD-name.md
.agents/adr/decision/YYYY/MM/DD-name.md
.agents/adr/rejected/YYYY/MM/DD-name.md
.agents/adr/archived/YYYY/MM/DD-rN-name.md
```

`YYYY` 是四位年份，`MM` 和 `DD` 是两位月份和日期。中文配对在同目录使用相同 basename 和 `.zh.md` 后缀。两份语言文件共用日期和修订号，并一起移动。

只有归档决定带 `rN`。第一次反转产生 `r1`，此后该决定每反转一次，`N` 增加一次。序列跨日、跨月、跨年连续计算。其他决定的反转、普通更新、命名纠正、目录移动、语言配对和多条关系链接，都不消耗该序列的编号。

当前决定与每份归档的 `YYYY/MM/DD` 都使用同一首次提出日，即使实际归档发生在之后的年份。这会把同一决定的历史归在一起，不对单月目录设文件数量上限。各生命周期根目录保留已有 `.gitkeep`，只为实际记录建立时间目录。ADR 指南和术语表仍位于 ADR 根目录。

### 反转历史

完整后继保存在规范 `decision/` 路径，被替代的双语版本移到下一个 `archived/` 修订。后继的 `Reverses` 指向该归档，归档的 `Reversed by` 指向其真实后继。

A 被 B 反转后，A 的归档起初指向正式路径中的 B。如果 C 随后反转 B，同一路径就包含 C。此时 A 的 `Reversed by` 必须跟随 B 指向 B 的归档，不能把 C 记作 A 的直接后继。B 保留指向 A 的链接，C 指向 B 的归档。

当前权威引用继续使用规范正式路径，特定历史选择的引用跟随该版本进入归档。按引用的内容分类，不按引用源位于当前目录还是归档目录分类。从各来源的新目录重新计算相对路径，修复双向语言链接和受影响入站引用，并保留或更新被引用的标题片段。文件路径稳定不意味着标题片段不可变。

### 命名

对每份保留的 ADR 主标题、各级小节标题和文件名应用[文档规则](../../rule/documentation.zh.md#命名)及 [well-said](../../../skills/well-said/SKILL.md)。使用简短祈使句、短语或名词，只命名一个主题，把细节留在正文。`Changes` 标题带日期前缀，不豁免其主题文字的命名规则。

完整叶子文件名不超过 60 字符，包括 `DD`、适用的 `rN`、主题、语言后缀和扩展名。把年月移入目录不能代替名称清理，也不放宽上限。名称纠正后，普通反转保持规范路径，错误的历史名称不成为永久别名。

### 历史纠正

纠正全部保留的提案、当前决定、归档决定和被拒绝提案，不只约束未来记录。根据正文、关系字段、提案来源和相关 Git 历史确定各记录的身份、首次提出日、真实反转顺序、规范主题和语言配对。按证据纠正关系错误，不把现有名称或链接当成权威顺序。

保留每项已记录选择、理由、约束、不确定性、历史能力范围、原作者、实际归档日和事件日期。名称与目录纠正不反转这些 ADR 记录的选择，也不为每项身份额外增加一次反转。原路径和逐记录的原文件名日期仍可从 Git 历史恢复。

在同一变更中修复受影响的关系链接、正文链接、语言链接、入站引用和片段，不保留重复旧 ADR 文件来掩盖漏改引用。历史格式示例或 Git 对象路径的原拼写就是被引用事实时，可以保留原值。

同步维护双语 ADR 指南、术语表、文档规则、仓库规格和受影响仓库引用。具体格式归指南，长期目标和可观察不变量归仓库规格。已有 ADR 维护 Skill 提案保留独立的选择和生命周期。

### 机制契约

反转[明确 ADR 内容边界](../decision/2026-10-15-clarify-adr-content-boundaries.zh.md)的日期保留与维护边界。其生效的维护条款要求命名调整保留每项已记录日期，[ADR 指南](../README.zh.md#文档布局)则通过各个平铺文件名表达日期。现有机制后继使用不同的文件名日期，本提案要求整个身份统一使用一个首次提出日。保留每份后继的文件名日期与统一到身份首次日期不能同时成立。这改变日期含义及历史纠正的允许范围，不把改名本身当成反转依据。

完整的机制后继须保留其他全部仍生效规则，包括：

- ADR 术语、小型双语术语表、两种文档类型、由目录表达生命周期状态，以及不使用 `Status` 字段。
- 新需求前的检索和分类，除维护者要求拆分外一项需求一个提案，获准提案先独立合入再实施，以及在形成决定时删除已消耗提案。
- 同目录双语权威、同一变更完成配对、双向链接、语义冲突处理、owner 和原 writer 元数据、必需正文章节及可选分析章节。
- 可独立理解的动机、必要契约边界、迁移承诺及历史细节的保留、真实替代方案、可信风险和允许的空章节形式。
- 在带日期 `Changes` 下记录非冲突更新，反转前指出具体冲突，完整后继承接仍生效规则，实际归档元数据及准确的直接关系。
- 维护者对批准、拒绝和归档的控制，不表达冲突选择的事实维护，以及在适用的关系和事实链接修复后冻结。命名维护继续保留历史实质内容，身份日期按本提案统一。
- 以审查、仓库搜索和 Git 历史维护 ADR。本提案不增加专用 Skill、分类系统、翻译 sidecar、归档 manifest、索引或常驻维护脚本。重复维护或实际失败指出具体不变量后才增加机械检查的既有条件保持不变。

## 考虑过的替代方案

**保留逐记录日期和平铺布局。** 这只能把当前路径保留到下一次反转，仍会让当前引用移动，同日归档仍需其他区分方式，生命周期根目录也会持续积累记录而没有年月分组。

**仅对未来记录应用约定。** 这会把已有长名称、不一致的身份日期和错误历史关系留在纠正范围之外。读者仍需使用两套命名约定来追溯同一决定的历史。

## 验收标准

1. 每份保留的 ADR 正文都位于其生命周期的年月布局下，具有完整、语义一致的同目录语言配对。当前决定和提案不带修订号，归档决定使用 `rN`。
2. 历史规范纠正后，决定在同日或跨日、跨月、跨年普通反转时，正式路径和首次提出日保持不变。每份被替代版本都可单独访问。
3. 每项身份第一次反转产生 `r1`，后续反转只递增自身序列，无关决定或普通维护不改变该序列。
4. 当前记录及其归档按同一首次提出日归入目录，`Archived` 保留实际归档日，`Changes` 条目保留实际事件日期。
5. 原主题的延续保持路径和序列，抽出的独立主题使用不同路径和自身序列，同时保留真实来源与反转关系。
6. 多次反转后的 `Reverses` 和 `Reversed by` 仍标识真实直接前后继。当前权威引用和历史版本引用指向各自预期内容，包括标题片段和双向语言链接。
7. 全部保留 ADR 的主标题、各级小节标题和文件名满足简短、单主题规则。完整文件名包含适用的修订号和中文后缀，仍满足 60 字符上限。
8. 历史纠正保留已记录选择、理由、约束、不确定性、能力范围、作者、归档日期和事件日期。纯规范纠正不新增反转，也不留下重复兼容文件。
9. 完整的 ADR 机制后继保留上述未受影响规则。指南、术语表、文档规则、仓库规格及实际文件以双语表达同一契约。

## 风险

把共同来源误认为相同身份，可能合并独立决定或给归档分配错误序列，让原本没有先后替代关系的历史选择看起来互相取代。

路径迁移或后续反转若把所有引用都当成当前权威引用，可能把历史引用重定向到不同内容。遗漏双向链接或标题片段，也可能让某份语言配对或被引用的证据无法访问。
