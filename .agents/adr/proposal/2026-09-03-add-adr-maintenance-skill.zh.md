# ADR 提案：添加 ADR 维护 Skill

Decision owner: Ruokee
Draft writer: Mind (OMP GPT-5.6 Sol)

[English](./2026-09-03-add-adr-maintenance-skill.md) | 中文

## 动机

[ADR 机制决定](../decision/2026-09-02-establish-adr-mechanism.zh.md)在机制仍随实际使用发生变化时，选择依靠评审、仓库搜索和 Git 历史，而不增加专用 Skill。

建立当前机制与随后细化编写规则时，都需要作出机械检查无法替代的判断。

Agent 现在需要从项目说明、本地 ADR 指南、当前记录，以及必要时的 Git 历史中自行整理维护步骤。一项范围明确的 Skill 可以提供这套步骤，而本地规则仍是权威来源，也可以继续变化。

## 提议

### 能力与启用条件

添加一项由模型自动调用的第一方 Skill，名称为 `adr`。英文组件位于 `skills/adr/SKILL.md`，中文完整变体位于 `variants/zh/skills/adr/SKILL.md`。

任务创建、审查、更新、反转、拒绝、归档或以其他方式维护 ADR 或本地 ADR 规则时，使用这项 Skill。适用的项目说明要求用 ADR 记录长期决定时，也应在修改决定前使用。一般架构讨论、普通文档编辑，以及没有采用 ADR 机制的仓库不触发这项 Skill。

Skill 只维护项目已经采用的 ADR 机制。批准或拒绝提案、归档决定，以及作出长期决定，仍由维护者负责。

### 本地权威来源与读取顺序

先读取适用的项目说明，再定位并读取项目的 ADR 指南、术语规则、与需求相关的活跃提案和当前决定。确认相同需求是否曾被拒绝时读取 rejected 提案。只有关系、稳定身份、最初作者或原有理由要求时，才读取 archived 决定和 Git 历史。

Skill 提供分类、维护和审查步骤，不得内置本仓库的固定路径、模板、章节名、状态值、文件名规则、语言要求或生命周期迁移规则。本地规则与 Skill 的通用步骤不同时，以本地规则为准。

### 维护步骤

编辑前，按照本地规则搜索相关记录，并根据本地机制的创建、更新或反转流程判断需求类型。

修改文件前列出完整修改范围，包括所需语言版本、关系与生命周期变更、规则引用和受影响的入站链接。

把所需语言版本视为一份逻辑记录，并比较其含义。发现冲突时，应报告问题，不能代替维护者选择其中一个版本。

按照本地编写规则处理替代方案、风险和空章节。Skill 不得用自己的内容规则取代本地规则。

完成独立工作后，再为维护者负责的生命周期操作请求批准。交付前检查本地结构、链接和语义要求，并运行仓库当前规定的验证入口。

### 决定替换与打包

本提案与当前 ADR 机制决定中不增加专用 ADR Skill 的选择冲突。如果提案获准并完成实现，将反转[建立 ADR 机制](../decision/2026-09-02-establish-adr-mechanism.zh.md)。替代决定必须保留原决定中仍然有效的全部规则，并增加 Skill 的职责。

第一版的每种语言组件只包含一个 `SKILL.md`。这套步骤很短，需要作为整体使用，因此不增加 `agents/`、`workflows/`、`references/`、示例或术语表。实现时在中英文能力索引中记录这项 Skill。

## 考虑过的替代方案

**继续依靠评审、仓库搜索和 Git 历史。** 当前 ADR 机制在规则刚建立时选择了这种做法。它不增加需要分发的能力，但每项 ADR 任务都必须从仓库文件重新整理分类、权威来源、双语维护和审查步骤。

**先增加检查器。** 当前机制决定同时推迟了检查器和 Skill。检查器可以执行稳定的机械约束，但已经发生的维护工作需要判断变更类型、查找决定归属、确认替代方案是否真实存在，并比较双语含义。这些工作还不能转化为明确的机械检查。

**要求手动调用。** 这会让 ADR 维护只在用户明确说出 Skill 名称时可用。直接操作 ADR，以及项目规则要求审查 ADR，已经提供了更窄的触发信号。要求用户额外记住调用 Skill，可能在最需要维护步骤时漏掉它。

## 验收标准

1. `skills/adr/SKILL.md` 和 `variants/zh/skills/adr/SKILL.md` 提供同一项由模型自动调用的 Skill 的完整变体，并保持语义一致。每个组件只包含自己的 `SKILL.md`。
2. 启用范围覆盖直接处理 ADR、修改 ADR 规则，以及适用项目说明要求用 ADR 记录的长期决定。一般架构讨论、普通文档编辑和没有 ADR 机制的仓库不触发它。
3. Skill 在操作前读取项目说明和本地 ADR 权威来源，不得内置本仓库的固定路径、模板、章节名、状态值、文件名规则、语言要求或生命周期迁移规则。
4. 维护步骤搜索活跃提案和当前决定，区分创建、更新和反转工作，列出完整修改范围，保留由维护者决定的生命周期操作，处理所需语言版本，修复受影响链接，并运行本地验证。
5. 审查步骤拒绝编造的替代方案和风险，报告语义冲突而不越权解决，并在没有合格条目时接受本地规则规定的空章节写法。
6. 实现时归档当前 ADR 机制决定，并创建一份完整的替代决定，保留原决定中仍然有效的规则，同时增加 Skill 的职责。
7. 中英文能力索引对职责范围和模型调用方式的描述一致。

## 风险

Skill 的通用分类步骤可能落后于各项目实际采用的 ADR 做法。Agent 可能在应用本地规则前进入错误的维护流程，从而创建不必要的提案，或修改错误的当前记录。

如果项目说明把模型自动调用当作唯一 ADR 触发方式，模型未能识别一项间接表达的长期变更时，该变更可能绕过决定审查，并与现有决定冲突。
