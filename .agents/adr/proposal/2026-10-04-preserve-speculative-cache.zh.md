# ADR 提案：在缓存对齐期间保留投机压缩

Draft owner: Ruokee
Draft writer: pro-20x/gpt-6-astra

[English](./2026-10-04-preserve-speculative-cache.md) | 中文

## 动机

将远端压缩请求与已确认的在线前缀对齐，同时保留原生投机压缩。

`@ruokee/omp-qol` 0.5.0 的缓存模块通过 `session_before_compact` 绑定请求归属。OMP 将该事件的任何 handler 都视为可能取消或替换压缩，因此拒绝投机工作，避免绕过扩展的否决权。只读 handler 也会触发同一限制。缓存调整因此取消了原生后台准备，可能增加压缩阈值处的可见等待。

[当前决定](../decision/2026-10-04-align-remote-compaction-cache.zh.md#远端压缩缓存对齐)接受这一损失，并要求基于事件确定归属、包装公开的手动压缩方法、保留一份前序载荷，以及在操作重叠时停用。保留投机压缩需要不同的归属来源和操作各自的参照。记录现有限制不能满足这一要求。

## 分析

OMP 18.5.1 的 `d0cc52397dc2a68d39cba49b0009b9e50ffd643e` 提供了有源码依据的替代入口。[模型注册表](https://github.com/can1357/oh-my-pi/blob/d0cc52397dc2a68d39cba49b0009b9e50ffd643e/packages/coding-agent/src/config/model-registry.ts#L3006-L3025)依据明确的模型和会话身份创建 resolver。[手动压缩](https://github.com/can1357/oh-my-pi/blob/d0cc52397dc2a68d39cba49b0009b9e50ffd643e/packages/coding-agent/src/session/session-maintenance.ts#L3396-L3440)、[投机压缩](https://github.com/can1357/oh-my-pi/blob/d0cc52397dc2a68d39cba49b0009b9e50ffd643e/packages/coding-agent/src/session/session-maintenance.ts#L2182-L2255)和[普通自动压缩](https://github.com/can1357/oh-my-pi/blob/d0cc52397dc2a68d39cba49b0009b9e50ffd643e/packages/coding-agent/src/session/session-maintenance.ts#L4794-L4815)都把该 resolver 及各自的根取消信号交给原生压缩。

[V2 构建器](https://github.com/can1357/oh-my-pi/blob/d0cc52397dc2a68d39cba49b0009b9e50ffd643e/packages/agent/src/compaction/compaction.ts#L1753-L1775)将同一信号传入鉴权和传输。[鉴权驱动](https://github.com/can1357/oh-my-pi/blob/d0cc52397dc2a68d39cba49b0009b9e50ffd643e/packages/ai/src/auth-retry.ts#L153-L169)把信号交给 resolver。观察该调用可以将根信号绑定到明确的会话和模型身份，不需要读取凭据，也不需要注册[会否决投机压缩的 hook](https://github.com/can1357/oh-my-pi/blob/d0cc52397dc2a68d39cba49b0009b9e50ffd643e/packages/coding-agent/src/session/session-maintenance.ts#L2050-L2064)。

这些是源码证据，不是所提包装方案的运行验证。注册表共享、resolver 创建顺序、并发快照和取消生命周期仍需运行证据。普通在线请求也可能使用 resolver，因此身份本身不能证明请求是压缩。最终请求还必须独立匹配预期端点和 V2 形态。

## 提议

### 不否决压缩的归属方式

用所属上下文的模型注册表实例及其返回 resolver 的薄包装，替换缓存模块的压缩事件和公开手动方法包装。保留进程持有的最终传输和原生信号组合包装。只将明确的所属会话和模型身份绑定到 resolver 的根信号，再沿原生信号派生关系追踪到出站请求。不通过时间、载荷相似性、缓存键或路由标识推测归属。

缓存对齐不得注册 `session_before_compact`，不得将其保留为备用路径、隐藏其他 handler 或修改宿主否决检查。本模块不得停用投机启动、等待或结果使用。其他扩展仍持有自己的 hook，包括单独启用的 QoL 压缩超时模块，它们仍可能使 OMP 停用投机。缓存模块不得更改它们的设置，也不得宣称投机在整个进程中已经启用。

包装原样转交原生参数、接收对象、凭据结果、返回的 Promise、错误、信号和取消原因。观察 resolver 不得读取或修改凭据材料、增加鉴权调用或接管凭据刷新与轮换。重试、模型和方法回退、投机结果校验与历史提交继续由 OMP 负责。

### 参照与生命周期

保留最近一份已确认的在线载荷，供后续操作使用。根信号一旦绑定合格参照，该操作在原生各次尝试中保持同一参照。后续在线请求只改变未来操作的可用参照，不使已绑定的投机操作失效。不同且归属明确的根信号可以并存，单纯重叠不构成停用模块的原因。

只有确认原样到达实际在线传输的载荷才能提供参照。保留现有的完整请求等价边界：仅复用已识别的工具定义和已证明的共同前缀，保留压缩尾部、触发项、不透明数据、显式工具选择、缓存键、路由、模型策略、响应及已存历史。投机快照无法匹配已确认参照时保持原生请求，不把更新的在线输入拼接到旧快照。

根信号身份未知或冲突、上下文过期、缺少发送确认或请求存在任何无法识别的差异时，完整请求保持原样。重试不得取得更新的参照，后续操作不得通过含糊的根信号复用继承前序操作的参照。鉴权解析完成和单次传输结束都不代表操作完成。仅在最新在线候选或仍有效的原生信号归属需要时保留参照，不积累无界的已完成操作历史。

保留现有的进程唯一 owner 和配置匹配激活规则。配置冲突、无法使用的激活、owner 退出、会话导航和包装被覆盖均停止改写并报告有界原因。相关模型或上下文变化必须阻止过期绑定继续改写。只还原仍由本模块持有的函数，包括注册表方法原始的属性形态；同一进程生命周期内，不允许任何激活接管已释放的 owner。所需接口无法安全观察时，保持原生请求并报告调整不可用，不以停用投机替代。

### 范围与决定替换

反转[当前 QoL 决定](../decision/2026-10-04-align-remote-compaction-cache.zh.md)。冲突条款包括单份前序载荷的归属规则、事件及手动方法归属入口、操作重叠时停用的规则，以及接受投机压缩丢失。这些条款不能与操作各自的参照、基于 resolver 的身份和原生并发投机同时生效。

后继决定必须保留五个模块、配置权威、owner 冲突、宿主职责和文档的所有仍有效规则。缓存对齐仍默认关闭，只覆盖所属主会话中明确选定提供方的非 Codex `openai-responses` V2 请求。不新增设置、序列化器、日志设施、试验控制或自动安装与配置变更。本提案不改变维护下限。

实现时同步更新组件版本和中英文行为文档。状态必须报告可用性、归属或拒绝原因及改写次数，不暗示本模块控制其他扩展的投机否决权。源码分析、实际运行证据和提供方缓存测量分别记录。受维护的原生请求准备接口提供等价能力后，使用该接口。

## 考虑过的替代方案

- **保留压缩事件绑定。** 这是已部署的方式，能够取得原生根信号，但只读 handler 也会触发宿主否决，不能满足保留投机的要求。
- **单独使用 `session.compacting`。** 寻找投机期间也会触发的事件时考虑过。它包含会话和消息，但没有根信号，无法独立确定并发传输请求的归属。
- **等待原生请求准备接口。** 缓存调研时考虑过。直接使用原生请求准备可以避免这些包装，但所查扩展 API 无法把扩展提供的传输贯通到三种维护路径。本提案不修改宿主，并要求等价的受维护接口出现后迁移。

## 验收标准

1. 原生投机已启用且没有其他否决 handler 时，启用缓存对齐不阻止投机启动、准备或使用有效结果。在线回合推进期间，匹配的投机 V2 请求能够完成对齐。
2. 手动、普通自动和投机 V2 请求使用明确的会话、模型和根信号归属。其他会话及无法识别的请求保留完整原请求。
3. 即使出现更新的在线请求，已确认参照在原生鉴权和传输重试中仍保持不变。并发根信号不得交换参照；取消、导航、上下文变化或含糊的根信号复用不能授权过期改写。
4. 鉴权结果和失败、原生返回值和 Promise、取消原因、重试、回退、投机校验与历史提交保留原生语义。一次失败既不终结仍有效的原生操作，也不授权后续无关工作。
5. 包装冲突或接口不可用时保持原生行为，状态准确且原因有界。停止时仅还原仍归本模块所有的包装，不覆盖其他扩展，也不留下保留请求正文的已完成操作历史。
6. 默认设置、提供方与 API 边界、严格等价检查及其他四个模块保留原契约。中英文文档和后继决定说明新的归属与投机行为，分别注明实际运行覆盖和缓存收益边界。

## 风险

- 宿主改变 resolver 创建、注册表共享或信号组合方式，可能破坏归属或鉴权委托。错误归属可能修改其他操作的输入；保守拒绝则可能使缓存对齐在适配修复前不可用。
- 并发原生操作保留各自的在线参照。长寿命信号或错误的释放规则可能比单参照实现更长时间保留较大的会话和工具载荷。
- 过期或不匹配的快照若遇到宽松的等价检查，可能改变模型输入。保留完整请求的拒绝边界，可能在在线工作推进后跳过更多后台请求，降低调整的缓存收益。
- 其他扩展可能替换被观察函数或保留压缩否决权。缓存调整可能直到重启前都不可用，投机也可能因这一独立原因仍被停用；不准确的状态会掩盖实际可用行为。
