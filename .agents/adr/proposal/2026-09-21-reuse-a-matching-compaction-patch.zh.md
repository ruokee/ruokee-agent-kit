# ADR 提案：复用配置一致的压缩补丁

Draft owner: Ruokee
Draft writer: deepseek/deepseek-v4.1-flash

[English](./2026-09-21-reuse-a-matching-compaction-patch.md) | 中文

## 动机

压缩期限实验在进程级安装一个补丁，并在已有其他激活持有该补丁时停止改写。OMP `18.2.4` 会为创建的每个会话绑定已加载的扩展，并再次调用它们的工厂函数；部分路径复用已准备好的 factory 而不重新求值模块，但工厂函数在任何一条路径上都会运行（`packages/coding-agent/src/sdk.ts:505-518`、`packages/coding-agent/src/extensibility/extensions/loader.ts:479-508`）。子代理会话因此在运行中的进程里会走到本模块的冲突分支。

于是运行中的 OMP 进程只要启动子代理就会走到冲突分支：第一个激活安装的补丁停止改写，第二个激活不安装任何东西，该进程在剩余生命周期内一直使用原生的五分钟期限。设置在界面上仍显示实验已开启，而 `/qol` 报告 `incompatible` 与 `runtime-conflict`，用户没有改动任何配置却失去了该调整。开启 `compactionTimeoutEnabled: true` 的真实 OMP `18.2.4` 会话中，补丁被停止与第二次激活出现在同一毫秒，这正是子代理激活在日志中的样子。

该冲突分支实现的是[新增可配置的 OMP 体验调整](../decision/2026-09-20-add-omp-qol.zh.md)中的「归属不明确」条款：进程内已存在其他 owner 时，该进程内的调整停用，而不是共享或覆盖。该条款针对的是在「补丁应该做什么」上真正不同的 owner，例如属于其他会话的窗口，或已不再适用的配置快照。

不过，包版本与生效配置快照都一致的两次激活并不会因此变成同一个对象：补丁改写的窗口由安装它的那个激活的事件打开，而窗口是进程级的，包装只按调用发生的时间是否落在窗口内、以及数值范围是否匹配来改写期限，不识别调用属于哪个会话。保留补丁说明已安装的策略对进程仍然适用，不说明哪个激活能独立驱动窗口，也不能把安装方激活的生命周期转交给后来的激活。因此本提案同时修改再次激活的规则与再次激活报告的内容。

## 提议

针对上述再次激活的情形收窄该条款：当以下条件全部成立时，第二次激活保留已安装的补丁，而不是停止它。

- 该激活自身要求开启实验：总开关开启，本模块的开关与键可用，因此不会依据默认值安装或开启任何东西。
- 其包版本与已安装补丁记录的版本相同。
- 其生效的压缩配置快照与补丁建立时的快照相同：enabled、`timeoutMs`、`floorMs`、`guardMs` 与 `notify`。
- 补丁仍属于本模块：未被先前的冲突停用，当前 `AbortSignal.timeout` 仍是已安装补丁的包装。

这类激活不安装第二个包装，也不停止补丁。它不注册窗口事件、不打开窗口，因为窗口属于安装方激活，因此它不报告 `enabled`，而是报告 `incompatible`，原因为 `patch-owned-elsewhere`：进程补丁存在、由其他激活持有，本激活无法独立驱动窗口。该原因只说明窗口不由本激活打开，不说明本会话的压缩绝不会被改写：安装方的窗口关闭时，本会话的压缩使用原生期限；窗口打开期间，进程内所有匹配数值范围的调用，包括本会话的压缩，同样被延长。记录的激活 cwd 仅用于诊断，不参与比较，因为子代理可能在同一配置下运行于其他目录。

`/qol` 在命令运行时从进程 registry 解析压缩行，而不是重复某一次激活的结果。当本模块的包装由其他激活安装时，该行报告归属；该激活停止补丁之后（冲突、重叠窗口、实验被关闭），该行报告对应原因；其他扩展替换了 `AbortSignal.timeout` 时，该行报告 `patch-overwritten`。会话不会把无法由自己驱动的补丁持续显示为 `enabled`。

安装方激活结束自己的会话时，该进程不把补丁留给后来的激活。`session_shutdown` 结束它打开的窗口，并且只在 `AbortSignal.timeout` 仍是本模块安装的包装时还原原生函数；registry 留下 `owner-stopped` 形式的有界终态，记录该进程的补丁已由其 owner 释放。此后的 `/qol` 报告该终态，不再报告 `enabled`，也不把已经退出的激活当作活跃 owner。该进程不再安装新补丁、不接管、也不重新竞争 owner，配置一致的后续激活遇到该终态时报告该终态而不是安装补丁；该调整恢复到该进程需要重启 OMP，从 owner 退出到重启之间没有任何会话获得延长。`session_switch` 属于同一激活继续服务新会话，只结束当前窗口，不算激活退出。

其余规则保持不变：一个进程只有一个包装，归安装它的激活所有；改写所在的窗口由该激活自己的事件打开；配置快照或版本不同、总开关使其关闭、键无效、设置无法读取、注册表槽位本版本无法读取，或包装已被其他扩展替换的第二次激活，仍在现有规则停止它的地方停止补丁，并报告同样的原因。安装方激活关闭实验时仍会还原原生函数。保留补丁的激活不产生冲突报告：其他激活持有补丁是已声明的单 owner 范围，不是故障。

组件在 `projects/omp-qol/README.md` 与 `projects/omp-qol/docs/adjustments.md` 中提供中英文对照的规则说明，自动检查覆盖上述结果。

## 考虑过的替代方案

- **保留规则并说明后果。** 在决定是否改动组件时考虑。这样只要启动过子代理，所有运行中的进程都不再有该调整，实验实际上只对从不委派的会话有效。
- **改宿主，让会话不再重复激活进程级扩展。** 在权衡修复位置时考虑。按会话绑定是刻意设计：每个 `Extension` 闭包持有本会话的 cwd、事件总线与 runtime，只有受限子会话这条路径不加载扩展。改该模型会影响所有扩展，而不只是本调整；本组件也无法在不重建宿主的情况下验证结果。
- **让最新的激活接管包装。** 在选择冲突行为时考虑。这样配置快照与已安装补丁不同的会话可以就地替换补丁，正是现有决定拒绝的「覆盖」。
- **共用补丁，并让每个激活各自注册窗口钩子。** 在决定再次激活可以深入到什么程度时考虑。那样多个会话会打开与关闭同一个窗口，而现有规则把属于其他会话的窗口视为归属不明确并据此停用实验。
- **对保留补丁的激活报告 `enabled`，把限制留给文档说明。** 在决定再次激活可以声明什么时考虑。那样会话会被读成已被完整服务，而补丁实际服务于另一个激活的事件，正是本提案要移除的报告缺陷。
- **owner 退出后由下一次匹配激活安装新补丁。** 在选择恢复路径时考虑。这样该进程不必重启就能重新获得该调整，而且新补丁由仍然存活的激活持有，与首次安装的规则一致。代价是「该进程当前是否启用该调整」取决于之后是否还有激活出现，`/qol` 在 owner 退出后没有确定的终态可报，本提案选择确定终态加重启恢复。
- **识别请求归属，让窗口只作用于持有它的会话。** 在评估能否消除窗口副作用时考虑。包装的调用点拿不到会话或请求身份，要按会话判断就得改变压缩调用链的类型与宿主接口，超出本组件的范围；现行决定已接受窗口内无关 timeout 被延长的副作用。

## 验收标准

1. `projects/omp-qol` 的自动检查覆盖保留路径：版本与快照一致的第二次激活保留已安装补丁、不安装第二个包装、报告 `incompatible` 与 `patch-owned-elsewhere`，且安装方激活的窗口仍在改写期限；快照不同、包版本不同、本模块开关关闭、总开关关闭或键无效的第二次激活以 `runtime-conflict` 停止补丁；设置无法读取的激活仍会停止可识别的补丁；已停止的补丁对之后配置一致的激活保持停止；保留补丁的激活运行之后补丁被停止时，报告的状态跟随 registry 变化。
2. 自动检查覆盖进程级窗口的交错情形：非 owner 调用在 owner 窗口之外保持原生期限，窗口内同样被延长；非 owner 的 `session_shutdown` 不关闭 owner 的窗口，owner 的窗口仍按自己的事件改写期限。
3. 自动检查覆盖 owner 退出：`session_shutdown` 结束窗口，并在当前函数仍是自己的包装时还原原生函数（已被其他扩展替换时不还原），留下 `owner-stopped` 终态；该进程后续会话的 `/qol` 报告该终态，不报告 `enabled`；此后配置一致的激活报告同一终态且不安装新补丁；`session_switch` 只结束当前窗口，同一激活继续服务新会话。
4. 在同一次真实 OMP CLI 运行中证明：启动并结束子代理会话不再停止补丁；`/qol` 对安装该补丁的会话持续报告 `compaction: enabled`，对共享该进程但不持有补丁的会话报告 `compaction: incompatible (patch-owned-elsewhere)`；owner 会话退出后 `/qol` 报告终态。该运行记录 OMP 版本、所用模型与组件版本，并与自动检查分开报告。
5. `projects/omp-qol/README.md`、`projects/omp-qol/README.zh.md`、`projects/omp-qol/docs/adjustments.md` 与 `projects/omp-qol/docs/adjustments.zh.md` 以中英文对照说明新规则及其边界，并递增组件版本。
6. 组件自身文本不再把配置一致的第二次激活描述为冲突，也不承诺仅共享进程的会话能获得延长保证或不受改写影响：包括注册表说明、内联注释与 `/qol` 输出示例。
7. 承载该变更的决定反转[新增可配置的 OMP 体验调整](../decision/2026-09-20-add-omp-qol.zh.md)，并保留该决定中仍然有效的每一条规则。

## 风险

- 配置快照比较成为已安装补丁与未安装它的会话之间的唯一门槛。若给生效配置新增字段却没有同步更新该比较，复用范围会无声扩大，某个会话可能在它从未选择的配置下被保留。比较与快照类型必须一起改动。
- 保留补丁的激活不驱动窗口，也不因此获得延长保证：窗口关闭时它的压缩使用原生期限，窗口打开时它与进程内其他匹配调用一样被改写。状态行与文档是唯一说明这件事的地方；没有它们，子代理会话会被看成已被完整服务且不受影响。
- 状态解析依赖命令运行时读取 registry。把状态缓存在激活时刻会重新引入本提案要移除的缺陷，因此检查与解析必须一起测试。
- 安装方激活退出后，该进程在重启之前不再延长任何压缩期限，`/qol` 一直报告 `owner-stopped`。这是选择的终态：释放补丁而不让后续激活重新安装，代价是该进程的剩余生命周期没有该调整。
- 进程级窗口意味着窗口内与该调整无关的 timeout 也会被延长。该副作用在现行决定中已被接受，本提案保留它，只在契约、状态与文档里如实说明，不因此引入请求归属识别或多 owner 协调。
- 放宽归属规则后，后续改动可能继续滑向共用或覆盖补丁。若组件文档与决定中没有明确边界，下一次涉及第二次激活的改动就可能削弱其余拒绝原因。

## 变更

- 去掉请求隔离的表述：保留补丁的激活不注册窗口事件，也不保证自己的压缩获得延长。窗口是进程级的，窗口关闭时非 owner 使用原生期限，窗口打开时进程内匹配的调用都会被改写。
- 增补 owner 退出规则：`session_shutdown` 结束窗口并在仍是自己的包装时还原原生函数，留下 `owner-stopped` 有界终态；后续激活不安装新补丁，恢复需要重启 OMP；`session_switch` 只结束窗口。
- 验收标准拆成三组：保留路径、进程级窗口的交错情形、owner 退出与恢复边界，并补上该终态下的真实 CLI 检查。
- 保留补丁的激活所报告的状态是 `incompatible` 与原因 `patch-owned-elsewhere`：补丁属于另一个激活，不服务本会话的压缩。
- `/qol` 在查询时从进程 registry 解析压缩行，而不是重复激活时的结果，因此之后的停止会体现在进程内每个会话里。
- 动机不再声称每个会话都会重新求值入口模块，改为说明工厂函数在每个会话上都会运行，可能走模块加载路径，也可能走复用的 prepared factory。
- 归属相关表述区分了三件此前被当作同一件的事：本扩展的另一次激活、持有进程补丁的激活，以及当前窗口所归属的激活。
