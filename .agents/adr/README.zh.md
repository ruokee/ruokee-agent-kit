# 架构决策记录

[English](./README.md) | 中文 | [词典](../../docs/dictionary/adr.zh.md)

创建、修复、更新、反转、归档、审查 ADR，或在项目工作中改变持久选择前，先加载 [maintain-adr](../skills/maintain-adr/SKILL.md)。Skill 持有主要结构、生命周期、编写规则和维护操作，本页保存仓库补充与导航。

## 项目补充

以 `.agents/adr/` 为 ADR 根目录。Skill 的 `decision/` 目录保存当前决定，`archived/` 保存曾经生效、后来被替代的决定。本 README 文件对留在根目录，两个目录始终使用 `.gitkeep` 保存在 Git 中，即使已有记录。

共享术语见[词典 ADR 页](../../docs/dictionary/adr.zh.md)。命名和链接遵循[文档规则](../rule/documentation.zh.md)，检查遵循[开发规则](../rule/development.zh.md)。长期目标位于 [.agents/spec/](../spec/README.zh.md)，变化影响目标时加载 [maintain-spec](../skills/maintain-spec/SKILL.md)。

## 语言

每项 ADR 是同目录的英文和中文文件对，分别为 `DD-name.md` 和 `DD-name.zh.md`。归档使用 `DD-rN-name.md` 和 `DD-rN-name.zh.md`，身份日期与修订号一致。

无后缀英文文件是默认公开链接，中文文件是审计对应版本。两者语义同等权威，并一起移动。可以先起草任一语言，但两份文件必须在同一变更中补齐。语义冲突阻止合并，直到维护者解决。完整元数据块后紧接双向语言链接，负责人和起草者字段一致，标识符保留仓库原拼写。

主题标题翻译为中文。`Decision owner`、`Decision writer`、`Reverses`、`Archived`、`Reversed by` 等元数据键保持仓库原拼写。

Skill 章节的中文对应名称如下：

- `Motivation`：`动机`。
- `Analysis`：`分析`。
- `Decision`：`决定`。
- `Alternatives considered`：`考虑过的替代方案`。
- `Consequences`：`结果`。
- `Changes`：`变更`。

替代方案章节为空时，英文只写 `None`，中文只写 `无`。

## 权限

维护者决定是否采用持久选择及归档被替代决定。Agent 可以在授权工作中起草和实现，但这些决定需要明确授权。已有有效批准时直接复用，不重复要求。任务状态、Plan、审查结论或实现完成不授予批准、归档、集成或任务关闭权限。

使用现有 tk 任务保存讨论、批准及其范围、普通被否决选项和待执行安排。公开协作可以使用可访问的 Issue 或 PR，不将其中任何平台设为必需依赖。正式决定的必要理由和重要否决选项须让公开读者无需私有任务记录即可理解。有长期约束的“不采用某选项”本身可以成为决定。不改变持久选择的小修改或快速处理不需要 ADR。

## 集成

需要实现的选择，其正式决定随对应实现一起集成。纯文档选择可以作为文档变更集成。已批准但待执行的安排保存在任务中，替代变更合入前，当前决定仍是主线权威。worktree、本地提交、审查和独立合并权限遵循 [Git 规则](../rule/git.zh.md)。

继续开发获准时，实现单元可以从包含所需依赖、已验证且已提交的前置候选创建新分支，不必等待其合并。冻结前置候选，保留各单元相对自身基线的可审查范围。这本身不批准选择，不授予归档或集成权限。

实现后，在同一变更中形成所需决定和完整后继、更新无冲突决定，并归档被替代版本及维护直接关系。决定保存必要公开理由，归档保存历史契约。未采纳草稿不进入归档。
