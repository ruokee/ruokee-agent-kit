# ADR 决定：同目录维护中英文公开文档

Decision owner: Ruokee
Decision writer: OMP GPT-6 Astra
Reverses: [维护中英文公开文档](../archived/2026-08-20-maintain-bilingual-public-documentation.zh.md)

[English](./2026-09-07-colocate-bilingual-docs.md) | 中文

## 动机

仓库将中英文公开文档放在同目录配对维护，使每个版本可以独立阅读，对应版本也位于同一组件或主题旁。仓库对外公开，代码和默认文档使用英文，Ruokee 使用中文审查技术决定和使用细节。

仓库和组件入口页还需要明确职责，让读者能够发现能力并进入详细文档，不必面对相互竞争的索引或重复合同。

## 决定

### 语言与范围

代码、注释、配置和默认公开文档使用英文。公开行为和用法同步维护对应中文文档。普通公开 Markdown 页面采用同目录 `name.md` 和 `name.zh.md` 配对。仓库和组件入口页使用 `README.md` 和 `README.zh.md`，不按语言拆分目录。

对应文档保持双向语言链接，每份文档都应独立成立。同一变更中更新并审查两种语言，要求行为、限制和指令一致，不要求逐句翻译。路径、命令、API 名称、状态值和代码标识符保留仓库原值。

内部实现笔记、注释、生成文件和仅面向维护者的材料，只在目标读者需要时翻译。公开行为或用法首次需要中文文档时定义真实文件对，不创建空的语言占位文件。

ADR 使用 [ADR 机制决定](./2026-09-23-clarify-adr-content-boundaries.zh.md)定义的更严格文件对格式。两份文件在语义上具有同等权威，并且一起移动，保留现有元数据和生命周期规则。

### Skill 打包

Skill 语言变体保留宿主可发现的组件布局。根据 [Skill 打包决定](./2026-08-20-package-self-contained-skill-variants.zh.md)，英文 Skill 位于 `skills/<name>/`，中文变体位于 `variants/zh/skills/<name>/`。独立命名的 tk Skill 保留 `projects/tk/skills/` 下的路径。普通文档的文件名规则不改变 Skill 文件名、身份或安装路径。

### 公开入口

[英文仓库 README](../../../README.md) 和[中文仓库 README](../../../README.zh.md) 提供语义一致的能力索引与开发说明。它们区分用户触发和 Agent 触发的 Skill，并按适用 Harness 对扩展分组。每个 Skill 条目链接基础版本和中文变体，每个扩展条目链接对应语言的组件 README。

组件 README 文件对介绍能力并链接使用和设计文档。详细命令、参数和规范性行为仍由其所属页面维护。tk README 文件对按照 [tk 文档决定](./2026-09-11-align-tk-usage-patterns.zh.md)提供这类导航。

不维护独立的 Skill 索引页面、重复的语言目录入口页，也不在被取代的路径保留跳转占位文件。页面移动时修复受影响的入站链接和命令示例。使用[文档相对链接](./2026-08-24-use-document-relative-file-links.zh.md)，并保留[组件自包含](./2026-08-24-keep-components-self-contained.zh.md)要求。

## 考虑过的替代方案

按中英文分别维护文档目录。这是一种可行的配对方式，但需要采用与 ADR 和现有组件文档不同的路径约定。同目录配对让普通公开页面使用同一套文件名规则，并将对应版本放在一起。

## 结果

英文继续作为默认公开语言，公开行为和用法具有完整的中文对应版本。读者可以在当前页面旁找到另一语言版本，并通过仓库和组件 README 文件对进入各项能力。

每项相关变更都需要维护两种语言及其链接。文件对和链接检查可以发现遗漏，但不能证明语义一致，仍需人或有能力的 Agent 比较含义。使用现有仓库检查，并明确检查受影响的链接，不新增永久翻译或文档结构检查器。

公开页面移动后，外部书签和入站链接可能失效。仓库内维护的引用会同时修复，但无法在此更新所有外部引用。
