## 动机

从仓库移除 `@ruokee/omp-codex-web-access` 扩展，并取代维护它的决定。

该扩展通过 OMP 的 `openai-responses` API 访问转发 Provider 的模型，并用 OMP 原生插件设置中的五个键配置两个工具。它在 2026-10-08 被标记为即将弃用：维护者报告近期 OMP 版本可用托管网页搜索访问转发 Provider 的模型，而这正是 `codex_web_search` 覆盖的路径，因此在该路径可用时该工具与宿主能力重复；当时还没有会话确认过网关执行托管搜索工具。页面提取当时没有原生等价物。

维护者移除了该组件，并接受两个工具随之消失：页面提取不迁移到其他组件、OMP 设置或宿主配置，也不计划替代物。仓库是该组件唯一的发布渠道，因此没有已发布的发行物需要迁移路径，也不发布、不标记弃用、不下架任何包。

## 决定

### 被移除的组件

仓库不维护 `@ruokee/omp-codex-web-access`。`projects/omp-codex-web-access` 及其仓库内容已不存在，除本决定与宿主下限决定里的移除条目之外，没有文件把它当作现存组件引用，也没有组件提供 `codex_web_search` 或 `codex_web_fetch`。

仓库的现行记录陈述这次移除：根 README 双语页、两种语言的 `docs/installation`、改动路径检查配置、spec 层，以及命名该组件或引用其设置条款的决定。宿主维护规则继续为其余面向 OMP 的组件保留一个共同下限，去掉一个名称不改变该下限，也不改变其他组件合同。

### 不再保留的规则

被取代决定只有一个主题，也就是该组件：它的包、两个工具、设置键、激活、迁移规则与模型执行。组件不存在后，这些条款都没有对象，因此本次移除不保留其中任何一条。[维护提高 OMP 使用体验的拓展](./20-omp-qol.zh.md)与[在 smart-cache 中提供 remote 对齐](../10/10-remote-alignment.zh.md)依赖的插件设置合同由这两条决定自行陈述：OMP 拥有设置文件、用户与项目作用域的合并以及解析。

已归档的决定与 Git 历史保留对它的提及。

## 考虑过的替代方案

**保留组件以维持页面提取，只移除搜索工具。** 在判断页面提取是否需要去处时考虑过。这样可以保住宿主不提供的那个工具，但仓库会为一个维护者已不再认可其需求的工具继续维护该组件、它的检查与文档。

**保留组件目录但停止维护。** 在决定如何退役该组件时考虑过。组件清单与所有引用点保持不变，但仓库会继续为一个已无用途的组件保留条目，「即将弃用」状态也会在没有删除日期的情况下继续悬置。

**直接移除组件，不取代设置决定。** 在判断移除是否需要走 ADR 流程时考虑过。这样省掉提案与归档，但一条现行决定会继续维护一个已不存在的组件，决定链条也会失去它被移除的原因记录。

## 结果

- 从本仓库安装该组件的用户在移除自己的副本后失去两个工具。复制安装会一直运行到用户删除它或某次宿主变更使其失效，并且不再获得维护。
- 仓库的面向 OMP 组件清单与宿主维护规则不再包含该组件。共同的 OMP `18.5.0` 下限以及其他组件合同都不变。
- 页面提取从仓库的能力中消失且没有替代物，需要它的调用方只能改用其他工具或直接抓取页面。
- 插件设置合同不再有单一的所属决定：依赖它的决定自行陈述它，将来采用原生插件设置的组件自行陈述依据或为该合同建立决定。
