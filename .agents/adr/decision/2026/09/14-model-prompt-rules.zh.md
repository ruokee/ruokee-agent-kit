# 模型提示词规则

Decision owner: Ruokee
Decision writer: OMP DeepSeek V4.1 Flash
Reverses: [模型提示词规则](../../../archived/2026/09/14-r3-model-prompt-rules.zh.md)

[English](./14-model-prompt-rules.md) | 中文

## 动机

在 smart-context 中维护模型提示词规则，保持规则文件与逐 turn 行为不变。

本能力需要上下文扩展中的独立开关，不再依赖 QoL 总开关。迁移归属须保留匹配、诊断、提示词保真和既有覆盖，不新增注入路径。

## 分析

维护者需要用户自撰的 Markdown 规则，在不修改扩展源码、宿主文件或分发物的前提下让不同模型得到不同的系统指令。Smart-context 独立于任何组件模板或策略替换提供该能力。公开 `before_agent_start` 事件暴露当前 turn 的系统提示词块与有效模型，并接受扩展后的数组。原生 handler 按实际扩展加载顺序串联，没有优先级设置，安装命令的先后也不代表执行顺序。

## 决定

### 组件开关

自包含的 `@ruokee/omp-smart-context` 按[组件边界](../08/24-component-self-containment.zh.md)与[包级合同](../10/12-smart-cache.zh.md)持有规则。`modelPromptsEnabled` 是独立的原生 boolean 设置，默认 `false`，没有总开关。关闭时不注册注入 handler、不读取规则目录、不诊断未使用文件。设置在激活时读取一次，改动需要重启 OMP，导航或新会话不刷新快照。

无效 boolean 只停用本模块。未知设置、非对象设置根或设置读取失败拒绝整个包配置。`/smart-context` 显示模块有效状态和停用原因，不运行模型，不暴露规则正文或模型标识。

组件声明直接的 pi-utils peer；宿主 peer 不设限，其维护下限在组件 README 的兼容性小节声明，该小节是这一下限的权威说明。组件在[宿主内组件按共同的 OMP 下限维护](./28-host-maintenance.zh.md)之下按 OMP 18.5.0 维护，该决定持有所有面向 OMP 组件的下限。

### 规则应用

追加步骤在每个被覆盖的 turn 读取当前 profile 的用户 agent `model-prompts` 目录及项目 `.omp/model-prompts`。只读取直接子级、非隐藏、小写 `.md` 普通文件。保留区分大小写的 `exact`、`model`、`contains` 和 `regex` 匹配、同文件条目的 OR 语义，以及每个匹配文件仅追加一次。校验并移除 frontmatter，移除开头 BOM，正文逐字节保留，包括换行符。

返回新数组，先按原顺序保留全部输入块，再为每个匹配文件追加一个块。不修改输入块，不包装、裁剪、重新渲染或改写宿主内容。用户目录正文先于项目目录，同目录按文件名排序，异步读取不改变结果。[模型提示词规则 Spec](../../../../spec/omp-smart-context/model-prompts.zh.md) 维护详细文件与匹配合同。

没有匹配时该步骤不返回值，turn 输入保持不变。系统提示词是唯一渠道。

### 诊断

无效规则、无法读取的目录，以及校验之外抛出的错误，通过组件现有渠道报告：交互会话用 `ctx.ui.notify`，否则用宿主 logger；按当前事件的会话、来源与原因去重，包括回到更早的会话或会话重叠的情况。诊断携带固定原因码与相对规则作用域可定位的来源，绝不携带规则正文、绝对路径、原始解析错误、正则源码或对话内容。文件失败只影响该文件，目录失败只影响该目录，意外处理错误保留传入块及更早组件的结果；诊断本身失败也不能中断模型 turn。正则按 JavaScript 正则运行，无超时也无沙箱。

### 宿主覆盖

每个 turn 使用其有效事件模型与当前 cwd；没有模型就不读取规则。刷新的粒度是每个 turn，而不是每个 Provider 请求、临时中途切换或自动回退，因此新增、编辑、删除与修复在下一个被覆盖的 turn 生效，无需重启，也不需要正文快照或缓存。覆盖范围是运行公开 `before_agent_start` hook 的普通主会话与普通子 Agent，每个子 Agent 保留自身模型、角色与独立块。不为 plan-mode 子 Agent、Handoff、标题、分类或其他旁路新增注入入口，后续 handler 保留改变最终输入的权力。

项目目录中的规则文档会把仓库内容变成系统提示词文本。项目规则可以成为系统指令，本组件不增加信任门槛、安全隔离、正则沙箱或超时，也不设置正文大小限制。公开文档说明该目录与注入方式。

### 上游复核

[模型提示词规则 Spec](../../../../spec/omp-smart-context/model-prompts.zh.md) 维护宿主提供模型作用域指令时的复核合同，形式见上游 [issue #6739](https://github.com/can1357/oh-my-pi/issues/6739) 或等价能力：

- 宿主覆盖哪些匹配维度，例如精确的 `provider/model` 键、裸模型 id、子串与正则；
- 宿主文本与已被替换或自定义的系统提示词如何组合：替换还是追加，以及它在块顺序中的位置；
- 宿主文本何时刷新：每个 turn、每个 Provider 请求、模型切换、临时切换与回退时；
- 宿主如何发现规则：目录、用户与项目优先级，以及文件顺序。

复核结果决定本地能力是保留、只补宿主未覆盖的部分，还是移除，并带相应的版本变更。

### 验证

[模型提示词指南](../../../../../projects/omp-smart-context/docs/model-prompts.zh.md#验证)定义组件检查范围。

通过实际提示词组装和序列化的受控运行记录候选、锁定宿主库、有效 fixture 模型及最终请求。handler 返回值本身不作为面向 Provider 的证据。验证正文仅一次到达请求、不含 frontmatter、模型变化重新匹配、宿主块和动态内容保留，以及连续 turn 或提示词重建不累积正文。真实模型调用和完整 CLI/TUI 矩阵不是集成门槛。历史运行保留原归属与条件。

### 迁移

移除 QoL 的实现、登记、设置和状态。从用户级与项目级 QoL 设置清除 `modelPromptsEnabled`，先解析项目覆盖，再为每个层级保留旧有效 `enabled && modelPromptsEnabled` 结果。无关设置和规则文件不变。更新扩展入口与设置后重启，不增加运行时回退或自动配置迁移。

后继替代 QoL 归属、总开关依赖，并以上述受控集成门槛替代强制真实宿主覆盖。匹配、注入、诊断、失败隔离、覆盖、信任边界及原生替换复核继续有效。不要求其他扩展已安装或排在前面。

## 考虑过的替代方案

无

## 结果

- 规则不依赖另一个扩展已安装、排在前面或同步更新，设置与运行时依赖均在 smart-context 内。
- 项目目录中的规则文件会把仓库内容变成系统提示词文本。OMP 不做项目信任校验，项目设置与扩展对当前目录无条件加载，因此一个带有 `.omp/model-prompts/*.md` 的克隆仓库可以为在其中打开的会话添加指令。维护者把自己的规则放在用户目录。
- 若宿主改动开始把上一个 turn 的覆盖结果当作输入回灌，追加文本可能不断累积。追加步骤依赖宿主每个 turn 从基础提示词构建提示词，这一点若改变，每个匹配正文会在每个 turn 再增加一份。
- 规则正文会增大每个匹配 turn 的系统提示词。没有大小限制或预算检查，因此一个很大的规则文件会把全文加到会话后续的所有 turn，并挤占其他提示词内容。
- 文本匹配无法区分有意匹配与偶然匹配。`contains` 或 `regex` 规则可能作用于比作者预期更多的模型，而无法编译的正则只会丢弃该规则，诊断也不说明作者本想覆盖哪些模型。
- 追加步骤在 hook 运行的每个 turn 读取两个规则目录，因此缓慢或远程的目录会逐 turn 延迟提示词组装，且没有缓存可以摊薄。
- 只复制模块开关而不折算 QoL 旧有效总开关，可能启用用户已关闭的规则。因此迁移在删除旧键前先计算两个层级的有效值。
