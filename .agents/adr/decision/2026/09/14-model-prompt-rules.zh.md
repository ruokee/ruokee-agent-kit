# 模型提示词规则

Decision owner: Ruokee
Decision writer: OMP DeepSeek V4.1 Flash
Reverses: [模型提示词规则](../../../archived/2026/09/14-r2-model-prompt-rules.zh.md)

[English](./14-model-prompt-rules.md) | 中文

## 动机

在与之对照的系统提示词扩展离开仓库之后，把模型提示词规则继续保留在 QoL。

已归档决定把规则从 `@ruokee/omp-system-prompt` 迁入 QoL，并在同一次改动中把模板、Delivery 章节与页脚留给该组件，还要求它在实际加载顺序中先于 QoL 运行。[移除 omp-system-prompt 扩展](./07-omp-system-prompt.zh.md)删除了该组件，因此把这些行为归给它的边界、以及两个组件之间的加载顺序要求都没有对象。规则本身、其匹配、其诊断渠道与其覆盖范围不受影响。

## 分析

维护者需要用户自撰的 Markdown 规则，在不修改扩展源码、宿主文件或分发物的前提下让不同模型得到不同的系统指令，而 QoL 独立于任何组件模板或策略替换提供这项能力。公开的 `before_agent_start` 事件暴露当前 turn 的系统提示词块与有效模型，并接受扩展后的数组。原生 handler 按实际扩展加载顺序串联，没有优先级设置，安装命令的先后也不代表执行顺序。

## 决定

### 组件开关

自包含的 `@ruokee/omp-qol` 在[保持可分发组件自包含](../08/24-component-self-containment.zh.md)与[维护提高 OMP 使用体验的拓展](./20-omp-qol.zh.md)之下持有这些规则。`modelPromptsEnabled` 是原生 boolean 设置，默认 `false`，受 `enabled` 控制。两个开关都开启时才注册规则 handler、读取规则目录并诊断未使用文件。设置在激活时读取一次；改动需要重启 OMP，切换会话或导航都不会刷新快照。

无效的 boolean 只停用本模块。未知设置、非对象的设置根或设置读取失败，按现有 QoL 合同拒绝全部模块。`/qol` 显示本模块的有效状态、boolean 与停用原因，不运行模型，也不暴露规则正文或模型标识。

组件声明直接的 pi-utils peer；宿主 peer 不设限，其维护下限在组件 README 的兼容性小节声明，该小节是这一下限的权威说明。组件在[宿主内组件按共同的 OMP 下限维护](./28-host-maintenance.zh.md)之下按 OMP 18.5.0 维护，该决定持有所有面向 OMP 组件的下限。

### 规则应用

追加步骤在 hook 运行的每个 turn 读取用户规则目录与项目规则目录，用每个规则文档的 frontmatter 匹配该 turn 的有效模型，并返回一个新数组：先按原顺序保留全部输入块，其后为每个匹配文件一个块。匹配的规则按其正文逐字节追加，该步骤既不修改输入块，也不包装、裁剪、重新渲染或改写宿主内容。用户目录的正文先于项目目录，同一目录内按文件名排序，异步读取不会改变结果。匹配键、文档格式、校验原因与排序规则由组件 README 的[模型提示词规则小节](../../../../../projects/omp-qol/README.zh.md#模型提示词规则)作为现行公开合同记录。

没有匹配时该步骤不返回值，turn 输入保持不变。系统提示词是唯一渠道。

### 诊断

无效规则、无法读取的目录，以及校验之外抛出的错误，通过组件现有渠道报告：交互会话用 `ctx.ui.notify`，否则用宿主 logger；按当前事件的会话、来源与原因去重，包括回到更早的会话或会话重叠的情况。诊断携带固定原因码与相对规则作用域可定位的来源，绝不携带规则正文、绝对路径、原始解析错误、正则源码或对话内容。文件失败只影响该文件，目录失败只影响该目录，意外处理错误保留传入块及更早组件的结果；诊断本身失败也不能中断模型 turn。正则按 JavaScript 正则运行，无超时也无沙箱。

### 宿主覆盖

每个 turn 使用其有效事件模型与当前 cwd；没有模型就不读取规则。刷新的粒度是每个 turn，而不是每个 Provider 请求、临时中途切换或自动回退，因此新增、编辑、删除与修复在下一个被覆盖的 turn 生效，无需重启，也不需要正文快照或缓存。覆盖范围是运行公开 `before_agent_start` hook 的普通主会话与普通子 Agent，每个子 Agent 保留自身模型、角色与独立块。不为 plan-mode 子 Agent、Handoff、标题、分类或其他旁路新增注入入口，后续 handler 保留改变最终输入的权力。

项目目录中的规则文档会把仓库内容变成系统提示词文本。项目规则可以成为系统指令，本组件不增加信任门槛、安全隔离、正则沙箱或超时，也不设置正文大小限制。公开文档说明该目录与注入方式。

### 上游复核

组件记录当宿主自己提供模型作用域指令时需要做的复核，形式见上游 [issue #6739](https://github.com/can1357/oh-my-pi/issues/6739) 或等价能力：

- 宿主覆盖哪些匹配维度，例如精确的 `provider/model` 键、裸模型 id、子串与正则；
- 宿主文本与已被替换或自定义的系统提示词如何组合：替换还是追加，以及它在块顺序中的位置；
- 宿主文本何时刷新：每个 turn、每个 Provider 请求、模型切换、临时切换与回退时；
- 宿主如何发现规则：目录、用户与项目优先级，以及文件顺序。

复核结果决定本地能力是保留、只补宿主未覆盖的部分，还是移除，并带相应的版本变更。

### 验证

组件检查覆盖各匹配键的正反用例、同一文件内的多条目择一语义、规则校验与 BOM 处理、LF 与 CRLF 的正文保真、两个目录之间不受读取完成顺序影响的排序、目录缺失，以及追加块不跨 turn 累积。

真实宿主检查记录所使用的 OMP 版本、模型与观察到的面向 Provider 的请求，handler 的返回值不算 Provider 证据。检查确认追加文本到达请求、frontmatter 绝不出现、模型切换后按新模型重新匹配、宿主块与动态内容保留，以及追加文本不跨连续 turn 或中途提示词重建重复出现。

### 决定反转

| 已归档决定中的生效条款 | 选择与冲突 |
| --- | --- |
| 模板、Delivery 章节与页脚归系统提示词组件，由它继续维护 | 该组件及其仓库内容已被[移除 omp-system-prompt 扩展](./07-omp-system-prompt.zh.md)删除。把上述行为归给一个仓库中已不存在的组件的边界不能继续有效。 |
| 两个组件共存时实际加载顺序必须是系统提示词组件在前、QoL 在后，且互不依赖对方文件 | 两个组件中的一个已不存在，该要求没有对象。提示词管线中不再有任何环节依赖另一个扩展被安装或排在前面。 |

本次反转只改动表中的两个条款，选择本身不因它变化。本决定完整记录留在 QoL 的规则：组件开关、规则匹配与注入、诊断与失败隔离、覆盖范围、上游复核与验收。已归档决定说明规则为何迁入 QoL，以及当时考虑过哪些替代方案，不再承载任何现行约束。[为系统提示词扩展添加模型作用域提示词规则](../../../archived/2026/09/14-r1-model-prompt-rules.zh.md)的反转随这些规则一同转移，并由本决定承接，因为它把规则迁入的组件正是本决定记录的组件。

## 考虑过的替代方案

反转已归档决定时有过这些选择。

- **保留已归档决定为现行决定，把它的两个条款改写成事实性维护。** 在核对哪种机制适用时考虑过。事实性维护用于在路径、名称或验证入口移动时保持现行决定准确；这里条款失去了对象，改写就等于用不被允许反转决定的机制反转决定。
- **用 `## 变更` 追加一条记录撤回这两个条款。** 作为更轻的机制考虑过。追加内容只在不与决定冲突时允许，而撤回现有条款约束力的记录与之冲突，因此这条路不成立。
- **把模型提示词规则随被移除的组件一起迁出 QoL。** 在判断这些规则是否还有对象时考虑过。本次移除删除的是组件而不是能力：规则在任何宿主上都服务会话，其运行从不依赖该扩展的模板，公开文档也一直把它们描述为 QoL 的一个模块。

## 结果

- 规则不再依赖另一个扩展被安装、排在 QoL 之前或同步更新。产生本模块的两组件协同更新流程随之消失。
- 项目目录中的规则文件会把仓库内容变成系统提示词文本。OMP 不做项目信任校验，项目设置与扩展对当前目录无条件加载，因此一个带有 `.omp/model-prompts/*.md` 的克隆仓库可以为在其中打开的会话添加指令。维护者把自己的规则放在用户目录。
- 若宿主改动开始把上一个 turn 的覆盖结果当作输入回灌，追加文本可能不断累积。追加步骤依赖宿主每个 turn 从基础提示词构建提示词，这一点若改变，每个匹配正文会在每个 turn 再增加一份。
- 规则正文会增大每个匹配 turn 的系统提示词。没有大小限制或预算检查，因此一个很大的规则文件会把全文加到会话后续的所有 turn，并挤占其他提示词内容。
- 文本匹配无法区分有意匹配与偶然匹配。`contains` 或 `regex` 规则可能作用于比作者预期更多的模型，而无法编译的正则只会丢弃该规则，诊断也不说明作者本想覆盖哪些模型。
- 追加步骤在 hook 运行的每个 turn 读取两个规则目录，因此缓慢或远程的目录会逐 turn 延迟提示词组装，且没有缓存可以摊薄。
