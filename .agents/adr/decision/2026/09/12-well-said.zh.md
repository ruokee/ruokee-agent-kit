## 动机

保留 `well-said` 作为指导自然、直接表达的双语 Skill，来源署名写在仓库根 README，许可与来源事实写在本决定。

[上一版本](../../../archived/2026/09/12-r2-well-said.zh.md)把署名与许可文件放在写作指令旁边。这两个位置都不适合这类材料。Skill 里的文件会作为指令进入 Agent 上下文，或与指令一起被宿主和 Agent 当作同一个组件读取，法律通知对写作会话没有意义，还可能被读成能力规则的一部分。署名与许可信息服务于仓库的读者，由仓库把它们记在 Skill 树之外。

重写从能力最原始的需求和原始资料出发。旧 Skill 只作辅助参考，不作为验收清单。章节覆盖或范围不同，本身不能说明重写稿有问题。

记录须区分 Ruokee 对 well-said 的作者归属，以及 Lauren Tan 对复用的 unslop 材料的作者归属。

## 决定

### 能力范围

保留 `well-said` 作为独立编写、可由模型调用的 Skill。适用说明为"输出任何内容时使用"，包括回复、文档、代码和配置中的注释，以及 Agent 交流。继续支持明确调用。

每个语言组件的 `SKILL.md` 提供完整的英文或中文写作指南，按写作流程、文风模式、防御性表述、可见的编写会话残留、文章写作和作者声音组织。两种语言都保留原意，以及作者真实的观察与判断。两个版本均不依赖其他 Skill 或仓库支持文件。

将防御性表述视为文字问题，也视为可能尚未完成工作的信号。覆盖证明姿态、认知边界和未执行工作的交代。两种语言都列出中英文代表表达，说明危害和处理方式。这些表达用于提示判断，不构成禁用词表。

区分表述问题和工作问题的处理方式。只是措辞过于保守时，把已有依据的结论说清楚。工作缺失或结果有误时，在授权范围内补做或返工。工作本身没问题时，按读者需要重写有用段落，删除空洞段落。保留事实、实际风险、重要未知、授权条件、必要论证，以及用户或适用流程要求的状态报告。

### 组件布局

英文组件继续位于 `skills/well-said/`，中文组件继续位于 `variants/zh/skills/well-said/`。两者都是自包含分发组件，只包含 `SKILL.md`，其中提供写作指令，并在 frontmatter 的 `metadata.version` 中声明版本。

Skill 正文不重复来源署名、许可文本或版本号。来源署名由仓库根 README 的条目承载，上游路径、固定版本与许可由本决定记录。

使用 `1.0.0` 作为正式发布的起始版本。后续发布遵循仓库版本政策。普通 Skill 不增加包 manifest、检测器、plugin 或运行时依赖。

[第一方能力决定](../08/20-first-party-capabilities.zh.md)区分 well-said 主体归属和复用材料的作者归属。文风章节大幅保留来源措辞、示例与有效组织，并作必要衔接和补充。保留的原文来自 [Cursor plugins / pstack](https://github.com/cursor/plugins/blob/99559f2f52047978602ef365589275831e76af07/pstack/skills/unslop/SKILL.md)，版本为 `99559f2f52047978602ef365589275831e76af07`，采用 [pstack MIT 许可](https://github.com/cursor/plugins/blob/99559f2f52047978602ef365589275831e76af07/pstack/LICENSE)，版权人为 Lauren Tan，年份为 2026。后续复用其他材料时，须在分发前核实来源、权限、署名和通知。

完整写作指南保持在一个文件中。只有实际内容与加载测量表明有必要时，才移出篇幅可观的低频补充材料。日常写作仍由 `SKILL.md` 中的完整规则支持。

### 编辑权限

写作规则适用于自然语言文本，包括代码和配置中的注释。引文、命令、标识符、原始日志、录制输出及其他字面材料，在其用途或用户请求要求逐字保留时保持原样。

遵循用户指定的文件、文本和结构。审阅请求在未获编辑授权时保持只读。

unslop 的明确禁令保持强制性；标点规则、其示例与写作规则本身由 [variants/zh/skills/well-said/SKILL.md](../../../../../variants/zh/skills/well-said/SKILL.md) 持有。

允许在授权范围内调整结构，包括重排段落、合并重复、重写开头和结尾。调整非常广泛时，Agent 可以询问是否整篇重写；已有授权即可执行，不设置人为改动比例门槛。保留固定结构。

对照原始信息和当前请求复核结果。尤其不能把未测试环境写成不支持环境、把义务写成已经完成的行为、把假设设计写成已有能力。保留具体未知，查证有实际影响的矛盾，不以流畅改写掩盖问题。

### 加载

将 Skill 应用于输出前，取得完整 `SKILL.md`。描述、摘要或截断片段不能代替完整指南；宿主未提供的内容需要补齐。当前上下文已有完整正文时复用，不为每次回复重复读取。上下文丢失导致所需内容不可用时，恢复该内容。

起草和编辑时综合应用相关章节。纠正、撤销和替换要求时检查当前有效需求及会话残留；润色请求关注文风；反复自证时检查证明姿态。这些信号用于在已有正文中确定关注点，不触发额外文件读取。普通输出同样遵循完整的适用规则，已经清晰的文字可以不改。

加载失败时，使用已有规则与保护边界，必要时说明受影响的检查范围，不宣称已经应用缺失内容。分别验证宿主发现、完整加载与规则遵循；仅有完整加载不能证明写作质量。

验证写作规则时，使用新输入测试与回归检查。

### Agent 交流

写作范围明确包括 Agent 之间的自然语言消息：委派、任务交接和评审反馈。这类消息面向将要执行任务的 Agent，也面向之后阅读它的人。

- 传递任务、材料、授权与范围限制、影响继续工作的实际状态以及验收标准。简短消息只需包含会改变接收方行动的项。
- 省去发送方的重试、等待、批次调度和上下文整理叙述，除非它们改变接收方的下一步行动。
- 保留阻塞、权限缺失、未核实或部分完成的写入、未满足的依赖，以及防止重复副作用所需的信息；不把未完成或未知状态写成已完成。

## 考虑过的替代方案

- 短核心加三份按需加载的专项指南。低频专项材料较多时可能节省上下文，但增加了信号识别、文件读取和多指南综合处理。完整单文件省去日常写作中的这些依赖。

## 结果

过度清理可能删除限定、迁移义务、证据、有用历史或作者声音，产生流畅但误导的文字。共同保护规则以及应该保留和应该修改的配对案例需要约束所有章节。

完整加载可能让当前回复不需要的细节占用上下文，较长文件也可能使关键规则更容易被忽略。测量实际内容和加载行为，保持结构清楚，同时检查漏清理与有害误改。
