# 上下文 Pin

## 动机

将上下文 Pin 作为自包含扩展 `@ruokee/omp-smart-context` 中显式开启的能力维护。

安装其他上下文能力不能自动增加模型工具。已有 Pin 用户迁移包后，需要保留已接受的正文、journal 身份和生命周期行为。

## 决定

smart-context 包拥有 Pin，不依赖独立 Pin 包或其运行时文件。独立开关 `pinEnabled` 默认 `false`，来自包的原生激活快照。非法 Pin 设置只停用 Pin，其他有效能力继续可用。

关闭 Pin 时不注册 `ctx_pin` 工具、`/ctx-pin` 命令或 Pin 投影 handler，保留已有 journal 记录和普通历史。开启时只注册一次，并使用当前会话事件上下文初始化，不等待新增 handler 再次收到同一事件。宿主继续保留 `/pin` 自用。

会话 journal 继续作为权威来源。保留受支持的 `omp-context-pin`、`omp-context-pin-change`、`omp-context-pin-result` 数据标识及 schema version 2，也保留整数身份、revision、重试身份和重放。不改写用户日志，不引入独立存储。既有重置、导航、分支、重启和压缩语义继续有效。

[工具合同](../10/17-context-pin-tool-contract.zh.md)规定六个动作、当前条目写入、查找前重试识别、完整 `show` 和来源标签。读取操作不写入。用户提交保留确认，Agent 变更采用非主动交付。所有工具动作声明审批级别 `read`；Pin 不新增授权或来源准入门禁，也不写用户配置。保留文本不提高指令权限，不恢复撤销的授权，不重启已完成工作。

[Pin Spec](../../../../spec/omp-smart-context/pin.zh.md) 维护用法、记录、编号、重置、持久化、缓存行为和可调整的字节上限。上限约束单条正文及活跃正文总量。拒绝写入不改变状态，超限时仍可读取条目和取消固定。[主 Spec](../../../../spec/omp-smart-context/README.zh.md) 维护共同目标、不变量、宿主下限及组合验收。[Pin 指南](../../../../../projects/omp-smart-context/docs/pin.zh.md) 说明用户操作与限制。

验收采用仓库检查及实际 journal、投影路径的本地受控运行。已提交压缩后的最终请求逐字包含最新有效正文，旧 revision 不能在其后重新生效。组合请求不重复 Pin 投影或模型规则，每条请求最多有一个对齐改写方。受控响应验证这些机制，不验证模型生成摘要的质量、真实 Provider 收益或 TUI 行为。历史证据保留原有条件。

迁移需要显式开启 `pinEnabled`、移除旧扩展并重启。包不会自动安装或迁移配置。

## 考虑过的替代方案

- 默认开启 Pin。已有用户无需增加开关，但仅安装其他能力的用户会多出模型工具。默认关闭保留选择，代价是迁移时显式设置。

## 结果

- 已有用户漏配 `pinEnabled` 时，在开启前不会产生新增投影。journal 数据仍可重放。
- 按当前条目写入的合同，用户确认旧草稿后可以覆盖较新正文。更新后，旧尾部消息和 opaque 历史仍可能保留早期文本。
- 活跃正文字节上限不约束 token、元数据或累计 revision，完整请求仍可能溢出。具体取值由组件决定，不固定为 ADR 常量。
- 规范记录与模型投影相互独立。跨重启、排队和压缩的恢复可能遗漏投影，或交付重复及过期 revision。边界选错会丢失已接受的变更，其他扩展或最终 Provider 转换也可能改变消息顺序。因此验收检查被测组合的最终请求。
- Provider 原生远端压缩让部分历史保持不透明。Pin 保留该载荷，不声称对其去重。
- 保留文本可能被理解为授予权限，会话内整数也可能跨会话冲突或从错误范围恢复。来源标签、说明措辞及会话级高水位处理这些风险；Provider 边界的最终 role 以核对结果为准。
- 非主动交付可能把变更推迟到下一次普通 prompt。当前请求从规范记录推导自身变更。用户提交由交给宿主的文本识别，并在持有该文本期间认领一次。
- 请求采集可能泄露凭据。采集在写盘前排除敏感传输字段，不改变实际请求。
