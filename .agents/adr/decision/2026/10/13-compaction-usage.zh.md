# 压缩用量

Decision owner: Ruokee
Decision writer: OMP DeepSeek V4.1 Flash
Reverses: [压缩用量](../../../archived/2026/10/13-r1-compaction-usage.zh.md)

[English](./13-compaction-usage.md) | 中文

## 动机

通过 [smart-context](./12-smart-cache.zh.md) 将 OMP 的 soft 压缩与 Handoff 用量记录到会话 journal，直到验证过的原生记账替代补偿。

会话压缩时，OMP 会发出自己的摘要请求：`soft` 方法的 summary、short-summary 与 turn-prefix 调用，以及 `handoff` 方法的请求。这些请求都由提供方计费，用量也会报告给宿主，但数值止于摘要调用：没有写入任何 `model_usage` 条目，读取这些条目的会话统计因此漏掉它。于是会话文件少算了该会话的成本，基于这些统计的报告、预算或配额视图也按该会话执行过的压缩次数偏差。

上游把该缺口记为 [issue #15031](https://github.com/can1357/oh-my-pi/issues/15031)，并在 [pull request #15034](https://github.com/can1357/oh-my-pi/pull/15034) 中修复。

## 分析

宿主所需的数字本就在其遥测通道中流动，而默认安装下该通道是关闭的。每个本地压缩与 handoff 请求都经过同一个插桩补全包装层：它创建 chat span、把该请求的 oneshot 类型盖在 span 上，并发出携带用量快照与响应结束原因的 chat usage 事件。压缩与 handoff 的调用点在每次调用前从 agent 解析遥测配置，除非用户配置过遥测，否则解析不到，因此默认安装既不产生 span 也不产生事件。该通道因此是取得这些数字的唯一公开入口，而启用它会改变宿主行为：有配置存在时，宿主会为本来跳过的模型步骤创建 span 并运行钩子路径。

该通道的三个性质决定了补偿的形态。被取消或失败的尝试同样会发出事件，快照全为零、结束原因为错误，因此没有过滤的写入方会记录零用量噪声。仅有用量快照不足以写入条目，因为会话文件还要存实际运行的 api，而它只能由会话自身的模型注册表从事件给出的 provider 与 served model 解析。此外没有任何路径能到达请求本身，因此在包装层内部被重试掉的尝试无法恢复。

退出条件是运行时可观察的。[pull request #15034](https://github.com/can1357/oh-my-pi/pull/15034) 由宿主自己记录这些请求，并为此从 `@oh-my-pi/pi-agent-core` 导出 `compactionRequestUsage`，包根也会再导出它，因此调整可以直接读取该导出识别这种宿主，而不必依据版本号推断。

## 决定

### 公共配置

`compactionUsageEnabled` 是 smart-context 中独立的原生 boolean 设置，默认 `true`，没有总开关。随包的激活快照读取，修改在下次启动 OMP 时生效。模块设置非法只停用本能力。`/smart-context` 报告有效状态与固定原因，不启动模型 turn，不暴露请求内容。

其效果是：一个完成的压缩或 handoff 请求会出现在会话的用量条目中，以及宿主据此推导的统计里。

### 介入位置

本调整替换宿主 `Agent` 原型上的 `telemetry` 访问器，压缩与 handoff 调用点在每次调用前解析该值。进程级登记和按归属释放访问器独立于对齐包装、journal 及模型规则状态。

用户已有的配置会被保留：其 tracer、成本估算器与 chat usage 钩子继续服务它们原本服务的每个请求，本调整不向导出添加任何内容。没有配置时，本调整提供惰性配置，其 tracer 创建宿主本来会创建的 span、记录本模块读取的三个属性，且不导出任何内容。

请求由宿主盖在该请求自己 span 上的 oneshot 类型识别，类型取自本模块包在 tracer 外的包装层。本调整不读取 span 上的其他属性，也不触及请求、模型、缓存键、历史或会话文件。

### 记录内容

范围内共四种 oneshot 类型：`soft` 的三个摘要类型与 `handoff`，对应 `compaction:summary`、`compaction:short-summary`、`compaction:turn-prefix` 与 `compaction:handoff`，即上游修复所解析的 purpose。该列表是封闭的：`compaction_native` 与 `branch_summary` 属同一族但修复同样不记录，宿主标注的其他类型都属于宿主已记账的调用方。

一个完成的请求通过会话管理器自身 API 写入一条 `model_usage`，落在请求所属会话的分支上，包含解析出的 purpose、实际 api、provider、model 和 stop reason、提供方 token 数，以及宿主携带时提供方给出的分项成本。条目形状与宿主为自身旁路请求写入的一致，因此会话统计会计入它。不编造 API、Provider 或价格。

未消耗任何 token 的尝试不写入，因此被取消或失败的尝试不会留下零用量噪声。会话在本进程中已不存在、或 api 无法解析的请求不写入而是计数，因为猜测的 api 与缺失的条目是可见的，而错误的条目看起来已被修好；本组件从不自行估算提供方成本。

### 退出

激活时读取原生 `compactionRequestUsage` 导出，宿主自己记录这些请求时保持停用并报告原因，避免重复条目。[用量 Spec](../../../../spec/omp-smart-context/usage.zh.md#原生替代) 维护需要验证的原生记账与统计行为。PR #15034 合并触发复核，不证明某个已安装宿主正确记账。

已发布的原生行为经验证能替代补偿后，删除模块代码、设置、状态、文档和检查，更新本决定与能力清单，保留历史 journal 条目。不删除请求对齐，也不因本能力退出而反转包级合同。

### 迁移

移除 QoL 实现、登记、停止路径、状态和 `compactionUsageEnabled` 设置，从用户级与项目级 QoL 设置中清除此键。在 smart-context 中保留旧有效 `enabled && compactionUsageEnabled` 结果，先解析项目覆盖再计算。新默认值不能启用原本被 QoL 总开关关闭的记账。保留无关设置并重启，不增加回退读取器或自动配置修改。

### 验收

使用仓库检查，以及实际候选和锁定宿主记账路径的受控请求。验证范围内消耗 token 的每条请求仅记一次、正确会话身份、用户 telemetry 保留、提供方成本数据、排除及零 token 请求、原生自动停用，以及宿主统计增量。历史真实 CLI 证据保留实际条件，不作为集成门槛。本合同替代 QoL 归属、总开关依赖和继承的真实 CLI 门槛，四类 purpose 和数据合同保持不变。

## 考虑过的替代方案

无

## 结果

- 挂接遥测配置会改变宿主行为。有配置存在时，宿主会为本来跳过的模型步骤创建 chat span 并运行钩子路径，为每个请求增加工作量，并向用户已配置的导出发送内容属性。惰性配置与 tracer 包装使导出保持为空、只读取 oneshot 类型，代价是此前直接短路的压缩与 handoff 请求现在多出包装层自身的工作。
- 用量可能归属到错误请求或分支。事件 span 若不是读取类型的那个 span，条目就描述其他请求；落入其他分支会使目标统计漏记。因此 `/smart-context` 显示启用时总计仍可能错误。类型取自事件自身 span，跳过未知 span，并在写入时解析分支位置。
- 宿主自己记账后，仍启用的补偿会抬高 token 数与成本。删除模块前由原生检测及 `/smart-context` 状态防止重复。
- 条目位于所属压缩之前，依赖宿主的活动窗口记账。宿主变化可能在不拒绝 journal 条目的情况下使总计漏记，因此受控验收同时观察宿主统计增量和记录。
- 提供方成本依赖组件声明的宿主下限之后才出现的字段。宿主不再盖类型戳或把本模块没见过的 span 交给事件时，本调整只会不写入。维护证据逐项记录未验证场景，不暗示存在连续的可用宿主范围。
- 任一 QoL 配置层级遗留迁出键都会拒绝整个配置。复制模块值而不折算旧总开关结果可能意外开启记账。
