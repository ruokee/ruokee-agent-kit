# Context Pin 工具契约

Decision owner: Ruokee
Decision writer: OMP DeepSeek V4.1 Flash

[English](./17-context-pin-tool-contract.md) | 中文

## 动机

调用者应按当前 Context Pin 条目操作，不必提供 revision，并应能一次读取完整活跃集合。

此前的公开契约要求 `update` 和 `delete` 提供 `expectedRevision`，调用者必须在每次写入前读取，revision 变化会拒绝写入。工具还只有摘要列表和单条读取，需要整个活跃集合的调用者只能组合多次读取或依赖旧视图。这些要求增加工作，也容易让 Agent 在不检查其他活跃条目的情况下局部修改。

## 决定

`ctx_pin` 工具提供六个动作：`list`、`get`、`show`、`create`、`update` 和 `delete`。

`update` 和 `delete` 按 id 指向活跃条目，并作用于执行时的当前条目。公开 schema 不再接受 `expectedRevision`。revision 仍保留为内部记录、显示值和重放依据。

重试沿用现有操作身份。已接受操作的重试返回原结果，不追加记录，不改变活跃集合和后续写入。重试识别先于当前条目查找，因此已接受的 `delete` 重试在条目已删除后仍返回原结果。相同身份携带不同动作、条目目标、来源或正文时是冲突；不比较 revision。

`show` 只读。返回当前分支全部活跃条目，包括每个条目的 id、来源、revision、UTF-8 字节数和完整正文，以及条目数、总活跃字节和分支上限。空分支时说明没有固定正文，并报告总活跃字节为零和分支上限。它不追加记录，不改变 revision、活跃用量或投影。

分支容量拒绝报告分支上的总活跃字节、被替换正文（`create` 为零）、拟写入正文、尝试后的总量和超出量。单条拒绝报告正文大小、单条上限和单条超出量。两种拒绝都不写入、不改变活跃集合，并要求调用者检查整个活跃集合。两种拒绝都不把拆条描述为减少活跃字节的方法。

用户确认的编辑或删除作用于当前条目。对话框打开时显示的 revision 只是展示信息，不是准入条件。旧草稿因此可能覆盖对话框打开期间被更新的正文。

既有受支持的 journal 记录保持原样重放；条目 id、操作身份和 revision 不重新编号，也不迁移。

[Pin Spec](../../../../spec/omp-smart-context/pin.zh.md) 维护 smart-context 中 Pin 能力的动作列表与可观察行为合同。[主 Spec](../../../../spec/omp-smart-context/README.zh.md) 说明共同目标和不变量，[Pin 指南](../../../../../projects/omp-smart-context/docs/pin.zh.md) 说明用户操作。[当前 Pin 决定](../09/15-omp-context-pin.zh.md)负责激活边界并继续有效，本工具合同保留其 `read` 审批档位和对组件可调上限的委托。

## 考虑过的替代方案

无

## 结果

- 旧用户草稿或从旧视图编辑的 Agent 可能覆盖较新的正文。用户确认对话框写入，但两个入口都不再通过 revision 门槛拒绝并发变化。
- `show` 可能返回大量正文并消耗上下文。它是显式读取，不是默认动作。
- 仍发送 `expectedRevision` 的旧调用者可能因宿主拒绝未知字段而失败。公开文档和 schema 同次修改。

## 变更

### 2026-10-24 完整集合读取

`list` 返回与 `show` 相同的全部完整活跃正文及元数据，调用者复核活跃集合时无需逐条读取。`get` 保留完整单条读取。三个动作均逐字保留空白、换行和长正文，不改变记录、修订、活跃用量或投影。动作集合和 journal 格式保持不变。

完整 `list` 响应比预览消耗更多上下文。按宽度显示的标签仅用于交互选择列表，不截短工具结果。
