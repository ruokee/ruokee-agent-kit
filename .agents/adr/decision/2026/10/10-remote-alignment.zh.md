# Remote 对齐

Decision owner: Ruokee
Decision writer: OMP
Reverses: [Remote 对齐](../../../archived/2026/10/10-r2-remote-alignment.zh.md)

[English](./10-remote-alignment.md) | 中文

## 动机

在 `@ruokee/omp-smart-context` 中维护远端压缩缓存对齐，覆盖主会话、原生子会话及同进程导航。

普通请求在上下文处理器返回之后还会完成其他转换，原生 V2 则独立准备保留历史。比较中间上下文或要求所有请求选项都相等，会拒绝有效的共同内容修复。每个会话需要自己的已确认参照，以及导航结算后的恢复路径。

Remote 与 Handoff 修复的协议和证据不同。Remote 的 Responses V2 规则只用于 remote 请求，不用于 Handoff。整合包归属不改变两者算法。

## 分析

最终已发送结果与其源范围证明的是不同事实。观察最终载荷可以证明实际发送内容，却不能证明跨范围结果在原生裁剪之后仍有可复用的部分。普通请求若只发送了不可分结果 `Y = F(U, T, s)`，而 V2 把 `T` 改为 `T'`，就可能不存在独立发送过的 `U` 结果。复用整个 `Y` 仍保留对已移除内容的依赖；计算 `F(U, T', s)` 会生成新结果，还可能重复处理器副作用。更多来源信息不会创造不存在的独立已发送结果。

因此，复用边界支持完整保留范围与可独立复用的局部结果。不可分依赖变化保持原生请求，并计为未对齐。不把处理器限制为一对一转换，不改变原生裁剪，不要求新增处理器协议，也不把未知证明等同于已证明不可能。客户端对齐、原生可用性与 Provider 缓存收益分别判断。

## 决定

### 公共配置

Remote 对齐是 [smart-context 扩展](./12-smart-cache.zh.md)的一项能力，扩展决定记录本包、能力模型及共同维护下限。

Remote 公共合同使用 OMP 原生设置：`compactionCacheEnabled` 默认 `false`，`compactionCacheProvider` 默认 `""`，`compactionCacheMode` 默认 `"hooks"`。模式只接受 `standard` 和 `hooks`，不决定是否启用修复。用户显式选择一个准确的已配置 Provider 名称。不新增 Provider 列表、其他模式、Handoff 占位设置或第二种配置来源。

该 remote 合同的模式集合有意闭合，因为两种模式保留不同的准备及复用承诺；扩展集合须形成新的合同决定。多 Provider 选择及 Handoff 接口不属于本次范围，不是对单独定义能力的永久禁止。原生设置仍是唯一来源，以保留宿主管理的覆盖优先级与重启语义。

OMP 管理用户值、项目覆盖及解析。将有效设置读取并校验为一份激活快照，重复激活事件不重复登记。改动须重启 OMP；创建或导航会话不刷新既有快照。子会话使用自己的实际模型、API、工具、提示词与身份，不使用父会话模型，也不重新热读配置。非法设置或接口不可用只影响对应能力或登记，不停用其他活跃会话。诊断写键与固定规则，不回显取值。

`/smart-context` 不启动模型 turn，只报告 remote 状态。状态区分 `disabled`、`unavailable`、`awaiting-reference`、`already-aligned`、`rewritten` 与 `rejected`。分别保留在线确认、操作绑定、候选校验及发送的原因，避免后续缺少参照覆盖原始证明失败。逻辑操作与物理发送及重试分别计数；改写、原生结果采用和 Provider 缓存命中是不同结果。诊断只用有界计数、会话及操作局部标识和固定原因，不包含请求正文、opaque、凭据、原始端点、私人路径或动态私密键。不携带正文采样日志、试验环境变量、采样命令或特殊限流中止策略。

### 目标请求

覆盖所选 Provider 在主会话及原生 `task`、Eval 子会话中的非 Codex `openai-responses` 原生 V2 请求。保留首次、再次及进程恢复后的压缩，以及宿主向相应会话类型提供的手动、自动、轮内和投机入口。宿主缺少某个入口不要求扩展新增。非目标 Provider、模型、API、Codex、V1 与无法识别的形状保持原生行为。

没有上下文处理器时，两种模式均完成通用对齐，且都要求最终传输确认与完整候选校验。`standard` 保留已识别的原生修复，不因新增观察入口获得通用处理器投影。`hooks` 额外复用已证明的完成上下文处理，包括插入、重排、恢复和跨范围合并。两种模式都不重新运行处理器、不识别配套扩展的正文格式、不读取其私态，也不维护替代 Provider 序列化器。

只有实际普通主循环 dispatch 提供参照。源历史、完成准备、既有载荷回调的最终结果和实际传输必须对应同一次 dispatch，并原样到达发送边界。标题、advisor、cache warming、Handoff 及其他旁路请求不能成为普通参照。新的在线候选确认前暂停未来操作绑定；已经绑定的操作保留不可变旧参照，包括明确的缺少参照状态。观察失败局部处理，不吞掉原生回调、resolver 或传输异常。普通及非目标请求逐字节不变。

### 复用单元

复用单元是同一次普通请求已经发送、可独立提取的结果，须证明源对应、组装边界，以及全部源依赖仍完整保留在原生 V2 范围且未变化。操作捕获的参照和相关处理条件须有效。输出相同、数组长度、索引、仅有来源信息或消息看似独立都不足以构成证明。

完整保留源范围可以作为包含全部已发送结果的一个单元，合法处理器可以改变消息数量与顺序。优先使用完整范围证明，再尝试局部匹配；合法重复源消息或局部匹配歧义不能使已证明的完整范围失效。只保留部分源时，复用原生逐项语义或已有独立结果证据所证明的单元，且证明须贯穿后续每项转换。保留原生改写项，不用旧原文替换。

不可分单元的依赖被裁剪或改写、且没有独立已发送部分结果时，完整目标请求保持原生形式，报告 `projection-dependency-changed`。源、依赖或结果边界未知时，完整请求保持原生形式，报告 `projection-unconfirmed`，这是证明缺口，不表示转换天然不可投影。这些拒绝只通过相应安全边界，不计为对齐。已知完整范围和独立局部正例仍为必需项，裁剪或黑盒处理都不允许一律拒绝。

完整候选通过校验后才一次原子替换。保留 system 内容、日期及 cwd 提醒、工具 schema 与描述、已识别的 reasoning/replay 及默认语义、新增普通/工具/图片历史、原生工具输出裁剪、调用与结果配对、压缩专用尾部、trigger 和 opaque 替换历史及其顺序。不展开或重建 opaque，不补回已移除依赖，不重算处理器输出，不改为按转换结果而非原生源历史裁剪。

按字段原生含义分类，不要求普通请求与 V2 的所有选项相等。保留 V2 自己的 `max_output_tokens` 原值或缺省，不补入在线限制。其已知合法差异不能阻止无关共同内容对齐。只有证明原生 `tool_choice: auto` 为隐式默认、且在线没有显式选择时，才可规范化它。保留显式工具选择、模型策略、鉴权、路由、缓存键、Provider 响应及已存历史；差异使参照失效时拒绝。每项未分类差异都保留完整原请求。候选相同记为 `already-aligned`，不计改写，也不因此重新序列化。

### 包装归属

遵循[共享请求对齐合同](./22-request-alignment.zh.md)，不把用量 telemetry、模型规则状态或 Pin journal 纳入协调器。不读取 Pin 私态，不用当前规则重建已发送输出。

进程只安装一组传输及原生信号组合包装，每个实际模型注册表只薄包装一次 resolver，每个实际会话独立登记。兼容的重复登记幂等，第二个会话不是归属冲突。区分持久会话身份与 Provider 会话身份，明确绑定会话、模型、dispatch、原生根信号、epoch 及协调器代次。模型相同、端点、缓存键、时序或相似正文都不能证明归属。原生端点与 V2 形状仍须独立检查。

保存信号父关系，并在使用信号时解析归属，覆盖先派生后绑定 resolver，以及多个普通 dispatch 共享根信号。归属明确的不同操作可以并存。每项原生操作在较新在线工作、处理器状态推进、认证刷新和传输重试之间保留初次捕获的不可变参照。重试不能取得较新参照。身份未知或冲突、取消、失效 epoch、旧协调器代次或含糊复用都使该请求保持原生形式，不停用其他有效会话。

切换、分支或树导航之前撤销该会话旧 epoch 与参照。导航中不确认新参照。成功、取消或失败之后，核对原生转换状态已结算且当前身份有效，再通过新的普通发送恢复资格，不要求重启进程。不只依赖成功事件或计时器，不恢复旧操作。子会话完成、关闭、取消或替换只释放自己的登记；revive 的子会话须取得新的有效参照。

只还原仍由自己持有的函数及其原始属性形状。会话包装丢失只影响该登记；共享传输或信号归属丢失影响依赖它们的登记。混装版本、不可读取的注册表与外部覆盖属于冲突，不构成抢占或重装他方包装的许可。最后一个登记结束后释放共享资源；后续新登记可以创建新的协调器代次，旧操作仍失效。只保留各会话最新参照及原生操作可达快照，共享不可变数据，不在每次重试复制大型数据。不维护不断增长的已完成操作历史；没有活跃目标登记需要时不解析正文。

### 原生职责

OMP 保留准备、触发、投机启动与等待、取消、认证及传输重试、模型与方法回退、结果校验及采用、历史提交和续接。原样转发原生参数、receiver、凭据结果、Promise、异常、信号与取消原因。不读取凭据内容、不增加认证或参照请求、不包装公开的手动压缩方法，也不把一次凭据解析或传输结束视为操作完成。非 V2 回退保持原生行为，不报告为 V2 成功。

不注册 `session_before_compact`，不把它作为回退，不隐藏其他处理器、不绕过否决，也不修改其他扩展设置。QoL 单独启用的期限模块及其他扩展仍可按自身合同否决投机。Remote 对齐保留原生投机结果直接采用，不发替代请求，但不承诺投机已全局启用。

按能力及结构选择受维护行为。受维护原生接口在所有必需路径提供等价结果、配置语义、隔离与失败行为时，通过行为验证后替换本地适配，不仅凭上游 PR 合并就替换。

### 决定反转

后继以 smart-context 和 `/smart-context` 替代 smart-cache 归属及状态入口，以仓库检查和受控集成替代必需的真实 Provider 收益发布门槛。来源证明、模式、会话范围、原生职责、生命周期、诊断及原生替换条件继续有效。

早期 QoL 切换保留在归档决定中。QoL 继续拥有自己的合同，包括期限 owner 的 `owner-stopped` 终态和 replay 归属。对齐可新建协调器的生命周期不放松这两项边界。

### 直接切换

在用户级与项目级把既有 smart-cache 设置迁入 smart-context，保留有效启用状态、Provider、模式和覆盖关系。运行时代码不读取旧命名空间，不修改用户设置或安装。移除旧扩展入口并重启相关进程，不热转移在途 owner 或参照。共存的旧 smart-cache 或 QoL remote owner 产生冲突，不授权接管。不保留别名、shim 或跨组件运行时依赖。

[组件 Spec](../../../../spec/omp-smart-context.zh.md) 规定通过仓库检查和使用实际候选、锁定宿主库的本地受控运行验收。保留两种模式的正例与拒绝用例、独立开关、原生请求语义及只读状态。真实模型调用、缓存收益测量和完整 CLI/TUI 矩阵不是集成门槛。Provider 收益声明需要完整分母下的真实可比重复测量。

组件双语文档拥有详细设置与命令、适用性、副作用、原生关闭表现、固定源码基线、实际运行版本和原生替换条件。历史证据保留原条件，区分源码检查、受控集成、真实 CLI 覆盖、客户端对齐、原生采用及 Provider 测量。

## 考虑过的替代方案

- **新增冻结纯投影合作协议。** 它允许一次有状态准备后计算新结果，但要求处理器合作及无副作用证明，改变已发送结果复用合同，也不保证新结果复用旧 Provider 缓存。本决定不新增该协议。

## 结果

- 源对应错误、单元边界丢失或并发归属错误可能插入另一会话内容、补回被移除历史或破坏工具配对。替换前须完成整段与局部证明、明确身份、不可变快照及原子拒绝；只有保守拒绝仍会留下必需正例缺口。
- 宿主变化或竞争进程包装可能使调整不可用；错误还原会覆盖其他扩展。能力检查、按归属还原与受维护宿主行为证据减小风险，但不承诺通用兼容。
- 多个活跃会话及长寿命原生操作可能保留大型载荷。共享不可变参照、释放不可达操作避免重试复制与已完成历史增长，但不限制宿主活跃操作的数量或寿命。
- 迁移命名空间时遗漏某个配置层级可能停用原本启用的修复，或改变项目覆盖。显式迁移保留有效设置，不静默开启原本未生效的修复。
- 正确对齐的请求仍可能不命中 Provider 缓存，不可分依赖变化仍未对齐。新增维护可能不足以产生收益；受控对齐成功证明机制行为，节省效果需要单独的真实测量。
