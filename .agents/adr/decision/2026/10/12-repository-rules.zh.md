## 动机

在 `.agents/rule/` 下用双语维护仓库工作规则，与规格和 ADR 并列，让每条规范性陈述只有一个归属层。

仓库已有说明各组件与领域当前目标的文档类型，也有记录持久选择理由的文档类型，两者的职责都不包含「在这个仓库里工作要怎么做」。提交、分支、worktree、验证和文档的规则当时放在根 `AGENTS.md` 里，与仓库定位和导航混在一起；[仓库规格](../../../../spec/repository.zh.md)的不变量也把动作约束与交付物性质混在一起。[历史规格契约](../../../archived/2026/10/04-r1-specifications.zh.md#分工)点出了缺口：贡献者说明归仓库文档与 README，导航和非平凡规则归 `AGENTS.md`，却没有页面拥有工作规则本身。[历史 ADR 契约](../../../archived/2026/08/22-r6-adr-mechanism.zh.md#编写记录)也放不下它们，因为一条规则没有替代方案和结果需要记录。

## 分析

本仓库的规范性陈述分为五类。只看交付物即可验证的陈述是规格不变量：仓库文件链接相对所在文档、普通公开页面成对提供两种语言、Prettier 格式化全部受跟踪 Markdown。约束动作、步骤、顺序、授权或禁止的陈述是规则：提交、合并、推送和删分支是四个独立授权，开发期检查在请求审查前运行，完整检查在最终候选上运行。记录选择、替代方案和结果的陈述是决定。组件安装与使用的说明是组件文档。入口本身与不读其他页面也必须成立的非平凡规则属于 `AGENTS.md`，而这些规则各自在本层保留归属页面。

同一约束常以不同形式出现：规格完整说明有效交付物的性质，规则约束动作和权限，用户参考也可以独立描述相同行为。这些职责不能成为规格省略要求或另立相反要求的理由。

以下决定构成规则层的依据。历史引用标明采用时的选择，当前引用标明持续有效的约束；它们都不与增加规则层冲突：

- [增加规格层](../../../archived/2026/10/04-r1-specifications.zh.md)记录了规格、ADR 与组件文档的分工，并把贡献者说明留给仓库文档、README 和 `AGENTS.md`。本决定在这套分工中增加第四种文档类型，不反转其中任何部分。
- [明确 ADR 内容边界](../../../archived/2026/08/22-r6-adr-mechanism.zh.md)保持当时 ADR 的内容规则和生命周期不变。规则不保留历史，因此不能替代决定所记录的契约。
- [保持可分发组件自包含](../08/24-component-self-containment.zh.md)禁止可分发组件内部引用组件以外的文件。规则层是组件目录之外的仓库文档，引用方向让每个可分发组件都不依赖它。
- [同目录维护双语公开文档](../08/20-bilingual-docs.zh.md)要求普通公开页面使用同目录语言配对，规则页面遵循它。
- [按范围执行开发检查](../09/12-repository-checks.zh.md)定义了受影响检查的选择方式和完整门的记录方式。规则说明这些检查在什么时机运行、留下什么证据。
- [审查授权](../09/06-review-authorization.zh.md)规定审查请求不授权修改被审查的文件，Git 规则在分支工作中陈述这一点。

## 决定

### 归属

`.agents/rule/` 承载仓库的工作规则，这一层的定义由该层 [入口页](../../../../rule/README.zh.md)给出。目录名与 `spec` 一样取单数。

一条规范性陈述只有一个归属层，规格、决定、规则、组件文档、仓库文档与 `AGENTS.md` 的分工由 [maintain-spec](../../../../skills/maintain-spec/SKILL.md#division-of-work) 说明。`AGENTS.md` 陈述的规则仍以本层页面为归属页面，改动时两份文本一起更新。

### 文件

规则文件布局、规则文件命名与当前的活动清单由 [规则层入口页](../../../../rule/README.zh.md#文件布局)拥有。`.agents/adr/` 用子目录表达记录的生命周期状态，而规则是就地编辑的当前约束，不保留历史。

### 单条规则的写法

单条规则的写法、出处追溯与引用方式由 [规则层入口页](../../../../rule/README.zh.md#单条规则的写法)拥有。

### 编辑

规则的编辑方式、哪些规则改动先走 ADR 流程，以及规则文件不承载哪些内容，由 [规则层入口页](../../../../rule/README.zh.md#编辑规则)拥有。

### 引用方向

引用方向以及规则层作为说明性文档的性质，由 [规则层入口页](../../../../rule/README.zh.md#引用方向)拥有。

### 迁出内容

根 `AGENTS.md` 保留仓库定位、按活动的导航，以及每次变更必须留意的非平凡规则，并链接拥有完整程序的规则页。[仓库规格](../../../../spec/repository.zh.md)完整说明交付物性质和验收，不包含工作程序或仓库文件链接。非规格索引提供相关规则和决定导航。[根 README](../../../../../README.zh.md) 保留贡献者概览、布局和各层链接，不重复长程序。

规则层不单独建规格：规则层的目标、边界与验收由仓库规格承接，因为本层描述的领域就是仓库本身。只在一台机器上成立、写出设备上使用的模型、提供方、端点或绝对路径，或承载个人工作偏好的规则不进入这一层，也不进入受跟踪文件。只存在于 Git 之外的工作约定同样如此，例如任务状态和任务材料的保存方式。组件内部的规则留在组件内：`SKILL.md` 的指令是交付给宿主的产品，不是仓库规则。首批交付还覆盖当前已经适用、却还没有归属文档的仓库工作规则，因此来源是仓库的可公开工作规则，而不是一份文件清单。

记录每条来源条目的归属，对照来源正文复核迁出的规则，保留条件、例外、权限和无关规格要求。选择器回归测试覆盖新增规则路径，并保留共享输入与未知路径的完整检查回退。

### 规则的读取

规则层 [README](../../../../rule/README.zh.md) 说明规则层的定义、文件布局、单条规则的写法、编辑规则、引用方向以及本决定，并按活动索引各规则页面。`AGENTS.md` 声明规则层的位置，按 ADR、规格入口已有的形式链接规则入口，承载导航与非平凡规则，并以「尽可能」的强度说明验证与评估工作读取适用规则。宿主在会话开始时注入 `AGENTS.md`，而规则页面只在读者决定打开时才被读取，因此规则页面可能始终没有到达，已提交的压缩也会丢掉会话已经读到的内容；`AGENTS.md` 因此重复每次变更使用最多的规则，以及 Agent 最不容易想到要去加载的规则。其余规则仍按需读取：不增加宿主注入机制，也不要求加载全部规则。

## 考虑过的替代方案

无

## 结果

每个活动有一个页面陈述当前约束动作的规则，`AGENTS.md` 与规则层 README 索引这些页面，贡献者或 Agent 因此能找到约束某一步骤的规则及其关联规格与决定。

迁出 `AGENTS.md` 后，规则不再随宿主在会话开始时注入的说明一起到达，Agent 可能在未读到约束其工作的细节时动手。`AGENTS.md` 重复每次变更使用最多的规则，以及读者最不容易想到要加载的规则，其余细节仍按需读取：导航条目、按活动的索引和 `AGENTS.md` 要求读取适用规则能缩小这个范围，但没有机制强制。

`AGENTS.md` 与规则页面就常驻规则各陈述同一份约束，后续改动只更新其中一处时，另一处就留下过时规则。`AGENTS.md` 只重复每次变更使用最多的规则和读者最不容易加载的规则，复核时对照两份文本，因为没有任何机制机械核对它们。

## 变更

### 2026-10-22 内部维护方法

[maintain-spec](../../../../skills/maintain-spec/SKILL.md) 和 [maintain-adr](../../../../skills/maintain-adr/SKILL.md) 持有对应文档的主要方法。Spec、ADR README 文件对持有项目补充和导航，规则层保留跨活动项目规则。内部项目 Skill 属于仓库维护材料，与可分发组件内部指令不同。每条规范仍只有一个主要归属，项目入口提供触发与导航，不复制完整方法。
