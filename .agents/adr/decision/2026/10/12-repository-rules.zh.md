# 仓库规则

Decision owner: Ruokee
Decision writer: OMP DeepSeek V4.1 Flash

[English](./12-repository-rules.md) | 中文

## 动机

在 `.agents/rule/` 下用双语维护仓库工作规则，与规格和 ADR 并列，让每条规范性陈述只有一个归属层。

仓库已有说明各组件与领域当前目标的文档类型，也有记录持久选择理由的文档类型，两者的职责都不包含「在这个仓库里工作要怎么做」。提交、分支、worktree、验证和文档的规则当时放在根 `AGENTS.md` 里，与该文件的仓库定位和导航混在一起；[仓库规格](../../../../spec/repository.zh.md)的不变量也把动作约束与交付物性质混在一起。[规格规则](../../../../spec/README.zh.md)自己点出了这个缺口：其中的分工把「告诉贡献者怎么做」交给仓库文档与 README，把导航和非平凡规则交给 `AGENTS.md`，却没有页面拥有这些规则本身。[ADR 规则](../../../README.zh.md)也放不下它，因为一条规则没有替代方案和结果需要记录。

## 分析

本仓库的规范性陈述分为五类。只看交付物即可验证的陈述是规格不变量：仓库文件链接相对所在文档、普通公开页面成对提供两种语言、Prettier 格式化全部受跟踪 Markdown。约束动作、步骤、顺序、授权或禁止的陈述是规则：提交、合并、推送和删分支是四个独立授权，开发期检查在请求审查前运行，完整检查在最终候选上运行。记录选择、替代方案和结果的陈述是决定。组件安装与使用的说明是组件文档。入口本身与不读其他页面也必须成立的非平凡规则属于 `AGENTS.md`，而这些规则各自在本层保留归属页面。

同一条约束常以两种形式出现，这不构成重复：规格说 commit message 是英文 Conventional Commits 且 scope 来自固定集合，规则说在什么时机运行格式化钩子、哪些文件属于当前任务，以及每个 Git 动作需要哪一项授权。只有两层都在陈述同一件事才是重复，而这一层消除的正是这种重复。

以下现行决定与规则层有关，且都不与它冲突：

- [增加规格层](./04-specifications.zh.md)记录了规格、ADR 与组件文档的分工，并把贡献者说明留给仓库文档、README 和 `AGENTS.md`。本决定在这套分工中增加第四种文档类型，不反转其中任何部分。
- [明确 ADR 内容边界](../08/22-adr-mechanism.zh.md)保持 ADR 的内容规则、生命周期和术语表不变。规则不保留历史，因此不能替代决定所记录的契约。
- [保持可分发组件自包含](../08/24-component-self-containment.zh.md)禁止组件内部引用组件以外的文件。规则层是组件目录之外的仓库文档，引用方向让每个组件都不依赖它。
- [同目录维护双语公开文档](../08/20-bilingual-docs.zh.md)要求普通公开页面使用同目录语言配对，规则页面遵循它。
- [按范围执行开发检查](../09/12-repository-checks.zh.md)定义了受影响检查的选择方式和完整门的记录方式。规则说明这些检查在什么时机运行、留下什么证据。
- [审查授权](../09/06-review-authorization.zh.md)规定审查请求不授权修改被审查的文件，Git 规则在分支工作中陈述这一点。

## 决定

### 归属

`.agents/rule/` 承载仓库的工作规则：贡献者或 Agent 必须做什么、按什么顺序、持哪项授权，以及什么被禁止。它位于 `.agents/spec/` 和 `.agents/adr/` 之旁，目录名与 `spec` 一样取单数。

一条规范性陈述只有一个归属层。规格说明对象应当是什么、哪个可观察结果显示它达到目标；决定记录持久选择、理由与结果；规则陈述约束动作的要求；组件文档告诉用户如何安装和使用组件；仓库文档与 README 告诉贡献者如何在仓库中工作；`AGENTS.md` 承载导航，以及不读规则页面时也必须成立的非平凡规则。`AGENTS.md` 陈述的规则仍以本层页面为归属页面，改动时两份文本一起更新。规则不承载长篇理由：读者需要理由时，规则链接拥有它的决定，或拥有它所执行性质的规格。

### 文件

规则扁平放在同一目录，按活动一文件一份，采用同目录 `name.md` 与 `name.zh.md` 配对，标题下方紧接互相指向的语言链接。层自身的规则是 `README.md` 与 `README.zh.md`。规则文件不带日期、不带状态、不设子目录：`.agents/adr/` 用子目录表达记录的生命周期状态，而规则是就地编辑的当前约束，不保留历史。

首批交付覆盖仓库边界、规划、Git、验证和文档。文件集合跟随活动变化，出现真实的活动需求时新增页面，因此这个数量是交付清单，而不是封闭集合。

### 单条规则的写法

一条规则用祈使句陈述一个约束，最多补一句简短说明。规则不编号，引用一条规则使用文件路径加小节标题，因为编号会变成需要维护的清单，而这一层不引入清单文件。规则追溯到一条规格不变量、一条现行决定或维护者的明确决定；没有这样的出处时，只要它是当前确实执行的做法即可，但不得与规格或现行决定冲突。规则保留原有的条件、例外、强度和权限，用「尽可能」表述的规则保持该强度，禁止性规则保留它的例外。

### 编辑

规则新增、删除或改变它所承载的持久选择时，例如授权边界、流程要求或发布策略，先走 ADR 流程再改规则；不改变持久选择的编辑性澄清不需要决定层流程。规则就地编辑，不保留历史、状态、评审意见、任务信息和会话信息。

### 引用方向

引用单向。规则可以链接组件文件、组件文档、规格和决定。可分发组件内部的文件不得链接、命名或依赖 `.agents/rule/`，组件的运行、构建和分发不依赖规则层。规则是说明性文档：Markdown 检查和变更路径选择器把它当作普通 Markdown，这一层不引入检查器、分类系统或清单文件。

### 迁出内容

根 `AGENTS.md` 让出工作规则的长文，保留仓库定位、按活动的导航，以及每次变更都要留意的非平凡规则，并链接拥有完整陈述的规则页面。[仓库规格](../../../../spec/repository.zh.md)让出工作程序类条目，保留交付物性质、结果验收，以及本次迁移未触及的全部要求，并链接拥有迁出细节的页面。[根 README](../../../../../README.zh.md) 让出重复陈述 `AGENTS.md` 的程序段落，保留面向贡献者的概览、布局小节和各层入口链接。

规则层不单独建规格：规则层的目标、边界与验收由仓库规格承接，因为本层描述的领域就是仓库本身。只在一台机器上成立、写出设备上使用的模型、提供方、端点或绝对路径，或承载个人工作偏好的规则不进入这一层，也不进入受跟踪文件。只存在于 Git 之外的工作约定同样如此，例如任务状态和任务材料的保存方式。组件内部的规则留在组件内：`SKILL.md` 的指令是交付给宿主的产品，不是仓库规则。首批交付还覆盖当前已经适用、却还没有归属文档的仓库工作规则，因此来源是仓库的可公开工作规则，而不是一份文件清单。

### 规则的读取

规则层 [README](../../../../rule/README.zh.md) 说明规则层的定义、文件布局、单条规则的写法、编辑规则、引用方向以及本决定，并按活动索引各规则页面。`AGENTS.md` 声明规则层的位置，按 ADR、规格入口已有的形式链接规则入口，承载导航与非平凡规则，并以「尽可能」的强度说明验证与评估工作读取适用规则。宿主在会话开始时注入 `AGENTS.md`，而规则页面只在读者决定打开时才被读取，因此规则页面可能始终没有到达，已提交的压缩也会丢掉会话已经读到的内容；`AGENTS.md` 因此重复每次变更使用最多的规则，以及 Agent 最不容易想到要去加载的规则。其余规则仍按需读取：不增加宿主注入机制，也不要求加载全部规则。

## 考虑过的替代方案

**把层名定为 `standard` 而不是 `rule`。** 选择层名时考虑过。标准化体系和若干文档分类法把与 ADR 并列的第三层称作 standards，该词读起来像面向团队外部读者的出版物集合。

**把规则写成根目录的单文件 `RULES.md`。** 选择层的位置时考虑过。单文件容易找到，但无法按主题承载语言配对，且每个活动都要通过同一个文件编辑，与仓库现有的文档布局不符。

**把工作规则继续留在根 `AGENTS.md`，不新增层。** 作为现状考虑过。它不需要新的文档类型，但 `AGENTS.md` 把导航、定位和规则放在一起，仓库规格又以另一种形式重复了其中若干条，且没有任何页面以规则本身为主题。

**给规则编号并维护清单。** 选择引用方式时考虑过。编号和清单让规则容易被检查表引用，但仓库没有为 ADR 或规格维护这样的列表，且每次增删规则都要维护编号。

## 结果

每个活动有一个页面陈述当前约束动作的规则，`AGENTS.md` 与规则层 README 索引这些页面，贡献者或 Agent 因此能找到约束某一步骤的规则及其关联规格与决定。

迁出 `AGENTS.md` 后，规则不再随宿主在会话开始时注入的说明一起到达，Agent 可能在未读到约束其工作的细节时动手。`AGENTS.md` 重复每次变更使用最多的规则，以及读者最不容易想到要加载的规则，其余细节仍按需读取：导航条目、按活动的索引和 `AGENTS.md` 要求读取适用规则能缩小这个范围，但没有机制强制。

规则在迁移中可能丢掉条件、例外或权限，留下的文本便允许或禁止了错误的事情，例如丢掉「审查请求不授权修改被审查文件」这一条，或把「尽可能」写成强制要求。为每条迁出的规则记录归属并对照来源正文复核是防护手段。

`AGENTS.md` 与规则页面就常驻规则各陈述同一份约束，后续改动只更新其中一处时，另一处就留下过时规则。`AGENTS.md` 只重复每次变更使用最多的规则和读者最不容易加载的规则，复核时对照两份文本，因为没有任何机制机械核对它们。

仓库规格可能在移除工作程序类条目时丢掉不属于工作程序的要求，例如 commit scope 集合、双语配对规则或某条验收标准。为每条来源条目记录归属让未受影响的条目保持可追溯。

变更路径选择器可能把只含规则页的变更分类错误，或放宽后的正则不再把共享输入和未知路径回退到完整检查，导致某分支实际改了共享输入却被记为仅文档变更。选择器回归测试覆盖新路径。

英文规则与其中文配对可能漂移，两份权威文本对同一条约束给出不同说法，各语言的读者遵循不同的规则。两份文件在同一次改动内更新并由复核比较语义，因为格式检查看不出语义差异。
