## 动机

以自包含的语言 Skill 和同语言 OMP Prompt 模板提供 workloop，按活动加载指令。

目标澄清、实现、核验和交付需要在源码仓库之外仍可读取的一致合同。Skill 与宿主 Prompt 同时维护完整流程会产生相互竞争的权威。大篇通用必读正文还会让配置和单个操作提前加载尚不需要的执行或协作细节。

直装让所选语言 Skill 及对应入口由同一方式管理。工作流可以使用 Markdown 和既有 Harness 机制，无需运行时。规划条件、执行许可和各类评估需要明确边界，避免将准备当成实现或用户验收。

## 决定

### 组件

在 `projects/workloop/` 维护第一方纯指令组件，包含 Markdown Skill、组件文档和按语言区分的 OMP Prompt 模板。没有 OMP 包清单、Extension、运行时代码、构建系统或专用安装器。

英文 `workloop` 和中文 `workloop-zh` 是组件拥有的可独立发现身份，各自包含完整工作流所需指令。两种语言同次维护，能力与要求等价，使用相同组件版本。不在仓库普通 Skill 或语言变体根目录复制正文。

tk 是按名称和公开接口使用的必需依赖，不导入实现或引用其文件。其他工具和 Skill 只在需要时成为前提，安装不安装这些依赖。使用 GitHub 或 GitLab Issue、PR 管理任务仍属暂缓，不是永久禁止；项目仍可将提交 PR 作为交付目标。

面向新任务，不提供旧入口别名、旧材料名称兼容或工作流及材料迁移。按原身份和有效要求继续、修复、恢复 workloop 自身任务。

### 指令归属

各安装语言 Skill 只引用自身目录，遵循[组件自包含决定](../08/24-component-self-containment.zh.md)。入口负责用途、前提、实际请求解析、操作路由、最低跨操作边界及指令恢复。保留用户语言、项目写作规则、事实完整性、有效要求，以及暂缓能力与禁止的区别。

操作负责自身步骤和结果材料。共享 Task 归属、自检、角色选择、协作及执行约束在每种语言中各有一个所有者，并明确加载条件。直接引用和 Prompt 调用汇入所选操作，Setup 读取配置指引。不用另一篇同等大的通用必读正文替代入口。

没有新增参数不清除足够的当前会话或 Task 上下文。直接继续，不要求重述；只有当前 Task 或所需目标无法确定时才补充信息。引用或编辑指令不构成执行请求。

### 操作

提供 `clarify`、`exec`、`verify`、`ship` 和 `supervise`，完整行为由[组件规格](../../../../spec/workloop.zh.md)承载，可执行指导由[组件](../../../../../projects/workloop/README.zh.md)提供。

Clarify 明确目标、必要调研与设计、重要选择和独立 Plan，不授予执行权。Execute 在当前会话实现，Supervise 调度独立 Worker 而不实现。没有明确收窄时，两者连续完成获授权 Plan。Worker 在分派边界停止，不收窄负责人的总体范围。

Verify 对准备材料或冻结实现候选独立只读判断，裁决为 `passed`、`changes required` 或 `unable to determine`。Ship 按有效授权达成项目定义的结果，没有通用集成或发布动作包。核验与交付都不等于用户验收或 Task 关闭。

Check 是隐含准备活动，不另设必需入口。材料及设计缺陷返回 Clarify，实现偏差返回 Execute。交付反馈重开受影响工作，有独立目标或边界时另归 Task。

### 材料

结果保存在所属 tk Task。每个执行任务都有独立 `plan.md`，单单元任务也不例外。Plan 保留稳定单元标签、已完成结果及子任务归属，单元交付可独立评估的完整结果。可选活动不要求空材料。

目标、设计、实施证据、自检、独立评估及交付记录分别负责。保留历史候选评估及失败，不为命名统一迁移旧文件。执行产出的 Markdown 属于实现候选。[规格](../../../../spec/workloop.zh.md#材料)定义材料必要内容，组件指令说明用法。

保存遵循有效许可及更窄的不写入、仅对话限制。稳定结果归普通材料，实时角色路由、临时授权和待完成分派归可恢复会话状态。保存材料不授予实现或生命周期权限。

### 检查

Plan 形成后自检准备材料的矛盾、遗漏和可预见执行阻塞，不预检环境。未决需求和重要选择返回讨论。独立准备审查只按请求启动。没有明确限制时，请求覆盖作者修复及同一合适只读核验者的必要复查，直到当前通过或出现真实阻塞。

每次自检使用新的只读上下文，由作者修复。按任务选择三至五次默认上限，外部指引可覆盖。准备自检与每个实现单元分别计数。准备自检按 Clarify 轮次计数：上一轮返回后，因新的请求、返回的材料或设计缺陷，或因需求、依据变化，新一轮从自己的计数开始，上一轮耗尽不阻止本轮。仅为获得新计数而宣布的轮次仍属同一轮。每轮准备自检和每个实现单元内，首次检查与复检累计。材料修订、修复、复检及独立反馈不重置适用计数。会话恢复或另一 Agent 继续同一轮同样不重置。开启新一轮不重置任何实现单元的自检计数。启动或通信失败不消耗实质检查次数。当前通过立即结束自检。达到适用上限后停止检查，完成可处理修复，报告未解决和未复检工作，不虚构成功。

每个实现单元都需要自检和独立 Verify。独立 Verify 不受自检轮次上限限制，准备自检耗尽不自动请求独立审查。检查保留许可、候选身份、证据，以及有证据缺陷和无法判断的区别。

实际运行改变的行为，记录候选、范围、条件、输入、观察、证据、覆盖和限制。区分文件检查、加载路径、宿主发现、实际 UI 或模型行为及用户结果。候选变化使受影响证据失效；仅在明确身份和范围内复用未变证据，不声称独立重跑。检查不产生用户验收或受保护许可。

### 协作

各角色的宿主、准确模型选择器、推理和位置按明确请求、继续有效选择、外部默认独立确定。Verify 不继承执行者模型，不静默替换不可用选择。Senior 须明确分派，不能修改要求、扩大范围、豁免 Verify 或授予受保护许可。

通过所选协作工具保持角色隔离、正常启动、普通消息分派、明确位置及候选冻结。推荐 Herdr，不强制。Verify 自行解析依据，实现者清单是证据，不是权威。复用合适的 Verify 和已分派 Senior 会话，与实现隔离；先处理忙碌分派再接新项。不读取工作中私有会话文件、不操作其他 Agent 问答框、不发送未经请求的中途消息。

默认等待最终结果，后台返回后也阻塞等待，不轮询、不从生命周期状态推断裁决。显式 `nowait` 只改变跨会话等待，不改变原生自检屏障、检查、范围或权限。保留待完成分派，最终结果到达后恢复。核对发送者、范围、候选、裁决和已保存报告；重复可能已完成的动作前先恢复既有结果。最终回复不等待接收者。

### 权限

可预见需求选择在 Clarify 解决。执行授权覆盖范围内普通实现、修复、本地准备、检查、临时进程及项目要求的候选保留。复用有效授权，已授权临时目录检查保持其范围。不以避免重复批准为由将所有重要选择推迟到最后。

项目受保护的提案批准、归档、集成、推送、发布、安装、费用、特权动作及 Task 关闭，需要各自有效授权。核验不是验收，验收不授权无关动作。保留明确确认请求及人工接入点。缺少许可、需求决定或外部状态只阻塞依赖动作，其他已授权就绪工作继续。

Execute 和 Supervise 禁止结构化问答工具，也禁止委派绕过。必须由用户决定的问题用普通文字提出，其他不受影响的已授权工作继续。`confirm` 要求逐项确认，不取消检查或这一禁令。

项目工作规则允许时，已验证提交的前序可在集成或最终用户审阅前提供开发依赖。冻结其候选，各单元相对基线保持可独立审阅。前序变化后刷新受影响后继和证据。分支不能替代必需部署、服务或已发布产物。保留未集成候选供有序交付，不为继续开发而擅自合并。

### 恢复

在可恢复上下文中保留当前活动的范围、依据、适用候选、授权、明确限制、已完成检查次数及下一步。以普通文字保留禁止结构化问答等限制，不只保留 `noask`。协作规则管理实时角色、路由、资源和待完成分派，只改配置不携带完整执行状态。

入口、当前操作或当前必需 Reference 缺失时，从实际安装 Skill 重新加载。记得路径或曾经读过不表示指令仍然可用。对照实际效果恢复，避免重复已完成工作或待完成请求。不要求宿主专用 Pin API，加载指令不强制保证遵守。

### 初始化

Setup 经简短条件入口路由提供，不是安装或普通使用前置。它在适用 `AGENTS.md` 一类外部指引中维护选定角色默认、自检上限、协作选择、项目工作惯例及 Ship 定义。不复制通用工作流算法，不在分发指令嵌入本机模型，不建立通用用户与项目配置层级。默认更新保留活动明确选择，配置不授权执行。

直接按所请求操作行动，不主动预检工具、环境或文件可用性。实际失败后只获取解决问题所需事实及相关准备或诊断指引。这不取消质量检查，也不授权不可用动作。

### 分发

使用既有 Harness 发现和加载机制复制完整 Skill，或采用受支持链接。安装文档负责首次安装、完整替换、切换语言、移除及实际加载条件，区分放置、发现和加载正文。不猜测未知宿主路径，不规定封闭 Harness 名单。仓库普通 Skill 安装器不管理本组件。

一次 OMP 安装选择一种完整语言 Skill 及对应的 `/wl-clarify`、`/wl-exec`、`/wl-verify`、`/wl-ship`、`/wl-supervise` Prompt。模板固定 Skill 身份，只传操作、加载指示和输入。空参数不生成输入标题或段落，非空参数保留宿主解析后的字符，不经过模板转义或二次解释。只将选中模板安装到实际 Prompt 发现位置。

直装前解除旧 workloop 包资源及自有同名文件命令，保留无关资源。遵循宿主实际模板加载行为，不假定文件命令重载也重载模板。其他 Harness 使用完整 Skill 和自然语言操作，不需要专用集成或 OMP 命令语法。

### 规格

[组件 Spec](../../../../spec/workloop.zh.md) 定义目标和可观察验收，Skill 与[组件文档](../../../../../projects/workloop/README.zh.md)负责操作及使用细节，保持这些合同一致。

[Skill 布局决定](../08/20-skill-variants.zh.md)将组件 Skill 保留在项目内，普通同名语言变体规则不变。仓库检查格式化已登记组件 Markdown，包括两种已知语言 Skill 的共享 Reference 目录内全部 Markdown 和语言 Prompt 路径，Reference 无需逐文件登记。不增加工作流运行时检查。未知操作或语言、旧命令路径、非 Markdown 文件、共享输入及混合未知变更仍完整回退。

## 考虑过的替代方案

将完整 Skill 放在普通 Skill 和语言变体根目录可复用该布局，但会与 OMP 模板分散归属。集中维护组件接受单独分发路径，避免重复 Skill 正文。

将全部共同指令保留在入口或必读共享文件中，能提供一个直观读取位置，但每项活动仍要加载无关执行和协作细节。操作归属及条件 Reference 使规则只有一个所有者，无需全员加载。

## 结果

指令文本无法强制执行操作或许可边界。Agent 未加载当前指令或无视它们时，仍可能跳过检查或越权。自包含加载和恢复减少上下文缺失，但不替代独立核验，也不证明模型行为可靠。

每种语言都承载完整权威合同。只更新一种语言，会让另一种语言获得不同许可或检查要求，即使两者都能加载。同次维护并判断语义等价是持续成本，仅版本一致不够。

残留同名 OMP 文件命令先于新 Prompt 模板运行，只复制模板可能让旧入口继续生效。安装需要解除自有资源冲突，并观察宿主真实发现及加载条件。

## 变更

### 2026-10-23 规格完整性

组件规格完整表达必要操作行为、权限、边界和验收，不含实现描述或仓库文件链接。Skill 提供 Agent 执行指令，组件文档提供同一合同下独立可用的指导。非规格索引承载语言、主题和决定导航。这保留了必要结果与操作、使用方法之间的职责划分。

### 2026-10-25 Clarify 轮次准备计数

准备自检按 Clarify 轮次计数。上一轮返回后，新一轮从自己的计数开始；同一轮内，材料修订、修复、复检及独立准备反馈共享计数，不重置。会话恢复或另一 Agent 继续同一轮同样不重置。开启新一轮不重置任何实现单元的自检计数。Clarify 操作拥有轮次边界及记录，自检 Reference 拥有计数。本条补充未定义边界，不改变独立 Verify 上限或实现单元计数规则。

### 2026-10-29 工具中立

协作终端由用户或项目选定，例如 Tern、Herdr、tmux。所列工具仅为示例，通用指引不内置工具偏好；使用所选工具支持的接口和指引，不把其他工具的专属运行前提作为协作条件。本条替代上文「协作」一节中推荐 Herdr 的表述，角色隔离、身份定位、正常启动、普通消息分派、候选冻结和最终结果交付要求不变。
