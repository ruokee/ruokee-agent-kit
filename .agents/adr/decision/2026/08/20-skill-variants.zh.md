# Skill 语言变体

Decision owner: Ruokee
Decision writer: OMP GPT-5.6 Sol
Reverses: [Skill 语言变体](../../../archived/2026/08/20-r2-skill-variants.zh.md)

[English](./20-skill-variants.md) | 中文

## 动机

分发完整、自包含的 Skill 语言变体，由组件负责内部源布局。

前驱要求项目拥有的 Skill 使用固定子目录，使普通源码整理需要修改仓库级决定，却没有保护额外的安装接口。真正的边界是组件归属和宿主发现，不是内部目录名。

源码路径选择语言材料，安装后的 Skill 使用宿主预期的身份和路径。安装链接中的源码专用前缀会破坏这一分工。只安装一个组件时，跨组件文件引用也会失效。

## 决定

普通公开英文 Skill 使用 `skills/<name>/`，对应的同名中文变体使用 `variants/zh/skills/<name>/`。这些根目录是仓库安装接口。对应文件集合、主题、可观察指令和版本在同次变更中保持一致。

项目拥有其分发 Skill 的源码和语言资源，在自身组件内选择内部源布局。不同语言的 Skill 可以具有可独立发现的身份。每种语言保持完整、自包含，等价指令和版本一起维护。组件文档负责源码布局和安装细节，内部移动不改变安装身份。

纯 Skill 只包含发现、理解和使用它所需的材料，包括 `SKILL.md` 入口和必要的本地指导。不包含 Plugin manifest、marketplace 元数据、`meta.toml`、宿主专用 Agent 定义、包 changelog 或包级 README。辅助材料的组织由组件负责。

将所选语言安装到其正常宿主 Skill 路径，不保留源码专用布局前缀。文件引用相对于所在文档书写，目标留在该分发组件内。书面路径、导入、包依赖和运行时读取都不允许访问其他组件或仓库支持文件。安装路径不授予跨组件访问权限。

每个 Skill 独立解释自身领域、术语和运行规则，不靠加载另一个 Skill 补全这些解释。可以按名称提及其他组件、工具或 Skill，不必仅为提及声明依赖。实际前置条件须显式声明，并按名称或通过公开接口使用，包括 Skill 加载接口。前置能力不允许跨组件文件引用。

导入保留正文含义，并区分路径适配与编辑修改。任何语言都不能悄悄省略可观察能力或必需指令；翻译需要时可采用不同解释。

## 考虑过的替代方案

要求统一的项目内部源子目录。这使源码位置可预测，但无害的内部移动也会改变仓库政策。安装身份、组件归属和完整语言分发已能提供所需一致性，无需这一耦合。

## 结果

只要安装身份、完整语言分发和组件内引用仍有效，源码布局变化无需修改公共规则。验证须检查语言选择后的引用，不能只检查源码树。

源码与安装路径有意不同。依赖未公开内部源路径的消费者，应使用组件维护的构建或安装接口。
