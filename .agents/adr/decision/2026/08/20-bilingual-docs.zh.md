# 双语文档

Decision owner: Ruokee
Decision writer: OMP GPT-6 Astra
Reverses: [双语文档](../../../archived/2026/08/20-r2-bilingual-docs.zh.md)

[English](./20-bilingual-docs.md) | 中文

## 动机

以同目录文件对维护完整的英文和中文公开文档，规格语言导航放在正文之外。

每个语言版本都必须可以独立阅读，对应版本位于同一组件或主题旁。仓库对外公开，代码和默认文档使用英文，Ruokee 使用中文审查技术决定和使用细节。

仓库和组件入口页还需要明确职责，让读者能够发现能力并进入详细文档，不必面对相互竞争的索引或重复合同。

## 决定

### 语言范围

代码、注释、配置和默认公开文档使用英文。公开行为和用法同步维护对应中文文档。普通公开 Markdown 页面采用同目录 `name.md` 和 `name.zh.md` 配对。仓库和组件入口页使用 `README.md` 和 `README.zh.md`，不按语言拆分目录。

普通页面保持双向语言链接。规格正文不含仓库文件链接，包括语言链接；非规格索引提供两个语言入口。每份文档都应独立成立。同一变更中更新并审查两种语言，要求行为、限制和指令一致，不要求逐句翻译。路径、命令、API 名称、状态值和代码标识符保留仓库原值。

内部实现笔记、注释、生成文件和仅面向维护者的材料，只在目标读者需要时翻译。公开行为或用法首次需要中文文档时定义真实文件对，不创建空的语言占位文件。

ADR 使用 [ADR 机制决定](./22-adr-mechanism.zh.md)定义的更严格文件对格式。两份文件在语义上具有同等权威，并且一起移动，保留现有元数据和生命周期规则。

### Skill 打包

Skill 语言变体按 [Skill 打包决定](./20-skill-variants.zh.md)保留宿主可发现的组件布局。普通英文 Skill 位于 `skills/<name>/`，中文变体位于 `variants/zh/skills/<name>/`。以独立项目形式维护的组件，其包含的 Skill 保留在 `projects/<component>/skills/` 下。普通文档的文件名规则不改变 Skill 文件名、身份或安装路径。

### 公开入口

[英文仓库 README](../../../../../README.md) 和[中文仓库 README](../../../../../README.zh.md) 提供语义一致的能力索引与开发说明。它们区分用户触发和 Agent 触发的 Skill，并按适用 Harness 对扩展分组。每个 Skill 条目链接基础版本和中文变体，每个扩展条目链接对应语言的组件 README。

组件 README 文件对介绍能力并链接使用和设计文档。规格包含完整要求，详细用户参考独立说明相同合同。tk README 文件对按照 [tk 文档决定](./29-tk-documentation.zh.md)提供导航。

不维护独立的 Skill 索引页面、重复的语言目录入口页，也不在被取代的路径保留跳转占位文件。页面移动时修复受影响的入站链接和命令示例。使用[文档相对链接](./24-relative-links.zh.md)，并保留[组件自包含](./24-component-self-containment.zh.md)要求。

## 考虑过的替代方案

按中英文分别维护文档目录。这是一种可行的配对方式，但需要采用与 ADR 和现有组件文档不同的路径约定。同目录配对让普通公开页面使用同一套文件名规则，并将对应版本放在一起。

## 结果

英文继续作为默认公开语言，公开行为和用法具有完整的中文对应版本。读者从普通页面或规格索引进入另一语言，并通过仓库和组件 README 文件对进入各项能力。

每项相关变更都需要维护两种语言及其导航。使用现有仓库检查，并明确检查受影响的链接，不新增永久翻译或文档结构检查器。

公开页面移动后，外部书签和入站链接可能失效。仓库内维护的引用会同时修复，但无法在此更新所有外部引用。
