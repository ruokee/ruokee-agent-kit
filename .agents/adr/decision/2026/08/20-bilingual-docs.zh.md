## 动机

以同目录文件对维护完整的中英文公开文档，由组件负责内部 Skill 语言资源布局。

每种语言都须独立可读。英文是默认公开语言，中文支持维护者审查决定和用法。语言等价与入口发现不需要固定项目内部的 Skill 子目录。前驱的固定子目录使局部源码移动也要改变公开语言政策。

## 决定

### 语言范围

代码、注释、配置和默认公开文档使用英文。公开行为和用法维护完整中文文档。普通公开 Markdown 使用同目录 `name.md` 和 `name.zh.md` 配对。仓库和组件入口使用 `README.md` 和 `README.zh.md`，不按语言拆目录。

普通页面保持双向语言链接。规格正文不含仓库文件链接，包括语言链接；非规格索引提供两种语言入口。每份文档独立成立。两种语言一起更新和审查，保持行为、限制与指令等价，不要求逐句翻译。路径、命令、API 名称、状态值和代码标识符保留仓库拼写。

内部实现笔记、注释、生成文件和维护者材料只在读者需要时翻译。公开行为或用法首次需要中文时创建真实文件对，不建立空语言占位文件。

ADR 遵循 [ADR 机制](./22-adr-mechanism.zh.md)更严格的配对格式。两种语言具有同等语义权威，按其元数据与生命周期规则一起移动。

### Skill 打包

Skill 语言分发遵循 [Skill 打包决定](./20-skill-variants.zh.md)，包括普通 Skill 发现根、组件归属、安装身份、语言等价与自包含。各项目选择内部 Skill 源布局。普通文档的文件名规则不改变 Skill 文件、身份或安装路径。

### 公开入口

[英文仓库 README](../../../../../README.md) 和[中文仓库 README](../../../../../README.zh.md) 提供等价的能力索引与开发说明，区分用户触发与 Agent 触发的 Skill，按适用 Harness 对扩展分组。每个 Skill 条目链接两种语言，每个扩展条目链接对应语言的组件 README。

组件 README 文件对介绍能力，导航使用和设计文档，不复制详细命令库存或规范合同。规格完整陈述要求，用户参考独立解释相同合同。

不维护独立 Skill 索引页、重复的语言目录入口页或被替代路径的跳转占位文件。页面移动时修复受影响入链和命令示例，使用[文档相对链接](./24-relative-links.zh.md)，保留[组件自包含](./24-component-self-containment.zh.md)。

## 考虑过的替代方案

按中英文拆分文档目录可行，但需要不同于 ADR 和既有组件文档的路径约定。同目录配对让普通页面采用同一文件名规则，并将对应版本放在一起。

## 结果

读者通过普通语言链接或规格索引进入完整的两种语言。安装身份和完整分发不变时，组件内部源移动不改变语言政策。

每项相关变更维护两种语言和导航，使用既有仓库检查及明确的受影响链接检查，不新增永久翻译或文档结构检查器。

移动公开页面可能破坏外部书签。仓库链接一起修复，但无法在此更新全部外部引用。
