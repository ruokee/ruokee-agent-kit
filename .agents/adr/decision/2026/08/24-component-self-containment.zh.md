# 组件自包含

Decision writer: OMP DeepSeek V4.1 Flash
Reverses: [2026-08-24 r1 组件自包含](../../../archived/2026/08/24-r1-component-self-containment.zh.md)

[English](./24-component-self-containment.md) | 中文

## 动机

保持组件文件自包含，同时允许组件正文声明它需要的工具或 Skill。

先前的决定禁止组件文件链接、依赖或指示 Agent 加载另一个 Skill、Extension、Plugin 或 Package，并把运行时需要另一个仓库组件的示例纳入规则范围。按字面理解，这段表述也禁止工作流声明自己需要 tk，或 Skill 按名称提及另一个可加载的 Skill。规则针对的失败，是仓库文件引用解析到组件之外，并且只安装该组件时失效。按名称或公开接口提及工具或 Skill 不会形成这种文件引用。组件有合理的运行时前置条件，读者需要看到明确声明。

指向另一个组件或仓库支持文件的链接有相同的失败模式。组件若链接到另一个组件拥有的文件或仓库级材料，可能在源码树中有效，安装后却失效，并形成一项未声明的要求：两边必须使用相互兼容的版本。语言变体遵守相同边界，因为变体作为一个组件安装。

## 决定

将每个 Skill、Extension、Plugin 和 Package 视为自包含的可分发组件。对于当前 Skill，组件根目录是 `skills/<name>/` 以及各个 `variants/<language>/skills/<name>/` 目录。未来增加的组件类别在各自根目录下遵守同一规则。

组件内的仓库文件引用必须解析到该组件目录内。这包括 Markdown 链接、书面文件路径、导入、包依赖和运行时文件读取。组件不得链接、导入或读取另一个仓库组件的文件或包，也不得依赖组件目录之外的仓库支持文件，包括 `.agents/spec/`、`.agents/rule/` 和其他仓库级材料。像 `../code-quality/...`、`../../docs/...`、`skills/<name>/...`、仓库根相对路径和绝对路径这样的引用不会解析到组件内部，违反这一边界。

组件正文可以提及其他组件、工具或 Skill，把它声明为前置条件，并按名称或通过公开接口指示使用，包括加载 `skill://grill-me` 这样的 Skill。声明的前置条件不是文件或代码依赖。组件不必内置该前置条件、复制其实现或提供回退。前置条件必须显式声明，不能通过指向另一个组件文件的链接隐式形成。

自包含表示组件的文件集完整、能够独立安装、具有确定版本并可被单独阅读。它不表示组件没有运行时前置条件；组件的完整功能可以依赖已声明的前置条件。

需要另一个仓库组件文件的示例违反这一边界。按名称调用公开工具或 Skill、且不读取另一个组件文件的示例允许。组件仍可引用公开外部资料、外部 URL 和上游文档，讨论一般概念，提及与组件同名的外部库，前提是它不需要另一个仓库组件的文件。

组件目录之外的仓库级文档、ADR、manifest、安装器和集成代码，可以在描述或组装组件时引用它们。限制适用于从可分发组件内部发出的引用。

## 考虑过的替代方案

**维持宽泛禁止。** 组件无法声明真实的前置条件，读者只能自行推断。合法的名称引用，例如工作流需要 tk、Skill 提及另一个待加载的 Skill，仍会被当作越界。

**只禁止 Markdown 链接。** 书面路径、导入和运行时读取会被允许。组件仍可能以安装后失效的形式引用自身之外的文件，规则针对的失败会重新出现。

**内置所有前置条件。** 组件复制另一个组件的文件或实现，从而不存在外部前置条件。这会在组件之间重复内容，副本的版本与行为也会逐渐不一致。

## 结果

每个组件的文件集仍可脱离另一个仓库组件或源码仓库布局独立安装、确定版本并被阅读。组件可以声明它需要的工具或 Skill，读者能看到所声明的前置条件。组件的完整功能可以依赖该前置条件，仓库无法保证其版本兼容；缺少前置条件或版本不兼容可能导致失败或更弱的结果。组件仍不得链接另一个组件的实现。

相关组件可能重复少量指导。只保留适合该组件的内容，不要镜像整份文档。内容在组件之间迁移时，应在同一变更中迁移必要说明并删除旧的越界引用。审查时，任何解析到组件目录之外的文件引用都应视为边界违规。

仓库级文档仍负责比较组件、说明组合方式和记录组件关系。
