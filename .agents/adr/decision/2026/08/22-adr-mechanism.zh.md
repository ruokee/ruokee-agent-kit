## 动机

通过内部 `maintain-adr` Skill 维护双语当前决定和被替代决定，由任务跟踪讨论和执行。

持久选择需要一处当前引用和可分别访问的历史契约。任务材料已经保存讨论、批准和执行安排。[前驱](../../../archived/2026/08/22-r7-adr-mechanism.zh.md)还要求活跃与被拒 ADR 提案以及提案先行集成。这重复了工作跟踪，即使维护者已经批准选择，也仍要把独立提案作为前置条件。

Skill 持有可复用的结构、生命周期和编写方法。Skill 与 ADR README 都保存完整方法，会产生相互竞争的权威来源。项目补充保留本地政策，可分发组件之外的术语权威仍是仓库词典。

## 决定

### 维护归属

[maintain-adr](../../../../skills/maintain-adr/SKILL.md) 持有 ADR 的主要维护方法、[记录规则](../../../../skills/maintain-adr/references/records.md)和[编写规则](../../../../skills/maintain-adr/references/writing.md)。它是 `.agents/skills/` 下的英文内部项目 Skill，不是公开安装源，可以引用所维护的项目文档。公开组件的自包含要求保持不变。

[ADR README](../../../README.zh.md) 持有仓库位置、语言政策、Git 流程和维护者权限，不重复完整方法。Agent 在适用维护或审查前加载 Skill，也覆盖影响持久选择的功能工作，然后读取已确认需求、相关当前决定及其 `Changes`、规格、补充和必要组件文档。普通阅读和没有持久选择变化的常规修改不要求 ADR。加载不授予写入或生命周期权限。

### 记录

以 ADR 为术语，`.agents/adr/` 为根目录。ADR 只有决定一种文档类型。`decision/` 保存当前决定，`archived/` 保存曾经生效、后来被替代的决定。目录表达状态，记录没有 `Status` 字段。用 `.gitkeep` 跟踪这两个根目录，项目补充留在 ADR 根目录。

讨论、批准、被否决选项和执行安排保存在现有 tk 任务中。公开协作可以使用可访问的 Issue 或 PR，不将其中任何平台设为必需依赖。未采纳草稿不属于归档决定。解释选择的重要否决理由进入该 ADR；具有长期约束的“不采用某选项”本身可以成为决定。普通否决不需要 ADR。

### 身份

新主题使用依据有效批准及已完成的对应实现首次编写正式决定的日期，以及简短规范英文主题。无需实现的纯文档选择使用决定编写日。讨论开始日、任务创建日和未来集成日都不提供身份，后续审查不使其改名。

既有决定保留身份日期和规范路径，包括继承自历史提案的日期。普通反转保留该身份。实际归档和变更日期保留为事件元数据，每项决定的归档序列从 `r1` 连续递增，跨日、月、年不重置。

抽出的独立主题获得自己的决定日期、名称和序列，共同前驱或关系本身不共享身份。语言对应文件、链接修复、普通更新和命名整改不消耗修订号。[记录规则](../../../../skills/maintain-adr/references/records.md#identity)拥有详细身份操作。

### 记录契约

每项记录都有英文和中文文件，负责人和原作者一致，完整元数据块后有双向语言链接，两种语言语义同等权威。同一变更补齐并一起移动，语义冲突由维护者解决。[项目语言补充](../../../README.zh.md#语言)拥有具体拼写和配对要求。

决定记录动机、完整选择、重要替代方案和结果。实质分析可放在动机后，开头说明一个具体动作或完整选择。无合格条目时，空替代方案章节也是完整结果。ADR 保留必要契约、理由、条件、不确定性和历史能力，不成为组件手册、执行计划或会话日志。[编写规则](../../../../skills/maintain-adr/references/writing.md)拥有精确标准，包括替代方案依据及各处风险陈述的因果和实质影响。

公开决定在读者无法访问私有任务材料时仍能说明选择及必要理由。批准记录不替代这一公开契约。

### 生命周期

需要实现的选择先在任务中保存批准和待执行安排，再将正式决定与对应实现一起集成。替代变更合入前，原决定仍是主线权威。没有实现动作的长期选择可以通过纯文档变更形成决定。不设置独立提案或被拒提案状态。

无冲突新增在末尾 `Changes` 下追加真实日期条目，独立新增可以链接另一决定。纯表达或有依据的事实修复不形成新选择。冲突选择须指出每条有效条款、新选择和二者不能同时成立的原因，并取得所需批准，无须另建 ADR 提案。代码量、新功能、宿主依赖或改名本身不构成冲突。

实现后，将获准选择与原决定范围内所有仍有效条款整合为完整后继。在同一变更中将被替代文件对归档到下一个未用修订号，并在规范路径写入后继。保留真实事件日期和原作者。`Reverses`、`Reversed by` 链接直接版本：C 替代 B 时，A 原来指向 B 的链接跟随 B 进入归档，不漂移到 C。

按含义而非源目录分类引用。当前权威使用规范路径，历史选择跟随对应版本。重算所有受影响路径、语言链接、入站链接和片段。归档在关系与事实链接修复后冻结。命名和有依据的身份修复不改变承诺，不解除历史冻结。不保留旧名别名，原拼写本身是所引事实时保留历史拼写。持续变化的 Skill 或规格不能替代解释历史选择所需的契约。

### 项目权限

维护者决定是否采用持久选择及归档被替代决定。Agent 按有效授权执行，复用已有批准，尊重只读请求。计划、任务状态、审查结论或实现完成不授予生命周期或集成权限。移除提案阶段不增加新的批准门禁。

本地候选、审查和独立集成权限遵循[项目集成政策](../../../README.zh.md#集成)与 Git 规则。获准的依赖开发可以使用已验证但未合并的前置候选，这本身不批准选择或归档。两个文档维护 Skill 都不负责任务 Goal 或任务生命周期。目标变化时按需使用 `maintain-spec`，不要求无条件同时加载。

### 自动化边界

保留评审、仓库搜索和 Git 历史，不增加分类体系、翻译 sidecar、归档 manifest、索引或常驻维护脚本。只有重复维护或实际失败确定具体约束后才增加机械检查。发现 Skill 和格式通过不足以说明维护正确，实际项目会话必须体现适用加载、读取有效依据，以及按已确认要求正确维护文档。

Skill、项目补充、文档规则、仓库规格、词典和受影响引用保持一致。公开分发、适配其他项目或宿主另行确定范围，不为它们预建通用框架。该机制不增加 tk 状态、命令、schema、模板或 ADR 集成接口，也不增加强制替代 RFC 流程。

## 考虑过的替代方案

保留独立的活跃和被拒 ADR 提案。公开读者可以获得专门的决定前记录，但它重复任务讨论与执行跟踪，并要求独立集成阶段。所选方案由决定保留理解已采纳选择所需的理由，包括重要的被否决替代方案。

完整规则留在项目 README，Skill 只提供通用步骤。这样保留指南归属，但每次维护都必须从两处拼合方法。让 Skill 持有主要方法，需要仔细迁移契约和引用，同时独立保留项目补充。

## 结果

每项决定的当前权威仍有稳定路径，被替代版本可分别访问。直接历史关系和完整后继仍需语义审查，格式检查无法证明。

任务保存决定前的工作，不再维护第二套 ADR 生命周期。如果必要理由只留在私有讨论中，公开读者便无法判断决定。因此公开记录须独立保留这些理由和重要替代方案，普通未采纳想法则不必留在公开 ADR 历史中。

主要方法按需提供，不保留第二套完整指南。Agent 跳过加载时，缩减后的补充不能提供遗漏规则，仍可能出现需求或历史关系错误。判断使用情况需要项目触发说明和真实维护证据。
