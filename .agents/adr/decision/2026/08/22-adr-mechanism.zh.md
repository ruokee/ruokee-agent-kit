## 动机

维护双语 ADR 提案与决定，保持决定路径稳定并保留可追溯的反转历史。

ADR 保存长期选择、理由、必要契约和生命周期。连续版本需要一个当前引用入口，以及可分别访问的历史记录，包括同一天内发生多次反转的情况。年、月目录用于归类记录，不把实际归档日期当作身份。

[此前机制](../../../archived/2026/08/22-r4-adr-mechanism.zh.md)要求命名维护保留每条记录的文件名日期，其后继使用不同日期。将所有版本统一到决定首次提出日期，改变了日期含义与历史维护边界，不改变其他 ADR 记录的选择。

## 决定

### 术语

使用 **ADR** 作为架构决策记录的主要术语。ADR 根目录为 `.agents/adr`。

使用 `proposal` 和 `decision` 作为两类文档。`proposal/` 保存活跃提案，`rejected/` 保存被拒绝的提案，`decision/` 保存当前决定，`archived/` 保存归档决定。目录表达类型与状态，文件头不含 `Status` 字段。

使用 `Create decision`、`Update decision` 和 `Reverse decision` 作为动作短语。`Reverse decision` 是动词短语，不是名词标签。后继在文件头元数据中使用 `Reverses` 链接归档前驱，前驱使用 `Reversed by` 链接实际后继。

在 ADR 根目录维护 `glossary.md` 和 `glossary.zh.md`。术语表包含 ADR、提案、决定、更新决定和反转决定。每项只有一段简明定义，并注明另一种语言中的对应术语。新增术语前，维护者必须明确确定其含义。

### 身份

决定首次提出日期与简短的规范英文主题名，标识其当前记录和全部归档版本。普通反转保留该日期与名称。实际归档日期保留在 `Archived: YYYY-MM-DD`，带日期的 `Changes` 条目保留真实事件日期。

承接原主题的后继沿用身份和修订序列。抽出为独立决定的主题获得自己的首次提出日期、规范名称与序列，并保留真实来源及反转关系。共享前驱或存在 `Reverses` 关系，本身不意味着属于同一身份。

提案使用自身首次提出日期，即使它提议反转更早的决定。拒绝提案时保留该日期。反转提案日期不替换旧决定的身份日期。

### 路径

ADR 正文使用以下路径：

```text
.agents/adr/proposal/YYYY/MM/DD-name.md
.agents/adr/decision/YYYY/MM/DD-name.md
.agents/adr/rejected/YYYY/MM/DD-name.md
.agents/adr/archived/YYYY/MM/DD-rN-name.md
```

`YYYY` 为四位年份，`MM` 和 `DD` 为两位月份与日期。中文文件在同目录使用相同名称及 `.zh.md` 后缀。当前决定与其所有归档都按身份的首次提出日期确定目录，即使实际归档发生在其他月份或年份。

只有归档决定带 `rN`。首次反转产生 `r1`，该身份此后每次反转将 `N` 递增一次，跨日、跨月、跨年均不重置。其他决定、普通更新、命名纠正、目录移动、另一种语言文件及多条关系链接不消耗该序号。后继在规范路径替代当前记录，不覆盖任何归档。

四个生命周期根目录都保留 `.gitkeep`，即使已有记录。只为实际记录创建时间目录。月目录没有文件数量上限。指南与术语表保留在 ADR 根目录。

### 提案流程

规划需求前先搜索活跃提案与当前决定，判断需求是增加无关能力、无冲突扩展当前决定，还是与当前决定冲突。

除非维护者要求其他拆分方式，一项需求创建一份提案。一份提案可以创建多项决定、反转多项决定，或同时执行两种操作。

实现开始前，将获准提案作为独立变更合入 `main`。从更新后的 `main` 创建新的短期实现分支。实现完成后，在实现变更中创建新决定、更新无冲突决定、反转冲突决定，并删除已落实提案。Git 历史保留独立合入的提案。

### 记录格式

每项 ADR 由同目录的英文和中文文件对表示，并保留双向语言链接。无后缀的英文文件是默认公开链接。两份文件语义同等权威，必须在同一变更中补齐，并一起移动。语义冲突会阻止合入，直到维护者解决。作者可以从任一语言开始。

标题在两种语言中都只写主题，类型与状态由目录表达。提案包含 `Motivation`、`Proposal`、`Alternatives considered`、`Acceptance criteria` 和 `Risks`，可在 `Motivation` 与 `Proposal` 之间加入 `Analysis`。中文章节为 `动机`、`提议`、`考虑过的替代方案`、`验收标准`、`风险` 和可选的 `分析`。被拒绝提案增加 `Rejection reason` 或 `拒绝原因`，修复事实链接后冻结。

决定包含 `Motivation`、`Decision`、`Alternatives considered` 和 `Consequences`，可在 `Motivation` 与 `Decision` 之间加入 `Analysis`。中文章节为 `动机`、`决定`、`考虑过的替代方案`、`结果` 和可选的 `分析`。归档决定保留该格式，修复关系链接和事实链接后冻结。

提案记录 `Draft owner` 和 `Draft writer`，决定记录 `Decision owner` 和 `Decision writer`。owner 是负责维护者，writer 是最初起草者，后续维护时不改变。文件对中的这两项字段保持一致。模型起草者名称不含提供方、路由器与渠道前缀，可以保留 `OMP` 等宿主或产品名。关系与生命周期元数据位于 writer 后、双向语言链接前。路径、命令、API 名称、元数据字段与代码标识符在两种语言中保留仓库原拼写。

每个 ADR 文件名、主标题与小节标题都遵循[文档命名规则](../../../../rule/documentation.zh.md#命名)。使用短祈使句、短语或名词命名一个主题，细节留在正文。`Changes` 标题的日期前缀不豁免其主题文字。完整叶子文件名不超过 60 字符，包含 `DD`、可选的 `rN`、主题、语言后缀与扩展名。

### 编写记录

`动机` 是第一个必需正文章节。第一段只写一句简短的话，直接说明要做的事情，不写记录做了什么。这句不依赖标题、链接或后文才能理解。后续段落承载具体问题、背景、理由与证据。新增能力不必被包装成缺陷。反转提案开头说明拟作出的改变，后继决定说明它记录的完整选择。

可选的 `分析` 只记录影响选择的观察、证据、约束、推导与不确定性。没有实质分析时省略。它不是实施计划或调研笔记副本，也不重复动机与替代方案。

ADR 记录完整连贯的长期选择、理由、必要边界与归属、重要公开承诺，以及重大的兼容、安全、成本和失败后果。技术内容只保留理解选择、重要取舍或保存有约束力契约所需的片段。配置权威、身份不可变性和进程级副作用可能需要具体标识符。

完整 API 与配置表、schema、命令参考和持续维护清单属于其所属公开文档。内部函数名、算法步骤、逐文件修改、执行计划、测试命令与验证日志属于实现文档、代码、测试或任务材料。验收标准写可观察结果，不写测试操作。链接可访问的公开契约，不把忽略的任务材料作为公开依据。

移走有约束力的条款不等于取消它。保留其含义与可访问引用。历史记录保留足以解释当时选择的原有细节，指向持续变化的当前文档不能替代历史契约。

区分有意封闭的协议、归属规则与安全边界，以及示例和可增长清单。优先链接所属清单，不固定数量或穷举文件树。封闭集合或禁止事项需说明受保护边界与理由。当前范围限制或初期不需要的选项不自动成为永久禁令。不能事后把既有禁令降格，也不为让文字可扩展而预建抽象和配置。

防御规则必须针对实际操作与危害。校验、修复、生命周期变化与重复激活可能需要不同前提。保留身份、权限与副作用保护，不以无关的全面限制取代它们。

只记录起草前已存在，或需求讨论与分析中真正考虑过的替代方案，说明每项何时成为实际选项。每项都是同一选择的另一种做法，不是事实、要求、约束、验收标准、实现细节或复述。风险写采用提议或相关遗漏造成的可信不良后果。删除无依据或归类错误的条目。适用章节没有合格内容时，英文只写 `None`，中文只写 `无`。描述性三级标题可整理必需章节，但不替代其二级标题，也不承载进度历史和复制清单。

### 决定生命周期

无冲突新增使用更新决定，追加到最后的 `Changes` 或 `变更` 章节，并使用带日期的三级标题。新增内容值得独立成为 ADR 时链接另一项决定。纯表达维护不形成新选择，不需要反转。

冲突选择使用反转决定。先合入提案，列出要反转的每项决定、有效条款、新选择和二者不能同时成立的原因。代码量、增加功能、增加宿主依赖或改名本身不足以证明反转。实现后，将每项旧决定仍有效的规则与获准提案整合成其范围内的完整后继，不复制组件实现规格。

同一变更将被替代的双语版本移入下一修订号归档。归档元数据在可选的 `Reversed by` 前增加 `Archived: YYYY-MM-DD`。后继的 `Reverses` 指向该归档，归档的 `Reversed by` 指向实际后继。归档不作为当前权威。

直接关系跟随版本。A 被 B 反转，B 随后被 C 反转时，A 的 `Reversed by` 跟随 B 进入 B 的归档，不漂移到当前路径上的 C。B 仍链接 A，C 链接 B 的归档。当前权威引用使用规范当前路径，特定历史选择引用跟随该版本进入归档。按引用含义分类，不按源文件所在目录分类。文件路径稳定不意味着标题片段不可改变。

### 维护

维护者负责批准或拒绝提案，以及归档决定。Agent 可在授权工作中研究、起草、实现和评审，作出这些生命周期决定仍需明确批准。只有拒绝理由仍可防止现实中重犯同类错误时，才保留被拒绝提案。

事实路径、名称或验证入口移动时，保持当前决定准确。事实维护不能表达冲突选择。语言文件一起移动，并在同一变更中修复关系链接、正文链接、语言链接、入站引用与标题片段，按各源文件位置重算相对路径。

命名规则覆盖全部保留的提案、决定、归档和被拒绝提案。根据正文、关系字段、提案来源与相关 Git 历史纠正身份日期、规范名称、修订顺序、主标题和小节标题，不把现有名称或链接当作权威。纠正有证据的关系错误。命名整改不增加反转，也不允许重写历史实质。不保留兼容性的旧文件副本。

保留每项记录的选择、理由、约束、不确定性、历史能力范围、原作者、实际归档日期与事件日期。身份日期规范化改变路径日期，不改变真实事件。Git 历史保留原路径与逐记录文件名日期。历史格式示例或 Git 对象路径以原拼写作为所引用事实时，可以保留原值。普通命名维护既不解除冻结，也不改变有约束力的承诺。

依靠评审、仓库搜索与 Git 历史，不增加专用 ADR Skill、分类体系、翻译 sidecar、归档 manifest、索引或常驻维护脚本。只有重复维护或实际错误确定具体机械约束后，才增加最小检查。

[ADR 指南](../../../README.zh.md)、[英文版本](../../../README.md)和双语术语表拥有具体格式与操作说明。[仓库规格](../../../../spec/repository.zh.md)说明长期目标与可观察不变量。指南、术语表、文档规则、规格与受影响引用在两种语言中保持一致。

## 考虑过的替代方案

**保留逐记录日期与平铺布局。** 围绕稳定决定引用和同日反转时考虑。当前路径仍随每次反转变化，日期不能区分同日归档，生命周期根目录仍持续堆积未分组记录。

**仅对未来记录应用规则。** 围绕历史纠正时考虑。已有长名称、不一致身份日期与错误关系会被保留，读者需要在同一历史中遵循两套规则。

## 结果

每项决定的当前权威有一个稳定路径，各被替代版本可独立访问。按身份确定的年、月目录将其历史归在一起，即使实际归档发生在多年之后。`Archived` 保存事件日期，不决定目录归属。

当前后继自身归档时，需要维护直接关系。把所有引用都当作当前权威，会把历史依据悄悄指向其他内容。把共同来源误当作共同身份，会合并独立决定或分配错误序列。

标题承载主题，不承载类型。读者通过目录、元数据和语言链接识别记录。查找依赖简短名称与仓库搜索，不依赖中央索引。

提案和实现需要独立分支及主线提交，保留独立理由与评审边界。反转需要对照前驱与提案重建完整当前契约。必要契约细节及双语语义一致性仍需评审判断，不是机械检查可证明的属性。

术语表保持精简。普通用词和尚未确认的近义词不会成为合同术语。
