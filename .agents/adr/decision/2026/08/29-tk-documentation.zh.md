## 动机

在两个自包含 Skill 源码树和独立可用的公开文档中维护完整双语 CLI 指导。

每种语言只有一个 Skill 和一份受维护参考资料。文件放在同一目录树，使源码与安装后导航一致。完整规格和明确主题归属，让 Agent 与用户无需私有工作记录也能获得相同合同。

## 决定

### 使用模式

记录、深度调研、迭代设计和草稿纸组织普通任务材料。任务可以组合使用，也可以都不使用。模式不增加元数据、schema 字段、`extra` 约定、运行时状态、命令或自动目录。正式决定遵守项目指定机制和位置。

只在信号出现后建议模式，并说明新增材料及维护。用户明确请求即授权采用，无需重复确认。采用不授予任务创建、生命周期、删除、移动或覆盖归属不明内容的权限，普通材料编辑沿用既有权限。

[Agent 行为规格](../../../../spec/tk-agent.zh.md#材料模式)保留各模式的信号、反例、默认值、历史、证据及清理要求，[模式参考](../../../../../projects/tk/skills/tk-cli-zh/references/patterns.md)提供操作指导。项目惯例可覆盖默认路径。只为实际工作创建材料，不预建空目录、不编造历史、不创建未来日期记录，也不自动重排现有任务。任务概要、详细材料和 WAL 保留各自职责。

### Skill 源码

`tk-cli` 和 `tk-cli-zh` 各自包含入口、完整参考资料及 Agent 元数据。源码和安装后的全部文件引用都在同一 Skill 内解析。装配收集完整目录树，拒绝缺失的 Markdown 目标。每种语言只有一份受维护参考资料，不依赖跨目录装配。

两种语言行为等价。[Skill 设计](../../../../../projects/tk/docs/design/skill.zh.md)按[自包含决定](./24-component-self-containment.zh.md)负责源码和分发组织。

### 合同归属

完整 [tk 规格集合](../../../../spec/README.zh.md#tk)负责必要行为和验收，包括必要命令、参数、字段、默认值、上限、失败语义及兼容性。规格不含仓库文件链接，不委托缺失要求。

组件用户参考独立描述相同合同。设计解释算法和内部机制，验证说明方法及证据。[设计索引](../../../../../projects/tk/docs/design/README.zh.md)为各主题导航一个主要说明页，可分发组件文档不依赖仓库规格。

[组件 README](../../../../../projects/tk/README.zh.md) 介绍 tk，链接双语指南及设计页，不复制详细合同。仓库入口链接组件入口。审查记录、任务路径、分支状态、实现日志及本地材料不进入公开页面。

ADR 保留长期选择、必要理由、重要替代方案及结果，链接可访问合同，不复制完整命令、字段或测试清单。

### 最终状态写法

公开文档陈述当前正式合同，不叙述设计修订、审查争论、开发阶段废弃命令、未发布格式兼容或 Agent 工作历史。历史决定保留真实合同。退出接入的说明只放在组件 README 的简短弃用声明中，当前参考描述受支持 CLI，不提供更新操作说明。

### 语言配对

普通公开 Markdown 按[公开文档决定](./20-bilingual-docs.zh.md)使用同目录 `name.md` 和 `name.zh.md` 配对，包括组件 README。指南和设计专题在一级标题后链接对应语言，Skill 语言变体保持独立自包含目录树。

仓库文件链接相对于当前文档，同目录及后代使用 `./`，外部目标使用必要数量的 `../`。页面不使用分离语言目录或跳转占位，移动时修复受影响入站链接和命令示例。

英文和中文语义等价。中文使用自然表达，不做逐句机械映射。命令、路径、字段、代码、日志、产品名及标识符保留规定拼写和大小写。

术语表只包含 tk 特定含义、固定大小写和稳定译法。普通技术词留在归属文档中。固定中文形式包括 `受管`、`草稿纸`、`人类可读`、`直接切换`、`支持的子命令`、`活动操作标记`、`表示切换`、`续跑令牌` 和 `续跑状态`。

### 分发文档

公开参考覆盖唯一 CLI 接口、两个语言身份、默认英文安装、互斥的 Harness 与自定义根目录目标、根目录映射，以及两个普通 Skill 的受限生命周期。

### ADR 生命周期

ADR 使用决定格式。`decision/` 保存当前决定，`archived/` 保存已采用且被替代的决定。语言对语义一致，不含 `Status` 字段。维护者控制采用和归档，设计、实现或验证完成均不自动授予这些权限。

任务保存讨论、批准和执行安排，不增加运行时状态或命令。正式决定独立于任务材料，保留公开可理解的理由及合同，包括重要被否决替代方案。未采纳草稿不是归档决定。需要实现的决定随实现集成，纯文档选择可以独立集成。

### 维护

公开行为变化时，一同更新完整受影响规格、设计和参考页、指南与 CLI 示例、两种语言、受影响 Skill、当前负责该选择的 ADR，以及验证方法和场景。

使用仓库 Markdown、链接、格式和拼写检查，并进行人工双语审查。重复维护或实际偏差证明具体不变量值得自动化前，不增加专用结构或翻译检查器。[文档设计](../../../../../projects/tk/docs/design/documentation.zh.md)和[术语表](../../../../../projects/tk/docs/design/GLOSSARY.zh.md)保存维护细节。

## 考虑过的替代方案

无

## 结果

读者可以从规格集合确定要求，也能独立使用组件指导。源码和安装后 Skill 具有可用的内部导航，无需维护重复的同语言参考资料。

双语 Skill 和公开指导仍需同步编辑。只更新部分文件可能使 Agent 遵循的采用或维护规则不同于用户读到的规则。格式和 Rust 检查不证明语义一致或 Agent 行为，这些职责由人工审查和适用 Harness 场景承担。

最终状态写法让公开参考聚焦用法。任务材料保留执行证据，ADR 保存理由，不成为进度日志。
