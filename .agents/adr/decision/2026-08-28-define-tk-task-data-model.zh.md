# ADR 决定：定义 tk Task 数据模型

Decision owner: Ruokee
Draft writer: OMP GPT-5.6 Sol

[English](./2026-08-28-define-tk-task-data-model.md) | 中文

## 动机

[tk 产品架构](./2026-08-21-define-tk-product-architecture.zh.md)把项目文件作为唯一权威的 Task 状态，因此必须为身份、路径、生命周期、关系、表示、发现、写入、迁移和清理定义一套明确模型。宽松识别或隐藏恢复状态会让普通项目文件产生歧义，也会使不同调用方看到不同的 Task 状态。

这套模型需要保持人类可读，同时能处理写入中断、schema 变化和项目级操作，但不能演变为数据库或事务引擎。

## 决定

### 项目与表示

项目使用 `.agents/tk_config.toml` 中的稀疏配置，选择一个项目相对 Task 根目录、可选子 Task 目录、Git 策略、创建策略和元数据模式。默认 Task 根目录是 `.tk`。

顶层 Task 使用 `YYYY/MM/DD-NN--slug`。子 Task 位于父 Task 下，并使用稳定的两位序号和 slug。目录拓扑定义父子关系。序号 `99` 是同级可用的最后一个编号。

项目统一使用 split 或 embed 元数据模式。split 把元数据存入 `tk.toml`，把正文存入 `TASK.md`。embed 把相同元数据存入受限 YAML frontmatter，并保留下方正文的原始字节。一个项目不会让不同 Task 混用表示形式。

Schema 1 包含不可变 UUIDv7 `id`、规范化 `name`、`planning`、`open` 或 `closed` 状态、不可变且带时区的 `created_at`、同一 Task 根目录内的 `depends_on` 和 `related_to` 关系，以及可选且可无损表示的 `extra`。schema 不存储父级、分支、优先级、分配对象、更新时间、关闭原因或会话身份。

每个正式发布的 schema 转换都保留相邻的前向迁移器。迁移按顺序应用这些迁移器，同时支持 split 和 embed，并保留 Task 正文。不提供降级、schema 0 或未发布开发格式的兼容合同。

### 候选、身份与生命周期

只有规范目录拓扑和当前元数据模式下严格合法的载体才能成为 Task 候选。相似 Markdown、损坏的 frontmatter、不完整载体、symlink、特殊文件、临时内容和越界路径会被忽略。`check` 可以诊断项目识别为受管位置中的无效内容，但发现过程不会虚构损坏的 Task 候选。

UUIDv7 是权威身份。路径用于定位 Task，名称用于描述 Task。只有 rename 可以修改 Task 名称和规范路径。

关系只能存在于同一个 Task 根目录内。Task 不能关联自身，`depends_on` 不能形成环。关系会去重并按 UUID 稳定排序。

`planning` 保存用户希望保留的早期想法、调查或计划。`open` 表示正在处理 Task。`closed` Task 可以读取，除此之外保持只读。关闭和重新打开都需要非空原因和当前明确授权。正常关闭还要求所有后代 Task 和依赖项均为 closed。强制关闭只绕过这两项检查。

严格模式项目创建顶层 Task 时需要当前明确授权。宽松模式项目可以保存值得持久记录的工作，不把创建视为执行承诺。创建 planning Task 仍要求用户表达保存这项早期工作的意图。

### 发现、搜索与 Git 策略

Task 根目录不维护永久索引或缓存。发现和项目级检查按需遍历规范文件。Git 项目使用 Git 根目录。非 Git 发现和精确绝对路径使用有界祖先检查，不会一直遍历到文件系统根目录。

精确读取和修改接受完整 UUIDv7 或规范 Task 路径。search 只把查询分类一次，类别依次为 UUID 或显式 Task 路径、现有材料路径、显式正则表达式或字符串，分类后不再回退。search 默认包含全部三种状态，并按 `uuid`、`path`、`regex`、`string` 的匹配类别顺序排列。同一类别按 `created_at` 降序、ID 升序排列。默认限制为 20，最大为 100。

Git 策略只在持久写入前运行。`track` 要求受管 Task 文件不被 Git 忽略，`ignore` 要求 Task 根目录被忽略，`none` 不调用 Git 策略命令。tk 不修改 Git 配置、忽略规则、索引、提交或历史。

### 持久化与维护

受管单文件变更先在同目录写入完整临时文件，再原子替换目标。普通写入不使用锁、租约、compare-and-swap 或自动合并。并发完整替换由最后完成的操作决定结果。

WAL 是按日保存的普通 Markdown 活动记录。元数据先提交，再自动追加 WAL。WAL 失败会返回警告，但不会回滚已经提交的元数据。actor 是归因文本，不表示身份或授权。

多目标操作先完成全部领域预检，再按确定顺序提交，在第一个错误或取消点停止，并返回已完成项、未完成项和原始错误。操作不会自动回滚，也不会写入续跑状态。后续调用重新读取规范状态并重新规划。

多目标项目写入会在首次持久写入前创建活动操作标记。标记记录操作、项目范围、Linux boot ID、PID 和进程启动时间。操作进程仍在运行时，其他写操作保持阻塞。操作进程退出后，其他写操作仍然保持阻塞，直到 GC 删除标记。read、search 和纯诊断仍然可用。活动操作标记不是通用锁。

清理清单只包含格式版本、操作进程身份、创建时间和 tk 临时路径。GC 只删除可以证明由 tk 创建的临时内容，以及已经结束的活动操作标记。它不会继续、回滚或修复 Task、迁移、rename 或组件操作。

rename 只更新 Task 本身并报告 Markdown 引用，不自动改写引用。`git_policy=track` 扫描 Git 跟踪的项目 Markdown；`ignore` 和 `none` 扫描 Task 根目录下的普通 Markdown。

`check` 验证受管项目状态，不修改内容。必要 I/O 失败会立即停止扫描并报告检查不完整。损坏的 `tk.toml` 只有在 tk 无法表达修复、Agent 已说明具体编辑且用户在当前对话中明确授权后，才允许人工修复。Task 恢复可用后，Agent 再次运行 `check` 并用 WAL 记录修复事件。

完整格式和操作细节见[数据模型](../../../projects/tk/docs/design/data-model.zh.md)与[工具 API](../../../projects/tk/docs/design/tool-api.zh.md)。

## 考虑过的替代方案

**只支持 split 或 embed。** split 便于直接检查元数据，embed 可以把一个 Task 保存在单个文件中。两者能够承载相同 schema，不需要把其中一种降为次要表示。

**使用锁、事务或持久恢复计划。** 这些机制会增加协调逻辑和第二个操作状态机。原子替换、完整预检、明确的部分提交结果、活动操作标记和从规范状态重试已经覆盖目标工作方式。

**rename 时自动改写 Markdown 引用。** 自动编辑可能修改无关文本或有意保留的历史内容。只报告引用可以保持 Task 变更精确，并把内容决定交给调用方。

## 结果

Task 状态保持人类可读，并能跨接口移植。由于没有永久索引，发现和部分维护操作需要扫描项目。search 只保留有界候选集，check、关系验证、迁移和表示切换可以使用与 Task 数量成比例的内存。

普通并发写入采用最后完成写入者语义。多目标失败可能留下合法的部分结果，调用方必须检查已完成项和未完成项后再重试。进程退出后不存在隐藏的续跑状态。

每个正式发布的 schema 转换都会成为长期维护代码。支持两种表示也要求两条路径具有等价的验证、迁移和正文保留行为。
