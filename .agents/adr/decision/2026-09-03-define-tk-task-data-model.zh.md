## 动机

[tk 产品架构](./2026-08-21-define-tk-product-architecture.zh.md)把项目文件作为唯一权威的 Task 状态，因此运行时必须为身份、路径、生命周期、关系、表示、发现、写入、迁移和清理定义一套明确模型。

旧模型同时使用 `subtasks_dir` 控制子 Task 创建和发现，使放置偏好成为 Task 可见性的一部分。改变配置、导入有效子 Task 或把子 Task 放在普通材料下，都可能隐藏有效受管数据。创建仍需要可预测的目标位置和编号规则，发现则必须识别已有有效载体，同时不能把普通 Markdown 当成 Task。

## 决定

### 项目、路径与表示

项目使用 `.agents/tk_config.toml` 中的稀疏配置，选择一个项目相对 Task 根目录、默认子 Task 创建目录、Git 策略、创建策略和元数据模式。默认 Task 根目录是 `.tk`。`subtasks_dir` 只控制后续子 Task 的创建位置，不限制发现，也不移动已有数据。

顶层 Task 使用规范的 `YYYY/MM/DD-NN--slug` 拓扑。新建子 Task 在父 Task 或其配置的 `subtasks_dir` 下使用稳定的两位 `NN--slug` 目录。已有子 Task 可以位于有效顶层 Task 下的任意真实后代目录。最近的有效祖先 Task 定义父级，元数据不保存 `parent`。

生成式直接子 Task 的序号分配检查所有已发现且叶子目录具有有效 `NN--slug` 的直接子 Task，取最大序号且不填补空洞。配置的创建目录只决定目标位置。序号 `99` 是可生成的最后一个同级编号，耗尽时在写入前失败。

项目统一使用 split 或 embed 元数据模式。split 把元数据存入 `tk.toml`，把正文存入 `TASK.md`。embed 把相同元数据存入受限 YAML frontmatter，并保留下方正文的原始字节。一个项目不会让不同 Task 混用表示形式。

Schema 1 包含不可变 UUIDv7 `id`、规范化 `name`、`planning`、`open` 或 `closed` 状态、不可变且带时区的 `created_at`、同一 Task 根目录内的 `depends_on` 和 `related_to` 关系，以及可选且可无损表示的 `extra`。schema 不存储父级、分支、优先级、分配对象、更新时间、关闭原因或会话身份。

每个正式发布的 schema 转换都保留相邻的前向迁移器。迁移按顺序应用这些迁移器，同时支持 split 和 embed，并保留 Task 正文。不提供降级、schema 0 或未发布开发格式的兼容合同。

### 载体发现、身份与生命周期

顶层发现首先要求规范拓扑、合法日历日期、非空 slug，以及与 slug 一致的元数据名称。后代发现随后遍历每个有效顶层 Task 下的真实普通目录。

后代目录只有通过项目元数据模式对应的标记才成为结构候选。split 模式以常规 `tk.toml` 为标记，有效 Task 还必须具有常规的配对 `TASK.md`。embed 模式要求常规 `TASK.md` 以可识别的 tk frontmatter 开头，其首个元数据键为 `schema_version`。完整载体必须通过严格的 schema、身份、表示和安全路径校验。

生成式 `NN--slug` 子 Task 必须让元数据名称与 slug 一致。非生成式子 Task 没有路径与名称一致性要求。带标记但无效的目录作为受管错误交给 `check`，普通发现不会返回。无关 `TASK.md`、普通 YAML frontmatter、符号链接、特殊文件、WAL、`.tk-tmp`、清理数据和 Task 根目录外路径不会成为 Task。除运行时自有路径外，普通目录和无效目录仍在最近有效祖先下继续遍历。

发现顺序固定。一次扫描最多接受 100,000 个真实目录和 256 层后代。超过任一上限或遇到必要 I/O 错误时，扫描失败且不返回部分任务图。

UUIDv7 是权威身份。路径用于定位 Task，名称用于描述 Task。重复 ID 仍是任务图诊断，并使 UUID 解析产生歧义。关系只能存在于同一个 Task 根目录内。Task 不能关联自身，`depends_on` 不能形成环。关系会去重并按 UUID 稳定排序。

`planning` 保存用户希望保留的早期想法、调查或计划。`open` 表示正在处理 Task。`closed` Task 可以读取，除此之外保持只读。关闭和重新打开都需要非空原因和当前明确授权。正常关闭还要求所有后代 Task 和依赖项均为 closed。强制关闭只绕过这两项检查。

严格模式项目创建顶层 Task 时需要当前明确授权。宽松模式项目可以保存值得持久记录的工作，不把创建视为执行承诺。创建 planning Task 仍要求用户表达保存这项早期工作的意图。

### 发现任务图、搜索与 Git 策略

Task 根目录不维护永久索引或缓存。每次操作按需构建一份按载体发现的任务图。搜索、精确路径解析、父级和后代检查、关系校验、`check`、schema 迁移、元数据模式切换和序号分配都使用这份图。

精确读取和修改接受完整 UUIDv7、绝对已发现 Task 目录、绝对受管载体，或当前项目中的相对已发现 Task 路径。绝对材料路径可以定位所属项目，但不是精确 Task 引用。Git 项目使用 Git 根目录。非 Git 项目通过规范顶层祖先和有界项目检查发现，不会一直遍历到文件系统根目录。

search 只把查询分类一次，类别依次为 UUID 或显式 Task 路径、现有材料路径、显式正则表达式或字符串，分类后不再回退。search 默认包含全部三种状态，并按 `uuid`、`path`、`regex`、`string` 的匹配类别顺序排列。同一类别按 `created_at` 降序、ID 升序排列。默认限制为 20，最大为 100。结果根据发现任务图报告 closed 祖先。

Git 策略只在持久写入前运行。`track` 要求受管 Task 文件不被 Git 忽略，`ignore` 要求 Task 根目录被忽略，`none` 不调用 Git 策略命令。tk 不修改 Git 配置、忽略规则、索引、提交或历史。

### 持久化与维护

受管单文件变更先在同目录写入完整临时文件，再原子替换目标。普通写入不使用锁、租约、compare-and-swap 或自动合并。并发完整替换由最后完成的操作决定结果。

WAL 是按日保存的普通 Markdown 活动记录。元数据先提交，再自动追加 WAL。WAL 失败会返回警告，但不会回滚已经提交的元数据。actor 是归因文本，不表示身份或授权。

多目标操作先完成全部领域预检，再按确定顺序提交，在第一个错误或取消点停止，并返回已完成项、未完成项和原始错误。操作不会自动回滚，也不会写入续跑状态。后续调用重新构建发现任务图，并根据当前受管文件重新规划。

多目标项目写入会在首次持久写入前创建活动操作标记。标记记录操作、项目范围、Linux boot ID、PID 和进程启动时间。操作进程仍在运行时，其他写操作保持阻塞。操作进程退出后，其他写操作仍保持阻塞，直到 GC 删除标记。read、search 和纯诊断仍然可用。活动操作标记不是通用锁。

清理清单只包含格式版本、操作进程身份、创建时间和 tk 临时路径。GC 只删除可以证明由 tk 创建的临时内容，以及已经结束的活动操作标记。它不会继续、回滚或修复 Task、迁移、rename 或组件操作。

rename 只更新 Task 本身，并报告解析出的父级、旧路径、目标路径和 Markdown 引用。非生成式子 Task 保持目录不变，只修改元数据。生成式子 Task 或顶层 Task 保留序号并更新 slug 路径。rename 不改写引用。`git_policy=track` 扫描 Git 跟踪的项目 Markdown；`ignore` 和 `none` 扫描 Task 根目录下的普通 Markdown。

`check` 在不修改内容的前提下校验带标记载体、生成式名称与路径一致性、UUID 和直接子 Task 序号唯一性、关系、WAL、活动操作标记与清理数据。它报告带标记的无效载体和解析出的逻辑父级。必要 I/O 失败或发现上限会停止扫描并报告检查不完整。损坏的 split 载体只有在 tk 无法表达修复、Agent 已说明具体编辑且用户在当前对话中明确授权后，才允许人工修复。Task 恢复可用后，Agent 再次运行 `check` 并用 WAL 记录修复事件。

完整格式和操作细节见[数据模型](../../../projects/tk/docs/design/data-model.zh.md)与[工具 API](../../../projects/tk/docs/design/tool-api.zh.md)。

## 考虑过的替代方案

**只支持 split 或 embed。** split 便于直接检查元数据，embed 可以把一个 Task 保存在单个文件中。两者能够承载相同 schema，不需要把其中一种降为次要表示。

**使用锁、事务或持久恢复计划。** 这些机制会增加协调逻辑和第二个操作状态机。原子替换、完整预检、明确的部分提交结果、活动操作标记和从当前受管文件重试已经覆盖目标工作方式。

**rename 时自动改写 Markdown 引用。** 自动编辑可能修改无关文本或有意保留的历史内容。只报告引用可以保持 Task 变更精确，并把内容决定交给调用方。

**继续只在 `subtasks_dir` 下发现子 Task。** 这种方式缩小扫描范围并保证生成式路径，但改变放置偏好会隐藏有效载体，使导入的子 Task 无法访问。

## 结果

Task 状态保持人类可读，并能跨接口移植。改变 `subtasks_dir` 不再改变可见性，导入或重新组织后的有效子 Task 载体仍然可用。

Task 下完全有效的载体即使原本只是示例，也会成为 Task。仓库不应把完整受管载体复制到普通材料中。把有效载体移动到另一个有效 Task 下，也会在不修改元数据的情况下改变推导父级、关闭阻塞项和同级编号。`check` 和 rename 会显示解析出的父级与路径，便于诊断。

递归发现会比配置路径发现读取更多目录。固定深度和目录上限避免无界工作，但大型或不可读材料树可能让全项目操作以显式错误失败。由于没有永久索引，发现、check、关系校验、迁移和表示切换可以使用与 Task 数量成比例的内存。

普通并发写入采用最后完成写入者语义。多目标失败可能留下合法的部分结果，调用方必须检查已完成项和未完成项后再重试。进程退出后不存在隐藏的续跑状态。

每个正式发布的 schema 转换都会成为长期维护代码。支持两种表示也要求两条路径具有等价的验证、迁移和正文保留行为。
