# ADR 决定：定义 tk 运行时与 CLI

Decision owner: Ruokee
Decision writer: OMP GPT-5.6 Sol

[English](./2026-08-28-define-tk-runtime-and-cli.md) | 中文

## 动机

请求编排、领域规则、持久化、输出、取消和资源限制必须由同一个运行时负责，使 [tk 产品架构](./2026-08-21-define-tk-product-architecture.zh.md)暴露的面向人的 CLI、stdio MCP 和 Harness 原生工具不会成为同一套任务行为的多份独立实现。

运行时还需要为脚本和适配器提供稳定的命令边界。它应以结构化方式报告预期失败，同时不能掩盖传输故障、操作系统错误或部分提交。

## 决定

### 语言与可执行文件

tk 由 `projects/tk/` 下的一个 Rust Cargo package 实现，并生成一个名为 `tk` 的可执行文件。公开 Linux 运行时路径是 `$HOME/.local/bin/tk`。

运行时按职责划分接口、应用、领域、持久化和维护部分。接口依赖公开的应用与领域合同。Harness 适配器使用生成的 schema 和公开进程行为，不依赖 Rust 私有模块。

大多数命令使用短生命周期进程。MCP 服务器只服务一个 stdio 连接，并为每次请求重新解析 cwd、项目和任务状态。运行时没有后台进程、项目图缓存或常驻索引。

### CLI 合同

公开命令树如下：

```text
tk search
tk read
tk create task
tk create subtask
tk update
tk log
tk init
tk check
tk rename
tk gc
tk schema generate
tk metadata migrate
tk metadata switch
tk mcp
tk install
tk uninstall
tk --version
```

`--actor` 不是全局选项。它只属于会追加 WAL 的 update、log 和 rename 操作。`init --force` 使用当前显式值和默认值重写项目配置，不读取或修改任务数据。

面向人的输出和 JSON 输出都是公开合同。JSON 使用包含 `ok`、`data`、`warnings` 或 `error` 的统一结果。稳定错误包含错误码、类别、面向人的消息和结构化详情。调用方根据错误码或类别分支，不能解析消息文本。

退出码保持一套稳定的宽泛映射。0 表示成功，请求失败使用 2，预期拒绝使用 3，存储和内部故障使用 4，环境故障使用 5，首次持久写入前取消使用 130。结构化错误负责表达具体原因。

### 请求上下文

请求依次从显式值、Harness 会话目录和运行时进程目录选择 cwd。完整的绝对任务路径或材料路径可以独立于 cwd 定位其所属项目。

actor 是 WAL 归因信息，不表示身份、授权或任务分配。直接 CLI 写入默认使用 `cli`。上下文值不会保存为任务状态。

项目发现和 Git 策略相互独立。read、search 和诊断可以在不受 Git 策略拒绝的情况下定位并检查项目。持久写入会在首次写入前立即运行共享 Git 检查。

### 进程与资源边界

运行时限制 search 候选、进程 stdout 和 stderr、生成 schema、WAL 读取和协议帧的大小。每条子进程输出流和每个 MCP JSON 载荷限制为 1 MiB。MCP 输入超限时关闭传输，输出超限时返回失败，不发送不完整帧。

search 逐项处理候选，并最多保留 100 个最佳项。check、关系图、迁移和表示切换等需要完整项目信息的操作，可以使用与任务数量成比例的内存。

单文件写入会在原子替换前响应取消。替换开始后，会完成当前替换再返回。多目标命令在提交点之间响应取消。首次写入前取消不会留下持久变更。提交点之后取消会使用与 I/O 失败相同的边界，报告已完成项和未完成项。

### 失败与版本合同

预期的领域和环境失败使用公开统一结果。panic、进程被终止、传输输出损坏和协议连接中断仍属于传输或内部故障。运行时不会为这些情况虚构领域结果。

元数据提交后的 WAL 追加失败作为警告返回。`check` 的必要 I/O 失败表示扫描不完整。部分提交包含已完成目标、未完成目标和原始错误。

运行时分别维护运行时版本、CLI 合同版本、任务 schema 版本、组件格式版本和清理清单版本。`tk --version --output json` 返回调用方需要的运行时、CLI 合同、任务 schema 和组件格式版本。

完整命令语法见 [CLI 参考](../../../projects/tk/docs/design/cli-reference.zh.md)。运行时分层、资源限制、取消和失败行为见[运行时设计](../../../projects/tk/docs/design/runtime.zh.md)。

## 考虑过的替代方案

**分别实现每个接口。** 独立的 CLI、MCP 和原生实现会重复验证、默认值、错误映射和兼容行为。

**使用常驻守护进程。** 守护进程会给本地文件产品增加进程监管、同步、缓存失效和服务可用性问题。

**为适配器提供私有子命令。** 隐藏入口会形成第二套进程合同，并允许 Harness 行为偏离公开 CLI。

**为每类失败定义不同退出数字。** 持续扩展数字会让脚本面对第二套错误分类。稳定 JSON 错误码和类别负责表达细节，退出码只保留宽泛 shell 语义。

**允许协议和进程输出无限增长。** 损坏项目或子进程可能耗尽 Harness 会话资源。固定限制使故障边界明确。

## 结果

所有接口共享一个可执行文件和一套错误模型。运行时变更可能同时影响 CLI、MCP 和原生调用，因此生成合同和兼容检查发生偏差时必须拒绝继续加载。

短生命周期进程为每次调用重新读取规范状态。这避免了缓存失效和过期项目图，代价是进程启动和重复的有界发现。

CLI 是公开兼容边界。命令名称、参数归属、JSON 字段、错误码和版本输出发生变化时，运行时、适配器、Skill、文档和验证必须在同一变更中更新。

## 变更

### 2026-09-05：创建不再接受正文输入

create 接口不再拥有正文输入。`tk create task` 把 `--body` 作为未知参数拒绝，create 工具请求和子任务 item 把 `body` 作为未知字段拒绝。运行时创建任务时自动生成 `# <规范化名称>` 作为初始正文。CLI 合同版本升到 2。

### 2026-09-05：rename 防止断链引用

`tk rename` 新增 `--ignore-brokenlinks`。执行会移动任务路径且存在旧路径引用时，在首次持久写入前以 conflict 错误和退出码 3 停止。该参数允许此次移动继续且不改写引用文件。dry-run 报告计划和引用，不写入内容。CLI 与 `tk_exec rename` 采用相同规则，CLI 合同版本保持 2。

### 2026-09-05：区分 read 返回限制与 WAL 完整检查

`tk read` 现在使用 `minimal`、`summary` 和 `detailed`，默认使用 `summary`。`minimal` 不读取任务正文或 WAL。`summary` 返回完整任务正文和不含正文的最近 WAL 条目，默认最多 5 条、4000 字节。`detailed` 增加 WAL 正文，默认最多 50 条、16000 字节。显式预算可以在 0 到两种视图共用的上限 50 条、16000 字节之间取值。运行时在确定返回字段后，按紧凑 JSON 的 UTF-8 字节数计量，并静默省略预算之外的条目，不返回截断字段、警告或诊断。完整历史继续通过每日 WAL 文件提供，不增加分页或完整历史读取模式。

`tk check` 使用单独的流式 WAL 检查器。它读取每个普通的每日 WAL 文件和其中全部条目，不设置固定的总文件数、总字节数或总条目数上限。必要 I/O 失败会指出失败路径，取消会使检查不完整，有效 WAL 的规模本身不会产生 `wal_truncated`。CLI 合同版本升到 3，生成 schema 以及 OMP 和 Pi 适配器会拒绝版本 2 合同。

### 2026-09-08：rename 恢复名称修复职责

`tk rename` 和 `tk_exec rename` 使用现有精确引用形式定位旧字符串名称或可识别生成式后缀需要修复的任务。命令参数、结果结构、引用保护、修复范围外的校验和 CLI 合同版本保持不变。
