# ADR 决定：新增可配置的 OMP 体验调整

Decision owner: Ruokee
Decision writer: OMP GPT-6 Astra

[English](./2026-09-20-add-omp-qol.md) | 中文

## 动机

OMP 有三种行为会打断本可自行继续的工作。hub `wait` 在它监视的后台工作仍在运行时返回空窗口，模型必须重新询问，而每次空返回都消耗一次轮次。遇到上游错误的轮次即便错误是瞬时的也会保持已结束状态，因为原生重试预算已耗尽，或该错误不在预算覆盖之内。远端压缩请求在固定的请求期限处被中断，压缩转而走回退路径而不是完成。

能够处理这些情况的扩展，与它要调整的行为并不在同一处。在 OMP 18.2.4 提交 [`1c0303b1f2ec515cbf4b44a9a49d68a029531aac`](https://github.com/can1357/oh-my-pi/tree/1c0303b1f2ec515cbf4b44a9a49d68a029531aac) 中，等待窗口取自[任务管理器](https://github.com/can1357/oh-my-pi/blob/1c0303b1f2ec515cbf4b44a9a49d68a029531aac/packages/coding-agent/src/async/job-manager.ts#L51)里的编译期阶梯，没有任何设置能触及它；没有设置会在错误之后继续轮次；压缩看门狗是[远端压缩](https://github.com/can1357/oh-my-pi/blob/1c0303b1f2ec515cbf4b44a9a49d68a029531aac/packages/agent/src/compaction/openai.ts#L239)与 [V2 流式压缩](https://github.com/can1357/oh-my-pi/blob/1c0303b1f2ec515cbf4b44a9a49d68a029531aac/packages/agent/src/compaction/compaction-v2-streaming.ts#L252)路径内的常量。宿主确实提供了扩展可用的介入点：重新注册原生工具并通过工具上下文委派、session stop 续跑请求、公开的错误分类器，以及压缩生命周期事件。源码核对能确立这些介入点和缺失的配置，但不能确立基于它们的调整在真实会话中行为正确。

该决定定义第一方组件 `omp-qol`、它与宿主保持的职责划分，以及使用者启用各项调整时接受的边界。

## 决定

### 组件与范围

在 [第一方能力边界](./2026-08-20-establish-first-party-capability-kit.md)与[自包含组件合同](./2026-08-24-keep-components-self-contained.md)下新增 `projects/omp-qol/`，包名 `@ruokee/omp-qol`。一个包包含三个可独立开关的模块：持续等待 hub、可续跑模型错误后的续跑，以及实验性的压缩期限延长。安装、配置入口与检查各只有一处，而每个模块保留自己的开关、可用状态与故障报告。

组件只通过 OMP 插件设置配置，遵循[原生设置决定](./2026-09-10-use-codex-web-plugin-settings.md)，取值、项目级覆盖与解析都由 OMP 负责。等待与保守的错误恢复默认启用，压缩延长明确为选择启用。模块报告自己的有效状态与不生效的原因，单个模块的故障不会停用其他模块。被拒绝的设置只写键与规则，不回显取值。

组件只限于这些行为调整。外部工具守卫（包括 Herdr 守卫）与无关的宿主行为不在其中。安装与迁移仍由用户决定：组件不改动已有扩展、用户配置或宿主安装文件。

### 宿主职责

任务与进程归属、消息消费、结果送达、审批等级、会话历史以及压缩协议都由 OMP 掌握。

等待模块重新注册原生工具，把每次调用委派给它，并且只在返回结果确定不含新信息时重复调用。期限只结束等待：后台任务与进程继续运行，已送达的消息或已结束的任务结果原样返回，用户取消保留自身原因。模块不为工具新增操作，转发原生审批等级与原生工具声明的可中断性，也不主张拥有它没有收到的结果。

恢复模块使用原生 session stop 续跑请求。固定安全排除项——取消、拒绝、认证与配额结果、上下文溢出和确定性失败——优先于配置，任何设置都不能把它们变成续跑。续跑同时受模块与宿主上限约束，每次续跑报告次数与等待时间，模块不声称重新运行是幂等的，也不声称已完成的工具调用不会重复。续跑正文是固定文本，不携带服务端错误内容。

### 压缩实验及其替换条件

压缩期限延长作为默认关闭的实验提供：一个受约束的进程级超时调整，通过全局注册表安装，保留原生压缩协议、历史替换、重试与回退。

启用它即接受其边界。在压缩窗口内，同一进程中无关工作发出的命中超时调用同样会被延长，因此该机制既不提供请求隔离，也不提供严格的项目隔离。它只能延长期限，不能缩短。归属不明确时——窗口重叠、窗口属于其他会话、事件顺序无法解释，或进程内已存在其他 owner——该进程内的调整停用并报告原因，而不是共享或覆盖。关闭时若当前值仍是本组件的函数则还原原生函数，否则报告该情况。

当 OMP 提供受支持的请求级超时设置或 hook 时，改用该接口并停止全局机制。同一期限策略不保留两个 owner。

### 文档与版本证据

在组件自身的 `docs/` 中提供中英文对照的逐项说明，并由两个 README 相互链接：原生行为与关闭扩展时的表现；为什么需要调整、核对过哪些原生配置或 hook；介入位置以及配置如何影响行为；副作用、取消与失败行为；何种上游变化会使该调整不再必要；源码基线所用的 OMP 版本与提交；自动检查与真实 OMP CLI 运行各自验证过的版本；适用条件与边界。

已核实的结论按调整项分开记录。包级的 peer 范围是关于宿主 API 的元数据，不是对任何调整项的验证；阅读源码也不等于运行。没有真实会话运行的项目记为未验证。

## 考虑过的替代方案

- **为每项调整分别发布扩展包。** 在选择打包方式时考虑。收益是独立发布与独立故障；代价是配置、兼容性、迁移与检查分散在三处安装中，而三项调整共享同一宿主基线。单个包让这些入口集中。
- **使用带独立解析器的专用配置文件。** 在选择配置来源时考虑。所需设置可以由 OMP 插件设置表达，另建解析器、优先级规则与更新路径会带来额外维护，而调整本身并不需要这些能力。
- **替换原生压缩流程。** 在判断期限控制需要多大权限时考虑。它能直接控制请求选项，但把压缩协议、历史替换、重试与回退路径交给本组件，其中还包括生成会话所依赖摘要的路径。
- **推迟压缩调整，等待 OMP 暴露请求级接口。** 在评估隔离性时考虑。它避免进程级副作用并降低维护量，但保留固定期限；本决定改为把受约束的全局机制做成显式、默认关闭的实验，并给出上述替换条件。
- **只记录这三个限制，不提供扩展。** 在提出组件之前考虑。它不增加代码与兼容性负担，但每个场景仍需用户或模型反复介入，而这正是各项调整要减少的情况。

## 结果

- 一个组件让三项调整共享一次发布、一份锁文件和同一个检查入口。破坏其中一个模块的宿主变化也会影响整个组件能否按原样安装，单次依赖升级影响三者。
- 自动检查无法确立宿主行为。每项调整都需要自己的真实会话证据，而在超过原生期限的远端压缩成功完成并随后仍能正常发起模型请求之前，压缩实验的收益仍未证实。
- 调整依赖不带兼容承诺的宿主细节：内置工具描述与空窗结构、`stopReason: "error"` 与公开分类器、`AbortSignal.timeout` 的身份，以及压缩生命周期事件的顺序。各模块被写成在识别失败时保持不生效并说明原因，而不是猜测，因此宿主升级可能停用某项调整而不会破坏会话，重新核对之后才再次信任该调整。
- 续跑会重发会话内容并消耗服务额度，重新运行的轮次可能重复失败轮次中的副作用。次数上限、固定排除清单与宿主上限减小了暴露面，但不承诺恰好一次的行为。
- 等待期限到达后仍有工作继续运行，而模型可能已不再关注它们。结果会说明期限已到，模型下一步需要重新检查。
- 压缩实验在窗口打开期间会延长同一进程中无关工作的命中期限，而窗口的开启事件并不指明将被计时的请求。清理无法缩短已经创建的期限，且一个进程只有一个包装。
- 文档针对固定的宿主基线维护，因此宿主升级时需要重新阅读引用的源码并更新受影响的章节，而不是扩大声明的 peer 范围。
