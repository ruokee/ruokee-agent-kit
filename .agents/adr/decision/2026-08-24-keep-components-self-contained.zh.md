# ADR 决定：保持可分发组件自包含

Decision owner: Ruokee
Draft writer: OMP GPT-5.6 Sol

[English](./2026-08-24-keep-components-self-contained.md) | 中文

## 动机

Skill、Extension、Plugin 和 Package 作为独立组件安装和分发。一个组件指向另一个组件的仓库相对链接可能在源码树中有效，但只安装前者时就会失效。它还会形成一项未声明的要求，两个组件必须使用相互兼容的版本。

Python 专项代码质量内容的迁移直接暴露了这个问题。`python-engineering` 反向链接了 `code-quality` 拥有的文件，导致安装后的 Skill 无法自包含。指向仓库支持文件的链接也有相同问题。

语言变体需要遵守相同边界。变体作为一个组件替换或安装，不能假定源码仓库或其他语言树同时存在。

## 决定

将每个 Skill、Extension、Plugin 和 Package 视为自包含的可分发组件。对于当前 Skill，组件根目录是 `skills/<name>/` 以及各个 `variants/<language>/skills/<name>/` 目录。未来增加的组件类别在各自根目录下遵守同一规则。

组件内的仓库文件引用必须解析到该组件目录内。组件文件不得链接、依赖或指示 Agent 加载另一个 Skill、Extension、Plugin 或 Package，也不得依赖组件目录之外的仓库支持文件。

该规则覆盖 Markdown 链接、书面文件路径，以及运行时需要另一个仓库组件的示例。它不禁止讨论一般概念，也不禁止提及恰好与组件同名的外部库。只要组件不依赖另一个仓库组件即可使用，仍可引用公开外部资料和上游文档。

组件目录之外的仓库级文档、ADR、manifest、安装器和集成代码，可以在描述或组装组件时引用它们。限制适用于从可分发组件内部发出的引用。

在 [`AGENTS.md`](../../../AGENTS.md) 中记录该规则，并清除当前所有语言树中的现有越界引用。

## 考虑过的替代方案

**允许组件声明依赖。** 这需要依赖元数据、版本兼容规则、安装顺序和跨宿主验证。当前组件不需要这套机制。

**允许跨组件文档链接，但禁止运行时依赖。** 文档链接失效仍会让安装后的组件残缺，并形成版本耦合。这种区分没有解决已经观察到的问题。

**将共享指导放在仓库级参考目录。** 组件仍会依赖不保证随其分发的材料。共享思想应根据各组件需要的范围和语言直接表述，不能通过仓库链接导入。

## 结果

每个组件都能脱离其他仓库组件和源码仓库布局独立安装、确定版本并被阅读。

相关组件可能重复少量指导。只保留适合该组件的内容，不要镜像整份文档。内容在组件之间迁移时，应在同一变更中迁移必要说明并删除旧的越界引用。

仓库级文档仍负责比较组件、说明组合方式和记录组件关系。审查时，任何解析到组件目录之外的链接都应视为边界违规。
