# 在 QoL 中补记压缩请求用量

Decision owner: Ruokee
Decision writer: OMP DeepSeek V4.1 Flash

[English](./2026-10-13-compact-usage-compensation.md) | 中文

## 动机

把 OMP 自身压缩与 handoff 请求的 token 用量与成本记录到会话文件中，作为 [omp-qol](../../../projects/omp-qol/README.zh.md) 的一项调整，直到已发布的 OMP 版本自己记录为止。

会话压缩时，OMP 会发出自己的摘要请求：`soft` 方法的 summary、short-summary 与 turn-prefix 调用，以及 `handoff` 方法的请求。这些请求都由提供方计费，用量也会报告给宿主，但数值止于摘要调用：没有写入任何 `model_usage` 条目，读取这些条目的会话统计因此漏掉它。于是会话文件少算了该会话的成本，基于这些统计的报告、预算或配额视图也按该会话执行过的压缩次数偏差。

上游把该缺口记为 [issue #15031](https://github.com/can1357/oh-my-pi/issues/15031)，并在 [pull request #15034](https://github.com/can1357/oh-my-pi/pull/15034) 中修复。截至 2026-10-13 该 PR 仍处于未合并状态，最新发布的 `@oh-my-pi/pi-coding-agent`（`18.10.3`）不含该修复。

## 分析

宿主所需的数字本就在其遥测通道中流动，而默认安装下该通道是关闭的。每个本地压缩与 handoff 请求都经过同一个插桩补全包装层：它创建 chat span、把该请求的 oneshot 类型盖在 span 上，并发出携带用量快照与响应结束原因的 chat usage 事件。压缩与 handoff 的调用点在每次调用前从 agent 解析遥测配置，除非用户配置过遥测，否则解析不到，因此默认安装既不产生 span 也不产生事件。该通道因此是取得这些数字的唯一公开入口，而启用它会改变宿主行为：有配置存在时，宿主会为本来跳过的模型步骤创建 span 并运行钩子路径。

该通道的三个性质决定了补偿的形态。被取消或失败的尝试同样会发出事件，快照全为零、结束原因为错误，因此没有过滤的写入方会记录零用量噪声。仅有用量快照不足以写入条目，因为会话文件还要存实际运行的 api，而它只能由会话自身的模型注册表从事件给出的 provider 与 served model 解析。此外没有任何路径能到达请求本身，因此在包装层内部被重试掉的尝试无法恢复。

退出条件是运行时可观察的。[pull request #15034](https://github.com/can1357/oh-my-pi/pull/15034) 由宿主自己记录这些请求，并为此从 `@oh-my-pi/pi-agent-core` 导出 `compactionRequestUsage`，包根也会再导出它，因此调整可以直接读取该导出识别这种宿主，而不必依据版本号推断。

## 决定

### 公共配置

组件新增一项调整，作为 [omp-qol](./2026-10-10-maintain-omp-experience-extension.zh.md) 的第六项。其公开合同是一个原生 OMP 设置键 `compactionUsageEnabled`，boolean，默认 `true`，受组件总开关约束。它可独立开关，按既有设置规则被拒绝或报告，并与其他键在同一激活快照中读取，因此改动在下次启动 OMP 时生效。

其效果是：一个完成的压缩或 handoff 请求会出现在会话的用量条目中，以及宿主据此推导的统计里。

### 介入位置

本调整替换宿主 `Agent` 原型上的 `telemetry` 访问器，也就是压缩与 handoff 调用点每次调用前解析的那个值；本模块在进程内持有该访问器，并在释放补丁时还原，与压缩期限调整持有自己 seam 的做法一致。

用户已有的配置会被保留：其 tracer、成本估算器与 chat usage 钩子继续服务它们原本服务的每个请求，本调整不向导出添加任何内容。没有配置时，本调整提供惰性配置，其 tracer 创建宿主本来会创建的 span、记录本模块读取的三个属性，且不导出任何内容。

请求由宿主盖在该请求自己 span 上的 oneshot 类型识别，类型取自本模块包在 tracer 外的包装层。本调整不读取 span 上的其他属性，也不触及请求、模型、缓存键、历史或会话文件。

### 记录内容

范围内共四种 oneshot 类型：`soft` 的三个摘要类型与 `handoff`，对应 `compaction:summary`、`compaction:short-summary`、`compaction:turn-prefix` 与 `compaction:handoff`，即上游修复所解析的 purpose。该列表是封闭的：`compaction_native` 与 `branch_summary` 属同一族但修复同样不记录，宿主标注的其他类型都属于宿主已记账的调用方。

一个完成的请求通过会话管理器自身的接口写入一条用量条目，落在请求所属会话的分支上，内容为解析出的 purpose、实际运行的 api、provider 与 model、提供方的 token 数，以及宿主携带时提供方给出的分项成本。条目形状与宿主为自己辅助请求写入的一致，这是会话统计会计入它的原因。

未消耗任何 token 的尝试不写入，因此被取消或失败的尝试不会留下零用量噪声。会话在本进程中已不存在、或 api 无法解析的请求不写入而是计数，因为猜测的 api 与缺失的条目是可见的，而错误的条目看起来已被修好；本组件从不自行估算提供方成本。

### 退出

本调整是有明确终点的补偿。它在激活时读取原生记录导出，在自身记录这些请求的宿主上以原因保持停用，因此已发布的修复会让补偿停用，而不是把条目写两遍。组件文档带有上游复核小节，形式与[模型提示词规则](./2026-10-15-use-qol-model-prompts.zh.md)相同，并指明需要检查的界面。当已发布的 OMP 版本自己记录这些请求时，移除本调整的代码、设置、文档与测试，从组件规格中删除该能力，并用一条决定记录这次移除。

### 发布证据

实现会把该调整加入[调整项文档](../../../projects/omp-qol/docs/adjustments.zh.md)、README 的调整项与设置表、`/qol` 状态报告以及 `package.json` 的设置 manifest，并更新[组件规格](../../spec/omp-qol.zh.md)的目标、公共面、不变量与验收标准。组件 `Z` 版本随本次改动递增。

## 考虑过的替代方案

无

## 结果

- 挂接遥测配置会改变宿主行为。有配置存在时，宿主会为本来跳过的模型步骤创建 chat span 并运行钩子路径，为每个请求增加工作量，并向用户已配置的导出发送内容属性。惰性配置与 tracer 包装使导出保持为空、只读取 oneshot 类型，代价是此前直接短路的压缩与 handoff 请求现在多出包装层自身的工作。
- 用量可能归属到错误的请求或分支。若事件的 span 不是读取类型的那一个，写入的 token 与成本描述的是另一个请求；若条目没有落在请求所属分支，它会对本应修正的统计不可见。两种情况下会话总计都是错的，而 `/qol` 仍显示启用，因此类型只从事件自身 span 读取、未知 span 不写入，分支位置在写入时读取。
- 宿主开始自己记录这些请求后，仍启用的调整会再记一遍，抬高 token 数与成本。退出检查与 `/qol` 报告的状态是代码移除前的防护。
- 临时补偿可能比它的条件活得更久。跨宿主版本保留时，它可能挂接到已经移动的界面、静默失效，并在用户以为会话记账完整时报告停用状态。版本文档、`/qol` 中的有界原因与上游复核小节让这一重叠保持可见。
- 本调整的条目位于其所属压缩之前，并依赖宿主自身的活动窗口规则被计入，因此将来该规则变化可能让它们悄无声息地从总计中消失。这也是实机证据记录宿主自身统计增量、而不只记录写入条目的原因。
- 已验证范围很窄。提供方成本依赖组件声明的宿主下限之后才出现的字段；只记录这四种类型；宿主不再盖类型戳或把本模块没见过的 span 交给事件时，本调整只会不写入。组件文档逐项记录未验证场景，而不暗示存在连续的可用宿主范围。
