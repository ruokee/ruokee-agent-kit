# ADR 决定：由 smart-cache 提供 remote 对齐

Decision owner: Ruokee
Decision writer: OMP
Reverses: [维护 QoL 模型提示词与既有体验调整](../archived/2026-10-07-maintain-qol-model-prompts.zh.md)

[English](./2026-10-10-use-smart-cache-remote.md) | 中文

## 动机

将远端压缩缓存对齐从 QoL 迁入独立扩展 `@ruokee/omp-smart-cache`，覆盖主会话、原生子会话及同进程导航。

[原 QoL 决定](../archived/2026-10-07-maintain-qol-model-prompts.zh.md)把 remote 对齐绑定到唯一主会话 owner。子会话激活不能驱动该 owner 的修复，导航释放资格后也没有同进程恢复路径。普通请求在上下文处理器返回之后还会完成其他转换，而原生 V2 独立准备其保留历史。比较中间上下文或要求所有请求选项都相等，会拒绝有效的共同内容修复。

缓存能力需要独立归属，同时保留 QoL 的等待、恢复、期限、重放及模型规则行为。Remote 与 Handoff 修复的协议和证据不同。迁移 remote 不批准 Handoff 集成，也不替换已安装的 Handoff 原型。

## 分析

最终已发送结果与其源范围证明的是不同事实。观察最终载荷可以证明实际发送内容，却不能证明跨范围结果在原生裁剪之后仍有可复用的部分。普通请求若只发送了不可分结果 `Y = F(U, T, s)`，而 V2 把 `T` 改为 `T'`，就可能不存在独立发送过的 `U` 结果。复用整个 `Y` 仍保留对已移除内容的依赖；计算 `F(U, T', s)` 会生成新结果，还可能重复处理器副作用。更多来源信息不会创造不存在的独立已发送结果。

因此，复用边界支持完整保留范围与可独立复用的局部结果。不可分依赖变化保持原生请求，并计为未对齐。不把处理器限制为一对一转换，不改变原生裁剪，不要求新增处理器协议，也不把未知证明等同于已证明不可能。客户端对齐、原生可用性与 Provider 缓存收益分别判断。

## 决定

### 组件与公共配置

在 `projects/omp-smart-cache` 维护自包含包 `@ruokee/omp-smart-cache`，使用自己的原生 `omp.extensions` 入口、设置、检查及中英文文档。遵循[第一方边界](./2026-08-20-establish-first-party-capability-kit.zh.md)与[自包含组件合同](./2026-08-24-keep-components-self-contained.zh.md)。不从 QoL 或本地原型导入运行时代码、设置读取器或文档。

Remote 公共合同使用 OMP 原生设置：`compactionCacheEnabled` 默认 `false`，`compactionCacheProvider` 默认 `""`，`compactionCacheMode` 默认 `"hooks"`。模式只接受 `standard` 和 `hooks`，不决定是否启用修复。用户显式选择一个准确的已配置 Provider 名称。不新增 Provider 列表、其他模式、Handoff 占位设置或第二种配置来源。

该 remote 合同的模式集合有意闭合，因为两种模式保留不同的准备及复用承诺；扩展集合须形成新的合同决定。多 Provider 选择及 Handoff 接口不属于本次范围，不是对单独定义能力的永久禁止。原生设置仍是唯一来源，以保留宿主管理的覆盖优先级与重启语义。

OMP 按[原生设置合同](./2026-09-10-use-codex-web-plugin-settings.zh.md#原生设置与作用域)管理用户值、项目覆盖及解析。将有效设置读取并校验为一份激活快照，重复激活事件不重复登记。改动须重启 OMP；创建或导航会话不刷新既有快照。子会话使用自己的实际模型、API、工具、提示词与身份，不使用父会话模型，也不重新热读配置。非法设置或接口不可用只影响对应能力或登记，不停用其他活跃会话。诊断写键与固定规则，不回显取值。

`/smart-cache` 不启动模型 turn，只报告 remote 状态。状态区分 `disabled`、`unavailable`、`awaiting-reference`、`already-aligned`、`rewritten` 与 `rejected`。分别保留在线确认、操作绑定、候选校验及发送的原因，避免后续缺少参照覆盖原始证明失败。逻辑操作与物理发送及重试分别计数；改写、原生结果采用和 Provider 缓存命中是不同结果。诊断只用有界计数、会话及操作局部标识和固定原因，不包含请求正文、opaque、凭据、原始端点、私人路径或动态私密键。不携带正文采样日志、试验环境变量、采样命令或特殊限流中止策略。

### 目标请求与模式

覆盖所选 Provider 在主会话及原生 `task`、Eval 子会话中的非 Codex `openai-responses` 原生 V2 请求。保留首次、再次及进程恢复后的压缩，以及宿主向相应会话类型提供的手动、自动、轮内和投机入口。宿主缺少某个入口不要求扩展新增。非目标 Provider、模型、API、Codex、V1 与无法识别的形状保持原生行为。

没有上下文处理器时，两种模式均完成通用对齐，且都要求最终传输确认与完整候选校验。`standard` 保留已识别的原生修复，不因新增观察入口获得通用处理器投影。`hooks` 额外复用已证明的完成上下文处理，包括插入、重排、恢复和跨范围合并。两种模式都不重新运行处理器、不识别配套扩展的正文格式、不读取其私态，也不维护替代 Provider 序列化器。

只有实际普通主循环 dispatch 提供参照。源历史、完成准备、既有载荷回调的最终结果和实际传输必须对应同一次 dispatch，并原样到达发送边界。标题、advisor、cache warming、Handoff 及其他旁路请求不能成为普通参照。新的在线候选确认前暂停未来操作绑定；已经绑定的操作保留不可变旧参照，包括明确的缺少参照状态。观察失败局部处理，不吞掉原生回调、resolver 或传输异常。普通及非目标请求逐字节不变。

### 复用单元与原子安全

复用单元是同一次普通请求已经发送、可独立提取的结果，须证明源对应、组装边界，以及全部源依赖仍完整保留在原生 V2 范围且未变化。操作捕获的参照和相关处理条件须有效。输出相同、数组长度、索引、仅有来源信息或消息看似独立都不足以构成证明。

完整保留源范围可以作为包含全部已发送结果的一个单元，合法处理器可以改变消息数量与顺序。优先使用完整范围证明，再尝试局部匹配；合法重复源消息或局部匹配歧义不能使已证明的完整范围失效。只保留部分源时，复用原生逐项语义或已有独立结果证据所证明的单元，且证明须贯穿后续每项转换。保留原生改写项，不用旧原文替换。

不可分单元的依赖被裁剪或改写、且没有独立已发送部分结果时，完整目标请求保持原生形式，报告 `projection-dependency-changed`。源、依赖或结果边界未知时，完整请求保持原生形式，报告 `projection-unconfirmed`，这是证明缺口，不表示转换天然不可投影。这些拒绝只通过相应安全边界，不计为对齐。已知完整范围和独立局部正例仍为必需项，裁剪或黑盒处理都不允许一律拒绝。

完整候选通过校验后才一次原子替换。保留 system 内容、日期及 cwd 提醒、工具 schema 与描述、已识别的 reasoning/replay 及默认语义、新增普通/工具/图片历史、原生工具输出裁剪、调用与结果配对、压缩专用尾部、trigger 和 opaque 替换历史及其顺序。不展开或重建 opaque，不补回已移除依赖，不重算处理器输出，不改为按转换结果而非原生源历史裁剪。

按字段原生含义分类，不要求普通请求与 V2 的所有选项相等。保留 V2 自己的 `max_output_tokens` 原值或缺省，不补入在线限制。其已知合法差异不能阻止无关共同内容对齐。只有证明原生 `tool_choice: auto` 为隐式默认、且在线没有显式选择时，才可规范化它。保留显式工具选择、模型策略、鉴权、路由、缓存键、Provider 响应及已存历史；差异使参照失效时拒绝。每项未分类差异都保留完整原请求。候选相同记为 `already-aligned`，不计改写，也不因此重新序列化。

### 归属、隔离与恢复

进程只安装一组传输及原生信号组合包装，每个实际模型注册表只薄包装一次 resolver，每个实际会话独立登记。兼容的重复登记幂等，第二个会话不是归属冲突。区分持久会话身份与 Provider 会话身份，明确绑定会话、模型、dispatch、原生根信号、epoch 及协调器代次。模型相同、端点、缓存键、时序或相似正文都不能证明归属。原生端点与 V2 形状仍须独立检查。

保存信号父关系，并在使用信号时解析归属，覆盖先派生后绑定 resolver，以及多个普通 dispatch 共享根信号。归属明确的不同操作可以并存。每项原生操作在较新在线工作、处理器状态推进、认证刷新和传输重试之间保留初次捕获的不可变参照。重试不能取得较新参照。身份未知或冲突、取消、失效 epoch、旧协调器代次或含糊复用都使该请求保持原生形式，不停用其他有效会话。

切换、分支或树导航之前撤销该会话旧 epoch 与参照。导航中不确认新参照。成功、取消或失败之后，核对原生转换状态已结算且当前身份有效，再通过新的普通发送恢复资格，不要求重启进程。不只依赖成功事件或计时器，不恢复旧操作。子会话完成、关闭、取消或替换只释放自己的登记；revive 的子会话须取得新的有效参照。

只还原仍由自己持有的函数及其原始属性形状。会话包装丢失只影响该登记；共享传输或信号归属丢失影响依赖它们的登记。混装版本、不可读取的注册表与外部覆盖属于冲突，不构成抢占或重装他方包装的许可。最后一个登记结束后释放共享资源；后续新登记可以创建新的协调器代次，旧操作仍失效。只保留各会话最新参照及原生操作可达快照，共享不可变数据，不在每次重试复制大型数据。不维护不断增长的已完成操作历史；没有活跃目标登记需要时不解析正文。

### 原生职责与兼容性

OMP 保留准备、触发、投机启动与等待、取消、认证及传输重试、模型与方法回退、结果校验及采用、历史提交和续接。原样转发原生参数、receiver、凭据结果、Promise、异常、信号与取消原因。不读取凭据内容、不增加认证或参照请求、不包装公开的手动压缩方法，也不把一次凭据解析或传输结束视为操作完成。非 V2 回退保持原生行为，不报告为 V2 成功。

不注册 `session_before_compact`，不把它作为回退，不隐藏其他处理器、不绕过否决，也不修改其他扩展设置。QoL 单独启用的期限模块及其他扩展仍可按自身合同否决投机。Remote 对齐保留原生投机结果直接采用，不发替代请求，但不承诺投机已全局启用。

遵循[共同 OMP 维护下限](./2026-10-04-raise-omp-host-floor.zh.md)，当前为 `18.5.0`。组件 README 双语页拥有下限声明，不设上限或版本白名单。宿主开发依赖锁定共同下限，不收窄宿主 peer，也不增加安装或激活版本门槛。按能力及结构选择受维护行为。受维护原生接口在所有必需路径提供等价结果、配置语义、隔离与失败行为时，通过行为验证后替换本地适配，不仅凭上游 PR 合并就替换。

### 决定反转与保留合同

本决定及[完整 QoL 后继决定](./2026-10-10-maintain-qol-without-remote.zh.md)反转[维护 QoL 模型提示词与既有体验调整](../archived/2026-10-07-maintain-qol-model-prompts.zh.md)。冲突选择如下：

| 该决定的现行条款 | 取代选择与冲突 |
| --- | --- |
| 组件与范围：六模块同属 QoL，包括 remote 对齐 | Remote 属于 smart-cache；QoL 保留等待、恢复、期限、重放及模型规则。切换后两者不能同时拥有同一 remote 能力。 |
| 组件配置、模型规则的既有能力保留及独立等待的设置保留：原有键全部保留，包括缓存键 | 切换时从 QoL 移除三个 remote 键，只在 smart-cache 声明。保留全部无关键、默认值、范围及校验规则。旧缓存键不能作为兼容路径继续接受。 |
| Remote 范围：只服务所属主会话 | 主会话、原生 task 和 Eval 各用自己的参照，撤销仅主会话排除条款。 |
| Remote 等价性及通用上下文变更：合法操作选项存在差异时仍以整条请求相等为门槛 | 保留完整原子安全，按原生语义校验已知字段，保留 V2 输出选项，复用已证明的完整或独立局部已发送单元。未知差异仍拒绝整个候选。 |
| Remote 的 owner 注册表绑定，以及配置匹配的后续激活不能驱动修复 | 共享进程分发及逐注册表包装服务独立会话登记。匹配子会话具备资格，不是只能观察的非 owner。 |
| Remote 配置冲突或不可用激活停止整个模块改写 | 非法或关闭的会话设置只停止该登记或能力；真实共享包装冲突影响依赖它的登记。 |
| Remote 关闭及导航终态，同进程不接管新 owner | 局部释放登记，导航结算后凭新发送恢复，最后释放后允许新协调器代次。旧 epoch 与操作始终不恢复资格。 |
| Remote 状态及有效模式属于 `/qol` | `/smart-cache` 拥有 remote 状态、模式、分阶段原因及计数；`/qol` 只保留其余调整。 |

全部不冲突规则继续有效。[完整 QoL 后继决定](./2026-10-10-maintain-qol-without-remote.zh.md)保留独立 wait 委派及期限、恢复的安全排除及受限续跑、实验性压缩期限模块的单 owner 窗口及 `owner-stopped` 终态、replay 的独立进程级归属及释放规则、[模型提示词规则](./2026-10-07-use-qol-model-prompts.zh.md)、原生设置权威、模块隔离、隐私、文档证据及宿主维护义务。尤其不能用本决定的 remote 恢复规则放松期限模块的 owner 终态，也不能因 replay 与缓存有关就迁走它。

本决定与上述选择一起保留在线确认、不可变根信号快照、原生生命周期、显式策略保留、有界资源、按归属还原、无否决、双模式、隐私及原生接口替换合同。其他现行决定不反转；smart-cache 通过非冲突追加纳入共同下限。

### 直接切换与公共文档

正式 remote 直接交付到 smart-cache，不发布 QoL 多会话过渡版。移除 QoL 的 remote 实现、设置消费、类型、旧行为测试、别名、再导出及公共状态入口，不保留 shim 或跨组件运行时依赖。保留有效消费者行为断言与全部无关 QoL 行为。

公共迁移说明放在仓库 README 双语页，须覆盖用户与项目层，不能只处理合并后的有效对象：保留旧有效 Provider 与模式，且只有旧有效 QoL 总开关 `enabled` 和 `compactionCacheEnabled` 均合法且启用时，才启用新修复。默认值或非法设置不能开启此前未生效的修复。用户显式设置新包值，从每个适用 QoL 层移除全部三个旧 remote 键并保留其他设置。旧键会成为 QoL 未知键，可能使整个组件拒绝配置，因此必须在变更源码加载前协调删除、新安装及重启。运行时代码不回退读取 QoL 设置，也不编辑用户配置或安装。

通过重启相关进程切换，不热转移在途 owner 或参照。误装共存旧 QoL remote 时保守报告冲突，不抢占其包装。Handoff 协议、支持、状态、收益证据及安装分别处理；本决定不替换其原型，不把 remote V2 规则用于 Handoff，也不新增 Handoff 占位接口。

组件文档以双语维护详细设置与命令、适用性、副作用、原生关闭表现、固定源码基线、实际运行版本及原生替换条件。源码检查、真实 CLI 覆盖、客户端对齐、原生采用和 Provider 测量分别标注。改变目标的实现变更同时更新 QoL 项目 Spec、新增 smart-cache Spec 及清单入口，并同步组件文档及检查注册。

## 考虑过的替代方案

- **先扩展 QoL，再迁移。** 在选择交付位置时考虑。它缩小首次安装变更，却增加一轮多会话合同、发布、配置及迁移验证。直接 smart-cache 交付避免中间维护路径。
- **保留不限组合的对齐承诺，停在限制结论。** 在选择复用合同时考虑。不可分结果的依赖被移除后，在不改变其他要求的条件下，更多观察无法产生缺失的已发送部分结果。它保留原承诺，但阻止完整交付。
- **新增冻结纯投影合作协议。** 在评估被裁剪的跨范围转换时考虑。它允许一次有状态准备后计算新结果，但要求处理器合作及无副作用证明，改变已发送结果复用合同，也不保证新结果复用旧 Provider 缓存。本决定不新增该协议。
- **重新运行普通准备或新增参照请求。** 在最终上下文设计中考虑。它重复有状态处理器副作用，可能读取比操作快照更新的状态，还可能增加请求。复用已发送结果保留已选边界。
- **等待等价原生接口或改用 Handoff。** 在评估包装维护时考虑。等待保留当前 remote 差异；Handoff 改变所选压缩协议且证据独立。等价原生接口仍是替换本地适配的条件。

## 验收标准

1. 新包自包含，通过原生 OMP 插件发现只加载一次，声明实际版本与受维护宿主基线。默认关闭、Provider 为空、默认 `hooks`；两个显式模式、原生用户/项目覆盖、非法值、激活快照及重启行为可观察。不暗读 QoL 设置，不热刷新配置。
2. 普通及非目标请求不变。两种模式对齐各自通用原生场景；`hooks` 还对齐完整范围插入、重排、恢复、合并、图片及已使用的后置转换，不重复处理器。完整范围包含合法重复消息时，即使局部匹配歧义也须成功。
3. 原生逐项及独立证明的局部结果在部分历史保留与工具输出改写中完成对齐。新增普通、工具及图片尾部、工具配对、opaque 替换历史及 trigger 保留原生内容和顺序。不可分依赖变化与未知证明缺口分别完整保留请求并给出原因；拒绝成功不是正向对齐结果。
4. System、提醒、工具 schema、replay/默认语义、无工具请求及合法 V2 输出限制差异保持预期行为。显式工具选择、未知字段、模型或工具失配及未证明转换不能造成部分或不安全替换。
5. 主会话、原生 task 与 Eval 各用自己的参照完成适用目标压缩。并行兄弟、父子交错、同模型不同历史、不同模型、非目标子会话、取消、完成及 revive 不混用上下文，不停用有效邻近会话。
6. 首次、再次及独立进程恢复压缩保留原生提交和正常续接。适用的手动、自动、轮内及投机路径保留原生调度、准备、等待、结果采用与回退。新在线工作及认证或传输重试保留旧操作快照；有效投机结果直接采用，不发替代请求。取消撤销旧资格，后续独立操作可以恢复。
7. 切换、分支及树导航在成功、取消和失败后，于转换结算后凭新普通发送恢复。旧在途操作保持失效，其他登记保持有效，正常恢复不要求重启进程或计时器。
8. 缺少参照、身份歧义、混装版本、外部覆盖、旧代次及接口不可用使受影响请求保持原生形式并给出可定位原因。最后登记清理只还原仍持有的函数及属性形状；后续登记不复活旧操作。活跃数据保留只随当前参照和可达操作，不随已完成历史增长。
9. 实际 `/smart-cache` 与 `/qol` TUI 命令不启动模型 turn。Remote 状态给出分阶段原因与有界计数，不暴露敏感内容。不混淆已对齐、已改写、原生采用与 Provider 命中结果。
10. 原生配置迁移移除旧用户及项目 QoL remote 键，保留有效启用选择和全部无关设置，同一请求只有一个 owner。与旧 QoL 共存时保守拒绝。QoL 其余模块及其他已安装扩展行为不变；remote 交付不替换 Handoff 独立原型或接管其请求边界。
11. 自动检查与真实受维护宿主 CLI/TUI 证据覆盖变化的公共合同、实际出站请求、原生结果与共同 `18.5.0` 下限。实现切换时，必需完整及受影响检查注册、选择映射、选择器回归、双语文档、项目 Spec 及完整后继决定一致。源码检查与合成 usage 不是真实 Provider 证据。
12. 另获授权的可比真实 Provider 运行反复观察到未缓存输入下降，同时保留客户端正确性及原生可用性。分别报告目标总体、已对齐与未对齐组，包含全部依赖变化拒绝、证明缺口及其他拒绝，并按会话类型与适用压缩生命周期分类。逻辑操作与物理请求分别标识。各组报告请求数、有效 usage 样本数、总/缓存/未缓存输入、零命中占比及 token 加权命中率。失败、取消、429、回退及缺失 usage 单列，不当作零命中，也不从分母消失。不承诺固定命中率、缓存驻留或节省金额；remote 收益不证明 Handoff 收益。

## 结果

- 源对应错误、单元边界丢失或并发归属错误可能插入另一会话内容、补回被移除历史或破坏工具配对。替换前须完成整段与局部证明、明确身份、不可变快照及原子拒绝；只有保守拒绝仍会留下必需正例缺口。
- 宿主变化或竞争进程包装可能使调整不可用；错误还原会覆盖其他扩展。能力检查、按归属还原与受维护宿主行为证据减小风险，但不承诺通用兼容。
- 多个活跃会话及长寿命原生操作可能保留大型载荷。共享不可变参照、释放不可达操作避免重试复制与已完成历史增长，但不限制宿主活跃操作的数量或寿命。
- 用户若在移除旧键前更新链接加载的 QoL 源码，可能因未知键拒绝失去全部 QoL 模块。用户/项目协同迁移与重启指引须保留无关设置，避免静默启用原本未生效的修复。
- 正确对齐的请求仍可能不命中 Provider 缓存，不可分依赖变化仍未对齐。因此新增维护可能不足以带来总体收益；发布判据是完整分母下的真实可比重复测量，而非合成成功计数。
