## 动机

本决定定义 tk 文档的维护方式，覆盖 [tk 产品架构](../decision/2026-08-21-define-tk-product-architecture.zh.md)所涉及的材料：Task 文件、Rust 运行时、CLI、MCP、原生工具、四个 Harness、组件生命周期、Skill 和双语公开文档。在每个页面重复同一合同会产生互相冲突的来源。只保留实现代码又会使行为和理由难以审查。

仓库以英文作为默认公开语言，同时需要完整中文材料供维护者直接审阅。两种语言必须描述同一个产品，但不能强迫中文逐句机械翻译。

## 决定

### 公开文档集合

公开 tk 文档位于 `projects/tk/docs/`，包含：

- 英文和中文用户指南；
- 英文和中文设计索引；
- 系统架构、数据模型、运行时、工具 API、CLI 参考、Harness 集成、安装、Skill 行为、验证、文档和术语表的双语对应页面；
- 仓库根 README 和中文 README 中的 tk 入口；
- `decision/` 下当前英文和中文 tk ADR；

评审记录、修订号、Task 路径、分支状态、实现日志和本地材料不进入公开页面。

### 主题归属

每项行为只有一个主要归属页面。system 负责产品边界和不变量。data-model 负责 Task 格式和持久化。runtime 负责进程和失败行为。tool API 负责逻辑请求与结果。CLI reference 负责命令拼写和退出行为。Harness integration 负责组件形式和适配器。installation 负责组件生命周期。Skill 负责 Agent 行为。validation 负责可观察验收。documentation 负责维护规则。术语表只负责项目特殊术语和固定译法。

参数表、算法或规范字段定义只出现在归属页面。其他页面链接到该页面，只陈述读者所需的上下文。

ADR 保存长期决定、替代方案和结果。它们链接当前公开合同，不复制完整命令、字段或测试清单。

### 最终状态写法

公开文档只陈述当前正式合同，就像产品从一开始便按该形式实现。文档不叙述设计修订、审查争论、开发阶段废弃命令、未发布格式兼容或 Agent 工作历史。

正式发布后的真实行为变化可以在用户需要时提供迁移说明。只存在于开发阶段的尝试不会形成兼容历史，也不会列为已移除功能。

### 英文与中文

每个 guide 和 design 专题都在一级标题后链接另一语言版本。仓库文件链接使用相对于当前文档的路径。当前目录或子目录中的路径以 `./` 开头，目录外链接使用所需数量的 `../`。

英文和中文页面语义对应。中文使用自然表达，不做逐句机械映射。命令、路径、字段、代码、日志、产品名和标识符保留规定的拼写与大小写。

术语表只包含在 tk 中具有特殊含义、需要固定大小写或必须保持稳定译法的术语。普通技术词留在归属文档中。固定中文形式包括 `受管`、`临时记事区`、`人类可读`、`直接切换`、`支持的子命令`、`活动操作标记`、`表示切换`、`续跑令牌` 和 `续跑状态`。

### Skill 与 ADR

四个权威 Skill 目录分别是 `projects/tk/skills/tk/`、`projects/tk/skills/tk-zh/`、`projects/tk/skills/tk-cli/` 和 `projects/tk/skills/tk-cli-zh/`。每个目录都自包含。同一模式的英文和中文 Skill 具有对应的语义覆盖。

ADR 提案和决定使用独立的仓库格式与目录。英文和中文文件对保持语义一致，维护者负责批准或拒绝提案，以及归档决定。

### 维护

公开行为发生变化时，同一变更必须更新归属设计页面、受影响的指南和 CLI 示例、两种语言、受影响的 Skill 内容、负责该决定的全部当前 ADR，以及对应验证合同。

仓库现有 Markdown、链接、格式和拼写检查与人工双语审查共同使用。在重复维护或实际偏差证明某项机械不变量值得自动化前，tk 不增加自定义文档结构或翻译检查器。

权威维护细节见[文档设计](../../../projects/tk/docs/design/documentation.zh.md)和[术语表](../../../projects/tk/docs/design/GLOSSARY.zh.md)。

## 考虑过的替代方案

**在每个相关页面重复完整合同。** 重复内容会让日常变更需要同步许多位置，也会使读者无法判断哪一份是权威来源。

**在公开设计页面保留实现历史。** 开发过程会遮挡当前合同，并把未发布尝试变成意外兼容承诺。

**把所有技术词都加入术语表。** 大型通用术语表会重复普通技术文档，并增加没有必要的翻译维护。

**构建 tk 专用双语结构检查器。** 结构相似无法证明语义对应或中文自然。现有检查加直接审阅已经足够，直到重复的机械故障证明某项规则值得自动化。

## 结果

读者可以从指南、设计专题、Skill 或 ADR 进入，并通过相对链接找到归属合同。每项规范细节只有一个主要维护位置。

每次产品变更都需要同步维护双语文档。格式检查无法证明语义一致或写作质量，因此仍需要人工审阅。

最终状态写法使公开文档保持紧凑，但评审历史和实现证据必须保存在 Task 材料或其他非公开记录中。ADR 保留理由，但不会变成发布说明或进度日志。

## 变更

### 2026-09-02：采用提案和决定模型

tk 文档现在引用 `decision/` 下的当前 ADR，不再用 `implemented` 状态表示当前记录。提案和决定分别使用不含 `Status` 字段的独立格式，生命周期权限仍归维护者。

### 2026-09-02：记录可选择的 Skill 与组件

文档覆盖 tools 与 CLI 模式、通过 `tk install` 选择英文或中文、四个 Skill 身份、多份组件载荷和分离的路由合同。上方四个 Skill 路径取代此前的英文 Skill，以及需要手动安装的中文 Skill。

### 2026-09-03：记录自定义 CLI Skill 根目录

文档现在覆盖多份 Harness 载荷、两份与 Harness 无关的 CLI Skill 载荷、互斥的安装目标，以及有限范围的自定义根目录生命周期。

### 2026-09-07：定义组件 README 导航

公开文档集合包括组件[英文 README](../../../projects/tk/README.md) 和[中文 README](../../../projects/tk/README.zh.md)。它们介绍 tk 并链接现有指南和设计页面，不重复详细命令或规范性合同。仓库 README 文件对链接到这些组件入口页。公开 Markdown 文档遵循[公开文档决定](../decision/2026-09-07-colocate-bilingual-docs.zh.md)，采用同目录 `name.md` 和 `name.zh.md` 配对；主题归属保持不变。
