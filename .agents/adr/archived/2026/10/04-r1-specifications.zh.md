## 动机

在 `.agents/spec/` 下维护中英双语规格（spec），描述每个组件和仓库领域当前的目标状态，ADR 继续记录决策及其理由。

仓库里原本没有一类文档专门从整体上说明每个组件应该做成什么样。这些信息分散在现行决定、决定中按日期追加的 `变更` 条目和组件文档里。例如，一个此后被移除的组件的目标由[只用模板决定](../../../archived/2026/09/07-r4-omp-system-prompt.zh.md)、[模型级提示词规则决定](../../../archived/2026/09/14-r1-model-prompt-rules.zh.md)和组件的 README 文件对共同构成。读者必须把这些来源合在一起，才能知道当前目标。Skill 体系和仓库约定的规则同样分散在现行决定、`AGENTS.md` 和[仓库 README](../../../../../README.zh.md) 中。

ADR 本来就不承担这个职责。[历史 ADR 契约](../08/22-r6-adr-mechanism.zh.md#编写记录)把 ADR 定义为持久决定的理由和契约，后继决定"不复制组件的实现规格"。组件文档面向安装和使用组件的人，仓库说明和 README 面向在仓库中工作的贡献者。它们都没有为维护者和 Agent 提供一份关于组件、Skill 体系或仓库约定的目标、边界和验收的当前说明。

## 分析

以下决定构成规格层的依据，均不与它冲突，因此本决定没有反转其他决定。历史引用标明本版本保留的契约。

- [同目录维护双语公开文档](../08/20-r2-bilingual-docs.zh.md)要求普通公开页面使用同目录、互相链接的 `name.md` 和 `name.zh.md` 文件对，入口页面使用 `README.md` 和 `README.zh.md`。仅面向维护者的材料只在目标读者需要时翻译。spec 面向维护者和 Agent，让 spec 保持双语在该决定允许的范围内。该决定中详细命令、参数和规范行为留在其所属页面的规则同样适用于 spec。
- [明确 ADR 内容边界](../08/22-r6-adr-mechanism.zh.md)规定 ADR 必须包含的内容。它写明迁移一条约束性条款并不取消它，指向持续变化的当前文档不能替代历史契约。spec 直接修改、不保留历史，所以不能替代决定中记录的契约。ADR 的内容规则和生命周期保持不变。
- [保持可分发组件自包含](../08/24-r2-component-self-containment.zh.md)禁止组件内部引用组件以外的文件，并允许组件目录以外的仓库级文档引用组件。`.agents/spec/` 下的 spec 属于这类文档。该决定的 `变更` 条目把每个组件的维护声明留在组件内部。
- [以共享的 Skill 参考文件源码统一 tk 使用模式](../08/29-r3-tk-documentation.zh.md)为每项 tk 行为指定 `projects/tk/docs/` 下的一个主要所属页面，包括系统边界、不变量和验证。tk 的 spec 如果复述这些内容，就会出现第二个所属页面，所以 spec 改为链接到所属页面。
- [建立第一方 Agent 能力工具集](../../../decision/2026/08/20-first-party-capabilities.zh.md)只在有真实组件时才增加新的顶层结构。`.agents/` 已经存在，规格层不增加顶层区域。

## 决定

### 位置

spec 放在 `.agents/spec/`，与 `.agents/adr/` 并列。该目录根部有一对 README，说明 spec 的写法，以及 spec、ADR 和组件文档如何分工。

`projects/` 下的每个组件都有 spec，`projects/tk` 作为整体也有。Skill 体系（包括 `skills/` 和 `variants/zh/skills/` 下的中文变体）有 spec，仓库级约定和宿主兼容策略也有。spec 文件清单由 spec README 维护。spec 依据现行决定和组件文档编写。归档决定不是当前依据，不搬入 spec。

### spec 格式

规格层 README 拥有编写契约。每份 spec 是同目录 `name.md` 与 `name.zh.md` 文件对，标题下紧接双向语言链接，两者描述同一目标并一起变化。适用章节依次为 `Goals`、`Out of scope`、`Public surface`、`Invariants`、`Host lower bound`、`Acceptance criteria`、`Related ADRs`，中文为 `目标`、`非目标`、`公共面`、`不变量`、`宿主下限`、`验收标准`、`相关 ADR`。省略不适用章节，例如仓库约定没有宿主下限。

spec 说明当前目标，就地修改，不保留修订历史、审查记录、任务记录或会话信息。依据包含 `Changes` 的当前决定和组件文档，不把归档决定引用或复制为当前权威。链接细节所属页，不复述命令、参数、设置表、文件格式和维护声明，只补必要上下文。相关 ADR 以链接列出，遵循文档相对链接规则。

### 分工

规格层 README 定义分工：spec 说明对象应该是什么；ADR 记录持久选择、理由、替代方案和后果；规则约束动作；组件文档说明安装与使用；仓库文档和 README 指导贡献者；`AGENTS.md` 提供导航和非平凡规则。spec 不能与现行决定冲突。冲突目标先走 ADR 流程再改 spec，不改变持久选择的修改不需要 ADR，是否需要由 ADR 规则判断。决定可以链接 spec，但不能用链接代替自身契约。组件目标变化在同一变更中同步 spec、组件和组件文档。

### 引用方向

规格层 README 定义单向引用。spec 可链接组件文件、组件文档、ADR 和规则；可分发组件内部文件不能链接、写出 `.agents/spec/` 路径或依赖它，保持安装后独立于仓库。spec 是说明性文档，组件运行、构建和分发不依赖它。既有 Markdown 检查处理规格层，不新增检查或其他读取方。

### 仓库入口

仓库中指引读者阅读 ADR 规则的说明和入口文档，同时写出 `.agents/spec/` 及其用途。

## 考虑过的替代方案

**把每份 spec 放进对应组件目录。** spec 会紧挨它描述的代码，但会随组件分发，把用户不需要的维护者材料带给用户。Skill 体系和仓库约定也没有单一的组件目录可以放它们的 spec。

## 结果

维护者和 Agent 可以找到每个组件、Skill 体系、仓库约定和宿主兼容策略的一份当前说明，包含目标、边界、不变量和验收，并链接到拥有细节的决定和文档。

spec、现行决定和组件文档可能描述同一目标。之后的变更只更新其中一处时，其余几处就会过时，按过时文本工作的维护者或 Agent 会朝错误的目标实现，或报告不存在的冲突。链接到所属页面能缩小重叠，但不能消除，也没有机械检查能证明它们一致。因此改变目标的变更在同一次变更中更新 spec。

如果某份 spec 漏掉了决定后来的变更，或带入了归档决定中的规则，它描述的目标就没有现行决定支持，按它工作可能删掉现行决定仍然要求的行为。spec 与现行决定不一致时以现行决定为准，并修正 spec。

增加或删除组件，或者增加需要单独 spec 的仓库领域时，同时更新 spec README 中的 spec 清单。
