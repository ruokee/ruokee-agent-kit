## 动机

把 Handoff 缓存对齐作为 `@ruokee/omp-smart-cache` 的第二项能力维护，与 [remote 对齐](../../../decision/2026/10/10-remote-alignment.zh.md)并列，各自持有开关与状态。

Handoff 依据实际对话生成压缩摘要或交接文档，并把这项工作作为侧请求发送，该请求重复会话的 system 提示词与工具定义。普通主循环 dispatch 已经发送过这些内容，而 Provider 按请求前缀缓存，因此一个重建成不同 system、丢掉在线 reasoning 设置或替换在线 tool choice 的侧请求，会为对话已经付过费的内容支付全额输入价格。Remote 对齐在各自的 Responses V2 规则下处理另一种请求形状，所以本能力需要自己的合同，而不是分用那些规则。[扩展决定](../../../decision/2026/10/12-smart-cache.zh.md)记录本包、能力模型与共同维护下限。

本机上的一个试验扩展对齐过这类侧请求。它留在仓库之外，是单会话实验，没有设置、没有逐会话隔离，对它从未执行的路径也没有已验收证据；它也不能作为 remote 之外的第二层包装交付：宿主在每个 seam 只暴露一个方法，remote 能力只还原仍由自己持有的函数，外来包装会使 remote 对齐以报告冲突的方式停止。

## 分析

本能力对齐的基准是已发送内容。观察最终侧请求或中间上下文，既不能证明在线请求包含什么，也不能证明它到达了传输，因此只有已确认的普通主循环 dispatch 能作为参照。宿主在该 dispatch 之后，依据会话自身历史与基础 system 提示词构造侧请求，并且不提供任何接口来标记某个请求属于 handoff、指明应作为其参照的 dispatch，或交出已准备好的侧请求。因此本能力从会话的请求准备与发送 seam 重建该操作，并使用这些 seam 携带的信号区分不同操作。

宿主通过自己的侧请求路径发送这项工作，而不是经由会话的流式入口，因此在那里观察到的参照属于普通 dispatch。准备阶段的两个 seam 收到同一个操作信号，正是这一点让一次绑定能跨这些 seam 覆盖同一操作。宿主日后改动该路径会使参照无法匹配，下面列出边界检查来应对这种风险。

试验的证据范围有限。它在真实请求上覆盖了这些 seam 与三项投影，对状态性上下文投影与用户主动切换 thinking 选择拒绝而不是覆盖，并测量了一对请求。它没有覆盖自动与投机压缩、取消与重试、模型与工具切换、多模态输入和子代理；服务端共享缓存也使各还原字段的贡献无法分离。

## 决定

### 公共配置

Handoff 对齐是 [smart-cache 扩展](../../../decision/2026/10/12-smart-cache.zh.md)的一项能力，无需另外的安装、包、设置读取器或扩展入口，并拥有自己的决定、开关、状态、计数与验收。

其公共合同是一个 OMP 原生设置 `handoffCacheEnabled`，boolean，默认 `false`。它只启用本能力；remote 的 `compactionCacheEnabled`、`compactionCacheProvider` 与 `compactionCacheMode` 保持不变。开关关闭时所有请求保持原生。不新增 Provider 白名单、模式或第二种配置来源；该开关与 remote 设置在同一份激活快照中读取，改动须重启 OMP。Remote 需要准确的 Provider 名称，是因为 V2 的 opaque、裁剪与路由语义随 Provider 变化；本能力只依赖 chat-completions 请求形状，并把参照绑定到同一会话、模型、提示词与工具集，因此增加一个 Provider 键只会增加配置面与第二份 Provider 清单，而不增加保护。改为由组件文档声明验证矩阵与缺口。

### 适用性

适用性按会话的 API 判定，而不是按 Provider 清单。模型 API 为 `openai-completions` 的会话是 Handoff 候选，API 为 `openai-responses` 的会话留给 remote 对齐，其他 API 两项能力都不适用。同一请求最多由一项能力接管，启用一项不会启用另一项。

### 参照绑定

只有已确认的普通主循环 dispatch 提供参照，且须在其 HTTP 响应确认发送之后。本能力对齐的调用永远不会成为参照。每个会话保留自己的参照，以及取得该参照时的归属：Provider、模型身份、API、system 提示词、thinking 状态与工具集。不含工具集的准备请求不提供参照，因此从不发送工具的会话保持原生。

参照对其所属操作不可变。更新的在线工作、认证刷新、传输重试与 handler 状态推进都不能移动它，重试也不能取得更新的参照。绑定在标识该操作的准备 seam 建立，在准备出站请求的 seam 解决，两者使用同一个信号。switch、branch、tree 导航、压缩提交与会话释放清空该会话的参照并使该会话的 epoch 失效；已绑定的操作保留自己的快照，新的普通发送在不重启进程的前提下恢复资格。

### 投影边界

只有在侧请求的 system 段是参照 system 的前缀、参照的非 system 历史是侧历史的严格前缀，且参照仍属于同一会话、模型、API、提示词、thinking 状态与工具集时，本能力才改写侧请求。在此边界内还原在线 system 段、参照持有的 `reasoning_effort`（参照持有该值时）以及在线 `tool_choice`（参照没有显式选择时）。它在宿主的 payload hook 之后一次替换请求 body，不改动侧指令、新增历史、缓存键、取消信号与其余请求选项。

投影逐轴还原。无法还原的轴只跳过并计数，不放弃整条改写；这些轴之外的已知缓存敏感字段与参照比对，不同则计数。字段差异不构成闸门，因为确定请求身份的是操作绑定，而不是字段相等。

边界之外的请求原样发送并给出固定原因：操作已失效、参照未确认、参照的会话/模型/API/提示词/thinking 状态/工具集发生变化，或 system 前缀与历史投影发生变化。`rejected` 表示本能力没有改写该请求，绝不表示请求被阻断、延迟或丢弃。候选与原请求相同则报告为已对齐，不重新序列化。

### 独立性

本能力与 remote 对齐共用本包、协调器、逐会话登记以及每个原生方法的一层包装，其余一概不共用：协议规则、载荷形状、原因码与收益证据都不共用。它不复用 remote 的 Responses V2 规则，一项能力拒绝请求或接口缺失不影响另一项。

`/smart-cache` 仍是单一命令，不启动模型 turn，并在各自的段落中报告两项能力各自的状态、分阶段原因与有界计数；remote 段落保持现有文案与字段。状态区分 `disabled`、`unavailable`、`awaiting-reference`、`already-aligned`、`rewritten` 与 `rejected`；在线确认、参照绑定、候选校验与发送结果分别保留，使后续的缺失参照不致抹去更早的证明缺口。诊断使用本会话与操作标识符、固定原因与有界计数，不包含请求正文、opaque 内容、凭据、端点、私密路径或动态私密键。

### 原生职责

OMP 保留文档生成、调度、触发、取消、认证与传输重试、模型与方法回退、结果校验、历史提交与续接。本能力不新增入口，不注册 `session_before_compact`，不替换手动压缩，不否决任何请求，不请求凭据，不修改设置，不伪造摘要，不校验文档结构，也不添加重试。它原样转发原生参数、receiver、Promise、异常、信号与取消原因；宿主选择的回退保持原生，而不报告为对齐。还原在线 tool choice 可能使模型返回工具调用而不是文本，这种失败表现为宿主自身的空文档结果。

按能力与结构选择受维护行为。当受维护的原生接口在所需路径上提供等效的结果、配置语义、隔离与失败行为时，以行为验证而非上游合入为准替换这些适配。

### 试验扩展切换

本机试验扩展只在能力通过自身验收、随后获得安装授权之前保持安装。那次经授权的切换会替换并停用该试验扩展；本决定不执行切换。试验扩展仍被自动发现期间，本包报告保守的包装冲突，而不抢占包装；切换通过重启相关进程完成，而不是传递在途状态。

## 考虑过的替代方案

无

## 结果

- 同一协调器中的两项能力可能相互干扰。为一项能力所做的改动可能影响共享包装、逐会话生命周期或另一项能力的诊断，因此一项能力的回退可能与另一项能力的改进一起发布。防护方式是把 remote 规则原样搬移，并在发布前重跑其验收。
- 用户可能在试验扩展仍被发现时启用开关。此时一层包装可能顶掉另一层，使对齐以报告冲突停止，或包装循环重复同一次改写；保守冲突报告与基于重启的切换限制这一后果，但不能阻止两者共存。
- 对齐请求不保证命中 Provider 缓存。本能力可能只增加维护而不重复已观测收益。
- 宿主改动侧请求路径会使参照无法匹配，本能力于是拒绝并报告固定原因，同时失去收益；若边界检查过宽，则可能还原宿主已不再打算使用的 system 提示词或 tool choice，产生错误或被截断的交接文档。
- 在宿主为文档生成构造的请求中还原在线 tool choice，可能使模型返回工具调用而不是文本，宿主的文档提取随之失败。本能力不执行工具、不添加重试，因此该失败保持宿主自身的结果，而不算作本能力的成功。
