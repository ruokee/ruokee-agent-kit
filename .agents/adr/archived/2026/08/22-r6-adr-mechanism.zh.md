## 动机

维护双语 ADR 提案与决定，保持决定路径稳定并保留可追溯的反转历史。

ADR 保存长期选择、理由、必要契约和生命周期。连续版本需要一个当前引用入口，以及可分别访问的历史记录，包括同一天内发生多次反转的情况。年、月目录用于归类记录，不把实际归档日期当作身份。

[此前机制](./22-r4-adr-mechanism.zh.md)要求命名维护保留每条记录的文件名日期，其后继使用不同日期。将所有版本统一到决定首次提出日期，改变了日期含义与历史维护边界，不改变其他 ADR 记录的选择。

ADR 术语表重复了词典已定义的词条，形成需要同步维护的第二份权威。现在，可分发组件之外的仓库内容以词典为唯一术语来源，ADR 指南指向词典的 ADR 页。

## 决定

### 术语

使用 **ADR** 作为主要术语，根目录为 `.agents/adr`。指南的文档布局把 `proposal` 和 `decision` 定义为两类文档。`proposal/` 保存活跃提案，`rejected/` 保存被拒提案，`decision/` 保存当前决定，`archived/` 保存归档决定。目录表达类型与状态，记录不含 `Status` 字段。英文使用 `Create decision`、`Update decision`、`Reverse decision` 作为动作短语，不作名词标签。`Reverses` 从后继指向归档，`Reversed by` 从归档指向实际后继。

### 身份

决定首次提出日期与简短规范英文主题名标识当前记录和全部归档。普通反转保留身份与路径。抽出的独立主题获得自己的首次提出日期、规范名称和序列，同时保留真实来源与反转关系；共同前驱或 `Reverses` 链接不代表身份相同。提案保留自己的首次提出日期，即使它反转更早决定，拒绝也保留该日期，不替换旧决定日期。`Archived` 和带日期的 `Changes` 保留真实事件日期。

### 路径

指南在 ADR 根目录下采用 `proposal/YYYY/MM/DD-name.md`、`decision/YYYY/MM/DD-name.md`、`rejected/YYYY/MM/DD-name.md`、`archived/YYYY/MM/DD-rN-name.md`。年为四位，月和日为两位。当前与归档路径都使用身份日期，即使跨年。只有归档带 `rN`，从 `r1` 起，每次该决定反转递增一次，跨日、月、年不重置。另一决定、语言对应文件、多条链接、普通更新、目录移动、命名整改不消耗序号。只为实际记录建立时间目录，月目录没有数量限制。指南留在根目录，四个生命周期目录以 `.gitkeep` 跟踪，即使已有文件。

每个保留的文件名、主标题和小节标题，包括 `Changes` 日期后的主题，都按命名规则以简短祈使句、短语或名词表达一个主题。完整叶子文件名连同日期、修订号、主题、语言后缀和扩展名不超过 60 字符。

### 提案流程

除非维护者要求其他拆分方式，一项需求创建一份提案；实现前，获准提案作为独立变更合入 `main`。实现从包含提案的 `main` 建立新短期分支。一份提案可以创建多项决定、反转多项决定，或两者兼有。实现后，在同一实现变更中创建新决定、更新无冲突决定、反转冲突决定，并删除已消费提案，Git 保留独立合入的理由。被拒提案按原日期和名称移入 `rejected/`，不加 `rN`，增加 `Rejection reason` 或 `拒绝原因`，事实链接修复后冻结。仅在其理由仍能防止现实错误时保留。

### 记录格式

每项 ADR 是同目录英文和中文文件对，`DD-name.md` 与 `DD-name.zh.md`，归档为 `DD-rN-name.md` 与 `DD-rN-name.zh.md`。两种语言语义同等权威，在同一变更中补齐并一起移动。英文是默认公开链接，中文是审计副本，可先起草任一语言。语义冲突阻止合入，直到维护者解决。路径、命令、API、元数据与标识符保持仓库拼写。

标题只承载主题。提案元数据依次为 `Draft owner`、`Draft writer`；决定为 `Decision owner`、`Decision writer`。owner 为负责维护者，writer 是原作者，后续维护不改变。模型作者名省略提供方、路由器和渠道前缀，可保留宿主名。语言版本的 owner 和 writer 相同。关系与生命周期字段放在 writer 后，完整元数据块后紧接双向语言链接。`Archived` 位于可选的 `Reversed by` 前。

提案章节依次为 `Motivation`、`Proposal`、`Alternatives considered`、`Acceptance criteria`、`Risks`，对应 `动机`、`提议`、`考虑过的替代方案`、`验收标准`、`风险`。决定章节为 `Motivation`、`Decision`、`Alternatives considered`、`Consequences`，对应 `动机`、`决定`、`考虑过的替代方案`、`结果`。先说明活跃提案再说明被拒格式，先说明当前决定再说明归档格式。

### 编写记录

两类文档均以动机开头，第一段是一句简短、独立可理解的话，说明动作或完整选择，不写记录做了什么。后续段落说明具体问题、背景、理由和证据；想要一种能力不必先包装成缺陷。反转提案说明拟改变什么，后继说明完整选择。可选的实质分析 `Analysis` 或 `分析` 紧接动机、位于提议或决定前，只记录影响选择的观察、证据、约束、推导和不确定性，不写实施计划、调研副本或重复内容。

记录连贯的持久选择、理由、必要边界、归属、重要公开承诺，以及实质兼容、安全、成本和失败后果。只有省略技术片段会妨碍理解选择、重要取舍或丢失有效契约时才保留。配置权威、不可变身份和进程级副作用可能符合条件。完整 API、配置表、schema、命令和清单归所属公开页面。内部函数、算法、逐文件修改、执行计划、测试命令和日志归实现文档、代码、测试或任务材料。验收描述可观察结果而非测试步骤。引用可访问契约，不引用忽略的任务材料，排除任务生命周期、分支、提交和会话上下文。

移动有效条款不取消它。保留含义和可访问引用，历史记录保留足以解释当时选择的原始细节，持续变化的当前文档不能替代历史契约。区分封闭协议、归属、安全边界与示例、可增长清单。优先链接所属清单而非固定数量或穷举文件树，并解释必要的封闭边界。暂时范围限制不等于永久禁止，不得事后弱化禁令或为可扩展措辞预建抽象。防御规则针对真实操作及危害，校验、修复、生命周期变化和重复激活可能有不同前提。保留身份、权限、副作用保护，不以无关全面限制替代。

审查各处替代方案与风险类内容，包括结果。先确认确实进入选择或存在可信因果，再判断移除会丢失的重要取舍、危害或边界。条目自称考虑过不算证据，需定位需求、分析、提案或历史来源。审查证据放在任务材料，不写进 ADR。删除无依据、归类错误或不重要的条目，不润色或搬到别处，保留独有约束与必要理由。合并重复原因时保留条件，不以条数、删除比例或字数衡量质量。结果可以是收益或已接受代价，不全是风险。历史内容按形成时证据判断。内部结构使用描述性三级标题，不替换必需二级标题，不复制进度或实现清单。

替代方案从 `None` 或 `无` 开始。仅收录同一持久选择中确实参与且解释重要取舍的不同做法，存在、看似可行或被提及不够。事实、要求、验收、当前方案复述、已定范围的简单反面和无实质取舍的实现排列不合格。后续约束出现前曾真实可选的方向，可保留必要理由，不复制探索或列出每个否决想法。空结果也是完整结果，只写规定的空标记。

风险同样从 `None` 或 `无` 开始，无数量要求。说明条件或遗漏、因果机制和决定特有的实质危害。保留剩余风险、兼容损失、持续成本及影响采用的不确定性。有重大失败路径的遗漏也可成立，不因涉及实现而排除。事实、约束、待办、重复行为和临时证据缺口本身不是风险。笼统的代码失败、文档漂移或读者误解不合格。分立权威漂移成冲突、取消修订检查导致旧正文覆盖新正文、处理器在注册条件下禁用推测启动，都是具体因果示例。无合格条目时只写 `None` 或 `无`。

### 决定生命周期

无冲突新增使用更新决定，追加到最后的 `Changes` 或 `变更` 章节，并使用带日期的三级标题。新增内容值得独立成为 ADR 时链接另一项决定。纯表达维护不形成新选择，不需要反转。

冲突选择使用反转决定。先合入提案，列出要反转的每项决定、有效条款、新选择和二者不能同时成立的原因。代码量、增加功能、增加宿主依赖或改名本身不足以证明反转。实现后，将每项旧决定仍有效的规则与获准提案整合成其范围内的完整后继，不复制组件实现规格。

同一变更将被替代的双语版本移入下一修订号归档。归档元数据在可选的 `Reversed by` 前增加 `Archived: YYYY-MM-DD`。后继的 `Reverses` 指向该归档，归档的 `Reversed by` 指向实际后继。归档不作为当前权威。

直接关系跟随版本。A 被 B 反转，B 随后被 C 反转时，A 的 `Reversed by` 跟随 B 进入 B 的归档，不漂移到当前路径上的 C。B 仍链接 A，C 链接 B 的归档。当前权威引用使用规范当前路径，特定历史选择引用跟随该版本进入归档。按引用含义分类，不按源文件所在目录分类。文件路径稳定不意味着标题片段不可改变。

### 维护

依靠评审、仓库搜索与 Git 历史，不增加专用 ADR Skill、分类体系、翻译 sidecar、归档 manifest、索引或常驻维护脚本。只有重复维护或实际错误确定具体机械约束后，才增加最小检查。

ADR 指南、中文对应版和[仓库词典](../../../../../docs/dictionary/adr.zh.md)拥有具体格式与操作。指南的有效契约保留在上文，不交给持续变化的引用承载。[仓库规格](../../../../spec/repository.zh.md)说明长期目标与可观察不变量。指南、文档规则、规格、词典与受影响引用在两种语言中保持一致。

维护者拥有提案批准、拒绝与决定归档权限；Agent 可以在授权内起草与实现，没有明确批准不能自行作出这些生命周期决定。规划前搜索提案和当前决定，确认需求是否需要提案。存在真实替代方案，且改变架构、归属、公开或宿主合同、持久格式、兼容或仓库流程的选择需要 ADR。局部修复、机械重构、普通文档变更、状态报告或临时计划不需要，除非改变持久边界。

语言文件一起移动，在同一变更修复关系、正文、语言、入站链接和片段。归档在关系与事实链接修复后冻结，被拒提案在事实链接修复后冻结。根据正文、关系、提案来源和相关 Git 历史修正有证据的名称、标题、身份、序列和关系。保留选择、理由、约束、不确定性、历史能力、原作者、实际归档日期和事件日期。身份规范化只改路径日期，不改事件；Git 保留原名。命名整改不增加反转、不解除冻结、不改变承诺，不保留重复旧名别名。历史格式示例与 Git 对象路径以拼写为引用事实时保留原拼写。事实维护不能反转决定。

## 结果

每项决定的当前权威有一个稳定路径，各被替代版本可独立访问。按身份确定的年、月目录将其历史归在一起，即使实际归档发生在多年之后。`Archived` 保存事件日期，不决定目录归属。

当前后继自身归档时，需要维护直接关系。把所有引用都当作当前权威，会把历史依据悄悄指向其他内容。把共同来源误当作共同身份，会合并独立决定或分配错误序列。

标题承载主题，不承载类型。读者通过目录、元数据和语言链接识别记录。查找依赖简短名称与仓库搜索，不依赖中央索引。

提案和实现需要独立分支及主线提交，保留独立理由与评审边界。反转需要对照前驱与提案重建完整当前契约。必要契约细节及双语语义一致性仍需评审判断，不是机械检查可证明的属性。
