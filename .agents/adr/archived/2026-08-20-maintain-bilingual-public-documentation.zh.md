# ADR 决定：维护中英文公开文档

Decision owner: Ruokee
Draft writer: OMP GPT-5.6 Sol
Archived: 2026-09-07
Reversed by: [同目录维护中英文公开文档](../decision/2026-09-07-colocate-bilingual-docs.zh.md)

[English](./2026-08-20-maintain-bilingual-public-documentation.md) | 中文

## 动机

仓库对外公开，代码和默认文档使用英文，但 Ruokee 使用中文审查技术决定和使用细节。只有英文会失去这条审计入口。每个文件都混写两种语言，则会让日常读取量翻倍，也会让导航变乱。

项目需要一套适用于用户文档的语言规则，不能只为根 README 设置特例。

## 决定

代码、注释、配置和默认公开文档使用英文。行为或用法变化时，在 `docs/zh/` 下同步维护对应的中文用户文档。

对应的中英文入口必须互相链接。每份文档都必须能独立成立。路径、命令、API 名称、状态值和代码标识符保留英文原值，让读者可以搜索仓库中的精确形式。

同一变更中审查两种语言。要求语义一致，不要求逐句或逐字节翻译。只要行为、限制和指令一致，中文可以采用更自然的解释。

不要求翻译所有内部实现记录、注释、生成文件或只供维护者使用的材料。公开的行为与用法文档必须成对维护。ADR 使用 [建立 ADR 机制](../decision/2026-09-02-establish-adr-mechanism.zh.md) 定义的更严格文件对格式。

## 考虑过的替代方案

无

## 结果

英文继续作为代码、配置、注释和公开文档的默认语言。公开行为和用法变化在同一变更中更新对应中文文档，对应入口保持双向语言链接。

命令、路径、API 名称和代码标识符保留仓库原值。每种语言的文档都能独立阅读，并与对应版本语义一致。只有目标读者确实需要时，才翻译内部文件和生成文件。

机械检查无法证明语义一致。文件对和链接检查可以发现遗漏，但仍需要人或有能力的 Agent 比较含义。

部分公开文档没有明显的对应版本。行为或用法首次需要中文说明时，由相应变更定义真实文件对，不提前创建空占位文件。

## 变更

### 2026-09-02：采用 ADR 文件对格式

ADR 使用 [建立 ADR 机制](../decision/2026-09-02-establish-adr-mechanism.zh.md) 定义的严格中英文文件对格式。两份文件在语义上具有同等权威，并且一起移动。
