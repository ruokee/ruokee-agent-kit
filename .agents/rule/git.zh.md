# Git

[English](./git.md) | 中文

[仓库规格](../spec/repository.zh.md)说明这些规则所服务的性质：`main` 是唯一的长期分支，集成通过 squash 合入完成，提交信息遵循固定的格式与 scope 集合。

## 分支

- 每个功能、修复或文档变更都从当前 `main` 创建短期分支，不在 `main` 上直接编辑或提交。
- 代码、配置、脚本、并行任务，以及无法确认独占主工作目录的任务，使用 `.worktrees/` 下的独立 worktree。
- 只有干净、没有并行工作且已确认独占时，串行说明性 Markdown 或 ADR 任务才可以使用主工作目录。
- 运行时模板不适用该例外。被测试读取的说明文档只有在同时运行其消费者检查时才适用。
- 编辑前创建并切换到短期分支。任务范围扩展到说明性 Markdown 之外或失去独占条件时，先停止共享目录编辑，把已有工作保存在独立 worktree 中再继续。
- 分支合入 `main` 后，在收尾阶段执行 `git worktree remove`。合并授权包含这项清理。

## 提交

- 只暂存属于当前任务的文件，每个原子任务分别提交到分支。
- 提交信息使用英文 Conventional Commits，类型取自标准集合，可选 scope 取自规格声明的集合。
- 让 `git commit` 运行质量钩子。钩子修改了任务文件时，先审阅并重新暂存，再重试提交。
- `git commit --amend` 只用于修改提交信息，不用来增加、删除或替换已提交的改动。
- 请求审查前提交任务改动，并保持工作树干净。

## 授权

- 提交请求只授权分支提交。
- 合入 `main` 必须在用户明确审阅并授权后进行，并对任务分支执行 squash 合并。不使用普通合并、快进合并、变基后快进或直接移动引用。
- 没有明确授权不得推送，也不得删除分支。
- 审查请求不授权修改被审查的文件。
