# 规则

[English](./README.md) | 中文

规则说明在这个仓库里工作要怎么做：贡献者或 Agent 必须做什么、按什么顺序、持哪项授权，以及什么被禁止。规则层位于 `.agents/rule/`，与[规格](../spec/README.zh.md)和 [ADR](../adr/README.zh.md) 并列。

读者需要规则背后的理由时，规则链接拥有该理由的决定，或拥有它所执行性质的规格。

## 按活动的规则

- [boundary.zh.md](./boundary.zh.md) 覆盖第一方范围、内容布局、公开内容和组件版本。
- [git.zh.md](./git.zh.md) 覆盖分支、工作目录、提交、授权、合入和收尾。
- [development.zh.md](./development.zh.md) 覆盖规划、环境、钩子、检查和证据。
- [documentation.zh.md](./documentation.zh.md) 覆盖文档、规格、决定、语言配对、命名、清理和文件引用。
- [terminology.zh.md](./terminology.zh.md) 覆盖规范用词、组件术语表、词典词条和语言配对。

## 文件布局

- 规则平铺在 `.agents/rule/` 下，一个活动一个文件，不设子目录，文件名不带日期和状态。
- 每个页面按 `name.md` 与 `name.zh.md` 配对；本层入口使用 `README.md` 与 `README.zh.md`。
- 活动集合随真实需求增长，上面列出的页面不是封闭集合。

## 单条规则的写法

- 一条规则用祈使句陈述一个约束，最多补一句简短说明。
- 规则尽量追溯到一条规格不变量、一条现行决定或维护者的明确决定。没有这样的出处时，只要它是当前确实执行的做法即可，但不得与规格或现行决定冲突。
- 规则保留原有的条件、例外、强度和权限。用「尽可能」表述的规则保持该强度，禁止性规则保留它的例外。
- 引用一条规则使用文件路径加小节标题，不给规则编号。
- 这一层不含长篇理由、规则编号和清单。需要理由时链接拥有它的决定或规格。

## 编辑规则

- 规则就地编辑。规则不保留历史、状态和修订记录。
- 同一规则在 `AGENTS.md` 与规则页中都有陈述时，无论先改哪一处，都在同一次变更中保持两处一致。
- 规则新增、删除或改变它所承载的持久选择时，例如授权边界、流程要求或发布策略，先走 ADR 流程再改规则。不改变持久选择的编辑性澄清不需要 ADR。
- 规则文件中不写任务信息、评审意见和会话信息。

## 引用方向

- 规则可以链接组件文件、组件文档、规格和决定。
- 可分发组件中不出现 `.agents/rule/` 下的任何路径。组件不得链接、命名或依赖这一层，运行、构建和分发都不依赖它。
- 规则是说明性文档。Markdown 检查和变更路径选择器像对待其他 Markdown 一样对待规则，这一层不引入检查器、分类系统或清单文件。
