# 文档

[English](./documentation.md) | 中文

[仓库规格](../spec/repository.zh.md)说明这些规则所维持的语言、配对和链接性质。

## 保持文档同步

- 文档与它所描述的代码保持同步，并在同一次变更中更新受影响的文档。
- 代码、注释、配置和默认公开文档使用英文书写。
- 每个普通公开 Markdown 页面维护语言配对：同目录的 `name.md` 与 `name.zh.md`，入口页为 `README.md` 与 `README.zh.md`，标题下紧接双向语言链接。规格正文不包含仓库文件链接，其语言导航放在非规格索引中。
- 同一对文件的两种语言在同一次变更中更新，语义保持一致。
- Skill 语言变体保持在各自现有的组件布局中，不在 Skill 之间新增跨语言链接。
- `.agents/skills/` 下的内部项目 Skill 使用英文。它们是维护材料，不是普通公开页面或公开语言变体。

## 命名

- 文件名与各级标题写成短的祈使句、短语或名词，除非有额外要求。
- 文件名里的连字符与语言后缀的句点是命名格式要求的分隔符，不是标点。
- 各级标题不写标点，只有 `-`、`.`、`、` 三个字符例外，不限位置。
- 不在文件名或标题中用并列连词连接多个主题，例如 `和`、`且`、`与`、`并`、`或`、`以及`、`and`、`or`、`as well as`，也不用顿号连接主题，除非额外要求需要多个主题。取舍也不例外。词内用字与表示单一关系的介词短语，例如「与其他文档的关系」，不算并列。
- 文件名与标题只写它们指名的那个主题，把组成部分留给正文。写 `调整 Task 目录布局`，而不是 `tk Task 目录树与子任务布局调整及重命名`。两个名称之间的斜杠，例如 `Observer / Pub-Sub`，是并列而不是一个主题。
- 中文变体标题里的英文术语写在正文首次出现处，不写在标题括号里。
- 锚点声明是锚点，不属于标题标点。本仓库不写这类声明，因为渲染环境由标题文本生成锚点，标题改名时要在同一次变更里更新指向它的链接。

## 清理

- 交付页面前先用 [`well-said`](../../variants/zh/skills/well-said/SKILL.md) Skill 检查，并清理它指出的问题。

## 文件链接

- 仓库文件链接相对于所在文档书写：当前目录或其子目录的目标用 `./` 前缀，离开该树时按需使用 `../`。
- 不使用前导 `/`、相对仓库根的目标，也不为仓库内的文件使用 GitHub 绝对 URL。
- 链接文字指名某个文件时，从仓库根书写该文件名，不加前导 `/`。
- 文档提到 `AGENTS.md` 时写行内代码，不写成链接。它的读者是在本仓库工作的 Agent，而不是公开文档的读者。

## 决定

- 创建、修复、更新、反转、归档或审查 ADR，以及项目工作影响持久选择时，先加载 [maintain-adr](../skills/maintain-adr/SKILL.md) 并读取 [ADR 项目补充](../adr/README.zh.md)。Skill 持有主要维护方法，补充持有项目语言、Git 和权限政策。

## 规格

- 维护或审查长期规格，或改变组件及仓库领域的目标、边界、验收之前，先加载 [maintain-spec](../skills/maintain-spec/SKILL.md)，读取[项目补充](../spec/README.zh.md)和受影响规格，并随变更同步更新。Skill 不维护任务 Goal，加载任一维护 Skill 都不扩大写入权限。
- 与决定同时更新受影响的规格。
- 在规格中完整表达已确认要求，不写实现描述或仓库文件链接。导航留在规格正文之外，不通过路径或引用委托需求。
