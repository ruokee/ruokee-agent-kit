# 仓库边界

[English](./boundary.md) | 中文

[仓库规格](../spec/repository.zh.md)说明这个仓库应当收录什么、不收录什么，以及其中的组件以什么形态交付。以下规则约束维持这些性质的动作。

## 第一方范围

- 仓库只收录 Ruokee 编写和维护的能力。
- 不加入第三方能力、fork 或上游镜像。第一方能力可以引用、摘录或改编第三方材料。
- 判断 fork 与否看第三方能力本身是否成为开发和维护的对象，而不只看是否复用内容或复用了多少。
- 保留来源署名，并遵守适用于被复用材料的许可和署名要求。
- 支持仓库内能力的第一方 manifest、适配器、安装器和验证工具可以放在本仓库。

## 内容布局

- 每项能力保持宿主原生或构建原生的格式。不把 Plugin、Extension、可执行程序或宿主 Package 塞进 `./skills/`。
- 英文 Skill 位于 `./skills/<name>/`，中文变体位于 `./variants/zh/skills/<name>/`。
- 纯 Skill 目录只放宿主可发现的 Skill 材料，例如 `SKILL.md`、workflow、reference、example 和 glossary。不把 Plugin manifest、市场元数据、包 changelog 或宿主专用的 Agent 定义复制进去。
- 每个可分发组件，包括每个语言变体，都保持自包含。其文件只引用该组件内的文件，不得链接、依赖或指示使用仓库中的其他内容。
- 变体内的链接按安装后的 `skills/<name>/` 路径书写，不带仅在源码中存在的 `variants/zh/` 前缀。
- 只有真实组件需要时才增加顶层区域，不为假设的能力分类预建空目录。

## 公开内容

- 受跟踪文件中不放开发者本地目录、机器清单、部署与恢复配置、敏感信息、凭据、私有主机名和内部服务 URL，Agent 笔记也一样。
- 受跟踪文件中不放设备上使用的模型、提供方和渠道配置，文档和测试夹具也一样。描述模型时使用通用说法。
- 仓库文件中不出现本地链接，也不出现被忽略文件与路径的信息，提交消息同样如此。

## 组件版本

- 将组件的 `X.Y.Z` 版本号更新与所包含的功能变更一并提交。
- 默认只递增 `Z`；调整 `X` 或 `Y` 由维护者决定。Agent 不按变更规模自行选择级别。
- 组件 manifest 与组件文档中声明版本的位置保持一致。
