# 设计

[English](./design.md)

`omp-smart-cache` 改写已经发送的请求，使其共同内容与 Provider 缓存的内容对齐，并保持请求含义不变。本包拥有已经证明的目标请求的出站正文；其余部分归 OMP。

## 参照

只有普通主循环 dispatch 的源、完成的准备、既有回调和实际出站 payload 属于同一次 dispatch，并原样到达传输层时，它才成为参照。原始历史、准备结果和 payload 必须对应同一次 dispatch。标题、预热、advisor 与 Handoff 请求保持原生正文，非目标请求同样如此。

每个原生操作冻结最初的参照，包括缺失参照状态，后续在线工作以及认证或传输重试都不替换它。每个 AgentSession 单独登记，使用自己的实际模型、工具、提示词、持久身份、Provider 身份、epoch 和 dispatch。一个进程分发器，加上实际模型注册表各一个包装，共同服务并发会话。模型相等、端点、缓存键、时序或文本都不作为身份依据。

## 复用

先证明完整保留的源范围，再做局部匹配；重复源消息仍然允许完整证明。只保留部分历史时，只有能够独立提取、且依赖和处理条件全部保留的已发送单元可以复用。仅凭输出、长度、索引或来源相等不构成独立性。

原生改写的工具输出保持改写状态，被删除的依赖不补回，新增的普通、工具及图片尾部、opaque 历史、调用与结果配对、trigger 保持原生边界。不可分结果的依赖发生变化时，整条请求保持原生并报告 `projection-dependency-changed`；来源或单元边界未知时保持原生并报告 `projection-unconfirmed`。两种拒绝都计入未对齐并保留在总数中。本包不提供冻结的纯投影协议，也不重新执行黑盒 handler。

## 模式

两种模式都对齐已识别的原生共同内容，包括有效工具 schema 准备、提醒、重放语义和隐式工具选择默认值。V2 保留自己的输出上限或缺省。

- `standard` 接受已识别的原生准备差异。
- `hooks` 还复用已经证明且实际发送的处理结果。完整保留范围支持合法插入、重排、恢复、跨范围合并、图片和既有后置 payload 转换。有状态 handler 只运行一次。

## 观察与所有权

实现从 `session_start` 之前观察原生 CLI/SDK 发布，并持续核对原 agent、runner 和 stream 身份。该观察不是认证任意已构造 Agent 的 API。未被观察或被更换的处理链仍可保留完整范围证明，但不能通过长度或输出相等取得局部原生独立性。具有历史依赖的图片准备和后续日期/cwd 提醒，在未建立局部依赖证明时同样需要完整范围证明。

switch、branch 或 tree 导航前先撤销旧 epoch。原生转换结算后，无论成功、取消还是失败，新的普通发送都会恢复资格。子会话结束或替换只释放自身登记。清理只恢复本包仍持有的包装，不接管竞争包装。共享资源在最后一个登记结束时释放，只保留当前参照及仍可从活跃原生操作访问的快照。

## 失败行为

未知字段、显式策略差异、模型或工具失配、身份歧义、缺失参照、操作取消、外部包装或不可用接口使整条请求保持原生。改写只覆盖非 Codex 的 Responses V2 远端压缩路径。凭据内容、参照与认证请求、Handoff 行为归 OMP，压缩否决属于安装它的组件。

更新时，在途参照留在正在运行的进程内。关闭开关，或移除本包并重启 OMP，即可恢复原生请求路径。
