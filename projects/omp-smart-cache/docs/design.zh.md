# 设计

[English](./design.md)

`omp-smart-cache` 改写已经发送的请求，使其共同内容与 Provider 缓存的内容对齐，并保持请求含义不变。本包拥有已经证明的目标请求的出站正文；其余部分归 OMP。

## 参照

只有普通主循环 dispatch 的源、完成的准备、既有回调和实际出站 payload 属于同一次 dispatch，并原样到达传输层时，它才成为参照。原始历史、准备结果和 payload 必须对应同一次 dispatch。标题、预热、advisor 与 Handoff 请求保持原生正文，非目标请求同样如此。

每个原生操作冻结最初的参照，包括缺失参照状态，后续在线工作以及认证或传输重试都不替换它。对远端对齐而言，标题、预热、advisor 与 Handoff 请求作为副请求保持原生正文；让 Handoff 请求与普通发送共享前缀的是 [Handoff 对齐](#handoff-对齐)。每个 AgentSession 单独登记，使用自己的实际模型、工具、提示词、持久身份、Provider 身份、epoch 和 dispatch。一个进程分发器，加上实际模型注册表各一个包装，共同服务并发会话。模型相等、端点、缓存键、时序或文本都不作为身份依据。

自动维护可以在工具循环的模型步之间提交历史，而不更换 run signal。新的普通 dispatch 将为它创建的凭据 resolver 绑定到当前 epoch、准备结果和最终发送，从而在提交后恢复会话参照，同时永久撤销旧根操作。后续压缩操作只有在自己的新根上才能捕获恢复后的参照，旧操作或重试永远不能取得它。身份歧义、已取消的信号和来自较早 dispatch 的 resolver 仍不具备资格。

原生压缩从 journal 历史重建源。宿主隐藏、归属于 agent 的 `eval-state-context` custom 消息是显示上下文的派生投影，不属于该源。只有已观察到原生构造的会话才识别这组精确元数据。普通请求及捕获的原始消息保持不变，在核对完整范围保留前，规范源不包含这项投影。`standard` 还会对照未过滤的源核对已识别准备。用户消息、其他 custom 消息及构造未确认的会话保留全部源依赖。这项识别不授予局部独立性，也不恢复裁剪过的工具输出。

## 复用

先证明完整保留的源范围，再做局部匹配；重复源消息仍然允许完整证明。只保留部分历史时，只有能够独立提取、且依赖和处理条件全部保留的已发送单元可以复用。仅凭输出、长度、索引或来源相等不构成独立性。

原生改写的工具输出保持改写状态，被删除的依赖不补回，新增的普通、工具及图片尾部、opaque 历史、调用与结果配对、trigger 保持原生边界。不可分结果的依赖发生变化时，整条请求保持原生并报告 `projection-dependency-changed`；来源或单元边界未知时保持原生并报告 `projection-unconfirmed`。两种拒绝都计入未对齐并保留在总数中。本包不提供冻结的纯投影协议，也不重新执行黑盒 handler。

## 模式

两种模式都对齐已识别的原生共同内容，包括有效工具 schema 准备、提醒、重放语义和隐式工具选择默认值。V2 保留自己的输出上限或缺省。

- `standard` 接受已识别的原生准备差异。
- `hooks` 还复用已经证明且实际发送的处理结果。完整保留范围支持合法插入、重排、恢复、跨范围合并、图片和既有后置 payload 转换。有状态 handler 只运行一次。

## Handoff 对齐

Handoff 依据当前会话生成文档或摘要，并把这项工作作为副请求发送，该请求由会话历史加上一个基础系统提示词构建。这条请求重复了普通主循环 dispatch 已经发送过的一段前缀，因此本能力让它与同一会话中已确认的普通请求对齐。远端对齐把这些请求视为带自身正文的副请求；让副请求与普通发送共享前缀的是本能力。

Handoff 支持 `openai-completions` 与 `openai-responses`。先证明操作归属，再按实际请求种类分派；Responses Handoff 不要求 remote 激活、Provider 匹配或特定模式，V2 仍由 remote 处理。其他 API 保持原生，一条请求最多由一项能力改写。

参照与远端能力要求的参照同源，都是已确认的普通 dispatch，并与观察时的所有权一起捕获：Provider、模型身份、API、系统提示词、思考状态和工具集合。参照对它所属的操作不可变；后续在线工作、认证刷新、传输重试和 handler 状态推进都不会替换它。switch、branch、tree 导航、压缩提交和会话释放会清除参照并使该会话的 epoch 失效，新的普通发送即可恢复资格，不需要重启 OMP。本能力对齐的请求永远不会成为参照。不含工具集的准备请求不提供参照，因此从不发送工具的会话保持原生。

待确认的普通参照冻结 dispatch 的 epoch、持久及 Provider 身份、取消信号和完整 owner。成功响应到达时重新核对这些事实。已失效或取消的待确认工作不能发布参照。工具归属在复制之前使用宿主的 wire-schema 转换，包括原生 callable schema。

原生构造观察在登记之前记录两个 Handoff 方法。未确认的基线保持方法不变；已安装包装丢失后，本能力报告为不可用。每次物理发送都在查询 memo 之前核对操作的完整 owner。owner 变化会永久撤销操作，即使后续重试的 body 相同或恢复先前取值也不能恢复。payload 回调只标记原生准备完成，共享传输边界才执行投影，并记录每次实际委派和重试。

只有在副请求的系统段是参照系统段的前缀、参照的非系统历史是副请求历史的严格前缀时，本能力才改写该副请求。Chat Completions 在边界内还原在线 system/developer 系统段、参照持有的 `reasoning_effort` 及没有显式选择时的在线 `tool_choice`。Responses 从同次普通 context dispatch 冻结原始来源，通过原生 serializer 标定准备结果中的 system；不能改从尚未同步的 Agent state 取得来源。确认最终普通发送及 2xx 后发布独立参照。Handoff 绑定的原生 snapshot 必须完整保留这份源前缀，并具有新增尾部。

来源比较只排除 assistant 顶层的 `completedAt` 和 `contextSnapshot`，宿主在 dispatch 后将它们补写为本地会话记账信息。其余字段，包括内容、Provider replay payload 和未知字段，必须严格相同。捕获的历史和出站 input 均不改变，最终 wire 历史仍须单独证明。

Responses 只恢复已证明的系统表达。顶层 instructions 要求参照等于已知系统片段，副请求为其文本前缀；恢复 instructions 时完整 input 不变。前置 developer 要求普通已知系统片段、共同历史与副请求系统边界唯一对应，只替换前置系统片段，历史 developer 保留原位。完整片段及同一片段内的文本后缀均可恢复。工具定义必须相同，新增历史、调用配对、图片、缓存键与 side 身份保留。

嵌套 reasoning、原生配置更新和 `none` 不投影为普通请求的值，宿主已有 auto-only 重试保持不变。严格识别的 reasoning 配置更新仅从共同历史比较视图中排除，实际出站 input 不删除或插入它们。有效思考和生成语义保持原生，差异分别计入 axes 或 unprojected。必要证明失败时整条保持原生；其余独立轴无法恢复时跳过并计数，无关字段不否决系统投影。完整候选在 payload hook 之后、最终传输时原子替换；相同候选不重新序列化。

在边界之外，请求携带固定原因原样发送：操作失效、参照未确认、参照捕获的所有权发生变化，或者系统前缀或历史投影发生变化。`rejected` 只表示本能力没有改写该请求，绝不表示请求被阻塞、延迟或丢弃。

文档生成、触发、投机采用、取消、认证与传输重试、模型与方法回退、文档校验、历史提交和续接归 OMP。手动 focus 与自动入口均经过原生共享生成器，扩展不新增命令或文档落盘。本能力不注册 `session_before_compact`，不替换手动压缩，不伪造摘要或增加重试。Chat Completions 恢复在线工具选择可能产生工具调用而非文本，其失败仍是原生结果；Responses 保留文档生成的原生工具选择。

两项能力共享本包、进程协调器、会话登记、同次普通 dispatch 的不可变观察事实，以及每个原生方法的一层包装。协议规则、载荷形状规则、资格证明、原因和收益证据各自独立，不使用 V2 证明建立 Handoff 资格。一项拒绝或缺少接口不影响另一项。协调器和激活条目带合同版本，外部版本报告 coordinator-conflict，不被改动或复用；激活快照使用本版本自己的进程级键。

## 观察

实现从 `session_start` 之前观察原生 CLI/SDK 发布，并持续核对原 agent、runner 和 stream 身份。该观察不是认证任意已构造 Agent 的 API。未被观察或被更换的处理链仍可保留完整范围证明，但不能通过长度或输出相等取得局部原生独立性。具有历史依赖的图片准备和后续日期/cwd 提醒，在未建立局部依赖证明时同样需要完整范围证明。

## 所有权

switch、branch 或 tree 导航前先撤销旧 epoch。原生转换结算后，无论成功、取消还是失败，新的普通发送都会恢复资格。子会话结束或替换只释放自身登记。清理只恢复本包仍持有的包装，不接管竞争包装。共享资源在最后一个登记结束时释放，只保留当前参照及仍可从活跃原生操作访问的快照。

## 失败行为

remote 的未知字段、显式策略差异、模型或工具失配、身份歧义、缺失证明、取消、外部包装或不可用接口使整条请求保持原生；它只改写非 Codex Responses V2，适用于主会话以及原生 task、Eval 子会话。Handoff 按上述独立证明与逐轴规则处理。凭据、参照请求、认证请求和原生回退归 OMP，压缩否决属于安装它的组件。

更新时，在途参照留在正在运行的进程内。关闭开关，或移除本包并重启 OMP，即可恢复原生请求路径。
