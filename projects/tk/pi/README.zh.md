# 面向 Pi 的 tk

[English](./README.md) | 中文

tk 持久化任务运行时的 Pi 组件。运行时把任务进度、共识和支撑材料保存在普通项目文件中，并单独安装在固定的用户级路径 `$HOME/.local/bin/tk`。本 Package 不包含该可执行文件。

## 内容

`tk install --harness pi` 选择一种模式和一种语言：

- `tools` 包含 Pi 原生适配器和选定的 Skill；
- `cli` 只包含选定的 CLI Skill 和本 Package 清单，没有原生工具注册。

两种模式提供同样的六项逻辑操作：search、read、create、update、log 和 exec。前五项返回统一的 JSON 结果，exec 保留原始 stdout 和 stderr 合同。

## 兼容性

`0.84.4` 是 Pi 的最低维护版本，本节是该数值的权威入口。Pi 使用自己的版本线，该数值与 OMP 版本无关。它表达维护承诺，不是安装或运行要求。维护没有上界，版本号也不阻碍使用：安装、加载、注册和诊断路径都不把宿主版本与该下限比较。

这项承诺只覆盖 `tools` 模式随包提供的宿主内代码。`cli` 模式组件不包含这段代码，不承担同一 Pi 版本维护承诺。低于下限的宿主不获得维护承诺，本声明也不表示下限以上的任一版本已经验证。

宿主版本与运行时合同彼此独立，三处版本标记各在不同的位置被声明或核对：

- 组件在嵌入清单中的条目声明运行时兼容范围 `>=0.1,<0.2`，运行时在验证、安装或卸载组件时用自身的版本判定该范围；
- 运行时内嵌的组件束声明 driver 合同版本 `1`，运行时要求该束与自己实现的 driver 合同一致；
- 生成的 native 工具合同声明 `contract_version 3`，适配器要求该取值以及固定的兼容范围 `>=0.1,<0.2`。

适配器通过固定路径上的运行时读取版本文档和 native 工具合同，并比较两者的运行时版本是否相同。它不读取 driver 合同版本，也不计算运行时版本是否落在该范围内。

本 Package 把 `@earendil-works/pi-coding-agent` 声明为无限制 peer（`*`）。它只标明适配器导入的宿主包，不是维护范围，也不证明任一宿主版本能够加载或运行本组件。

## 加载与失败行为

在 `tools` 模式，入口在注册第一个操作前完成以下预检：

1. 固定运行时路径存在；
2. 该路径是带有可执行位的普通文件；
3. 运行时版本文档可解析并带有运行时版本；
4. native 工具合同可解析，带有 `contract_version 3`、宿主的 harness 名和固定兼容范围；
5. 合同中的运行时版本与版本文档一致；
6. 六项操作、各自的请求 schema 以及宿主专属字段齐备。

任一检查失败时，入口输出一条有界诊断，并以零操作注册的状态加载。它不终止 Pi 会话，也不改用其他运行时。

注册过程中某次调用失败时，适配器停止注册后续操作并报告错误。失败前 Pi 已接受的操作可能保持注册。适配器不承诺回滚。

## 宿主差异

原生入口（`extension.ts`，仅 `tools` 模式）向 Pi 注册操作并绑定调用上下文：从 Pi 调用上下文读取工作目录与模型标识，并把 Pi 的取消信号传给运行时。请求未携带工作目录时使用 Pi 的会话目录。本适配器不设置加载模式。

共用映射层（`common.ts`，仅 `tools` 模式）执行预检、把逻辑请求映射为运行时参数、不经过 shell 直接启动可执行文件、限制 stdout 与 stderr，并解析统一的 JSON 结果。OMP 组件是另一个独立 Package，有自己的入口，并通过宿主加载元数据标注操作，Pi 不需要这一字段。

## 验证状态

适配器的自动检查针对桩宿主和桩运行时运行，覆盖预检、参数映射、取消、输出上限、预检失败时零注册，以及上文的注册中途失败行为。它们不能说明真实 Pi 版本如何加载或运行本组件。组件装配检查证明随包文件与组件源码一致，以及运行时版本取值，同样不是宿主行为证据。

真实 Pi 验证在 Pi `0.84.4` 上进行，使用与组件同源构建的 tk 运行时，隔离 HOME 与隔离项目。四种模式与语言组合都完成了安装、加载和卸载。不在终端中运行时，`pi config` 列出宿主从本 Package 取用的资源：`tools` 模式为扩展与所选 Skill，`cli` 模式只有所选 Skill，与所选模式与语言一致。在 `tools` 模式，真实 CLI 在帮助、模型列表和 print 路径上加载扩展并完成预检，为版本文档和生成的 native schema 启动运行时且不输出诊断；移除运行时后只输出一条有界诊断且不启动运行时，禁用扩展发现时同样不启动。已注册的操作清单、错误参数类型的拒绝和真实操作调用未在 Pi 上观察到：本次尝试的 CLI 入口都在工具执行前停止，或打开交互式会话。本次只观察到 Pi `0.84.4`。

更早的 tk 发行版随包提供的是其他版本的适配器，Pi 自身在历史中也更换过包名。那些记录描述的是其他版本，不是本版本。

## 安装与更新

使用随包携带它的运行时安装和移除组件：

```sh
tk install --harness pi --mode tools --language en
tk uninstall --harness pi
```

`tk install` 只读取执行该命令的可执行文件中内嵌的 payload。拉取更新的仓库内容既不会替换已安装的可执行文件，也不会改变其嵌入载荷，因此更新仓库不会更新已安装的组件。
