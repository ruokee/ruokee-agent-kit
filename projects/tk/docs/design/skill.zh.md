# Skill 行为

[English](./skill.md)

本文规定 Agent 使用 tk 时的理想行为。运行时负责强制执行元数据、路径、生命周期、关系、Git 和持久化规则。Skill 不复制第二套规则。

## 何时使用 tk

用户明确提到 Task ID、Task 名称、Task 路径、Task 分支或 tk 操作时使用 tk。

在 permissive 项目中，Agent 也可以为明显值得跨步骤或跨会话持久保存的工作创建 Task。快速问答、普通 TODO、一次性小改和随口想法不需要 Task。

Task 是值得持久保存的临时性努力。创建不代表用户或 Agent 已经承诺执行或完成。

## 生命周期含义

- `planning` 保存仍在形成的想法、调查或计划。
- `open` 表示正在实际处理。
- `closed` 表示该努力已经结束，可以是完成、放弃、不可行或被替代。

状态描述事实，不是优先级。

## 解析 Task

每个新会话默认不绑定 Task。

1. 用户提供完整 ID、精确名称、路径、目录名或分支时，先 search 或 read。
2. 完整引用唯一时直接 read summary。
3. 名称、UUID 前缀、文本和材料路径先 search，再使用返回的完整引用。
4. 多个候选无法根据用户信息唯一选择时，展示候选并询问。
5. 持续对话可以在当前会话中保留已经解析的 Task，但不把绑定写入 Task。

普通 catchup 是只读操作：读取 summary、`TASK.md` 入口和必要材料，报告当前目标、状态、依赖、已形成结论、阻塞和下一步，然后停止。只有用户同时要求继续工作时才继续。

## 创建

### strict

strict 项目的顶层 Task 只有在用户当前明确要求或确认创建时才创建。Agent 不能把“这个问题可能很重要”当成确认。

### permissive

permissive 项目允许 Agent 为值得持久保存的工作主动创建 Task，不要求已经承诺执行。Agent 根据语境选择状态：

- 内容仍在形成，且用户明确希望保存早期材料时使用 planning；
- 已经开始实际处理时使用 open。

创建后在同一回复报告 Task 名称、状态和路径。

### 子 Task

open Task 下的真实工作单元可以作为子 Task 创建，不需要重新取得顶层创建授权。不能在 closed 父 Task 下创建子 Task，也不能隐式重新打开父 Task。

批量创建只用于同一个父 Task 下相互独立的真实工作单元，不用于导入整个 backlog。

## `TASK.md`

`TASK.md` 保存紧凑的当前事实和重要入口：

- 目标；
- 范围和约束；
- 已采用的稳定决定；
- 重要材料链接；
- 当前仍有效的阻塞。

它不保存逐步聊天记录、命令流水、长篇研究正文或已经被替代的计划。详细材料写入 Task 目录中的普通文件，再从 `TASK.md` 链接。

Agent 可以编辑 `TASK.md` 正文和普通材料。受管元数据必须通过 tk 操作修改。

## 日志

事实一旦成为持久决定、纠正、可恢复里程碑、验证结果、协作结果或阻塞，就立即写 WAL，再开始下一条工作分支。

每条日志使用非空单行摘要，细节放在 Markdown body。actor 使用当前可获得的最具体模型或 Harness 信息。actor 只表示归因，不表示身份或授权。

不要记录例行读取、临时计划、工具流水和仍在形成的猜测。

## 更新、关闭和重新打开

更新前读取当前 Task。关系、extra 和生命周期通过 tk update 完成。

关闭前确认：

- 工作确实已经结束；
- 后代和依赖满足普通关闭规则；
- `TASK.md` 只保留当前结果和入口；
- 需要保留的验证或决定已经记录。

close 和 reopen 都需要非空原因和当前用户确认。closed Task 默认只读。新工作通常创建相关 Task，只有用户明确确认新工作仍属于原 Task 时才重新打开。

## 人工修复 `tk.toml`

日常修改始终使用 tk 公开操作。

当 `tk.toml` 已损坏，且 tk 无法表达修复时：

1. 精确说明要改的字段和最终内容；
2. 取得当前对话中的明确授权；
3. 只做说明过的最小编辑；
4. 运行 `tk check`；
5. Task 恢复可用后，用 WAL 记录人工修复事件。

不能手动编辑元数据、清理清单或 Harness 配置来绕过运行时拒绝。

## 错误处理

先读取稳定错误码、类别、详情以及已完成和未完成项。必要时重新 read 或 check 当前状态，再决定是否重试。

多目标操作失败后不假定运行时会回滚或续跑。Agent 根据当前规范状态和用户目标发起新的完整命令。

真正需要用户选择时明确说明选择影响。能够从工具、项目文件或现有材料确定的信息不向用户追问。

## 材料模式

以下模式是非穷举参考，项目说明可以补充或覆盖：

| 模式 | 适用内容 |
| --- | --- |
| scratchpad | 短期临时记事区，不作为最终交付 |
| research package | 需要保存来源、证据、结论边界和未解决问题的研究 |
| design revisions | 多轮相互替代的设计及当前版本入口 |
| review records | 多方审查、分歧和处理结论 |
| validation evidence | 可重复命令、环境、结果和验收判断 |

材料模式只组织普通文件，不增加运行时状态。
