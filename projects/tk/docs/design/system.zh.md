# 系统架构

[English](./system.md)

## 产品定义

tk 是一个面向本地项目的持久 Task 运行时。Task 是一项值得持久保存的项目内临时性努力。创建 Task 不代表已经承诺执行或完成它。

tk 使用项目文件保存状态，不建立数据库、全局 Task 注册表、后台索引、远程服务或常驻守护进程。它不负责优先级、排期、看板、Issue 镜像、Agent 编排或会话绑定。

## 系统组成

系统由以下部分组成：

| 部分 | 负责 | 不负责 |
| --- | --- | --- |
| Rust 运行时 | Task 领域规则、持久化、迁移、项目发现、CLI、MCP、生成工具合同、组件生命周期 | Harness 会话循环和模型调用 |
| Harness 组件 | Skill、工具注册、配置或适配器，以及对应安装目标 | Task 领域验证和存储规则 |
| Skill variants | 四个自包含模式与语言版本，负责 Agent 触发、授权、Task 使用和材料维护指导 | 强制执行运行时不变量或安装组件 |
| 公开文档 | 当前产品合同和用户说明 | 评审历史和 Task 本地材料 |
| ADR | 长期架构决定及其理由 | 实现进度和测试日志 |

一个 Cargo package 生成一个 `tk` 可执行文件。短生命周期命令执行后退出。MCP 服务器只在一个 stdio 连接期间存活，不缓存项目状态。

## Task 与 Harness 边界

Harness 是围绕模型、使模型能够作为 Agent 运行的软件环境，包括模型交互循环、系统提示、上下文管理、工具、权限和 hooks。Codex、Claude Code、Pi 和 OMP 是当前支持的 Harness。未来可以增加 Hermes、DSH 或其他 Harness，不需要改变 Harness 的定义。

Harness 负责：

- 加载 Skill；
- 注册 MCP 或原生工具；
- 提供会话工作目录和可用的模型信息；
- 呈现工具结果和加载错误。

Rust 运行时负责：

- 解析和验证 Task；
- 执行生命周期、关系、迁移和路径规则；
- 读写项目状态和 WAL；
- 生成 MCP 与原生工具合同；
- 安装、更新和卸载 Harness 组件。

Harness 不能复制一套 Task 领域规则。Pi 和 OMP 适配器不实现语义版本范围解析，兼容性判断由 Rust 完成。

## 源码和分发边界

`projects/tk/` 包含一个 Rust 运行时、四个自包含 Skill、当前 Harness 的原生组件源码和公开文档。具体目录属于实现组织方式，不是公共合同。

每个 Harness 选择都是自包含分发单元。组件内部不得引用仓库中的其他组件目录。内嵌载荷包含所选 tools 或 CLI Skill 的英文版或中文版。

组件只由 Rust 构建逻辑组装。Cargo 在 `OUT_DIR` 生成十六份确定性载荷、一个归档和一份清单，再把归档与清单嵌入可执行文件。组件安装只读取当前可执行文件内嵌产物。

## Task 操作流程

```text
调用方
  -> CLI、MCP 或原生工具
  -> 解析请求上下文
  -> 定位项目和 Task
  -> 严格读取与领域验证
  -> 写操作执行 Git 策略并检查活动操作标记
  -> 完成全部领域预检
  -> 按确定顺序提交
  -> 返回结构化结果
```

read、search 和纯诊断不会因为 Git 策略被拒绝。持久写入前才执行 Git 策略检查。

## Harness 组件流程

```text
用户选择 Harness
  -> tk 读取内嵌组件
  -> 校验组件格式、兼容范围、路径和摘要
  -> 校验 Harness 目标和官方接口
  -> 安装或更新 tk 专用内容与 tk 配置项
  -> 返回实际变更
```

卸载的结果目标是：Harness 恢复为从未安装过 tk 的状态，同时保留所有与 tk 无关的原有内容和后续修改。

## 系统级不变量

1. UUIDv7 是 Task 的权威身份。名称用于描述，路径用于定位。
2. Task 状态只有 `planning`、`open` 和 `closed`。
3. 一个项目选择一个 Task 根目录和一种元数据表示。
4. split 与 embed 都是正式支持的表示，不存在临时或次等表示。
5. 正常读写只接受当前 schema。正式发布的旧 schema 通过逐级迁移器升级。
6. 普通写入不使用锁、租约、比较交换或自动合并。
7. 单文件更新使用原子替换。多目标操作先完整预检，再按确定顺序提交。
8. 多目标写入中途失败时停止并报告已完成项和未完成项，不自动回滚。
9. 多目标操作的进程退出后不保留领域操作状态；后续调用重新读取当前规范状态。
10. GC 只删除 tk 创建且由最小清理清单标识的临时内容。
11. 所有 Task 项目关系都留在同一个 Task 根目录内。
12. Harness 名称和工具 schema 类型是不同概念。Harness 是产品，`mcp` 和 `native` 是 schema 类型。
13. 组件安装不访问网络，不读取 Task 项目，也不执行 Git 策略检查。
14. 安装、更新和卸载只操作固定的 tk 专用目标和 tk 配置项，不维护安装历史状态。
15. 公开文档只描述当前正式合同，不保留开发阶段旧命令和被替代行为。

## 平台边界

当前实现和自动化以 Linux 为目标。路径、执行位、进程身份和 Harness 用户级位置按 Linux 行为定义。

运行时使用固定用户级路径 `$HOME/.local/bin/tk`。Harness 组件不得安装第二份运行时、包装器或并行版本。
