# 关系与生命周期

## 关系

`depends_on` 和 `related_to` 包含同一 Task 根目录中的 UUID。运行时会对其排序和去重。

Task 不能引用自身。`depends_on` 必须保持无环。`related_to` 不具有依赖顺序语义。

使用 update 字段添加或移除关系。不要直接编辑载体。

## 生命周期状态

- `planning` 用于保留仍在形成中的想法、调查或计划。
- `open` 表示该工作正在处理中。
- `closed` 表示该工作已经结束。它可能已完成、已放弃、不可行或已被取代。

状态不代表优先级。

## 开始

`planning` 可以转为 `open`。运行时会追加生命周期 WAL 事件。

## 关闭

关闭处于 planning 或 open 状态的工作需要满足以下条件：

- 提供非空原因；
- 获得当前用户的明确确认；
- 所有后代均已关闭；
- 所有依赖目标均已关闭。

在请求确认前，应验证工作确实已经结束，`TASK.md` 已说明当前结果，并且持久证据已记录到 log 中。

强制关闭只会绕过后代和依赖检查。它不会绕过授权、原因、schema、路径、Git 或关系验证。仅当用户明确要求进行此类绕过时才可使用。

## 重新打开

重新打开需要提供非空原因、获得当前用户的明确确认，并且不存在已关闭的祖先。不要因为会话结束或出现新的相关工作而重新打开。新工作通常应放在已关闭树之外的相关 open Task 中。

已关闭的 Task 仍可通过 read、search 和 check 读取，但会拒绝普通修改和 WAL logging。

生命周期操作会自行追加机械性 WAL 事件。不要使用 log 重复记录这些事件。
