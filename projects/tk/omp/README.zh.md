# 面向 OMP 的 tk

[English](./README.md) | 中文

tk 持久化任务运行时的 OMP 组件。运行时把任务进度、共识和支撑材料保存在普通项目文件中，并单独安装在固定的用户级路径 `$HOME/.local/bin/tk`。本 Package 不包含该可执行文件。

## 内容

`tk install --harness omp` 选择一种模式和一种语言：

- `tools` 包含 OMP 原生适配器和选定的 Skill；
- `cli` 只包含选定的 CLI Skill 和本 Package 清单，没有原生工具注册。

两种模式提供同样的六项逻辑操作：search、read、create、update、log 和 exec。前五项返回统一的 JSON 结果，exec 保留原始 stdout 和 stderr 合同。

## 兼容性

`18.2.8` 是 OMP 的最低维护版本，本节是该数值的权威入口。它表达维护承诺，不是安装或运行要求。维护没有上界，版本号也不阻碍使用：安装、加载、注册和诊断路径都不把宿主版本与该下限比较。

这项承诺只覆盖 `tools` 模式随包提供的宿主内代码。`cli` 模式组件不包含这段代码，不承担同一 OMP 版本维护承诺。低于下限的宿主不获得维护承诺，本声明也不表示下限以上的任一版本已经验证。

宿主版本与运行时合同彼此独立，三处版本标记各在不同的位置被声明或核对：

- 组件在嵌入清单中的条目声明运行时兼容范围 `>=0.1,<0.2`，运行时在验证、安装或卸载组件时用自身的版本判定该范围；
- 运行时内嵌的组件束声明 driver 合同版本 `1`，运行时要求该束与自己实现的 driver 合同一致；
- 生成的 native 工具合同声明 `contract_version 3`，适配器要求该取值以及固定的兼容范围 `>=0.1,<0.2`。

适配器通过固定路径上的运行时读取版本文档和 native 工具合同，并比较两者的运行时版本是否相同。它不读取 driver 合同版本，也不计算运行时版本是否落在该范围内。

本 Package 把 `@oh-my-pi/pi-coding-agent` 声明为无限制 peer（`*`）。它只标明适配器导入的宿主包，不是维护范围，也不证明任一宿主版本能够加载或运行本组件。

## 加载与失败行为

在 `tools` 模式，入口在注册第一个操作前完成以下预检：

1. 固定运行时路径存在；
2. 该路径是带有可执行位的普通文件；
3. 运行时版本文档可解析并带有运行时版本；
4. native 工具合同可解析，带有 `contract_version 3`、宿主的 harness 名和固定兼容范围；
5. 合同中的运行时版本与版本文档一致；
6. 六项操作、各自的请求 schema 以及 OMP 专属字段齐备。

任一检查失败时，入口输出一条有界诊断，并以零操作注册的状态加载。它不终止 OMP 会话，也不改用其他运行时。

注册过程中某次调用失败时，适配器停止注册后续操作并报告错误。失败前 OMP 已接受的操作可能保持注册。适配器不承诺回滚。

## 宿主差异

原生入口（`extension.ts`，仅 `tools` 模式）向宿主注册操作并绑定调用上下文：从 OMP 调用上下文读取工作目录与模型标识，并把 OMP 的取消信号传给运行时。它通过宿主公开的加载元数据把 search、read、create、update 和 log 标为 essential，把 exec 标为 discoverable。

共用映射层（`common.ts`，仅 `tools` 模式）执行预检、把逻辑请求映射为运行时参数、不经过 shell 直接启动可执行文件、限制 stdout 与 stderr，并解析统一的 JSON 结果。Pi 组件是另一个独立 Package，有自己的入口，不设置加载模式。

## 验证状态

适配器的自动检查针对桩宿主和桩运行时运行，覆盖预检、参数映射、取消、输出上限、预检失败时零注册，以及上文的注册中途失败行为。它们不能说明真实 OMP 版本如何加载或运行本组件。组件装配检查证明随包文件与组件源码一致，以及运行时版本取值，同样不是宿主行为证据。

真实 OMP 验证在 OMP `18.2.8` 上进行，使用与组件同源构建的 tk 运行时，隔离 HOME 与隔离项目。四种模式与语言组合都完成了安装、加载和卸载。在 `tools` 模式，宿主把六项操作全部列为已注册工具，在调用前拒绝了类型错误的参数，并对项目中的任务实际执行了 search、read、create、update、log 和 exec。

另一次运行在同一份组件源码和由它构建的运行时上覆盖了 OMP `18.4.3`。经 `tk install --harness omp` 安装、加载以及调用路径与 `18.2.8` 一致：宿主在模型工具表中发送 search、read、create、update、log，exec 在显式启用前不出现在该表中；对隔离项目中的任务实际执行了这些调用。适配器从宿主调用上下文取得会话工作目录与调用模型。另注入四类预检失败（运行时缺失、兼容范围不同、合同中的运行时版本不同、schema 命令失败），每次只输出一条有界的 `tk:` 诊断，注册数为零。该次运行之后用同一份载荷复测了 `18.2.8`。真实宿主上的取消行为仍只由上述桩检查覆盖。

更早的 tk 发行版随包提供的是其他版本的适配器，那些安装记录描述的是当时的版本，不是本版本。

## 安装与更新

使用随包携带它的运行时安装和移除组件：

```sh
tk install --harness omp --mode tools --language en
tk uninstall --harness omp
```

`tk install` 只读取执行该命令的可执行文件中内嵌的 payload。拉取更新的仓库内容既不会替换已安装的可执行文件，也不会改变其嵌入载荷，因此更新仓库不会更新已安装的组件。
