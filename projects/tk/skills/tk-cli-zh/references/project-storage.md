# 项目和存储

初始化项目、解释项目发现或 Git 策略、迁移 schema 或切换元数据模式时阅读本文。任务字段和载体见[任务概念](./task-concept.md)。

## 项目标记

tk 从 `--cwd` 或当前工作目录向上寻找项目。满足任一条件的目录都可成为候选项目根：

- 存在 `.agents/tk_config.toml`；
- 存在默认任务根目录 `.tk/`。

非 Git 环境只检查最近的有限层级。Git 工作树内可以继续查找到 Git 根。发现项目后，tk 读取配置并校验实际任务根目录。

完整的绝对任务路径或材料路径可以先定位其所属项目，因此调用方可以从另一个项目的工作目录读取该任务。

## 配置文件

项目配置位于 `.agents/tk_config.toml`。配置是稀疏 TOML，只保存偏离默认值的字段。省略字段采用当前默认值，未知字段直接拒绝。

默认配置等价于：

```toml
task_root = ".tk"
subtasks_dir = ""
git_policy = "none"
creation_policy = "strict"
metadata_mode = "split"
```

全默认项目通常没有配置文件，`.tk/` 本身就是项目标记。

## `task_root`

`task_root` 指定项目根下的任务存储目录。默认值是 `.tk`。

值必须是非空的项目相对路径。绝对路径、`.`、`..` 或包含这些特殊分量的路径都会被拒绝。任务根及其已存在的上级目录不能经过符号链接，也不能解析到项目外部。

示例：

```toml
task_root = "tasks"
```

配置自定义任务根时必须保留配置文件。仅创建 `tasks/` 不足以让项目发现逻辑知道该目录是任务根。

## `subtasks_dir`

`subtasks_dir` 指定在每个父任务下创建子任务时使用的默认相对目录。默认值是空路径，表示直接在父任务目录下创建。

示例：

```toml
subtasks_dir = "children"
```

此时新子任务默认创建到 `<parent>/children/`。该字段只控制创建位置，不限制发现范围。父任务目录下其他位置已有的有效子任务仍应被发现。

空值有效；非空值必须是安全的相对路径，不能包含绝对路径、`.` 或 `..` 分量。

## `git_policy`

`git_policy` 控制写操作前执行的 Git 检查：

|值|行为|
|-|-|
|`track`|要求项目位于 Git 工作树中，任务根不能被忽略；已存在的项目配置也不能被忽略。适合把任务数据纳入版本控制的项目。|
|`ignore`|要求项目位于 Git 工作树中，且任务根必须被 Git 忽略。适合保留本地任务数据的项目。|
|`none`|不要求 Git，也不检查忽略状态。默认值。|

读取命令不执行写入策略检查。创建、更新、日志等写操作会在首次持久化前检查策略。

`track` 只验证路径未被忽略，不等于自动执行 `git add` 或提交。`ignore` 也不会替项目修改 `.gitignore`。

## `creation_policy`

`creation_policy` 控制 Agent 创建顶层任务时需要的授权：

|值|行为|
|-|-|
|`strict`|默认值。Agent 只有在用户明确要求创建任务，或明确确认创建时才能创建。|
|`permissive`|Agent 可以为明显需要跨步骤或跨会话保存状态的工作创建打开任务。用户已经表达的规划意图仍不等于授权创建。|

该策略不改变终端用户直接调用 CLI 的能力，也不允许调用方伪造 `user_confirmed`。创建子任务仍应服从当前父任务和调用入口的授权规则。

## `metadata_mode`

`metadata_mode` 选择整个项目使用的任务元数据载体：

|值|行为|
|-|-|
|`split`|默认值。受管元数据写入 `tk.toml`，正文写入 `TASK.md`。|
|`embed`|受管元数据写入 `TASK.md` 的 YAML frontmatter，正文紧随其后。|

同一项目只使用一种模式。不要手工修改配置值来切换模式；使用 `tk metadata switch`，让运行时转换全部任务载体并最后更新配置。

## 默认初始化

```text
tk init
```

默认初始化按以下顺序执行：

1. 将 `--cwd` 或当前工作目录解析为项目根。
2. 组装默认配置并校验路径。
3. 检查项目是否已存在以及 Git 策略是否满足。
4. 创建 `.tk/`。
5. 发现所有字段都等于默认值，因此不创建 `.agents/tk_config.toml`。

命令只初始化项目，不创建任务。

## 使用自定义配置初始化

```text
tk init \
  --task-root tasks \
  --subtasks-dir children \
  --git-policy track \
  --creation-policy permissive \
  --metadata-mode embed
```

只要最终配置至少有一个值偏离默认值，`init` 就创建 `.agents/tk_config.toml`，并只写入非默认字段。是否显式传参并不决定文件是否存在。例如，显式传入 `--git-policy none` 仍等于默认值，不会单独触发配置文件。

`--cwd` 和 `--output` 是调用参数，不属于项目配置，也不会写入配置文件。

## 已存在项目

未使用 `--force` 时，只要以下任一对象已经存在，初始化就返回 `project_already_initialized`，不写入文件：

- `.agents/tk_config.toml`；
- 本次配置指向的任务根目录。

这条规则也适用于只有空任务根、没有配置文件的默认项目。

## 强制初始化

```text
tk init --force [配置参数]
```

`--force` 使用本次参数和默认值重新计算项目配置。它可以在旧配置无法解析时恢复配置，也可以创建本次指定的任务根。

强制初始化不会读取、迁移、移动、删除或改写已有任务。它也不会把旧配置中未再次提供的非默认值保留下来。未提供的字段恢复默认值。

如果最终配置全部为默认值，`--force` 会删除已有 `.agents/tk_config.toml`，并确保默认 `.tk/` 存在。原先自定义任务根中的数据不会被移动或删除，但新配置也不再指向它。

## 初始化失败边界

路径、模式、策略和 Git 条件在首次持久化前校验。以下情况会在创建任务根或写配置前失败：

- 工作目录不存在或不是目录；
- `task_root` 或 `subtasks_dir` 不是安全相对路径；
- 任务根经过符号链接、落在项目外或已有路径分量不是目录；
- `track` 或 `ignore` 找不到 Git 工作树；
- 任务根的忽略状态不符合 Git 策略；
- 未使用 `--force`，但配置文件或目标任务根已经存在。

## Schema 迁移

schema 迁移只处理当前项目中有效的元数据载体，并只向前执行已发布的逐级转换。省略 `--file` 时选择项目内全部有效载体；显式 `--file` 必须指向当前项目中的有效 `tk.toml` 或 embed `TASK.md`。

迁移不改变元数据模式、任务 ID、状态、时间、关系、正文、目录和 WAL。已处于目标 schema 版本的载体跳过。降级、跳级和未知转换拒绝。

## 元数据模式切换

模式切换作用于整个项目，不支持只切换部分任务：

- `split` 到 `embed`：把元数据写入 `TASK.md` frontmatter，再删除对应 `tk.toml`；
- `embed` 到 `split`：写出 `tk.toml`，并保留 frontmatter 后的正文。

切换不改变字段值、目录、正文语义、WAL 或关系。所有任务预检通过后才开始提交，项目配置最后更新。

schema 迁移在当前元数据模式内升级格式；模式切换负责转换载体并更新项目配置。两项操作彼此独立。

## 多目标失败

迁移和模式切换先完成全量预检，再按确定顺序提交。`--dry-run` 与执行使用同一套规划和校验。

提交阶段失败时，结果会区分 `completed`、`uncompleted` 和原始错误。先运行 `tk check` 确认当前状态，解决阻塞后重新运行完整命令。运行时不自动回滚，也不在进程退出后继续执行。
