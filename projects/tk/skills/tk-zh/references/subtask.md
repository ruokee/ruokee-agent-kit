# 子任务

创建子任务，或处理放置位置、编号、发现、批量失败和重试时阅读本文。

## 创建输入

父任务必须唯一解析，状态只能是 `open` 或 `planning`。创建不会隐式重开 `closed` 父任务。

一次请求只为一个父任务创建 1 到 50 个同级子任务。每项必须有名称，可以有正文、`planning` 或 `open` 状态、历史 `created_at`、关系和 `extra`。批次中的关系只能指向已经存在的任务，不能指向同批次中尚未创建的兄弟任务。

子任务可以嵌套。名称不使用并列关系词；多个独立工作单元应当并列创建。子任务只用于需要独立状态、关系、WAL、正文或材料的工作单元，不用于把普通执行步骤或 backlog 逐项持久化。

## 配置目录

`subtasks_dir` 指定每个父任务下子任务使用的规范相对目录。默认值是空路径：

```text
<parent>/NN--slug/
```

配置非空时：

```text
<parent>/<subtasks_dir>/NN--slug/
```

例如，`subtasks_dir = "children"` 时，新任务创建到 `<parent>/children/NN--slug/`。

`subtasks_dir` 必须是安全相对路径。空值表示父目录本身；非空值不能包含绝对路径、`.`、`..`、符号链接或父目录逃逸。

直接子任务使用 `01..99`。运行时检查配置目录中的有效直接子任务，取最大 `NN--slug` 编号加一，不填补空洞。一个批次分配连续编号；序号 `99` 已占用时在首次写入前失败。

## 发现子任务

发现遵循配置的规范拓扑。对每个父任务，运行时只检查其 `subtasks_dir` 指定目录下名称有效的 `NN--slug` 直接普通目录。

该位置中的目录只有具备项目元数据模式要求的有效载体时才成为任务：

- `split` 模式要求有效且配对的 `tk.toml` 和 `TASK.md`；
- `embed` 模式要求 `TASK.md` 以有效的 tk YAML frontmatter 开头。

修改 `subtasks_dir` 会同时改变后续创建位置和发现范围，但不会移动已有任务目录。配置路径之外的已有子任务无法发现。

发现一个子任务后，运行时在其下递归应用相同规则。除配置的 `subtasks_dir` 路径外，普通材料目录不能位于可发现的父子任务之间。符号链接、特殊文件和非规范目录名不参与发现。

规范父任务是其配置子任务目录直接包含该子任务的任务。目录拓扑只表达父子关系，不自动创建依赖或关联，也不继承状态。

## 批量创建

运行时在首次写入前校验全部条目、父任务、授权、关系和目标路径，再按输入顺序创建。

字段或预检失败时不创建任何新任务。写入期间发生 I/O 错误或取消时可能部分提交。结果会区分 `completed` 和 `uncompleted`。调用方应重新读取父任务和当前子任务，再根据现状发起新的完整请求。

相同请求重试时，已经存在且内容匹配的直接子任务视为已满足，只为剩余条目分配新编号。名称相似但内容不同不算匹配。不要假定自动回滚或续跑令牌。
