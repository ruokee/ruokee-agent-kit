# Task 概念

## Task 边界

Task 是值得保存的临时项目工作。创建 Task 并不表示承诺执行或完成它。

当持久状态有助于工作跨越多个步骤、会话、Agent 或上下文压缩继续存在时，使用 Task。不要将 tk 用于快速回答、临时清单、优先级、日程、看板、外部 Issue、Agent 编排或会话绑定。

## 身份与位置

UUIDv7 是权威身份标识。名称用于描述 Task。路径用于定位 Task，并且可能在 rename 时发生变化。

顶层 Task 位于配置的 Task 根目录下。子目录拓扑表示父子关系。元数据不存储 `parent` 字段。

精确引用包括完整的 UUIDv7 值、绝对 Task 目录、绝对规范载体路径或项目相对 Task 路径。名称、前缀、文本、分支和材料路径都需要通过 search 查找。

## 元数据

当前 schema 1 仅包含：

- `schema_version`；
- 不可变的 `id` 和 `created_at`；
- 规范化的 `name`；
- `status`，值为 `planning`、`open` 或 `closed`；
- 同一 Task 根目录内的 UUID 集合 `depends_on` 和 `related_to`；
- 可选的 `extra`，且必须能够无损表示。

它不存储分支、父级、更新时间、关闭原因、会话、优先级、分配信息或安装状态。

split 项目将元数据存储在 `tk.toml` 中，将正文文本存储在 `TASK.md` 中。embed 项目将元数据存储在受限的 YAML frontmatter 中，并原样保留其下方正文的字节内容。

## `TASK.md`

在 `TASK.md` 中保留当前事实和重要入口：

- 目标；
- 范围和约束；
- 稳定的决策；
- 重要材料链接；
- 仍然适用的阻塞项。

将详细研究、设计、评审记录、验证证据和临时笔记放在普通文件中。运行时不会索引这些材料。

你可以编辑正文和普通材料。受管元数据必须通过 tk 操作修改。只有在 `tk.toml` 损坏时才可例外直接编辑，并且必须提供精确的拟议修改、获得用户当前授权、运行 `tk check`，并在之后写入一条 WAL 记录。
