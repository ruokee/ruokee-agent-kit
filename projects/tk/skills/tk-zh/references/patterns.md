# 使用模式

以下模式说明如何组织任务目录中的普通材料。它们不是 tk 的受管格式，也不增加元数据、schema 字段、`extra` 约定、运行时状态、命令或自动目录生成机制。应按实际工作创建文件，不要为了匹配示例预建空目录或占位文档。

## 采用与共通维护

一个 Task 可以组合采用以下任意模式，也可以都不采用。主动建议某种模式前，先确认相应信号已经出现，并说明它会增加哪些材料、以后需要维护什么。用户采用后，在 `TASK.md` 正文中简要声明，并链接已有的入口材料。用户明确要求采用某种模式时，该请求本身就是采用授权，不必再次确认。

采用模式不等于获得创建 Task 或改变其生命周期的授权。普通材料的日常创建和编辑沿用既有权限。删除或移动材料须遵守适用授权规则，覆盖归属或含义不明的材料同样如此；采用模式不会授予清理权限。

以下默认路径是一般的组织方式，项目规则和已有的材料结构可以覆盖它们。不要补造过去的活动，不要创建日期在未来的记录，也不要为了匹配示例迁移已有 Task。

`TASK.md` 保存当前事实、当前决定和重要入口。普通材料保存可复用的详细内容。WAL 即 Work Activity Log，通过 tk 追加简洁的持久事件摘要。三者通过链接配合，不要整篇互相复制。正式决定遵守项目指定的机制和位置。

## 记录

实质调查、实施、验证或决策活动已经发生在第二个本地自然日时，可以建议记录模式。同日任务，或只是计划以后继续而没有新的活动，不满足该信号。

默认材料：`records/YYYY-MM-DD-topic.md`，文件名包含本地日期和主题。

每份记录保存当时的背景、采取的动作、证据入口和当时结论。只为确有活动的日期维护记录，没有活动的日期不开页。先前判断按当时的写法保留，后续更正写入后续材料，`TASK.md` 指向仍然适用的结论。

记录可以链接稳定设计、参考资料和来源，这些内容各自保存在自己的材料文件中。记录不替代 WAL，也不替代正式决策记录。

## 深度调研

工作要求收集、保存或交叉核验外部来源，或已经存在来源清单和来源材料时，可以建议深度调研模式。只读一个已知文档或回答普通 API 用法问题，不满足该信号。

默认材料：

- `research/report.md` 保存结论；
- `research/README.md` 导航已有的调研材料。

调研计划、来源地图、主张核验或其他支撑材料按实际需要增加。只有 Task 专属来源需要本地留存时才创建 `research/sources/`，不要预建空的来源目录。

持续维护来源来历与访问日期、关键主张对应的证据、来源之间的冲突、仍未核验的部分，以及结论适用的边界。只有来源列表不足以说明证据支持了什么，未核验的推断要与事实保持区分。`TASK.md` 提供报告的直接入口。

## 迭代设计

出现两次以上相互替代的大幅改版、旧方案被整体推倒，或主要边界持续变化时，可以建议迭代设计模式。增量补充、措辞调整和普通评审修正不需要新版本。

默认材料：`revision_<N>/`，每个大幅改版对应一个自包含目录。其 `README.md` 说明背景、目标、主要方案和材料入口。

只有新的大幅改版才创建下一轮；普通问题通过编辑当前版本修正。被替代的版本保留当时状态。`TASK.md` 只把当前版本作为设计入口。需要解释取代关系时，把说明放在新版本中，不要改写旧设计来抹去先前的判断。

## 草稿纸

尚未整理的片段、笔记、命令输出、小脚本或其他临时文件需要持久保存时，可以建议草稿纸。无需留存的简短问答，或已经属于某份普通材料的结论，不满足该信号。

默认材料：`scratchpad/`，其中可以放任意文件和子目录，不强制文件名、格式或层级。

有价值的内容稳定后，整理到合适的普通材料，`TASK.md` 只保留必要的当前结论和入口。失效内容要与当前事实保持可区分，不要让旧推测读起来像当前事实。删除或移动草稿纸内容遵守适用授权规则。

## 材料入口

普通材料可以采用任意格式和目录结构，但重要入口应从 `TASK.md` 链接。链接文字说明材料内容，不要只写“详见这里”。

例如，入口名称与 `TASK.md` 链接的相对目标如下：

| 入口 | 相对 `TASK.md` 的目标 |
| --- | --- |
| 记录 | `./records/2026-09-11-usage-patterns.md` |
| 调研报告 | `./research/report.md` |
| 当前设计 | `./revision_2/README.md` |
| 草稿笔记 | `./scratchpad/probe-notes.md` |

在 `TASK.md` 中以相对 Markdown 链接指向这些目标。
