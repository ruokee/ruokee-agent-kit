# 工作活动日志

## 目的

WAL 是普通的仅追加 Markdown 活动日志。它记录不属于 Task 当前状态的持久事件。它不是事务日志、锁、重复检测器、授权记录或领域恢复系统。

每个 Task 在 `wal/YYYY-MM-DD.md` 下存储每日文件，其中的条目格式如下：

```markdown
## 2026-08-31T12:34:56+08:00 · actor

消息

可选正文
```

只有完整的 RFC 3339 时间戳、分隔符和 actor 行才能开始一个条目。普通 H2 文本属于前一个条目的正文。对于恰好形似完整条目标题的正文文本，此格式没有转义机制或长度前缀。

## 记录内容

事实持久化后应立即记录，并在开始另一个独立分支之前完成：

- 用户的决定和更正；
- 已验证的发现；
- 可恢复的里程碑；
- 验证结果；
- 已验证的协作结果；
- 会影响后续工作能否继续的阻塞项。

不要记录常规 read、命令记录、临时待办事项、百分比、未经验证的猜测，或已由运行时记录的生命周期事件。

消息必须是非空单行文本。详细信息写入 Markdown 正文。不同时刻形成的事实应分别写入不同条目。

## actor

actor 是单行署名，不代表身份、认证、授权或分派。只有 update、log 和 rename 请求接受该字段。优先使用最具体的可用模型值或 Harness 值。

## 失败处理

元数据会在自动追加 WAL 之前提交。如果追加失败，元数据仍保持已提交状态，结果中会包含警告。

重试前先 read Task 和 WAL。仅追加缺失的事件。不要重复执行元数据 update。已 closed 的 Task 拒绝新的 WAL 条目。

详细 read 同时受条目预算和字节预算限制。应将截断视为 read 边界，而不是把旧历史复制到 `TASK.md` 的理由。
