# omp-context-pin

[English](./README.md)

让固定条目的正文出现在该会话分支后续每一次普通模型请求中。条目以 `#<id>` 显示，其编号是限定在单个会话内的正整数。Agent 写入通过宿主显式的非主动交付模式到达模型，不启动模型轮次；用户确认的写入是一条普通用户消息，只包含草稿正文。压缩不会结束固定：提交后的压缩会从扩展自身的日志记录中重建正文。

## 用法

用户入口是 `/ctx-pin` 命令。

- `/ctx-pin` 打开当前分支的条目列表：新增项在最前，条目按创建顺序排列，关闭项在最后。每行显示条目的 `#<id>` 和正文开头，因此不需要存储标签。
- `/ctx-pin add <正文>` 直接固定 `add` 之后、隔一个空格开始的文本，不打开对话框。该空格之后的正文逐字保留：不做 shell 式分词、引号解析、转义还原或空白规整。
- 未知子命令或缺少正文时只给出简短用法提示，不发送任何消息。本版本不提供内联的查看、编辑和删除。

列表、查看正文和编辑草稿都是只读操作：不发送消息、不改变 Pin 状态，也不中断正在执行的轮次，放弃编辑不留任何痕迹。确认写入后会关闭列表。

列表使用宿主自带的选项组件绘制，因此跟随会话主题并按实际绘制宽度取宽。每行显示条目的 `#<id>` 与正文，连续空白折叠为一个空格，按该行可用宽度截断，正文未显示完时追加省略号；没有可见字符的正文只显示 id。

### 确认的写入

确认的写入通过宿主公开的消息接口作为一条普通用户消息提交，消息只包含草稿正文：

```
<正文逐字保留>
```

扩展按文本识别这条消息，因为它写出的文本就是本进程交出的文本。一次提交由一条消息认领，且只在本进程仍持有该副本期间有效：这次写入由消息本身承载，写入结清后该文本重新成为普通文本。与仍被本会话持有的草稿文本重复的文本可能被读作该草稿，这是用户可读、可编辑的消息所付出的代价。

宿主消费这条消息，且针对本进程记录的那次提交校验通过后，操作才生效：消息文本必须正是本进程交出的文本，当前会话、固定周期与分支正是草稿写入时的那些，被操作的条目存在，revision 仍与草稿打开时一致。文本是用户看得到的内容，因此被编辑过的消息、被引用的草稿、其他进程提交的消息，以及宿主恢复回来的消息，都按普通文本处理。在此之前命令只报告该写入处于待处理状态。

被接受的集合只在此刻变化，消费该消息的那次请求会把结果直接放在承载该操作的消息之后：已接受、无变化，或未应用及原因，并标明改变的条目。同一操作可能以另一个原因再次给出结果，每条结果只上报一次；会话或分支变化会让扩展忘记已经上报的内容，所以请求读不到这条结果时，扩展会再次上报它。结果不重复正文，也不自行启动轮次，更不增加持久化保证。同一份文本在上报操作时以宿主的非主动模式交给宿主，由宿主留到之后某一轮追加到分支且不因此启动轮次，用户看到的也是同一份文本。扩展会把这个结果写在承载对应操作的消息之后，并在宿主已经把副本记到分支更后面时仍保持该位置：每一次请求读到的都是这一份结果，位置与字节不变；会话或分支发生变化时，请求携带的内容随之结束。宿主始终不记录结果时，扩展最多保留 16 条待写结果，超出时先放弃最旧的。

一次操作只被应用一次。应用一次提交的是宿主真正运行的那条消息：提交会记录确认时会话已有的消息数，此后第一条文本相符的消息认领它；与更早历史重复的文本不会被读成操作，始终没有运行过的提交在新区段出现对不上任何待处理提交的消息时被放弃。承载它的消息留在分支中，但之后的请求不再把它读成操作，因此不会追加第二条，也不会重复报告同一结果。终态一旦给出，该操作对本进程就不再是操作：任何原因导致的拒绝都会保持，例如会话、分支、revision 或容量不符，用户在切回该分支或释放容量后仍保持被拒绝。无法读取范围而未给出结论的操作不是终态，等之后的请求能读取该范围时再应用。

宿主会在自己的时机把这条用户消息记入分支。在那之前，携带它的请求是这次写入唯一的表达位置，因此扩展既不会把正文再写一遍进该请求，也不会为它排队一条变更消息。

Agent 入口是 `ctx_pin` 工具的五个动作：

| 动作 | 输入 | 效果 |
| --- | --- | --- |
| `list` | 无 | 每个条目的 id、来源、revision 与大小，不含正文 |
| `get` | `id` | 返回一段完整正文及其 id、来源、revision 和 UTF-8 字节数 |
| `create` | `content` | 固定一段新正文 |
| `update` | `id`、`content`、`expectedRevision` | 替换正文 |
| `delete` | `id`、`expectedRevision` | 取消固定 |

`id` 参数取列表和回执上显示的整数，不接受数字字符串，也没有任何动作会隐式插入或通过改名创建。

通过 `/ctx-pin` 写入的来源记为 `user`，通过 `ctx_pin` 写入的来源记为 `agent`。`list` 和 `get` 报告条目创建时记下的来源，`update` 保持该来源。

工具的每个动作都声明最低审批档位 `read`。没有显式单工具策略时，`always-ask`、`write` 和 `yolo` 都不会为 Pin 操作弹出确认；用户显式把 `ctx_pin` 标为 `prompt` 或 `deny` 仍然生效。扩展不写入任何用户配置，也不自行增加授权或确认。类型、存在性、revision、容量与记录完整性校验保留：它们让操作作用于它原本指向的数据。

Agent 的 `create`、`update` 和 `delete` 会追加操作记录，并以同样的非主动模式交给宿主一条面向模型的变更消息，不额外启动轮次。记录是权威状态，变更消息是投影：当日志仍未显示它已发布时，会话或固定周期变化后会重发。请求按日志顺序表达已接受的变更，因此请求未携带的某条变更会让它之后的变更同属一个缺口：这些变更按顺序重新写入，原来承载它们的消息离开请求。重新写入的变更在请求持有对应工具调用时直接读在该调用结果之后，否则保持日志给它的位置，即排在承载更晚变更的那条消息之前；两者都不满足时放到末尾。这样更旧的正文不会最后读到，用户自己发送的消息保持原位。

扩展固定的是用户或 Agent 提供的文本。它不读取文件、不抓取 URL、不监视内容变化，也不会在没有操作的情况下改变条目。

空正文会被拒绝，被接受的正文逐字保留所有字符与空白。

## 记录与 revision

会话日志中的操作记录是权威状态。每条记录是自定义类型为 `omp-context-pin` 的一条日志条目，载荷如下：

| 字段 | 取值 |
| --- | --- |
| `schemaVersion` | `2`，本组件读写的载荷版本 |
| `operationId` | 一次用户提交或一次 Agent 写入调用的正整数，其重试沿用该编号；仅供内部使用，任何消息、列表或结果都不显示它 |
| `action` | `create`、`update` 或 `delete` |
| `entryId` | 创建时分配的正整数，在该会话中永不复用 |
| `revision` | 从 1 开始，每次被接受的 `update` 或 `delete` 加一 |
| `body` | `create` 与 `update` 的完整新正文，`delete` 没有正文 |
| `source` | `user` 或 `agent` |
| `toolCallId` | 产生该记录的 Agent 调用的宿主工具调用 id，用于解析其重试 |

`list`、`get`、被拒绝的写入和没有实际变化的写入都不追加记录。

变更消息使用自定义类型 `omp-context-pin-change`。每次读取都会重放当前分支的记录，因此重建的上下文、丢失的变更消息或仍然保留日志的重启都会得到同一状态。请求只携带当前分支自身的变更：一份副本若指向本分支从未接受过的操作，即使它指名的条目仍在、revision 也正好与本分支某次接受的相同，它也会被移除，因为同一会话的两条路径可以带着不同正文走到同一个 revision；本分支接受过的变更副本则保留。

用户确认的写入由用户发出的那条消息承载，因此不会为它再发送变更消息：扩展把该消息算作已展示这次写入，正文只会到达模型一次。写入结果是自定义类型 `omp-context-pin-result` 的消息，只标明该写入改变的条目、不持有任何 Pin 状态，重放会忽略它；宿主以同样的非主动模式把它留到之后某一轮，因此追加到分支时不启动轮次。扩展会把这个结果写在承载对应操作的消息之后，并在宿主已经把副本记到分支更后面时仍保持该位置：每一次请求读到的都是这一份结果，位置与字节不变；会话或分支发生变化时，请求携带的内容随之结束。宿主始终不记录结果时，扩展最多保留 16 条待写结果，超出时先放弃最旧的。

### 编号

条目 id 是限定在单个会话内的正整数，会话在需要指名条目时一律显示为 `#<id>`，且只向前推进。写入所依据的内部身份同样只向前推进。

- 条目 id 在该条目首次成功创建时分配，会话内永不复用，取消固定之后也不复用。
- 操作编号按每次用户提交、每次新的 Agent 写入调用分配。该提交或调用的重试沿用同一编号，因此重复调用或重复提交不会固定两次；编号之间允许出现空缺。
- 宿主的工具调用 id 始终是内部幂等键：模型既不生成、不填写也不解释它。Agent 重试时先校验调用内容一致，再通过该 id 从已持久化的记录中找到被接受的操作编号。
- 编号通过宿主公开的会话条目在整个会话范围内恢复，其中也包括本进程尚未消费的提交所预留的编号，以及宿主已持有的载体和结果所占用的编号。该扫描只分配编号，绝不把其他分支的正文、回执或操作应用到当前分支。
- 超出安全整数范围的编号，或无法可靠建立的分配状态，都会作为显式错误上报，而不是回绕或从 1 重新开始。宿主无法列出会话条目时，按宿主未提供该能力上报，并拒绝这次写入。

`schemaVersion` 为 `2`，身份为整数。更早的 `0.4.x` 候选写下的记录使用字符串身份；活动范围中出现这类记录时按不支持的格式上报，而不是与整数混用，切换是干净的：不会迁移旧记录，用户新开会话或重置范围即可。

在同一 revision 下重放相同 `operationId` 的记录是空操作。同一身份携带其他内容时按损坏处理，而不是当作重试。

## 重置

重置边界会结束该分支的固定周期：

- 成功执行 `/clear` 会开始新周期，上一周期的条目不再生效。它不会降低编号：条目 id 与操作编号从会话原处继续。
- `/new` 开始一个独立会话，拥有自己的条目与编号。
- `/fresh` 轮换 provider 流状态并保留本地历史，因此固定仍然生效。
- 切换分支或使用 `/tree` 会重放变为当前分支的那个周期的状态。

被重置淘汰的身份保持淘汰：重置前创建的条目不会在之后恢复，重置前操作的重试由账本给出答复，而不会追加第二条记录。

提交后的压缩边界会把当时的活跃正文冻结为一份快照。该分支带有对应宿主摘要时，快照放在摘要之后；没有对应摘要时，放在请求中最后一条摘要消息之后；请求没有任何摘要时，放在请求开头。没有产生新边界的压缩会保留上一份快照。扩展只移除自己写的变更消息，因此宿主在摘要旁边保留下来的用户消息可能与快照携带同一份正文。

当某条记录无法读取，或存储的值不符合本组件写入的版本时，该范围不再可用：扩展不再发送快照与新的变更，写入也会被拒绝并给出原因。一次会话中第一次遇到该情况的请求会报告一次，即在宿主日志中给出一条警告，宿主带有界面时再通过扩展界面给出一条提示；范围与原因相同的后续请求不再重复。记录本身保持原样，不会被修复或丢弃。

活跃集合是最新重置边界之后的范围，损坏也在这个范围内判定。重置已经替换掉的周期里出现的损坏记录不会阻断当前范围。该记录之前读到的身份仍然有效，那里创建的条目保持退役，那里接受过的操作也能答复重试；它之后的身份不再可知，因此重复其中某个身份会被当作新的调用。当前范围内部的损坏会按上面的方式停止该范围。

## 上限

单条正文不超过 16,384 UTF-8 字节，同一分支的活跃正文合计不超过 65,536 UTF-8 字节。超过任一上限的写入不改变任何内容，拒绝信息会给出上限、当前用量以及该操作会达到的大小。

## 持久化

固定正文存放在宿主的会话日志中。扩展只能向该日志追加记录并从中读取；它无法创建会话文件，也无法刷新该文件。宿主已经落盘的会话在进程之间保留固定正文。在核对的宿主中，已有调用方要求写入、文件本身已在盘上，或会话已有一条 assistant 回复时，宿主会写出该会话文件；在此之前记录的固定正文可能在进程退出后丢失；宿主始终不落盘的会话只在进程存活期间保留。`/ctx-pin` 对话框在打开时会说明该限制，工具描述也带有同样的说明。用户确认的写入在宿主消费该消息时才生效，因此宿主始终没有执行那条消息时，Pin 保持不变。若在写入被应用之前发生会话启动、切换或关闭，这次写入会被丢弃；宿主带有界面时，扩展会以一条提示报告这次丢弃，宿主开始关闭后该提示可能不再显示。

## 缓存行为

- 读取和没有实际变化的更新不会改动权威记录和已经发布的投影。它们对应的普通工具调用与结果仍可能延长宿主历史。
- 被接受的写入出现在尾部：Agent 写入是扩展的投影，用户写入是用户提交的那条消息。已经发布的消息保持原有位置。
- 基础快照只在提交后的压缩边界变化，此时宿主已经重建过历史。
- 工具定义、工具列表与 schema 都与当前固定集合无关；除指定的压缩折叠与过期队列过滤外，扩展不改写更早的 system、tool 或历史内容。

## 兼容性

`package.json` 中声明 peer 范围为 `>=18.1.8 <19`。自动化类型检查和测试套件针对宿主版本 `18.2.8` 运行；本组件的交互式实机运行使用 `18.1.16`。该范围只是元数据：它不构成运行时检查，也不代表范围内每个版本都被支持。注册任何内容之前，每次激活都会检查宿主的公开版本与 API 表面，包括确认写入所用的用户消息接口、恢复编号所用的会话条目，以及工具使用的 schema 构造器。发现问题时不会注册任何内容；宿主提供可用日志时会记录一条有界警告说明问题，没有可用日志时只能不注册且无法上报。宿主恢复回来的消息不会被读成操作：只有本进程记录过的提交才会被应用。

## 安装

克隆 GitHub 仓库，安装其锁定依赖，再把包安装到 OMP：

```bash
git clone https://github.com/ruokee/ruokee-agent-kit.git
cd ruokee-agent-kit/projects/omp-context-pin
bun install --frozen-lockfile
omp install "$(pwd)" --scope user
```

`omp install` 是 `omp plugin install` 的别名，`omp plugin link "$(pwd)" --scope user` 注册同一个目录。OMP 会读取 `package.json` 中的 `omp.extensions` 并加载 `src/extension.ts`，不需要手动设置扩展路径。

### 更新

注册指向这个检出目录，安装会一直从该目录读取包及其依赖。请在仓库根目录更新：

```bash
cd /path/to/ruokee-agent-kit
git pull
cd projects/omp-context-pin
bun install --frozen-lockfile
```

之后重启 OMP：运行中的进程会继续使用启动时加载的扩展代码，在同一进程中新建会话不会重新加载。固定正文存放在宿主的会话日志中而非这个检出目录，更新既不会改变也不会清除它们。
