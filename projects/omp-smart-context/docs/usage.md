# Compaction usage

## Native behavior

The source baseline below describes the host gap this module compensates for. Activation checks the actual host capability; version numbers alone do not enable compensation.

OMP sends its own summarization requests when a session compacts: the `soft` method's summary, short-summary, and turn-prefix calls and the `handoff` method's request, each with its own oneshot kind ([`compaction.ts:1012`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/agent/src/compaction/compaction.ts#L1012), [`compaction.ts:1226`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/agent/src/compaction/compaction.ts#L1226), [`compaction.ts:2098`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/agent/src/compaction/compaction.ts#L2098), [`compaction.ts:1112`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/agent/src/compaction/compaction.ts#L1112)). Each one reports the provider's tokens and per-component cost on the telemetry channel's chat-usage event ([`telemetry.ts:1489`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/agent/src/telemetry.ts#L1489)), and each is only a request: the answer is what the method needs, and its billing is not part of it.

The channel is off in a default installation. The wrapper starts a span only when the agent carries a telemetry configuration ([`telemetry.ts:492`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/agent/src/telemetry.ts#L492)), and the compaction and handoff sites resolve that configuration from the agent before each call ([`session-maintenance.ts:3410`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/session/session-maintenance.ts#L3410), [`session-maintenance.ts:4819`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/session/session-maintenance.ts#L4819), [`session-handoff.ts:182`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/session/session-handoff.ts#L182)). Without one, no span is created and no usage event is emitted, so the provider's numbers stay with the request and are dropped when it returns.

The journal has a place for them: a `model_usage` entry ([`session-entries.ts:82`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/session/session-entries.ts#L82)) written through the session manager's own API ([`session-manager.ts:3283`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/session/session-manager.ts#L3283)), and the session statistics add every such entry on the active branch to their totals ([`session-stats.ts:75`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/session/session-stats.ts#L75), [`session-stats.ts:173`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/session/session-stats.ts#L173)). The judge writes its own side requests that way ([`judgment/index.ts:113`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/judgment/index.ts#L113), [`judgment/index.ts:121`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/coding-agent/src/judgment/index.ts#L121)). Compaction and handoff requests do not, so a session file understates what the session cost by the number of compactions it performed, and every report or budget view built on those statistics is wrong by that amount.

Upstream tracks the gap as [issue #15031](https://github.com/can1357/oh-my-pi/issues/15031) and fixes it in [pull request #15034](https://github.com/can1357/oh-my-pi/pull/15034). Until such a host is released, this adjustment supplies the step the host skips.

## Motivation

The provider bills these requests, and the session that caused them does not show it. The size of the gap follows the session: a long conversation that compacts repeatedly pays for a summarization request each time, and a handoff request carries the whole retained history.

## Integration

The adjustment replaces the `telemetry` accessor on the host's `Agent` prototype, which is the value the compaction and handoff sites read.

- With no configuration in place, it answers with an inert one: a tracer that creates the spans the host would create, records the attributes this module reads, and exports nothing. A span carries no content, and the host's own `isRecording` answer for it is `false`.
- With a configuration in place, it keeps every field the user set, wraps the tracer the host would use, and calls the user's `costEstimator` and `onChatUsage` with what it received. The user's tracer keeps receiving its own calls and its own `this`; the wrapper forwards every span method it knows and adds nothing to an export. A configuration that already carries these wrappers is unwrapped first: the host hands a child agent a shallow copy of the configuration it read from the parent ([`sdk.ts:2385`](https://github.com/can1357/oh-my-pi/blob/3e3c488a58d294e3a10051da588628e2cfb9d35c/packages/coding-agent/src/sdk.ts#L2385), [`task/executor.ts:4252`](https://github.com/can1357/oh-my-pi/blob/3e3c488a58d294e3a10051da588628e2cfb9d35c/packages/coding-agent/src/task/executor.ts#L4252)), so wrapping that copy as it stands would chain the module inside its own wrapper and process every host callback twice.
- A request is identified by the oneshot kind the host stamps on the span of that request alone ([`telemetry.ts:153`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/agent/src/telemetry.ts#L153), [`telemetry.ts:1853`](https://github.com/can1357/oh-my-pi/blob/9348320cc4a30a7195d36a1f05a6c11bcb701a17/packages/agent/src/telemetry.ts#L1853)); the span's other attributes are not read, and nothing reaches into the request, the model, the cache key, the history, or the session file.
- Four kinds are in scope: the three `soft` summarization kinds and `handoff`. They map to the purposes `compaction:summary`, `compaction:short-summary`, `compaction:turn-prefix`, and `compaction:handoff`, which are the purposes the upstream fix resolves. The list is closed: `compaction_native` and `branch_summary` are requests of the same family that the fix does not record either, and every other kind the host labels belongs to a caller whose usage the host already accounts for.
- One completed request becomes one usage entry, written through `appendModelUsage` with the resolved purpose, the api, provider, and model that ran, the provider's token counts, the provider's per-component cost when the host carries it, a stop reason read from the request's own span attributes, and the branch position of the live session. The request's identity is a provider together with a model id, resolved through the session's model registry. The event names the provider as a telemetry label, which is a normalized name several provider ids map onto (`openai-codex` reports as `openai` by default, and a host may install any mapping), so a label is not an identity on its own: the provider id the estimator path reports before that normalization resolves the request when the host reports one, and otherwise the request is resolved only when the session's catalog offers its model id under exactly one provider. The provider written is that resolved provider id, never the label. A resolution that names another provider, that picks one of two providers serving the same model id, or that would take a label matching a registered provider as the request's own, is not a resolution: the api and provider of a different model are never written in its place, and the request stays unrecorded instead.
- The patch is process-wide and held in one registry slot. One installer owns it: a later activation, of this runtime or another, registers its own session with the installed patch and installs no second one, so an event reaches the journal of the session the request belonged to rather than the session that happened to install the patch.
- The session is found by the event's conversation id, or by the session the agent instance belongs to when the event carries none. A request without a live session, or without an identity its registry can name, is not written.
- A session that switches journals keeps its place in the patch: `/new`, `/resume`, and a fork keep the session manager and move it to another session id, so the module follows `session_switch` and re-registers the manager under its current id. The id it left is dropped with it, so a request that still names the old conversation finds no session instead of writing into the new one.
- An activation whose settings could not be read or were rejected stops a patch another activation installed, and installs nothing itself. A patch that stopped keeps its reason: `/smart-context` reads the live registry, so a stopped patch is reported in every session of the process rather than only in the session that saw it stop.
- A host that records these requests itself exports `compactionRequestUsage` from `@oh-my-pi/pi-agent-core`, which is the symbol the released fix adds. The adjustment reads that symbol when it activates, and stays inactive with `host-records-usage` on such a host, so the next OMP release that carries the fix stops the compensation instead of doubling its entries.

## Settings

`compactionUsageEnabled` defaults to `true` and accepts a boolean. It has no master switch. An invalid value disables this module and leaves the others alone; an unknown key or invalid settings root rejects the component configuration. Restart OMP to apply a change.

## Side effects

- The patch is process-wide. Every agent in the process reads the configuration it supplies, which is the user's own configuration extended by the module's hooks, so the user's tracer, hooks, and export continue to serve every span they already served. A child session's configuration is a copy of the one its parent read, and the module's own wrappers are unwrapped before that agent's configuration is wrapped again, so one host callback reaches the module once however many sessions inherit from one another.
- With no telemetry configured, the compensation makes the host create and run the instrumented wrapper for its compaction and handoff requests where it previously short-circuited. The wrapper's own work, not the export, is the cost: the inert tracer exports nothing, and the module adds no content attribute, no span link, and no event of its own.
- Only the `telemetry` accessor is replaced, and only on the host's `Agent` prototype. The host's `setTelemetry` path, the private field the main turn reads, and every other class member are left as they are, so ordinary turns keep the behavior they had, including a turn on a host that configured telemetry.
- A refused install restores the accessor it replaced. An activation whose own switches ask for the compensation off releases the accessor it finds in the process, an activation that cannot read its settings releases a patch another runtime installed, and an extension that replaces the installed accessor makes the module release it as replaced.

## Cancellation

- Cancellation of the adjustment: set `compactionUsageEnabled` to `false` and restart OMP, or restart without the extension. Nothing is written to disk and nothing survives the process; the entries already written stay in the sessions they belong to, as extra `model_usage` entries with a `compaction:` purpose.

## Limits

- Only the four purposes above are written. A native compaction, a branch summary, an evaluation completion, a skill description, and an image question keep their usage where it was.
- An attempt that consumed no token, such as a cancelled or failed request whose snapshot is all zeros, writes nothing. An attempt that was billed despite an error status is written when it reports tokens.
- A request whose api cannot be resolved is not written, and is counted in `/smart-context` as `unrecorded=api-unresolved` instead of being given a guessed api. A resolution that names another provider, or that prefers one of two providers serving the same model id, is not a resolution: a wrong api would make the statistics read as repaired. The same holds for a request whose session is no longer registered.
- The provider's per-component cost comes from the estimator path, which the host started to carry with `a3cdfbdd58` ([2026-10-01](https://github.com/can1357/oh-my-pi/commit/a3cdfbdd58b6647e216bc5dd3d7df8519f74de9a), "fixed telemetry to export provider-computed chat cost"). On a host without it, an entry is written with a zero cost and counted as `costMissing`; the module never estimates a price of its own.
- The entry carries the purpose, api, provider, and model that ran, and the usage and stop reason the request reported. It does not carry the request's content, the summary, the handoff document, or the model role, and the module stores nothing of its own.
- The module depends on the host's `Agent` prototype carrying a readable `telemetry` accessor, on the session manager accepting usage entries, on the chat-usage event carrying the request's own span, and on the oneshot kind being readable from that span. A host that stops stamping the kind, that hands the event a span this module did not see, or that stops answering reads through the accessor, makes the adjustment write nothing or stay inactive; it does not make it write a wrong entry, except for the branch position explained next.
- Usage attributed to the wrong branch would stay invisible to the statistics it was meant to correct. The entry follows the branch that is current when the request completes, which is the branch the compaction belonged to, because the compaction runs on that branch and blocks it until it finishes.
- Known limit of the compensation: an attempt that was retried away inside the host's own wrapper is not recoverable from the event the module reads. The module reads the span the event names, and the host's retry runs inside that request.

## Historical verification

These observations were recorded for the QoL implementation before its move to `omp-smart-context`. The `/qol` commands, versions, conditions, and limits below retain that historical scope. Current package checks are described in [Verification](./verification.md).

- **Source baseline**: OMP `18.5.0` at `9348320cc4a30a7195d36a1f05a6c11bcb701a17` for the telemetry channel, the oneshot kinds, the compaction and handoff sites, the usage-entry API, and the statistics reader; the provider-computed cost field was read at the installed `18.8.3` ([`a3cdfbdd58`](https://github.com/can1357/oh-my-pi/commit/a3cdfbdd58b6647e216bc5dd3d7df8519f74de9a)). Sources listed above.
- **Retirement surface**: [pull request #15034](https://github.com/can1357/oh-my-pi/pull/15034) records these requests in the host itself and exports `compactionRequestUsage` from `@oh-my-pi/pi-agent-core` for that purpose; the adjustment reads that export.
- **Automated checks**: OMP `18.5.0`, `bun test` and `tsc --noEmit`, with a recording host in place of the installed one. They cover the purpose table, the zero-token and non-compaction skips, the cost claim and its single use, the refusal set (no accessor, no usage writer, an unknown registry layout, a replaced accessor, an install the runtime did not take, a host that records the requests itself), preservation of a user tracer and of the user's own hooks, the inert tracer, a configuration inherited from a parent session once and twice, and an inherited configuration whose catalog serves its model id under two providers, the registry's accessor-identity contract, the identity resolution of a request's own model (another provider's entry for the same model id, a provider id that names no model of the session, a model id two providers serve, and a telemetry label that matches a registered provider while the session serves that model id twice all leave the request unresolved and counted, while a single catalog entry and the request's own provider id resolve), the provider id written for a request, a session that switches its journal and the id it left behind, and the `/qol` line.
- **Real OMP CLI**: OMP `18.8.3`, a configured provider and model, with `compactionUsageEnabled` on and the extension loaded from this checkout. Observed: a manual `soft` compaction wrote `compaction:turn-prefix`, `compaction:summary`, and `compaction:short-summary` entries with `api: openai-completions`, `provider`, and `model` matching the host's own main-turn entries and costs that reconcile with the host's own per-token prices; a second `soft` compaction wrote its two requests and no third one, because that run's short summary sufficed and no summary request was sent; an automatic `handoff` compaction wrote a `compaction:handoff` entry carrying input, output, and cache-read tokens and the provider's cost for each; a manual `/compact` under a handoff-only method order was refused by the host and wrote nothing; `/qol` reported `compactionUsage: enabled (entries=3)` and `(entries=2)` in those sessions with no `costMissing` and no `unrecorded`. In one session the host's own `/session` statistics, read before and after a `soft` compaction, moved by exactly the two entries that compaction wrote (input 201 → 774, output 2 → 317, total 4,939 → 5,827, cost 0.0000 → 0.0003), which is the delta the statistics were missing.
- **Real OMP CLI, session switch**: one session was compacted, switched with `/new`, and compacted again, all in one process. The second compaction wrote its `compaction:turn-prefix` and `compaction:short-summary` entries into the journal the session switched to, and `/qol` reported `compactionUsage: enabled (entries=4)` with no `costMissing` and no `unrecorded`. Every written entry named `api: openai-completions`, the `provider` and `model` of that session, which are the provider, model, and api the host recorded for its own main-turn assistant message in the same journal.
- **Real OMP CLI, label conflict**: one session was compacted on the same host. The `compaction:turn-prefix` (input 135, output 169, cache read 128) and `compaction:short-summary` (input 323, output 173) entries it wrote, and the host's own main-turn entry in that journal, all named `api: openai-completions`, the same `provider` and `model`, and `/qol` reported `compactionUsage: enabled (entries=2)` with no `costMissing` and no `unrecorded`. The deployment's label and provider id are the same string, so this run shows that the stricter rule keeps resolving a request whose identity is reachable, not that it decides a normalized label.
- **Not verified**: `compaction_native` and `branch_summary` requests (out of scope by design), a host that already records these requests (the retirement path runs against a stubbed export, not a released fixed host), a session resumed across a compaction other than the one exercised, a non-TUI mode, and a process with two sessions compacting concurrently. The inheritance path is covered by the recording host and by reading how the host copies a parent's configuration; no live run exercised it. A real request whose identity its session's registry cannot resolve is not exercised either: the skip is covered by the recording host and by independent probes against the locked host's telemetry. The provider of this deployment does not normalize its label, so on the live runs the raw provider id and the label are the same string. A host that normalizes the label and reports no raw provider id beside it is covered by the recording host and by those probes only, and it leaves a request unrecorded whenever the session serves that model id under more than one provider, rather than deciding from the label.
- **Upstream history**: the `soft` and `handoff` request usage was recorded in the session journal with `479e14a71c` (2026-10-09), discarded model requests including stale speculative summaries were billed with `f4db4d7e64` (2026-10-09), billed failed attempts and the `compactionRequestUsage` export arrived with `cef6b029b4` (2026-10-09), and the provider-computed chat cost was exported to the estimator path with `a3cdfbdd58` (2026-10-01). These arrived through [pull request #15034](https://github.com/can1357/oh-my-pi/pull/15034).
