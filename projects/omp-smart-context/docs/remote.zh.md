# 远端压缩对齐

[English](./remote.md)

OMP 从历史准备 Remote 压缩的方式不同于普通请求。系统指令、工具定义、提醒或历史的差异可能破坏共同前缀，导致缓存失配。本能力将符合条件的共同内容与同一会话已经发送的普通请求对齐。

## 启用

设置 `compactionCacheEnabled=true`，将 `compactionCacheProviderFilter` 设为当前模型的精确 Provider 名称，然后重启 OMP。命令及默认值见[配置](../README.zh.md#配置)。

当前模型必须支持 Remote，且 OMP 必须选择 Remote。筛选值只决定是否修复该请求，不改变模型、Provider、路由或压缩方式。不匹配时原生压缩仍正常工作，只是不做对齐。

覆盖主会话、原生 task 和 Eval 子会话中的非 Codex `openai-responses` V2。[Handoff](./handoff.zh.md) 使用独立开关。

原生 CLI/SDK 会话可在 eager 加载、缓存命中延迟加载或进程恢复后建立参照，无须特殊启动 flag 或删除缓存。手工构造 Agent 或替换私有准备函数不在本支持范围内。

## 模式

`compactionCacheMode` 接受：

- `standard`：对齐已识别的原生请求准备差异。
- `hooks`：共同内容可验证时，还可复用扩展已完成的处理结果。这是默认值。

两种模式均不重复运行上下文处理器、不恢复被裁剪的工具输出、不改变原生输出限制，也不会自行启用 Remote。扩展变换的内容无法安全复用时，两种模式都可能拒绝对齐。

未持久化的隐藏 Agent Eval 快照属于显示元数据。已持久化快照及恢复时重建的副本仍属规范历史，用户归属内容和其他自定义消息也保留。没有 id 的不透明压缩项仍保留原始字节。已知 `include_obfuscation` 差异保留 Remote 自己的值或缺省状态；未知流选项差异使请求保持原生。

## 查看结果

运行 `/smart-context` 查看 Remote 部分。启用后先发送普通提示词，让扩展获得可供比较的请求。

- `awaiting-reference`：等待已确认且符合条件的普通请求。
- `already-aligned`：无需改写，已对齐。
- `rewritten`：请求已对齐。
- `rejected`：无法验证对齐，请求保持原生，未被阻断。
- `unavailable`：配置、必要宿主接口或其他扩展的接口占用冲突导致不可用。

导航、模型或工具变化、取消及压缩可能使先前普通请求不再可用。新的普通工作可恢复未来对齐资格。字段和计数见[状态](./status.zh.md)。

## 限制

触发、准备、裁剪、凭据、重试、回退、采用、历史提交和续接仍由 OMP 控制。普通及范围外请求不变。请求差异无法识别、会话身份歧义或共同内容不足时，完整压缩请求保持原生。

对齐让共同请求前缀具备缓存复用条件，缓存可用性和计费取决于提供方。改写成功不承诺固定命中率或收益。

停止对齐时，设置 `compactionCacheEnabled=false` 后重启，或移除包后重启。已有在途工作属于正在运行的进程。
