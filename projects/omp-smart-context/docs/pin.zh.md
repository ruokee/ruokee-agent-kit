# Context Pin

[English](./pin.md)

让选定文本出现在当前会话分支后续每次普通模型请求中，包括压缩之后。文本保持有效，直到更新、取消固定或重置。固定不会提高指令权限，不恢复撤销授权，也不重新启动已完成工作。

## 启用

通过[原生配置](../README.zh.md#配置)设置 `pinEnabled=true`，然后重启 OMP。默认 `false`，关闭时没有 `/ctx-pin` 或 `ctx_pin`，也不新增 Pin 文本。已有记录和历史保留，重新启用后恢复受支持记录。

启用前移除旧独立 Pin 注册及加载它的手动路径，见[迁移](./migration.zh.md)。OMP 自身的 `/pin` 命令与本能力无关。

## 用户命令

- `/ctx-pin` 打开当前分支条目列表，可选择添加、已有条目或关闭。列表按宿主主题显示 `#<id>` 和缩短的正文预览。
- `/ctx-pin add <body>` 提交 `add` 后一个分隔空格之后的文本。后续空白及字符全部保留，不按 shell 引号或反转义规则处理。
- 未知子命令或缺少正文只显示用法，不发送消息。

查看条目和编辑草稿只读，不发送消息、不改变 Pin 状态，也不打断运行轮次。放弃草稿无影响，确认后关闭列表。

### 确认生效

确认写入会发送一条只包含草稿正文的普通用户消息。OMP 消费该消息，并确认目标会话、分支和条目仍匹配后，操作才生效。在此之前保持待处理。结果说明已接受、未变化或未应用，并给出受影响条目及原因。

编辑已提交消息后，它成为普通文本，不再作为 Pin 操作。引用草稿、恢复消息及其他进程提交的消息也只是普通文本。已确认草稿仍待处理时，重复完全相同文本可能被识别为该草稿。应用前切换会话、重启或关闭会丢弃待处理工作。消费后被拒的写入，不会在容量或分支状态变化后自动生效。

## Agent 工具

`ctx_pin` 提供：

- `list`：显示全部编号、创建来源、修订号及 UTF-8 大小，不含正文。
- `get`：传整数 `id`，读取一条完整正文及元数据。
- `show`：读取所有活跃完整正文及元数据，以及条目数、总字节和分支上限。空集报告零。
- `create`：传 `content`，固定新正文。
- `update`：传整数 `id` 和完整替换正文 `content`。
- `delete`：传整数 `id`，取消固定条目。

`content` 必须是非空字符串，文本原样保留。

编号是会话内正整数，显示为 `#<id>`，不复用，也不接受数字字符串。更新和删除操作当前条目，不接收修订号参数。显示的修订号只供参考，因此旧草稿可能覆盖更新正文。更新保留最初创建时的 `user` 或 `agent` 来源。

读取和正文未变更新不改变记录或活跃状态。Agent 写入不启动模型轮次，OMP 将已接受变更带入普通工作。重试已接受调用返回原结果，不重复写入或回退旧正文。任何动作都不隐式创建缺失条目。

全部动作使用 `read` 批准档位。没有显式工具策略时，`always-ask`、`write`、`yolo` 不为 Pin 弹出批准。显式 `prompt` 或 `deny` 仍有效。Pin 不修改用户配置，也不增加独立授权检查。

### Agent 使用建议

主动固定丢失后会影响后续行动的信息，不等用户提醒。遵守明确固定要求，其他情况下跳过易恢复事实。按用途而非形式判断信息价值。当前事实、恢复入口和完成提醒只要仍指导后续行动或防止重复工作，就应保留。

独立变化的主题分别固定。更新已有主题，不重复创建。每次发送完整替换正文，保留仍有效的条件、否定、例外、不确定性、义务及受保护原文。候选变化不扩大权限，也不解决尚未解决的条件。

主题仍有用，但事实改变或部分正文失效时使用 `update`。整个条目失效、被取代或重复时使用 `delete`。不要把不再影响后续行动的历史改成摘要继续保留，也不要连同失效部分一起丢弃仍有用的信息。

行动前先修正撤销权限和失效目标。同轮合并普通变化，等待或交付前保留恢复所需状态。内容未变的读取、常规命令、新请求或压缩本身不要求再次写入。不重复已接受的用户写入。引用只是恢复入口，工具不会自动读取它们。

## 容量

单条正文和当前分支全部活跃正文分别有 `16,384` UTF-8 字节上限。计算字节，不是字符或 token。拆成多条不减少总用量。

超限写入不改变状态。单条超限报告正文大小、单条上限及超出值。分支超限报告当前总字节、被替换正文用量或创建时的零用量、新正文用量、尝试总量、上限及超出值。两者均不附活跃条目预览。

重试前复核整个活跃集合，可用 `list` 查看概览。单条超限须缩短该正文，删除其他条目不能解决它的大小问题。分支超限须删除失效条目，更新仍有用的条目以去掉失效部分，再精简冗余文本。不得未经其他条目复核就反复缩短拟写正文重试。

保留仍有效的事实、要求及必须逐字保留的文本。若全部内容都必要，说明容量冲突，只做无损精简；仍不能容纳就停止该写入。超限时仍可读取和删除。元数据、工具历史及旧修订不受活跃正文上限约束，完整请求仍可能过大。

## 重置

- 成功 `/clear` 结束当前分支 Pin 期间，旧条目不再活跃，编号不重置。
- `/new` 建立独立会话，拥有自身 Pin 和编号。
- `/fresh` 更换提供方流状态，但保留本地历史和 Pin。
- 分支切换及 `/tree` 加载所选分支的 Pin，重启恢复宿主已保存的记录。

压缩本身不取消固定。提交压缩后，当前正文在宿主摘要旁恢复。原生用户消息及不透明历史仍可能包含较早或重复文本，Pin 不改写这些历史。

## 持久化

Pin 存在宿主会话日志中，可以追加记录，但不能创建会话文件或强制写盘。在 OMP `18.5.0` 中，明确要求保存、会话文件已存在或已有助手回复时宿主才写盘。新建未保存会话的 Pin 可能在进程退出后丢失。弹窗和工具描述会提示此限制。

确认写入但 OMP 从未消费消息时，Pin 不变。操作成功不等于另有一次写盘确认。关闭或移除能力不会删除会话日志或历史文本。

## 记录损坏

受支持记录使用版本 `2` 和整数身份。不支持或损坏的活跃记录使该范围内 Pin 不可用，停止新写入及新增保留文本消息，并在首次受影响请求报告警告。扩展保留记录原样。

新建会话或用 `/clear` 重置受影响期间。早前期间的损坏不使新活跃集合失效。不要为了改名旧 `omp-context-pin` 数据类型而编辑或转换日志。
