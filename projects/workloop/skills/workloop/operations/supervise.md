# Supervise

Apply the loaded [entry](../SKILL.md), then read [Task ownership](../references/task.md), [execution constraints](../references/execution.md), [role selection](../references/roles.md), and [collaboration](../references/collaboration.md). Coordinate the Plan through independent Builders. Each Builder implements, self-checks, repairs, and coordinates its independent Verifier.

## Resolve the Plan

Read the owning Task's goal, mandatory `plan.md`, linked unit details, dependencies, effective decisions, candidates, reports, and project rules. Return only the scope affected by incomplete preparation to [Clarify](./clarify.md); a Builder receives only a complete contract. Apply the shared execution constraints to real dependencies and unresolved contracts.

Apply execution constraints to the selected scheduling scope, continuous progress, permissions, and prohibition on structured questions. A Builder receives one part of the overall Plan scope. Supervision uses a Senior only when explicitly assigned; integration needs its own grant. Resolve Builder, Verify, and an explicitly assigned Senior independently under the role rules.

Keep Task, basis, scheduling scope, grants, restrictions, unit states, and next actions recoverable. Collaboration records hold live identities, routes, pending assignments, editing ownership, and resource locations; durable product materials hold the Task context.

## Assign work

Choose dependency-ready work delivering complete goal-level results. Keep interdependent work with the same Builder, including several serial units where useful. Goal, executor, and delivery boundaries may differ. Use separate Builders only for genuinely independent work when scope and project rules permit; separate files alone do not establish independence.

Assign through the workloop [Execute](./exec.md) operation, which owns implementation, lightweight main-session self-check, repairs, coordination of independent Verify, and execution records. The Verifier owns actual verification, evidence collection, verdicts, and rechecks. The Supervisor keeps to coordination.

Under the collaboration contract, supply Task, unit and Plan basis, working location, editing boundary, grants and restrictions, dependency candidate/base, required checks, authorized materials, expected result, stopping point, and live reply owner. Include an assigned Senior's scope and route when present. State the structured-question prohibition in plain language alongside any `noask`. Delegate only granted actions; stops follow effective scope.

## Coordinate candidates

Use one editing owner for shared files or logic, freeze candidates under review, and reuse suitable isolated Verify and assigned Senior sessions through the collaboration rules. A busy role finishes or recovers its current assignment before receiving another.

Preserve each completed candidate under project commit and branch conventions. Use verified dependencies under the execution constraints, keeping predecessors frozen, bases traceable, and descendants refreshed when a predecessor changes. External dependencies still require their actual state.

## Process results

Validate each final result's sender, Task/unit, candidate/base, changed scope, checks, self-check count and outcome, independent verdict and saved report, and limits. Read the report. Independent Verify comes from that report; lifecycle state, implementation claims, and self-check success stay separate.

Return in-scope findings to the original Builder for repair. The same suitable Verifier rechecks affected behavior with enough surrounding coverage, using still-valid evidence. Apply count resets under the shared self-check policy. For `unable to determine`, resolve the specific evidence or capability gap within the grant. Recover saved results after communication failure instead of duplicating work.

Material or design defects return affected work to Clarify, where redesign happens. Consult an assigned Senior only within its role boundary. State genuine user-only blockers in ordinary text and continue independent ready work.

After each current pass, save the result and schedule the next authorized ready unit in the same supervision. When the selected scope is verified, return its candidates together for user review or already-authorized delivery. Integration follows its own grant.

## Return

Save substantive scheduling outcomes in the owning execution record: units, bases, candidates, report links, coverage, repairs, and blocked dependencies. Subtask evidence stays with its owner; the parent links it.

Return concise per-unit implementation status, self-check count, independent verdict/report, candidate/base, review and delivery state, and concrete remaining blockers. Preserve the whole selected scope if some units remain blocked. Supervision completion covers scheduling; merge, installation, publication, and Task closure follow their own grants.
