# 交付

完整读取[公共合同](../SKILL.md)。根据项目的 Ship 定义、用户实际请求及有效许可交付所选结果。Ship 没有固定动作包，不一定表示生产发布或 Task 结束。

## 解析交付

读取所属 Task、目标、所选单元与候选、执行记录、当前独立核验及项目交付指引。明确请求的结果和可观察完成条件。已有项目定义时直接使用，不要求重新初始化。

例如项目可将 Ship 定义为提交 PR 等待维护者审查、启动本地应用供评估，或更新 Harness 安装并进行已授权试用。这些是不同项目定义的选项，不是所有项目都必须执行的步骤。PR 交付目标不将 Task 管理迁出 tk。

项目没有 Ship 定义时，采用无歧义的用户请求。二者仍留下重要选择时，指出该选择及最小所需决定，不虚构通用的合并、安装、发布流程，也不默默执行。遵循当前问答及写入限制。

## 核对就绪状态

明确实际交付对象、依赖顺序、当前 Verify 覆盖、验收状态及必需项目门禁。其他候选或只覆盖部分范围的通过，不覆盖本次交付。读取已保存报告，不只依据 Agent 的通过消息。保留有效证据，只重复候选或目标变化导致失效的检查，以及项目要求的检查。

区分用户验收、预先批准、动作许可及实际完成。直接交付请求可以授权项目定义的常规交付动作，复用有效许可，不重复索取。验收依据是用户明确表示或满足项目验收条件的证据，不仅凭操作名称推断。该请求不隐式授权无关目标或项目定义外的受保护操作。Verify 本身不提供交付许可。

项目要求集成时，使用规定方式及最终候选检查。对于依赖分支栈，保留各单元身份，按依赖顺序交付。准备不同集成候选可能使受影响证据失效，重新检查后才能视为已验证。项目目标若是运行服务或提交 PR，则判断该实际目标，不把合并设为通用前置。

缺少必需批准、许可、产物或外部状态时，阻塞依赖该条件的动作。继续不受影响的授权准备，不削弱门禁，不将未执行动作写成完成。

## 执行交付

只执行已解析的交付动作。常规步骤复用有效许可，取得项目要求单独授予的受保护许可。不因操作名称为 Ship 而增加推送、发布、部署、本机安装、重启、费用或破坏性清理。

观察实际目标位置及结果。安装与发现、重启与加载成功、运行与验收、提交与审查、发布与用户满意分别判断。依据项目完成条件记录交付候选和目标位置的实际观察。仅停止自己拥有或获准控制的进程和资源，授权清理前保留重建证据。

有证据的实现缺陷返回[执行](./exec.md)，目标、材料或设计问题返回[澄清](./clarify.md)。保留不受影响的已完成结果。交付反馈有独立目标或边界时，可以在任务创建许可内另建 tk Task，否则继续当前 Task。不强制每次交付追加效果测量阶段。

## 返回

保存获准的交付记录，包含 Task 及范围、来源候选与实际交付身份、目标位置、项目定义结果、实际动作及检查、观察、证据位置、偏差及剩余要求。链接相关执行和核验记录。

分别报告实际状态：项目目标达成或阻塞、运行或送审、验收结果、集成、适用的安装或重启，以及发布或生产交付。省略真正不适用的状态，不省略尚未完成的必需工作。反馈需要返回 Clarify 或 Execute 时注明受影响范围。

达到项目当前 Ship 目标不自动关闭 Task。遵循 tk、项目生命周期规则及用户实际关闭许可，不仅因操作名称就声称用户验收或生产交付完成。
