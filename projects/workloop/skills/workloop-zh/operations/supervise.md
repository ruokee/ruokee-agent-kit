# 监督

遵循已加载的[入口](../SKILL.md)，读取[任务归属](../references/task.md)、[执行约束](../references/execution.md)、[角色选择](../references/roles.md)和[协作](../references/collaboration.md)。通过独立 Worker 协调 Plan，不实现他们的改动，也不担任其独立核验者。

## 解析 Plan

读取所属 Task 的目标、必需的 `plan.md`、链接单元细节、依赖、有效决定、候选、报告和项目规则。准备不足时将受影响工作返回[澄清](./clarify.md)，不交给合同不完整的 Worker。

按执行约束处理所选调度范围、连续推进、许可及禁止结构化问答。Worker 范围不同于总体 Plan 范围，监督不启用 Senior，也不授权集成。按角色规则独立确定 Worker、自检者、Verify 及明确分配的 Senior。

保留可恢复的 Task、依据、调度范围、授权、限制、单元状态和下一步。协作规则管理实时身份、路由、待完成分派、编辑归属和资源位置，不将它们写入持久产品材料。

## 分派工作

选择依赖就绪且产出完整结果的单元。Worker 通常一次处理一个单元，也可在明确分派内串行完成多个。只有范围和项目允许时，才让独立 Worker 并行处理独立单元。不跨共享编辑或未决前提制造并行。

通过 workloop 的[执行](./exec.md)操作分派，由它负责实现、实际检查、自检、独立 Verify 和执行证据。不加载或复制其自检算法来替 Worker 检查。

按协作合同提供 Task、单元及 Plan 依据、工作位置、编辑边界、授权和限制、依赖候选或基线、必需检查、获准材料、预期结果、停止点及当前回复负责人。有已分配 Senior 时包含其范围和路由。用普通文字传达禁止结构化问答，不只写 `noask`。不分派未授权动作，不添加违背有效范围的停止条件。

## 协调候选

共享文件或逻辑只设一个编辑负责人，审查期间冻结候选，按协作规则复用合适的隔离 Verify 和已分配 Senior 会话。忙碌角色先完成或恢复当前分派，再接收下一项。

按项目提交与分支惯例保留已完成候选。遵循执行约束使用已验证依赖，冻结前序，记录基线，前序变动时刷新后继。外部依赖仍需要实际状态。

## 处理结果

逐项核对最终结果的返回者、Task/单元、候选或基线、变更范围、检查、自检次数与结果、独立结论和已保存报告及限制。实际读取报告。生命周期状态、实现声明和自检成功都不是独立 Verify。

范围内发现交回对应 Worker，不重置自检计数。要求受影响检查及同一合适核验者的独立复查。`unable to determine` 时在授权内解决准确的证据或能力缺口。通信失败后恢复已保存结果，不重复工作。

材料或设计缺陷将受影响工作返回 Clarify，不通过实现分派重新设计目标。仅在角色边界内咨询已分配 Senior。用普通文字说明必须由用户决定的真实阻塞，同时继续独立就绪工作。

每项当前通过后保存结果，继续分派下一项已授权就绪单元，不再索取继续指令。所选范围全部核验后，一起提交候选供用户审阅或进行已授权交付。不为继续调度而擅自集成。

## 返回

在所属执行记录保存实质调度结果：单元、基线、候选、报告链接、覆盖、修复和阻塞依赖。子任务证据归其所有者，父任务保留链接。

简要返回各单元实现状态、自检次数、独立结论及报告、候选或基线、审阅和交付状态及具体剩余阻塞。部分单元阻塞时仍保留完整所选范围。监督完成不表示合并、安装、发布或 Task 关闭。
