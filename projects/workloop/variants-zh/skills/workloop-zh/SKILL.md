# workloop

引导 Task 澄清目标、实现、独立核验，并完成项目定义的交付。这些指令引导 Agent 行为，不通过程序强制执行。

## 解析请求

完整读取本入口。根据用户、适用指引和当前上下文解析实际请求、项目、有效要求、范围及许可。没有新增参数不等于没有 Task 上下文：当前 Task 和目标清楚时直接继续，仅在无法确定时补充信息。引用、解释或编辑指令不表示请求执行它。导览请求只获得说明。

通过 tk 的公开接口及适用接口指引管理持久 Task，例如使用 tk-cli，不依赖 tk 的实现文件。其他 Skill 和协作工具只用于需要它们的活动。Setup 和导览不需要占位 Task。

## 加载活动

沿实际安装目录解析链接。完整读取所选正文，再按其中的条件读取 Reference，不遍历全部 Reference，也不加载无关操作。

- [澄清](./operations/clarify.md)：明确目标，调研、设计并形成或修订 Plan。
- [执行](./operations/exec.md)：当前会话实现并协调检查。
- [核验](./operations/verify.md)：独立评估准备材料或执行产出的候选。
- [交付](./operations/ship.md)：完成项目定义的交付。
- [监督](./operations/supervise.md)：调度独立 Worker，不亲自实现其工作。
- [设置](./setup.md)：按请求初始化或更新外部默认，不是安装或普通使用的前置条件。

## 保留合同

使用用户语言，遵循适用项目写作规则，并在可用时使用 well-said 一类写作 Skill。保留事实、决定、条件、否定、归属及真实不确定性。

区分已确认要求、用户指定约束、提议、观察和临时限制。代码、生成材料、测试或完成声明都不构成批准。动机不增加验收门禁。按有效决定处理冲突，不悄悄替换目标、缩小范围或取消能力。对不必要、不可行或有害工作提出质疑并说明证据。暂缓能力不等于永久禁止。只重开受影响工作，保留已完成结果。

workloop 面向新任务，不提供旧入口别名或材料名称迁移，仍支持自身 Task 的继续、修复和恢复。遵守所请求操作的权限；产出材料或检查通过不授权无关动作，也不授权 Task 关闭。

直接行动，不主动预检工具、环境或文件可用性。实际失败后记录错误，只获取在现有许可内解决问题所需的事实。不虚构替代品，不隐藏缺失前置条件，不削弱验收。

## 恢复指令

在可恢复会话状态中保留当前操作、有效范围和限制。各活动另行规定自身所需状态。本入口、所选正文或当前必需 Reference 离开上下文后，行动前从实际安装位置重新加载。记得路径不等于正文仍在。对照实际效果恢复状态，不重复已完成工作或待完成分派。不要求特定持久化 API；重读提供指令，不证明遵守。
