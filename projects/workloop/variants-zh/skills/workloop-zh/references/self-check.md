# 自检

Clarify 或 Execute 启动自检时读取，检查对象和结果位置由调用操作指定。自检与独立 Verify 分开。

## 检查

由当前负责产出的主会话在自身上下文完成自检。自检不使用子代理或独立检查者。对照当前目标、变更产物、相关 Task 材料、有效用户要求及项目指引，检查矛盾、遗漏、过时陈述和写作质量。

保持轻量检查。后续检查聚焦新增差异、未解决发现和影响结果的关键反例。实现调试归 Builder，实际验证、取证、判定和复验归独立 Verify。

## 计算次数

上限为五次。准备材料及各实现单元分别计数，完成一次实质检查占一次。讨论发生变化或验证完成时，主会话 SHOULD 重置适用计数。记录重置条件，保留此前结果。普通编辑和会话恢复保留当前计数，满足重置条件时按该条件处理。

当前候选通过即停止自检，首次通过也如此。未通过时修复可处理发现，在未达上限时检查受影响差异。避免为不实质影响正确性、一致性、目标或实际使用的细节反复检查。

达到上限后不再追加检查，完成可处理修复，报告未解决发现和未经过后续自检的变更。必需工作未解决仍阻塞完成。旧候选的通过适用于该候选。

## 保存结果

在调用操作的记录中保存结论、候选、累计次数与上限、重置条件、发现、修复及未复检改动。保留失败检查。在可恢复状态中保留当前计数和适用的重置状态。

Plan 形成后默认进行准备自检。准备阶段独立 Verify 只按用户请求启动，不因自检耗尽而启动。每个实现单元都需要自检和独立 Verify。独立 Verify 不受自检轮次上限限制，两者不能互相替代。
