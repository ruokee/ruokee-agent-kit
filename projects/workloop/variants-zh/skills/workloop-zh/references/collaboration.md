# 协作

首次跨会话分派或接收任务前读取，包括自检、独立 Verify、Worker 派工或已分配 Senior 的咨询。单会话 Setup 和无需协作的工作不读取。需要选择角色时遵循[角色选择](./roles.md)。

## 建立路由

协作终端由用户或项目选定，例如 Tern、Herdr、tmux；所列工具仅为示例，不是偏好。使用所选工具支持的接口及指引，所选工具有专属 Skill 或运行条件时按需加载；不因文档列举其他工具而加载其 Skill 或检查其环境。明确工作位置，正常启动，发现实时身份后以普通消息分派，不注入系统 Prompt。不操作其他 Agent 的问答对话框。

分派说明所属 Task、单元、依据、准确范围、候选或依赖基线、授权和限制、所需结果、报告位置、停止点及当前回复负责人。不假定共享会话历史。独立 Verify 只提供 Task、单元或材料范围、候选位置和回复负责人，让核验者自行解析依据，不提供实现者的审查清单。

## 隔离工作

同一文件或逻辑同时只有一个编辑负责人。审查期间冻结候选，核验者不得实现过目标，实现与核验上下文分开。

跨单元和复查复用合适的隔离 Verify 会话及明确分配的 Senior 会话。忙碌角色先完成或恢复已有分派，再接收下一项。没有合适会话或明确要求替换时才新建。自检另按自身规则每次使用新上下文。

不发送未经请求的中途消息，不读取工作中 Agent 的私有会话文件。只发送最终结果，有限 Senior 咨询作为单独分派。

## 接收结果

跨会话工作和咨询默认等待最终结果。使用协作工具的等待操作；命令转为后台后，使用宿主的阻塞式最终结果等待，直到结果或具体阻塞到达。不轮询，不从生命周期状态推断结论。

只有显式 `nowait` 允许省略这些跨会话等待。保留待完成分派，最终结果到达后恢复工作，不再例行索取继续指令。`nowait` 不改变原生自检最终结果屏障、范围、必需检查或验收。向负责人回复最终结果后不再等待负责人。

推进前核对返回者、Task/单元、候选、结论和已保存报告。证据缺失、过期、截断或冲突时澄清，不推定通过。送达失败时先恢复已保存结果再考虑重派。可能已经成功的非幂等动作须先核对效果，不直接重复。

## 保留实时状态

角色选择、实时身份、回复路由、所拥有资源、待完成分派和等待限制写入可恢复会话状态，与持久产品材料分开。恢复后先核对实际分派及效果，再重新发送工作。行动前替换已撤销授权，以普通文字保留限制，包括有效时禁止调用结构化问答工具。
