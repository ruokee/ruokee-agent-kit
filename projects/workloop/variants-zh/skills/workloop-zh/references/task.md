# 任务归属

Clarify、Execute、Verify、Ship 或 Supervise 解析或保存 Task 材料前读取。Setup 和导览不需要本 Reference。

## 确定归属

分派单元或保存材料前，使用 tk 公开接口及适用任务管理指引。同一工作线复用现有 Task。父任务、依赖、共享顾问或旧会话不会自动拥有新结果。创建、关系、元数据及关闭遵循 tk 和项目许可，不手工修改托管元数据。

继续、修复和恢复 workloop Task 时保留原身份与有效要求。Plan 内的单元标签保持稳定，新序列从 U01 开始，不机械地为每个单元创建子任务。执行链接单元或修改其父任务合同时，读取链接细节。

父任务保存跨单元决定和链接，子任务结果归子任务。稳定结果写入普通材料，实时角色选择、路由、待完成分派、所拥有的运行资源和临时许可状态保存在可恢复会话上下文。

## 保存结果

操作请求通常授权保存该操作的普通结果材料。复用已有文件，更新前先读，有意义结果形成后及时保存，返回前落盘。操作正文规定自身材料格式，辅助 Skill 的记录规则仍用于使用它的活动。

仅对话、不记录、不写入或更窄限制优先。目标位置确实无法确定时说明缺失信息，不另找位置绕过限制。存储限制阻塞必需的保存结果，不阻塞无关就绪工作；不声称尚未保存的报告已经存在。

可选活动不需要空文件或材料职责对应表。保存材料不授权实现、配置、Git 操作或 tk 生命周期转换，分别遵循这些动作的有效许可。

## 绑定证据

实际检查改变的行为，运行适度且项目要求的检查。记录范围、候选身份、条件、实际输入、观察、证据位置、覆盖、偏差及未验证部分。区分源码和文件检查、受控 Provider、宿主发现、实际 UI 或模型运行，以及用户结果。自动化成功本身不证明所需行为。

变更使受影响证据失效。复用未变证据时说明其作者、候选、条件、结果和范围，不声称独立重跑。没有要求和许可时，不增加安装、昂贵实验或效果指标。

实现、自检、独立 Verify、用户审查、交付、安装、重启、发布和 Task 状态分别判断。操作结束不关闭 Task。
