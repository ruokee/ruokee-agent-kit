# 执行约束

进入 Execute 或 Supervise 时读取；Clarify 形成 Plan、安排依赖及权限时也读取。以下执行限制约束 Execute 和 Supervise，Clarify 读取它们不表示进入执行，也不取消其获准的访谈方式。

## 解析范围

指定单元或子集时遵循该分派范围，否则从当前或首个未完成且依赖就绪的单元开始，继续剩余 Plan。会话通常同一时间处理一个单元，可以串行完成多个。引用的控制词、示例或否定不改变范围和许可。

区分 Plan 的完整范围和实施就绪条件。待澄清及受阻的子任务工作仍保留在父 Plan 中。按有效范围和许可将所需准备交给 Clarify，不分派为实施 Worker 的工作。实施该项工作前读取形成的子任务材料，更新父计划的下一步、依赖和链接。其他无关且已授权的就绪单元继续；准备完成或这些单元完成，均不表示未解决范围已完成。

实现、修复、自检、独立 Verify 及必要复查不因例行中间确认停止，无需另加 `auto` 或 `noask`。`confirm` 表示逐项确认，不取消必需检查。保留明确的人工接入点。

Execute 和 Supervise 期间不得调用 `ask` 一类结构化问答工具，也不得通过包装工具或其他 Agent 绕过。先读已有事实，作出已授权选择。必须由用户决定的问题用普通文字提出，同时继续不受影响的就绪工作。显式 `noask` 同样禁止结构化问答，恢复时保留这一含义。

## 分离许可

执行请求通常授权项目要求的范围内常规实现、修复、项目本地准备、检查、临时进程和保留本地候选所需操作。复用有效授权，不重复索取。已授权的临时目录文件检查仍属于其检查范围。

执行不自动授权提案批准、归档、集成、推送、发布、本机安装、费用、特权操作或 Task 关闭。遵循项目特定要求和更窄限制。核验不是用户验收，验收也不授权无关动作。可预见的重要需求选择在实现前解决，不将所有审批一律延后。

缺少许可、未决需求或必需外部状态只阻塞依赖它们的动作，其他已授权就绪工作继续。保留完整所选范围，不将已完成子集称为全部结果。材料或设计缺陷将受影响工作返回 Clarify，实现偏差在 Execute 修复。

## 使用已验证依赖

项目规则允许时，以任务本地提交保留已验证前序候选，在集成或最终用户审阅之前从冻结候选开始依赖开发。记录各单元基线和候选，保持变更可独立审阅。不把后续工作混入已完成前序候选，不为开始下一单元而擅自合并。

分支不能代替确实需要的部署、服务或已发布产物。前序变化时刷新受影响后继、检查及 Verify 证据。保留未集成候选，供以后按交付许可依次处理。

Worker 到分派边界停止，执行负责人继续总体已授权 Plan。Worker 停止或单元通过均不要求再取得一次例行继续指令。
