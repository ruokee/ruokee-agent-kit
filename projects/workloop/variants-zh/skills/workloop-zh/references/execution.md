# 执行约束

进入 Execute 或 Supervise 时读取；Clarify 形成 Plan、安排依赖及权限时也读取。以下执行限制约束 Execute 和 Supervise；Clarify 读取它们时仍保持准备阶段和获准的访谈方式。

## 解析范围

指定单元或子集时遵循该分派范围，否则从当前或首个未完成且依赖就绪的单元开始，继续剩余 Plan。会话通常同一时间处理一个单元，可以串行完成多个。范围和许可来自请求的控制词；引用的示例和否定只作说明。

区分真实依赖与未决合同。已明确的 Plan 可以包含依赖前序结果的后续单元，这些单元都带有已明确的合同。按有效范围和许可将所需澄清交给 Clarify。未解决范围保留在 Task 目标和 Clarify 材料中；读取形成的决定并在实施该项工作前修订 Plan。其他无关且已授权的就绪单元继续；未解决范围在 Plan 材料中保持自己的位置。

执行中发现使合同失效的事实时，暂停受影响工作，把问题和选项记录到 Clarify 材料。保留 Plan 记录、已完成候选和仍有效证据；继续有明确合同且不受影响的获授权工作。澄清后修订受影响合同。Plan 保留已明确单元，问题返回 Clarify。

实现、修复、自检、独立 Verify 及必要复查不因例行中间确认停止；连续推进是默认方式，`auto` 和 `noask` 保持可选。`confirm` 表示逐项确认，不取消必需检查。保留明确的人工接入点。

Execute 和 Supervise 期间，结构化问答工具如 `ask` 留在操作之外，包装工具和其他 Agent 同样不引入。先读已有事实，作出已授权选择。必须由用户决定的问题用普通文字提出，同时继续不受影响的就绪工作。显式 `noask` 携带同一规则，恢复时保持。

## 分离许可

执行请求通常授权项目要求的范围内常规实现、修复、项目本地准备、检查、临时进程和保留本地候选所需操作。复用有效授权，不重复索取。已授权的临时目录文件检查仍属于其检查范围。

执行授权上述范围内常规工作。提案批准、归档、集成、推送、发布、本机安装、费用、特权操作和 Task 关闭遵循各自要求和更窄限制。用户验收独立于核验，覆盖其列明范围。可预见的重要需求选择在实现前解决，不将所有审批一律延后。

缺少许可、未决需求或必需外部状态只阻塞依赖它们的动作，其他已授权就绪工作继续。保留完整所选范围，将已完成子集作为子集报告。材料或设计缺陷将受影响工作返回 Clarify，实现偏差在 Execute 修复。

## 使用已验证依赖

项目规则允许时，以任务本地提交保留已验证前序候选，在集成或最终用户审阅之前从冻结候选开始依赖开发。记录各单元基线和候选，保持变更可独立审阅。已完成前序候选保持冻结；后续工作进入自己的候选，集成遵循自己的授权。

确实需要的部署、服务或已发布产物保持实际状态；分支服务于开发候选。前序变化时刷新受影响后继、检查及 Verify 证据。保留未集成候选，供以后按交付许可依次处理。

Worker 到分派边界停止，执行负责人继续总体已授权 Plan。Worker 停止或单元通过后，总体 Plan 直接继续。
