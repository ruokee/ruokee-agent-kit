# 路径探索

在 [Clarify](../operations/clarify.md) 解析请求后、展开调研前，判断工作是否超出一次工作会话，或路线是否仍受未决问题影响。满足条件时读取本参考。继续已有 map 时使用本参考，不重新建图。小型清晰的 Plan 及其普通修订不需要 map。大型但路线已清晰的工作可以直接完成设计并形成 Plan；map 反映真实未决问题。本参考只服务于 Clarify，沿用现有入口、生命周期和执行模式。

## 把 map 留在 Clarify 材料

map 属于所属 Task 的 Clarify 材料，默认作为 `design.md` 的一节。已有专门材料时沿用，既有材料保持原位置。保存以下内容：

- 目的地和边界：已确认目标及排除的工作。引用已确认目标，目标保持唯一需求来源。
- 背景、参考和长期偏好。它们提供背景；执行需要单独许可。
- 已作决定，一行一项，并链接完整设计和证据；它们保留在各自材料中。
- 尚不能准确表述的范围。问题清晰后移入待解决问题，实现步骤在解决后形成。
- 能准确表述的待解决问题，写明真实依赖、可解决它的方法、所需证据或用户决定、完成条件及材料归属。
- 范围外事项及原因。误记可以纠正；削减已确认范围仍需有效用户决定。

使用有意义的标题或既有材料标识。不占用 Plan 的 `U01` 单元序列，不引入 decision 单元类型。已有 tk 子任务保留自己的材料；父级准备材料覆盖全部已确认范围并链接子任务结果，不为每个问题创建子任务。

## 推进问题

研究、原型、访谈和准备是 Clarify 内的解决方法，与单元类型和生命周期分开。

- 研究读取本地或外部资料并形成证据。事实齐全后，方案仍由用户选择。
- 原型提供供用户判断的具体材料。Clarify 内可以形成获准的草图或示例文本；实现代码、配置变更和外部动作按各自权限处理。确需先运行原型时，把原型自身的目标、做法和验收确定为可执行的限定工作，按 Execute 的 Plan 与检查规则处理；其结果回到主任务 Clarify。
- 访谈只处理事实和既有要求无法回答的重要选择。优先级由用户决定。
- 准备记录阻塞决定的外部条件。完成要求条件实际成立；请求或清单标记进展，外部动作按各自权限处理。

按真实依赖聚焦当前问题。问题解决后更新决定、依赖和模糊范围，继续当前请求允许推进的问题。一个会话可以解决多个问题，建图后是否继续由当前请求决定。明确子集、人工接入点和真实阻塞仍然有效。研究并行遵循既有协作权限；同一 map 同时只有一个编辑者，活动会话路由保留在可恢复会话状态中。

## 形成 Plan

当前规划范围内的目标、必要设计、重要选择、各单元结果和验收均已明确，且影响执行合同的未决问题和模糊范围均已解决时，才形成 `plan.md`。仍有阻塞时保留准备材料，合同完整后再形成 Plan。

Plan 包含完整、可独立评估的单元及真实依赖，可以链接已确定的设计和证据。待选方案、决定记录、待澄清子任务和“先研究再决定怎么做”的步骤留在 Clarify 材料。`U01` 等标签只标识执行单元。

承担 Plan 工作的子任务必须完成其合同及所需 Plan，该项工作才可执行。当前范围仍有不清晰的子任务时，完整范围保留在目标与准备材料中，父 Plan 在子任务合同完整后形成。用户明确划定独立实施子集时，为该子集形成完整 Plan，其余范围在所属 Task 材料中保持自己的位置。

单元按依赖就绪开始。后续单元可以依赖前序结果，服务或部署前提仍按实际状态判断。Execute、Ship 和受保护动作需要各自许可。

## 执行开始后的返回

执行中出现的新事实可能使当前合同失效。记录受影响单元及依据，把问题和选项交回 Clarify 材料。保留 Plan 记录、已完成候选和仍有效证据；继续有明确合同且不受影响的获授权工作。澄清后修订受影响合同，修订后的 Plan 仍须完整可执行。

## 检查边界

准备检查分别判断 Clarify 材料是否忠实覆盖范围，以及已交付的 Plan 是否只包含已明确的合同。尚未形成 Plan 时，设计讨论独立成立；一旦交付 Plan，仍需澄清的合同不能通过。正式 Markdown 交付和另获授权的原型按实际对象接受实施检查，包括服务于 Clarify 的情况。自检轮次和计数保持现有规则，问题留在其准备轮次内。
